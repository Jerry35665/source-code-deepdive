# 《etcd/raft 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》的第四卷,也是系列从单机转向分布式的转折点。全部结论来自对 etcd-io/raft(commit `3cbf6a74`,v3.7/3.8 世代)与 etcd(commit `e9e56564`)源码的逐行阅读,每处关键论断标注 `文件:行号`。

## 这卷写给谁

读过《Redis 卷》第 07 章(复制哨兵集群)或对分布式一致性有概念的工程师;正在使用或自研基于 etcd/raft 的系统(TiKV、CockroachDB、CockroachDB 类存储、自定义共识服务)的开发者。需要基本 Go 阅读能力;Raft 论文不是前置要求——本卷把论文概念在源码中的落点逐一处标注。

## 为什么选 etcd/raft

1. **Raft 的事实参考实现**:TiKV、CockroachDB、etcd、Kubernetes(etcd)共同依赖;本卷基于最新独立模块(go.etcd.io/raft/v3),包含 2024-2026 年的异步写管线等最新演进;
2. **正确性论证即代码**:九步 ABA 注释、投票反例注释、TLA+ 规约与轨迹验证——这是"如何工程化一个需要被证明正确的算法"的最佳教材;
3. **体量适中**:1.16 万行核心代码,一个会话可通读,但覆盖分布式系统的全部核心难题(选举、复制、成员变更、线性一致读、持久化次序)。

## 环境准备

```bash
git clone https://github.com/etcd-io/raft.git && cd raft
git checkout 3cbf6a74          # 与本卷行号一致

# 跑事件驱动仿真(交互式观察状态机)
go test ./rafttest -run TestInteraction -v
# 看 datadriven 用例(推荐从 probe_and_replicate.txt 开始)
less rafttest/testdata/probe_and_replicate.txt

# 模型检查(可选,数小时)
cd tla && ./validate-model.sh
```

没有环境也可以读:Go 代码可读性高,GitHub 网页版按 `文件名 + 行号` 跳转。

## 三种用法

1. **系统通读**(约 4-5 小时):01 全景 → 02 状态机 → 03 日志复制 → 04 选举与 ReadIndex → 05 Node 与集成 → 06 总结;
2. **自研 Raft 评审**:第 04 章的不变量清单(I1-I10)+ 第 05 章的 Ready 四步——拿这份清单对照你的实现,缺一条就是一个潜在分区脑裂;
3. **etcd 运维进阶**:第 05 章的 raftNode 顺序不变量、WAL fsync 策略、慢盘观测点(heartbeatSendFailures)。

## 本卷的四个统一约定

- **行号即凭证**:全部基于 3cbf6a74;raft 库已从 etcd 仓库拆分为独立模块,旧资料按旧布局描述的文件路径需换算;
- **与前几卷互为镜像**:Raft 的 Progress 流控对照 Redis 的 backlog;raft 的 VersionEdit 对照 LevelDB 的 MANIFEST;8 字节对齐帧对照 SQLite/Redis 的 WAL 格式——各章显式标注;
- **安全性论证给全文**:Leader Completeness 六步推理、ReadIndex 的心跳等价论证、ABA 九步时序都完整呈现;
- **勘误显式标注**:`needSnapshotAbort` 已移除(Progress 与 raftLog 解耦)、etcd 未启用 AsyncStorageWrites、raft 库位置变迁。
