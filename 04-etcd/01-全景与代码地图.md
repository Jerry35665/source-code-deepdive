# 第 01 章 · 全景与代码地图:一个状态机库与它的宿主

> 基线:etcd-io/raft commit `3cbf6a74`(2026-09-02,1.16 万行 Go)+ etcd commit `e9e56564`(2026-09-03)。

## 1.1 一组数字认识这个项目

| 指标 | 数值 |
|---|---|
| raft 库核心代码(不含测试) | 11,561 行 Go |
| 最大文件 | raft.go 2,162 行 |
| 测试文件 | 31 个(含 datadriven testdata) |
| etcd server 集成层 | etcdserver/raft.go 453 行 + server.go 2,461 行 |
| 许可证 | Apache-2.0 |
| 官方设计文档 | doc.go(399 行包注释)+ design.md |

**与前几卷对照**:这是系列第一个 Go 项目、第一个"库而非完整服务"。raft 库没有网络、磁盘、时钟——只有状态机;etcd 的 server 层负责把 tick/网络/磁盘喂给它。**读这个库 = 读"共识算法如何被剥去一切工程外衣"**,而读 etcdserver/raft.go = 看"外衣如何穿回去"。

## 1.2 raft 库的文件地图

```
raft/                    go.etcd.io/raft/v3
├── raft.go       2,162  核心状态机(角色/tick/Step/消息处理)
├── doc.go          399  作者的正式设计文档(必读)
├── node.go         616  Node 接口:通道门面(协程 run 主循环)
├── rawnode.go      557  RawNode:裸状态机 + Ready/Advance + 异步写管线
├── log.go          576  raftLog 三段式(stable/unstable/内存游标)
├── log_unstable.go 240  未落盘条目双缓冲
├── storage.go      326  Storage 接口 + MemoryStorage
├── read_only.go    —    ReadIndex 两种模式
├── confchange/     419  联合共识的线性化 Changer
├── tracker/              Progress 三态机 + Inflights 窗口 + 计票
├── quorum/               纯数学:多数派/联合配置/中位数提交
├── raftpb/               protobuf 消息定义(24 种消息类型)
├── rafttest/             事件驱动仿真(interaction_env + datadriven)
└── tla/                  TLA+ 规约 + 轨迹验证
```

依赖方向严格单向:`raft.go` → tracker/quorum;`node.go/rawnode.go` → raft.go;`rafttest` → 全部。quorum 包与主逻辑完全解耦(只靠 AckedIndexer 接口取数)——**纯数学被独立成包,让性质测试与复用成为可能**。

## 1.3 etcd server 侧的关键文件

```
etcd/server/
├── etcdserver/
│   ├── raft.go      453   raftNode 适配器:Ready 消费循环(tick/落盘/发送/apply)
│   ├── server.go   2,461  EtcdServer:启动、run 循环、apply 调度
│   ├── v3_server.go 1,290  对外 API 的服务端实现
│   └── bootstrap.go  773  启动三分支(无 WAL/新集群/有 WAL)
├── storage/wal/           WAL 实现:段文件、Record 格式、repair
└── storage/backend/       快照数据的真正归宿(bolt.db)
```

**模块演进注意**:raft 库自 etcd 3.6 起拆分为独立模块 `go.etcd.io/raft/v3`(server/go.mod 中引用 v3.7.0)——网上大量资料仍按"raft 在 etcd 仓库内"的旧布局描述,读代码时以 `etcd-io/raft` 独立仓库为准。

## 1.4 一条主线串起全部文件

```
客户端请求 → EtcdServer.Process → Node.Step(propc/recvc)
    → raft.Step(两层分发) → raftLog/maybeAppend → trk/Progress 更新
    → maybeCommit(排序中位数) → Ready 组装(node.go/rawnode.go)
    → raftNode 消费循环(WAL 落盘 → transport.Send → applyc)
    → EtcdServer.run → FIFOScheduler → applyAll → 状态机应用
```

读代码的钥匙是 **Ready 结构**(node.go:52-115):SoftState(易失)/HardState(必须持久化)/Entries/Snapshot/CommittedEntries/Messages/ReadStates 七个字段就是 raft 与宿主之间的全部接口。第 02-04 章讲 Ready 之前的算法,第 05 章讲 Ready 之后的宿主。

## 1.5 两条阅读路线

1. **协议优先**(推荐):02 状态机 → 03 日志复制 → 04 选举安全与 ReadIndex → 05 Node 与集成。跟着"一条提案从 Step 到 apply"走完全部层次;
2. **安全优先**:02(持久化栅栏)→ 04(推理链与不变量清单)→ 03(confchange)→ 05(验证体系)。适合要自研 Raft 或做共识系统评审的读者。
