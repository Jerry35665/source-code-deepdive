# 第 06 章 · 激活器与工程文化:socket/timer/path 与 AI 纪律

> 基线:commit `1f66b524`。核心:src/core/socket.c、timer.c、path.c;根目录 AGENTS.md。

## 6.0 全景:fd 的一生与 timer 双轨

```
SOCKET ACTIVATION:socket_open_fds(五种端口:TCP/UDP/unix/fifo/mqueue/USB)
 → LISTENING(io 源 EPOLLIN)→ 连接到达 socket_enter_running:
    Accept=yes:manager 代 accept→实例化 foo@N-….service,每连接一个实例(两道限流)
    Accept=no :不 accept,service 反向收集全部监听 fd→单实例
 → exec 子进程:close_all_fds→pack_fds 压到 [3,3+n)(断言 fds[0]==3)→清 CLOEXEC
 → 环境四件套:LISTEN_PID/LISTEN_PIDFDID/LISTEN_FDS/LISTEN_FDNAMES
TIMER:OnCalendar(实时轨,calendar_spec_next_usec)∥ OnBootSec/OnUnitActiveSec(单调轨)
 两轨各取 MIN 谁先到点谁触发;Persistent 戳文件实现开机 catch-up
```

**fd=3 约定的全部机械细节**:0/1/2 是 stdio 遗产,`SD_LISTEN_FDS_START=3` 让约定区间与保留区间天然不重叠;pack_fds 用 `fcntl(F_DUPFD)` 在 close-all 后把任意散乱 fd 无损压进 [3,3+n)(fd-util.c:409-453)——协议只需一个计数变量,无需传输 fd 编号本身。

## 6.1 socket:一次 IO 事件的两种分派

Accept=yes:accept 后 `instance_from_socket` 用本机/对端地址拼实例名,fd 所有权移交实例服务,每源限流(max_connections_per_source)。Accept=no:检查 Triggers 依赖无活跃 service 则排队 JOB_START,socket 进 RUNNING,由 service 侧 `socket_collect_fds` 反向收集 fd。**DeferTrigger= 的精妙**:触发遇事务冲突时挂安全网定时器、把自己加入"任何 unit 停止都重试排队"的观察队列、关掉 IO 源——"触发条件从 socket IO 变成了冲突依赖的消亡",状态机表达"暂时不能做、但别丢"的样本。触发限流默认不对称:Accept=yes burst 200 / no 仅 20——manager 先 accept 走了连接,而 no 模式依赖服务自己消费队列。

## 6.2 timer 双轨与 path 三型

日历轨(OnCalendar)面向人的日程,会被 NTP/管理员拨动;单调轨(OnBootSec 等)面向"自某事件起多久",天然免疫跳变。双轨并行+时钟跳变回调整表重算+Persistent 戳文件(仅信过去的时间戳,未来时间拒绝),让"错过就补跑"与"拨钟不重跑"同时成立——**单一时钟源做不到这三件事**。RandomizedDelaySec 的随机源用 machine-id+uid+unit id 做 SipHash:同一 unit 每次开机同一偏移,散布可预期、调试可复现。path unit 的监视矩阵浓缩在一张表:PathModified 与 PathChanged 唯一差别就是多订阅 IN_MODIFY;逐路径组件挂 watch(父目录重建也能跟上),装好 watch 后**再查一遍条件**处理 TOCTOU。

## 6.4 设计动机

1. **socket 激活**:把"端口已监听"与"服务已就绪"解耦——启动并行化不受依赖顺序约束,服务崩溃重启期间连接在内核队列排队不丢;
2. **fd 从 3 开始**:约定区间与保留区间不重叠,F_DUPFD 即可无损打包;
3. **timer 双轨**:墙上时钟面向人、单调时钟面向事件;补跑与不重跑同时成立;
4. **path 用 inotify**:事件驱动即时触发;但 inotify 只对已存在 inode 有效,所以逐组件 watch+二次检查;
5. **AI 纪律**:事故驱动的规则+人工金丝雀,与 CI 平行的"人工验证层"。

## 6.5 FAQ

**Q1:服务崩溃期间连接会丢吗?**
Accept=no 时连接在内核 accept 队列排队;服务重启后继续收。

**Q2:accept 后连接太多怎么办?**
max_connections 与 max_connections_per_source 两道限流。

**Q3:LISTEN_FDNAMES 是什么?**
冒号连接的 fd 名单,配合 NamedFileDescriptor 按名取 fd。

**Q4:PID1 自己能收 LISTEN_FDS 吗?**
能:容器管理器把预热套接字递给 PID1,按 unit 标签路由(main.c:3224-3280)。

**Q5:OnCalendar 写错了会怎样?**
解析失败在加载期报错;求下一匹配点有 1000 次迭代上限防死循环。

**Q6:重启后错过的 timer 会补跑吗?**
Persistent=yes 会:读戳文件补算 last_trigger(catch-up)。

**Q7:时钟被拨快/拨慢呢?**
time_change 事件整表重算日历轨;单调轨不受影响。

**Q8:PathModified 和 PathChanged 差别?**
仅多订阅 IN_MODIFY(写入中的每次 flush 都触发)。

**Q9:generator 是什么?**
启动早期把 fstab/cmdline 翻译成临时 unit 的短命程序;getty-generator 是生成实例的标本。

**Q10:socket 代理解耦工具是什么?**
systemd-socket-proxyd:socket 常驻、真正的服务按需启动并转发流量。
