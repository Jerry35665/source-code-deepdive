# 第 15 章 · 加密存储与 TPM2:密钥级联、PCR 分水岭与"降级而非砖机"

> 基线:commit `1f66b524`。核心:src/cryptsetup/cryptsetup.c(2,789 行)/ src/shared/tpm2-util.c(12,150 行)/ src/cryptenroll/。

## 15.0 全景:attach 的密钥级联

```
 systemd-cryptsetup attach VOLUME SRC [KEY-FILE] [crypttab 选项列]
 try 循环(默认 3 轮,arg_tries,注释给出顺序 cryptsetup.c:2630-2636):
   ① token 密钥(TPM2 > FIDO2 > PKCS#11,互斥取先 :2449-2458)
   ② 配置/自动发现的密钥(/etc/cryptsetup-keys.d/<卷名>.key,:2460-2485)
   ③ 空 password(try-empty-password=,每轮一次)
   ④ 交互提问(headless 直接禁用,报 ENOPKG :910-911)
 每轮失败 -EAGAIN 只作废一个输入,逐级降级(:2692-2723);耗尽报 EPERM
 进程开始即 mlockall("A delicious drop of snake oil",:2525-2526)
```

纠偏:try 循环里**没有独立的 recovery 分支**——恢复密钥只是被 `systemd-recovery` token 标记的普通口令(cryptsetup.c:844-848);check_registered_passwords 枚举 LUKS2 token 时,被 systemd-* token 引用的 slot 不算"常规口令 slot"。

## 15.1 PCR 7 默认绑定的分水岭

纠偏:"TPM2 默认绑 PCR 7"已是旧闻——tpm2-util.h:519-524 注释明言 **v258 起注册端不再默认绑 PCR 7**:`--tpm2-public-key=auto` 时 public-key PCR 默认取 **PCR 11**(cryptenroll.c:813-817),完全不给限制则注册"空策略"仅打提示(:818-825);PCR 7 只在解锁端作为 legacy 兼容掩码存活(TPM2_PCR_MASK_DEFAULT_LEGACY,cryptsetup.c:1969)。PCR 语义定义在 src/fundamental/tpm2-pcr.h:PCR7=SecureBoot 策略、PCR11=sd-stub 内核镜像、PCR12=内核命令行/凭证、PCR15=根卷密钥。bank 偏好 SHA256>SHA384>SHA512>SHA1,优先读固件 EFI 变量上报的激活 bank(tpm2-util.c:4108-4160)。

## 15.2 TPM2 解锁失败被系统性"非致命化"

纠偏:任何 TPM2 错误统一改写成 -EAGAIN 落回传统解锁(cryptsetup.c:1997-2000, 2116-2119);token 与开机状态失配的 6 种 errno(-EREMCHG/-ENOANO/-EPERM/-ENOSTR/-EREMOTE/-EADDRNOTAVAIL)触发 `token++` 换下一个 token 续试(tpm2-util.h:58-60; cryptsetup.c:2107-2111);PCR 中途抖动整体重试上限 30 次(tpm2-util.c:7172, 7406)——设计哲学是**降级而非砖机**。另外要测量 PCR 时(tpm2-measure-pcr=)强制走本进程手工路径拿 volume key,不用插件(cryptsetup.c:1401-1413)。

## 15.3 密封密钥的真实形态与策略分片

纠偏:sealed 密钥**不是 TPM 生成的**——是主机 RNG 随机数被 TPM 内 SRK/primary 密钥以 **KEYEDHASH** 对象加密后的 blob(tpm2-util.c:6970-7005);连同 tpm2-blob/tpm2-pcr-bank(不是 "pcrbank")/tpm2-policy-hash/tpm2_srk 存进 LUKS2 JSON token(:11321-11340)。优先用 SRK(handle 0x81000001)并序列化随 token 保存,否则退回 legacy primary(ECC 优先)。策略侧:签名 PCR(PolicyAuthorize)与 pcrlock(PolicyAuthorizeNV)**无法在同一条策略组合**,systemd 的解法是密钥分片——一个密钥拆两片,片 0 绑签名 PCR、片 1 绑 pcrlock(cryptenroll-tpm2.c:474-510);计算侧与真实 policy session 是两套对称实现(calculate vs build,tpm2-util.c:5697-5755)。带 PIN 启 DA 防爆破,不带置 NODA(:6990-6995)。

## 15.4 cryptenroll 与周边

按注册类型分文件:password/recovery/pkcs11/fido2/tpm2/wipe/list;周边配角 systemd-measure("为 PCR 11 预计算预期值",measure-tool.c:31-32)与 systemd-pcrlock(5,817 行,基于事件日志预测未来 PCR 状态)。与 homed 的衔接:homed 的 LUKS 后端复用同一 libcryptsetup 封装(cryptsetup-util 的 dlopen 原型列表,兼容 2.7 前头文件)。TCRYPT(VeraCrypt)与 token 互斥直接 EAGAIN;PKCS#11 模式强制禁用口令缓存。

## 15.5 设计动机

1. **密钥级联而非单点**:TPM2 坏了落 FIDO2,再落口令——解锁永远有路(cryptsetup.c:2692-2723);
2. **非致命化 TPM2 错误**:换 token 续试+30 次重试,固件更新不砖机(:2116-2119);
3. **v258 去掉 PCR 7 默认**:SecureBoot 策略变化不再导致根盘打不开;PCR 11 更精准绑定镜像(tpm2-util.h:519-524);
4. **KEYEDHASH 当载体**:主机侧生成密钥,TPM 只做封装,密钥可备份可迁移(tpm2-util.c:6970-7005);
5. **策略分片代替策略或**:绕开 TPM 策略组合的表达力限制(cryptenroll-tpm2.c:474-510);
6. **token 插件外置**:tpm2/fido2/pkcs11 编译为 libcryptsetup 外挂 .so,主进程可不走插件以便测量。

## 15.6 FAQ

**Q1:解锁尝试顺序?**
token 密钥→配置/发现密钥→空口令→交互提问(:2630-2636)。

**Q2:默认绑 PCR 7 吗?**
v258 起注册端不再默认;解锁端 legacy 兼容才回落 PCR 7(tpm2-util.h:519-524)。

**Q3:TPM2 坏了会开不了机吗?**
不会,-EAGAIN 落回传统解锁,降级而非砖机(cryptsetup.c:1997-2000)。

**Q4:密封的密钥是 TPM 生成的吗?**
不是,主机 RNG 生成、TPM 的 SRK 加密封装(tpm2-util.c:6970-7005)。

**Q5:签名 PCR 和 pcrlock 能同用吗?**
策略层不能组合,用密钥分片解决(cryptenroll-tpm2.c:474-510)。

**Q6:恢复密钥是特殊机制吗?**
不是,只是 systemd-recovery token 标记的普通口令(cryptsetup.c:844-848)。

**Q7:LUKS2 token 里存什么?**
blob/pcr 掩码/bank/policy-hash/srk 等字段(tpm2-util.c:11321-11340)。

**Q8:PCR bank 怎么选?**
SHA256>SHA384>SHA512>SHA1,优先固件 EFI 变量上报(:4108-4160)。

**Q9:headless 模式禁什么?**
交互提问,直接 ENOPKG(cryptsetup.c:910-911)。

**Q10:为什么要 mlockall?**
防密钥换出 swap;注释自称 snake oil 幽默(:2525-2526)。

## 15.7 小结与深挖方向

本章结论:**FDE 解锁=密钥级联+LUKS2 JSON token 元数据;TPM2=主机随机密钥+SRK 封装+可组合 PCR 策略分片,v258 起 PCR 7 默认退位**。深挖:
