# 第 01 章 · 全景架构:PID 1 的骨架

> 基线:commit `1f66b524`。核心:src/core/main.c、manager.c、unit.c。

## 1.0 全景:Manager/Unit/Job/Transaction

```
Manager(manager.h:183)——全局单例
├ units: 名字→Unit* / jobs: id→Job* / run_queue: Prioq / event: sd_event
├ 十余条工作队列(load/dbus/cleanup/cgroup_realize/gc/target_deps,manager.h:198-245)
├ Unit ×11 种类型:虚表数组 unit_vtable 分派(unit.c:83-95)
│   service 6679 行最大,target.c 最小;device/scope 是"外部世界的被动容器"
├ Job(unit.h:281 回指):unit 上的待办动作
└ Transaction:一次依赖求解的暂存区,成功才原子"安装"进 Manager
启动:main→run_systemd(main.c:3530)→manager_new(:922 五步立骨架)→manager_startup(:2168 九步点火)
     →do_queue_default_job(default.target)→manager_loop(:3621 死循环)
```

形态判定:`getpid()==1` 强制 system 形态,否则 user(main.c:3583-3585)。systemd 还是 multicall 二进制——以 `executor` 名字调用进入子进程执行器入口(main.c:4043-4047)。

## 1.1 启动九步与信号

manager_startup(manager.c:2168-2304):lookup paths→generators→enumerate(逐类型从磁盘/内核枚举 unit)→deserialize(reexec 场景)→fd 分发→IPC 通道(notify/D-Bus/Varlink)→coldplug(把"应有状态"真正生效)→vacuum+ready;回到 main 后 default.target 以 JOB_ISOLATE 入队(:2829-2870)。信号处理不走 handler:"信号→signalfd→事件循环";信号表本身就是文档——system 形态 SIGTERM 竟是 daemon-reexec(兼容 sysvinit),Ctrl-Alt-Del 走 SIGINT,SIGRTMIN+0..29 映射 default/rescue/emergency 等目标(manager.c:539-580,3333-3341)。事件源优先级:SIGCHLD 最前(-4)、信号次之(-3)、run_queue 最后(IDLE+1)——先收尸再干活(manager.h:746-753)。

## 1.2 reexecution:execve 自重启

升级/daemon-reexec/switch-root 都不走 fork 而**原地 execve 自己**:prepare_reexecute 把全部状态写进"每行 key=value"的序列化文本+要带走的 fd 集合(main.c:1334-1356),execv 自己带 `--deserialize=<fd>`(main.c:2261-2287),新实例从 fd 读回状态再 coldplug。取舍:文本可读可 diff、坏行可跳、未知 key 忽略——新旧版本序列化格式平滑演化。关机则 execve 到独立的 systemd-shutdown,失败还有 sync+reboot 直接系统调用兜底(main.c:3994-4005)——**"永不丢 PID 1"是这条链的设计底线**。

## 1.3 目录分层:basic/libsystemd/shared/core

basic(272 文件)是不依赖 libsystemd 的最底层工具,`UnitType` 枚举竟在此(unit-def.h:9-24);**sd-event/sd-bus 的实现在 src/libsystemd/**(对外 ABI);shared 服务多守护进程内部复用;core 才是 PID 1 策略层;udev/journal 是独立守护进程。依赖方向约束后"库稳定、策略自由"。

## 1.4 设计动机

1. **单线程 event loop**:全部状态共享在 Manager,优先级事件源把并发降维成队列顺序;run_queue 本身也是 defer 源按需唤醒(manager.c:761-779);
2. **execve+序列化文件**:exec 后旧地址空间不存在,"唯一可靠的遗产就是 fd";关机代码跑在无锁无堆的新镜像里;
3. **C 手工虚表**:Manager/事务/依赖传播算法只写一遍,11 类型只填约 30 个槽位(object_size 等把子类型内嵌偏移都元数据化);
4. **四层目录**:basic 可被最小二进制复用,libsystemd 受 ABI 约束;
5. **Transaction 暂存**:先物化"想要的世界状态",裁决成功才原子安装——依赖图从不半更新。

## 1.5 FAQ

**Q1:unit 类型几种?**
11 种(unit-def.h:9-24);常见"12 种"说法与当前源码不符。

**Q2:systemd --test 做什么?**
完整走 manager_new+startup 但不进主循环,打印事务摘要退出(main.c:3891-3895)。

**Q3:run_queue 是轮询的吗?**
不是:注册为 defer 事件源,平时 OFF,入队时 ONESHOT 打开(manager.c:2896-2906)。

**Q4:SIGTERM 发给 systemd 会怎样?**
system 形态=daemon-reexec(sysvinit 兼容);SIGINT 才是 ctrl-alt-del.target。

**Q5:升级时状态怎么保住?**
序列化文本+fd 集合穿越 execve;新实例 deserialize+coldplug 复原。

**Q6:11 类型哪些是被动容器?**
device/scope:描述外部世界已在跑的东西(udev 事件合成/外部进程)。

**Q7:主循环卡了怎么办?**
每轮 watchdog_ping;sd-event 睡眠上限取 watchdog 半周期,卡死即停跳。

**Q8:日志早期怎么写?**
journald 未起时直写 kmsg,挂载完成后切 JOURNAL_OR_KMSG 降级链。

**Q9:default.target 找不到呢?**
initrd 里 initrd.target,层层回退到 rescue.target(main.c:2829-2870)。

**Q10:AGENTS.md 是什么?**
上游提交给 AI 编码代理的硬规则(46 行):改源码必须加人工复核标记行;卷六展开。

## 1.6 小结与深挖方向
