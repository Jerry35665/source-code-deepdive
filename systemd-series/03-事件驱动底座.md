# 第 03 章 · 事件驱动底座:sd-event 与管理器调度

> 基线:commit `1f66b524`。核心:src/libsystemd/sd-event/sd-event.c(5529 行)。

## 3.0 全景:16 种事件源与一轮分发

```
事件源谱系(event-source.h:14-33):
 io(每源独立 epoll 成员)/ timer(五时钟,每时钟 1 个 timerfd)/ signal(每优先级 1 个 signalfd)
 child(优先 pidfd,退化 SIGCHLD+waitid)/ inotify(每优先级 1 个 fd)/ defer/post/exit
 /PSI 三种压力 / watchdog
一轮 sd_event_run:prepare(跑 .prepare 回调→arm 五时钟 timerfd)→wait(epoll_wait 一次)
 →dispatch(从 pending 堆弹 1 个:enabled>非限速>priority>pending_iteration)
```

一个 epoll 收敛全部并发;循环内时间缓存:`sd_event_now` 返回 epoll 回来时取的一份快照——同一轮所有定时器判定用同一把尺,消除派发漂移(sd-event.c:4712-4714)。default 事件循环绑定创建线程(prepare 时断言 tid,4562-4565)——**单线程多路复用在代码里的执行点**。

## 3.1 timer 双堆:accuracy 是向内核让渡的功耗空间

每时钟两张优先队列:earliest 按"最早可能到期"、latest 按"最晚必须到期"——两堆顶之间就是可自由调度唤醒的时间窗口(event-source.h:157-162)。`sleep_between` 把唤醒对齐到整分/整 10s/整 1s/整 250ms 边界,偏移取自 boot ID 哈希的 perturb——**全系统事件合并成一次 CPU 唤醒,多机之间又互错开**(sd-event.c:3524-3586)。默认 accuracy 250ms;Timer unit 的 AccuracySec 直接透传该参数。

## 3.2 三类"N 源并 1 fd"聚合器

io 源各自独立占 epoll 成员;真正做聚合的是 timer(每时钟 1 timerfd)、signal(每优先级 1 个 signalfd,改优先级要把源挪到新优先级的 fd 上)、inotify(每优先级 1 个 fd,InodeData 按 dev+ino 归并同 inode 全部订阅,watch 掩码按位或)。inotify 读侧策略:只要该优先级还有 pending 源就不再读新事件(无本地排队合并);IN_Q_OVERFLOW 时广播全部源——**宁可误报不可丢事件**。

## 3.3 限速建在事件源层

`sd_event_source_set_ratelimit` 只对可限速类型开放;检查点在 source_dispatch 入口,进入限速的技巧是"把源假装成 CLOCK_BOOTTIME 定时器"静默一个窗口(sd-event.c:3395-3507)——外科手术式掐掉事件风暴,循环其余部分照常。三层闸门由此分明:事件源限速、manager_loop 全循环节流(过快睡 1 秒)、unit 的 StartLimitBurst。

## 3.4 PID 1 的事件源清单与 SIGCHLD 接力

优先级表即文档(manager.h:737-754):cgroup inotify(NORMAL-10)→notify fd(NORMAL-5)→SIGCHLD defer(NORMAL-4)→信号(NORMAL-3)→cgroup empty(NORMAL-2,安全网)→D-Bus→run_queue(IDLE+1)。**收尸接力**:SIGCHLD 经 signalfd(io 源)只负责点亮一个 defer 源,defer 回调里 `waitid(P_ALL, WNOHANG|WNOWAIT)` 窥视不收尸(保留 /proc 可查),反查 unit 扇出事件后才 `waitid(P_PID)` 真收尸(manager.c:3170-3249)——回调看到的还是僵尸,信息完整。通知消息(sd_notify)被刻意排在 SIGCHLD 之前,否则"READY=1 后立刻退出"会丢最后一条状态。

## 3.5 设计动机

1. **自研 sd-event 而非 libev/libuv**:要的全是 Linux 专属原语(pidfd 等待/PSI/per-priority 聚合/时钟跳变),跨平台抽象是纯负担;
2. **单线程**:一个 epoll 把竞争降维成 pending 堆排序键;units/jobs 图全程免锁;
3. **accuracy 双堆**:定时器合并换续航;perturb 保证多机不同步唤醒;
4. **post 源**:"本轮所有活干完后跑一次"给状态广播/GC 确定时点——没有它连"循环空闲"都无法定义;
5. **限速建在源层**:风暴元凶总是某一个源,外科手术式掐掉而非全循环降速。

## 3.6 FAQ

**Q1:sd-event 支持哪些时钟?**
五个:realtime/boottime/monotonic/realtime_alarm/boottime_alarm(timerfd_create 能给的全部)。

**Q2:子进程等待用信号还是 pidfd?**
优先 pidfd(epoll 成员,不占信号路径);WSTOPPED 等组合退化 SIGCHLD+waitid。

**Q3:epoll 事件数超过缓冲怎么办?**
扩容重收,上限 10 倍(sd-event.c:4699-4710)。

**Q4:.prepare 回调有什么用?**
开睡之前最后刷新条件;可以把新源标 pending 使本轮直接跳过睡眠。

**Q5:回调返回负数会怎样?**
默认禁用该源;设 exit_on_failure 则整个循环带码退出。

**Q6:时钟跳变怎么感知?**
TFD_TIMER_CANCEL_ON_SET 标记的时钟源(NORMAL-1 优先级)+manager 的 time_change 源。

**Q7:同优先级事件谁先?**
pending_iteration:先标 pending 先服务。

**Q8:高优先级事件会被低优先级遮蔽吗?**
wait 里有阈值重试循环修补(上游 issue 18190,sd-event.c:4800-4834)。

**Q9:watchdog 怎么实现?**
sd_event_set_watchdog 用 timerfd 半周期自动发 WATCHDOG=1;循环卡死心跳即停。

**Q10:fiber/协程环境能用吗?**
能:检测到协程时整体委派 event_run_suspend,同一套原语驱动 fiber 化调用方。

## 3.7 小结与深挖方向

本章结论:**sd-event="单 epoll+五时钟双堆+三类聚合 fd+源级限速,把并发降维成堆排序"**。深挖:

1. fd_move_above_stdio 防外部代码误占 stdio 的细节;
2. origin_id 溯源戳:跨"事件循环代际"的引用直接判死;
3. inotify 改优先级需保留一轮 InodeData fd 的原因;
4. PSI 事件源的 write_list 重试;
5. SIGCHLD 窥视(WNOWAIT)与真正收尸分离的信息价值。
