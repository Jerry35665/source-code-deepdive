# 第 05 章 · 采样、词法与推理服务:最后一公里

> 基线:llama.cpp 4.5.0-dev(本快照)。勘误:`src/llama-sampling.cpp` 已重构为 `src/llama-sampler.cpp`(4385 行);`tools/cli/main.cpp` 只剩 5 行壳,真正的 CLI 在 `tools/cli/cli-context.cpp`。

## 5.0 从 logits 到 token 的完整链路

```
llama_decode(异步)→ synchronize
  → common_sampler_sample(common/sampling.cpp:594)
      1. set_logits: 取 logits → cur_p 数组
      2. rbudget 采样器(推理预算)先裁剪
      3. apply(chain): penalties→dry→top_n_sigma→top_k→typical→top_p→min_p
         →xtc→temperature→dist(默认顺序, common/common.h:261-271)
      4. 语法拒绝采样: 抽出 token 先单点校验, 不合法才整词表重采样
  → accept(喂回 grammar/penalties 历史)→ detokenize → SSE 推给客户端
```

三个关键点:

1. **logits → 概率化的时机不固定**:硬截断类采样器(top-k/min-p/penalties)直接操作 logit,只有 top-p/typical/mirostat 内部需要概率时才局部 softmax——**logit 空间数值稳定,可用 -INFINITY 表达"绝对禁止"**;
2. **CPU 采样与后端采样双轨**:4.5 引入 `llama_sampler_backend_*`(top_p 用 ggml 算子在 GPU 上完成);与 grammar/推理预算互斥;
3. **采样器是无状态流水线 + 有状态旁路**:`llama_sampler` 是 11 个函数指针的接口对象(name/accept/apply/reset/clone/free/backend_*),apply 改写 cur_p,accept 维护历史。

## 5.1 采样器链

链的组装按用户顺序,默认序即上面那串。**顺序语义非常重要**:penalties/DRY 必须在排序截断前改 logit;temperature 必须在所有截断之后、dist 之前缩放(截断阈值都与最高 logit 相关,先降温会改变相对形状)。mirostat 是例外:整条链替换为 temp + mirostat。

**大词表的性能工程**(12 万+词表):

- top-p 的自适应部分排序:未排序时先只排**前 256 名**开始累积概率,不够才升级全排序(llama-sampler.cpp:1556-1593)——均值复杂度近 O(N);
- top-k ≤128 时走 histogram-bucket 部分排序;
- dist 的单遍优化:**采样与归一化合并成一遍**(先算 `sum_tgt = sum×rnd`,边扫边累计边归一),注释称快 3 倍(1190-1208);
- `temp<=0` 退化为 argmax,greedy 路径零随机。

**语法约束的乐观路径**(common/sampling.cpp:646-675):默认先按普通链采样出 token,再对这一个 token 做单点语法校验,不合法才回退"整词表掩码 + 全链重采样"——**绝大多数 token 合法时,GBNF 全词表掩码成本被完全跳过**。GBNF 本身把语法编译为推演栈 + 词表掩码(llama-grammar.cpp),4.5 新增 TOKEN/TOKEN_NOT 元素与惰性触发 + 缓冲重放。

## 5.2 分词与 chat template

- **三模型分词**(llama-vocab.cpp):BPE/SPM/WPM 各自实现 tokenize 虚函数;unicode-data.cpp 支撑 NFD 规范化与字节级 fallback;
- **chat template**:common/jinja/ 内嵌了一个 Jinja 求值器;4.5 的架构级重构是**差分自动解析器**——对任意 Jinja 模板做静态分析后自动生成 PEG 流式解析器(common/chat.cpp:1311-1345),取代为每个模型手写工具调用解析器,**新模型模板理论上零代码适配**;
- **CLI 的架构级重构**:不再直接驱动 llama_context,而是内嵌一个随机端口的 llama-server 线程、以 HTTP 客户端身份交互(cli-server.h:36-55)——彻底消灭双推理循环。

## 5.3 server:slots 与 continuous batching

4.5 的 server 已模块化(server.cpp 壳 + server-context/server-queue/server-task/server-http)。并发模型:**每个 slot 是一个独立的推理会话**(独立采样链、grammar、n_keep),server-queue 把 HTTP 请求变成任务,主循环把多个 slot 的 token 合并进同一个 decode batch——这就是 continuous batching 的服务端组织。streaming 经 SSE 推送,不完整 UTF-8 被截断缓冲(server-context.cpp:282)。

## 5.4 FAQ

**Q1:top-p 和 min-p 什么区别?**
top-p 按累积概率截断(阈值随分布形状变化);min-p 按"最高概率 × 系数"做绝对底线(形状无关),对高温更稳。

**Q2:采样器顺序能随便调吗?**
不能:penalties 必须在截断前,temperature 必须在截断后 dist 前——顺序错了截断阈值失去意义。

**Q3:GBNF 会让生成变慢吗?**
乐观路径下几乎不会:单点校验替代全词表掩码,只有不合法(罕见)才回退重采样。

**Q4:CLI 里改参数要重启吗?**
CLI 已内嵌 server,经 HTTP 交互;server 的 slot 级参数可按请求改变。

**Q5:新模型的 chat template 要写代码适配吗?**
4.5 起理论上不用:Jinja 模板静态分析自动生成解析器。

## 5.8 小结与深挖方向

本章结论:**最后一公里 = "无状态流水线 + 有状态旁路"的采样器链 + 乐观路径的语法约束 + slot 化的 continuous batching**;性能工程密集处全在"12 万词表 × 每 token 一次"的热路径上(部分排序、单遍归一、后端双轨)。深挖:

1. 后端采样与 grammar 互斥的统一路径;

4. DRY/XTC/adaptive_p 等新采样器的统计语义。
