# 第 02 章 · 推理主循环与计算图:一张图的两种命运

> 基线:llama.cpp master tarball(2026-09 世代,版本号已从代码移除)。行号以当前解压快照为准。

## 2.0 全景:推理是一条环

```
tokenize → 组 batch → 切 ubatch → 分配 KV 槽位 → 构图(或复用图)
  → sched 切图到多后端 → 异步执行 → 抽取 logits → 采样 → token 拼回 batch → 循环
```

一句话分层:**llama_model 是静态的权重+hparams;llama_context 是动态的执行状态(KV、计算 buffer、调度器);llama_graph_context 是"模型结构 → ggml 节点"的翻译器;ggml_backend_sched 是"节点 → 物理设备"的放置器。**

加载编排(llama.cpp:316-378):`llama_model_load` 串起 model_loader → create → load_hparams(GGUF 元数据→hparams)→ load_vocab → load_tensors。设备选择默认枚举所有 GPU/RPC,`SPLIT_MODE_TENSOR` 时把多卡包成一个 "Meta device" 做张量并行(src/llama.cpp:158-313)。`sched_reserve()` 用**最坏情况图**预分配计算 buffer(src/llama-context.cpp:582-712)——运行期不存在分配失败。

## 2.1 ubatch 切分:三种策略

`llama_batch` 是用户的平行数组;`llama_ubatch` 是切分后进图 的微批。`llama_batch_allocr::init`(llama-batch.cpp:25-391)先清洗:越界校验、补全缺省字段——**没给 logits 时只标最后一个 token**:

```cpp
if (!batch.logits) {
    if (output_all) { output.resize(batch.n_tokens, true); }
    else {
        output.resize(batch.n_tokens, false);
        output[output.size() - 1] = true;   // 只对最后一个 token 出 logits
    }
}
```

这就是 **decode 与 prefill 无独立代码路径的机关**:prefill 一大串 token 只有最后一个带 logits=1,图里 `inp_out_ids` + `ggml_get_rows` 把 LM head 从 n_tokens 行裁到 n_outputs 行(models/llama.cpp:174-177)。差异全部来自 batch 标志;线程数也按 `n_tokens>1` 自动切换(llama-context.cpp:2492-2509)。

三种切分(llama-kv-cache.cpp:708-720 按流数选择):

- **split_simple**(476-508):顺序取前 n_ubatch 个,单序列 prefill 走这条;
- **split_equal**(510-679):多序列并行的"方阵切法"——一个 ubatch 只收互不相交的序列集,各序列轮流各取一个 token,得到规整的 `[n_kv, n_seq_tokens, 1, n_streams]` 4D 张量;
- **split_seq**(681-721):整个 ubatch 只装一个序列集,给 recurrent 模型(Mamba 类)用。

## 2.2 计算图构建与"图复用"

`process_ubatch`(llama-context.cpp:1334-1404)是每微批必经之路,最大亮点是**图复用**:

```cpp
if (!graph_reuse_disable && res->can_reuse(gparams)) {
    // 拓扑相同 → 跳过构图与 sched 重新切图
    n_reused++;
} else {
    res->reset(); ggml_backend_sched_reset(sched.get());
    gf = model.build_graph(gparams);
    ggml_backend_sched_alloc_graph(sched.get(), gf);
}
res->set_inputs(&ubatch);          // 只写输入张量的数据
graph_compute(res->get_gf(), ubatch.n_tokens > 1);
```

`can_reuse` 要求 ubatch 形状全等、n_outputs 相等、sampler 集相同(llama-graph.h:815-867)。**decode 稳态生成每步零构图开销**。为保拓扑恒定的两个机关:`build_inp_embd` 用 `ggml_build_forward_select` 把 token/embd 双输入都放进图按批内容选择(llama-graph.cpp:2418);backend sampler 用 dummy row 固定单输出图拓扑——**"图是形状的函数而非数据的函数"贯穿全部设计**。

一个单层 Transformer 的 ggml 节点图(简化):embd 查表 → RoPE → QKV 线性 → attention(KV 从 cache 读)→ 残差 → RMSNorm → FFN(SiLU 门控)→ 残差 → ×n_layers → 终 Norm → LM head(get_rows 只取输出行)。

## 2.3 输出乱序的惰性补偿

多 ubatch 切分会打乱输出行序。decode **只用选择排序记录 `output_swaps` 而不搬数据**(llama-context.cpp:2004-2030),直到用户首次调 `get_logits_ith` 才在 `output_reorder()` 真正交换(2233-2299);配合全异步 `tensor_get_async` 抽取(1874-1977)——**生成循环稳态下不发生任何同步等待**。

KV 失败的重试:ubatch 分配槽位 `FAILED_PREPARE`(如碎片化)时,做一次 `memory_update(true)` 后重试;某 ubatch 计算失败则把各序列从失败位置 `seq_rm` 回滚,保证 KV 与实际计算一致(llama-context.cpp:1829-1850)。

## 2.4 FAQ

**Q1:decode 和 prefill 是两套代码吗?**
不是,一套代码;差异全部来自 batch 标志(logits 只标末位 vs 全标)与线程配置。

**Q2:为什么 decode 稳态没有构图开销?**
can_reuse 判定形状全等即复用整张图,只重写输入张量数据。

**Q3:多序列怎么并行 prefill?**
split_equal 方阵切法:互不相交的序列集各取一个 token 组成方阵,注意力按 4D 张量并行。

**Q4:recurrent 模型怎么切批?**
split_seq:一个 ubatch 只装一个序列集——状态按序列串行推进,不能混批。

**Q5:输出行序乱了怎么办?**
记录 swaps 惰性交换:用户没要 logits 就永远不搬。

## 2.5 小结与深挖方向

本章结论:**llama.cpp 的推理层 = "图的形状函数化 + 惰性的一切"**——构图可复用、输出重排可延迟、抽取全异步。深挖:

1. can_reuse 的相等判定覆盖度(哪些形状变化会漏判);
2. pipeline_parallel 的图间流水收益;
3. Meta device 张量并行的切分策略;
4. M-RoPE 的 4 维位置广播对 batch 约束的影响。
