## 1.2 仓库结构

```
llama.cpp/
├── src/            推理核心
│   ├── llama.cpp / llama-context.cpp   入口与执行状态
│   ├── llama-graph.cpp                 模型结构 → ggml 计算图
│   ├── llama-model.cpp / models/       加载与各架构构图
│   ├── llama-kv-cache*.cpp             KV 缓存(iswa/hybrid)
│   ├── llama-sampler.cpp               采样器实现
│   ├── llama-vocab.cpp / unicode*      分词
│   ├── llama-arch.cpp / llama-hparams  架构常量与超参
│   └── llama-quant.cpp / llama-model-loader.cpp / gguf*
├── ggml/           自研张量库(独立项目精神上)
│   ├── src/ggml.c / ggml-backend.cpp / ggml-quants.c / ggml-common.h
│   └── src/ggml-cpu / ggml-cuda / ggml-metal / ggml-vulkan / ggml-opencl / ggml-sycl
├── common/         高层封装(sampling/chat/jinja/log)
├── tools/          server / cli / quantize / imatrix / mtmd(多模态)…
└── tests/ benches/
```

分层铁律:**src/ 只依赖 ggml 的公共头;ggml 不知道 llama 的存在**。ggml 因此被 vLLM 等第三方独立复用。

## 1.4 一条主线串起全部文件

```
GGUF 文件 → model-loader(mmap)→ llama_model(权重+hparams)
  → llama_context(KV cache + sched 预分配)
  → 用户输入 tokenize → batch → ubatch 切分
  → 图构建/复用(llama-graph)→ ggml_backend_sched 切分到多后端
  → CPU/CUDA/Metal 执行(块量化整数点积)
  → logits → sampler 链(+GBNF)→ token → KV 写回 → 循环
  → server 的 slot 把 N 个会话拼进同一个 batch
```

**两个"一以贯之"**:① 张量格式即内存布局(GGUF→文件→显存全程零转换);② 图是形状的函数而非数据的函数(一切惰性)。二者共同构成"消费级硬件跑 LLM"的物理基础。
