# 《llama.cpp 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》的第八卷(终卷)。全部结论来自对 llama.cpp master tarball(2026-09)源码的逐行阅读,每处关键论断标注 `文件:行号`。

## 这卷写给谁

用过 llama.cpp/Ollama/LM Studio、想知道"7B 模型怎么塞进 8GB 内存还能跑"的工程师;想进入 AI infra 领域的系统程序员;需要 Go/C++ 之外再懂一点 C 与 GPU 编译宏的读者——但 AI 概念(attention/KV cache)在本卷内自足解释。

## 为什么选 llama.cpp

1. **端侧 AI 的事实标准**:Ollama/LM Studio 的引擎;ggml 被 vLLM 等复用;
2. **演进最快的系列项目**:defrag 之死、llama-sampler 重命名、CLI 内嵌 server 都是 2025-2026 的新事——本卷是"AI infra 的当下";
3. **量化技术的活教材**:从 q4_0 到 iq1 的完整光谱,每一档都有精确的 bpw 与块布局。

## 环境准备

```bash
git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build && cmake --build build -j        # CPU 版即可构建

# 与源码互动的三把钥匙
./build/bin/llama-cli -m model.gguf -p "你好" --verbose   # 看图构建/后端日志
./build/bin/llama-quantize --help                          # 量化菜谱
./build/bin/llama-bench -m model.gguf                      # 性能基准
```

## 三种用法

1. **系统通读**(约 4-5 小时):01 → 02 → 03 → 04 → 05 → 06;
2. **AI infra 面试**:各章 FAQ(约 70 条)——为什么 FA 下 V 不转置、defrag 为什么被删、K-quant 位压缩、GBNF 乐观路径;
3. **自研推理引擎**:第 02 章(图复用)+ 第 04 章(零 malloc)是可以直接照抄的工程蓝图。

## 统一约定

- **行号即凭证**:基于 master tarball(2026-09);该项目周更,以函数名检索定位;
- **演进勘误显式**:defrag 已删、llama-sampling→llama-sampler、server 模块化、CLI 内嵌 server;
