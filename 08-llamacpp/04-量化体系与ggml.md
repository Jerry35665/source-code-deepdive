# 第 04 章 · 量化体系与 ggml:块结构契约、整数点积与零 malloc

> 基线:llama.cpp master tarball(2026-09)。行号以当前快照为准。

## 4.0 全景:量化的三层与一条旅程

产品主张"在消费级硬件上跑 LLM"的物理前提是**把权重从 FP16 压到 2~6 bit/权重**。量化体系分三层:

1. **格式层**(ggml-common.h):每种量化类型一个 C 结构体 = "块布局契约",所有后端共享同一份宏定义,`static_assert` 钉死字节大小——GGUF 文件里的量化数据就是这些结构体的朴素数组,**文件格式与内存布局零拷贝对齐**;
2. **算法层**(ggml-quants.c):`quantize_*_ref` 是确定性参考实现,K-quant/i-quant 带 imatrix 加权标定;
3. **运行时层**:激活按块动态量化为 Q8(`from_float/vec_dot/vec_dot_type` 三元组驱动),点积走纯整数路径。

一块权重的旅程:**GGUF mmap → 逐块标定 → 块结构直接驻留显存/内存 → vec_dot 整数点积 → 每块乘 scale 累加浮点和**。全程没有"反量化成大矩阵再乘"的中间态——这是 8GB 内存能跑 7B/13B 模型的根本原因。

## 4.1 块格式逐字节

**基本块**(QK=32):

```
block_q4_0(18B/32 = 4.5 bpw):
+--------+----------------------------+
| d (2B) | qs[16](32 个 4bit)         |
+--------+----------------------------+
反量化: x[j] = d * (q[j] - 8)

block_q4_K(144B/256 = 4.5 bpw,super-block):
+--------------+------------------+----------------+
| dm(4B: d+dmin)| scales[12](12B)  | qs[128](256×4bit)|
+--------------+------------------+----------------+
w = d * sc[j] * q - dmin * m[j](8 个子块 × 32 元素)
```

两个精妙点:

1. **q4_0 的带符号 scale**:`d = max / -8`(ggml-quants.c:132)——把绝对值最大的权重映射到码字 0 而非 15,配合 +8.5f 舍入实现对称量化,省掉 min 字段;
2. **K-quant 的 scale 分层量化**:super-block 用 1 个 f16 + 16 个 6-bit 子块 scale,把 scale 摊销成本降到每权重不足 1 bit;q2_K 最极端——连子块 min 都单独量化配独立 dmin(2-bit 码字动态范围太小,min 偏置精度直接决定误差)。

12 字节装 16 个 6-bit 数的位压缩用三个掩码解包(kmask1/2/3,quants.c:2069-2074)——理解 K-quant 的门槛。所有块结构 `static_assert` 逐字节锁死布局(显式排除编译器填充),GGUF 字节流可直接 `reinterpret_cast` 成块指针。

**i-quant(码本)**:iq4_nl 用 16 个非线性码字;iq2/iq1 的 qs 字段是"8 权重组模式表"的索引——**离线搜索出的最优字典**,配合 imatrix 把 bpw 压到 1.5~2.5;强依赖 imatrix,缺了直接拒绝量化。

## 4.2 per-layer 混合精度:量化质量不在格式在菜谱

`use_more_bits`:首尾 1/8 层 + 每三层补偿(llama-quant.cpp:434-436);attn_v 系被单独标记为量化敏感(157-161);70B 因 GQA 共享使 V 矩阵只有 1/8 大小而升 Q5_K(559-564)。**量化质量不来自单一格式,而来自这张"张量类别 × 层位 × 超参"的混合表**。

## 4.3 ggml:张量表示与三段式零内存分配

`struct ggml_tensor` 以 ne[](逻辑形状)+ nb[](步长)描述,支持任意 stride 的视图;计算图 cgraph 以哈希集去重的拓扑访问构建。**内存三段式零动态分配**:

1. context 是永不单点释放的 bump allocator(张量数据内联在结构体后,ggml.c:1708-1764、1820);
2. gallocr 按 **measure-then-alloc** 两遍规划整图缓冲;
3. CPU 侧唯一工作区 wdata 在 `ggml_graph_plan` 期定死(ggml-cpu.c:2829-3056)——**推理热路径上不存在任何 malloc**。

backend sched(ggml-backend.cpp)四遍扫描把图按后端切分(split),权重 placement 决定驻留设备;MoE 专家按需拷贝。CPU 线程池带 barrier,mul_mat 动态分块;激活现场量化进 wdata(1323-1358)。

## 4.4 FAQ

**Q1:q4_0 和 q4_1 的区别?**
q4_1 多一个 min 字段(仿射);q4_0 用带符号 scale 达到近似效果且省 2B——实践中 q4_0+精细格式(K-quant)胜出。

**Q2:q4_K 的 4.5 bpw 怎么算?**
(16B scales + 128B qs + 4B dm)×8 / 256 = 4.5。注释直接标在 ggml-common.h。

**Q3:为什么激活侧要量化成 q8 并存 bsums?**
带 min 的仿射量化点积可降为"一次整数内积 + 一次标量校正";冗余刻意放在激活侧——**激活写入一次、随行数摊销读取**(权重则被反复读)。

**Q4:i-quant 为什么强依赖 imatrix?**
码本固定,标定自由度只剩选择;没有重要性加权,1.5-2.5 bpw 的误差不可控。

**Q5:推理时还有 malloc 吗?**
没有。三段式:bump allocator + measure-then-alloc + 预定的 wdata。

## 4.5 小结与深挖方向

本章结论:**量化 = "块结构契约(文件=内存)+ 整数点积 + per-layer 菜谱";ggml = "零分配 + 图级调度"**。llama.cpp 用一份自研张量库同时服务 CPU/桌面 GPU/手机,靠的不是算子数量而是"格式即内存布局"的纪律。深挖:
