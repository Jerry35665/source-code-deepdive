## 11.0 全景:三层并发叠加

```
并发(后台 worker 线程 ConcurrentMarking::RunMajor,worklist 驱动,
     64KB/1000 对象检查一次 ShouldYield)
+ 增量(主线程步进:分配观察器 64KB/256KB 或前台任务触发,步上限 5ms/1ms,
     按 500ms 总预算折算步长,incremental-marking-schedule.h:51-52)
+ atomic pause(Stop 增量标记→PublishAll→重扫根→ephemeron 串行收敛
     →关屏障→并发清扫→并行疏散)
正确性:两个写屏障(标记屏障 Dijkstra 染灰 + 代际屏障 OLD→NEW 记 SlotSet)
```

## 11.1 Scavenger:并行复制

**页级并行**:OLD_TO_NEW slot set 页列表+ParallelWorkItem::TryAcquire 抢页,job 在根遍历**之前** post(scavenger.cc:1732-1738);**对象级**:map word 的 relaxed CAS 转发(:1975-1992),CAS 赢家复制、输家回滚分配用 forwarding 地址。晋升判定:对象地址在 age mark(=上轮 scavenge 后的 to-space 分配顶)之下即"已跨一轮 GC"直接晋升 OLD/SHARED_SPACE,否则先试半空间复制;复制失败回退晋升,全败 OOM(new-spaces.cc:429-431;scavenger.cc:2083-2091)。

## 11.2 写屏障:单方向+组合

**只需记录 OLD→NEW**:scavenge 从根遍历,老生代自身不扫——漏记即漏活。快路径两个页标志位:`!PointersFromHereAreInteresting`→return(非标记期且 host 非老页零成本);标记屏障单行 `if(!IsMarking(host)) return; MarkingSlow(...)`(heap-write-barrier-inl.h:51-79)。MarkingSlow→MarkValueLocal=TryMark(原子 0→1)+push 本地 worklist(:149-154 bitmap 物理位置)。SlotSet:两级位图,一页 64 bucket(每 bucket 32 cell×32bit=1024 槽,basic-slot-set.h:277-284),主线程写 OLD_TO_NEW 非原子、后台写 OLD_TO_NEW_BACKGROUND 原子(heap-write-barrier.cc:404-417)。

## 11.3 并发标记与增量步进

**并发标记**:后台 worker 线程跑 ConcurrentMarking::RunMajor,worklist 驱动,64KB/1000 对象检查一次 ShouldYield(:369-370,:469 让出);worklist 分段 64 元素,**steal=整段偷取**锁竞争摊薄 64 倍(worklist.h:402-411,:462-471);on_hold 列表见 marking-worklist.h:120-124。**隐式三色**:单 MarkBit,白=0、黑=1、灰=已标+在 worklist(marking.h:71-74 原子置位 Relaxed_SetBits,0→1 返回真,并发去重根基);bitmap 物理位置=页 metadata+MarkingBitmapOffset(marking-inl.h:149-154)。**增量步进**:分配观察器 64KB/256KB 触发+前台任务,步上限 1ms/5ms(incremental-marking.cc:56-59);标记总预算 500ms(schedule.h:51-52)。

## 11.4 evacuate 与 atomic pause

evacuate 候选:碎片率 70%+配额,按最空页优先,防 compact→expand 抖动(mark-compact.cc:622-630,:658-810);并行疏散(:4929-5041)每 worker 一个 Evacuator。三模式(:4717-4746):new→old 复制/整页晋升/old→old 压缩,可 abort。**atomic pause 全序**(:2581-2676):Stop→PublishAll→重扫根→弱语义**串行**收敛(:2645-2648)→DeactivateAll;本版 Sweep() 在 Evacuate() 之前(:556-557),清扫不占停顿。

## 11.5 设计动机

1. **为什么并发标记是 GC 的圣杯**:主线程停顿=用户可感知——并发把停顿从"与堆成正比"压到"与根集成正比";三色的并发实现是所有现代 GC 的必修课;
2. **三色+写屏障的数学不变式**:黑对象的白子嗣必被屏障染灰——Dijkstra 变体的正确性证明(V8 用 markbit 置位+worklist,非 SATB 快照);
3. **为什么分代是所有优化前提**:弱分代假说使 Scavenger(复制)+MarkCompact(标记)各司其职;没有分代,并发标记每次都全堆;
4. **原子字段写的前提**:所有 tagged 写必须原子——这不是性能优化,是并发标记的正确性前提(concurrent_marking 直接 CHECK 拒启)。

## 11.5 FAQ

**Q1:增量标记的步长怎么定?**
1ms(任务)/5ms(分配驱动)(:56-59);按 500ms 总预算折算步长。

**Q2:并发标记的后台线程几个?**
由 flags 控制:默认并行度=CPU/2;64KB/1000 对象检查一次让出(:369-370)。

**Q3:Scavenger 的 CAS 转发是什么?**
(:1975-1992):并行复制时先 CAS map word 为转发指针,赢家复制,输家读转发——保证只复制一次。

**Q4:write barrier 的成本?**
快路径两个位标志检查(:51-79):非标记期且 host 非老页→零成本返回。

**Q5:atomic pause 还有多长?**
(:2581-2676):重扫根(根集少量)+弱收敛(串行)+关屏障——与堆中存活对象成正比但远小于全堆标记。

**Q6:MinorMS 是什么?**
新生代标记-清扫替代复制(flag :3822-3823 实验):避免复制的搬运成本,适合大新生代。

**Q7:疏散选择为什么按最空页优先?**
(:622-630):碎片率 70% 阈值——腾出整空页比均匀分散更高效。

**Q8:Sweep 在 Evacuate 之前?**
(:556-557):清扫不占停顿(并发),疏散占停顿——顺序使并发清扫与 STW 疏散不冲突。

**Q9:MemoryReducer 什么时候收缩堆?**
空闲后逐步(:18-21,:92-94):连续空闲触发的堆大小减半。

**Q10:为什么 Scavenger 是并行的但 Mark-Compact 是并发+并行的?**
Scavenger 短(1ms 级)并行复制够了;MarkCompact 长需要并发标记+增量步进——复杂度与停顿成正比。
