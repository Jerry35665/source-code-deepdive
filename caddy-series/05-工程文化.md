## 5.0 全景:Go 现代项目的工程四柱

```
构建(xcaddy:插件=Go 包)│ 测试(caddytest:进程内真服务器)
发布(goreleaser+tag 验签+cosign)│ 安全(默认安全清单)
```

## 5.1 xcaddy:插件经济学的构建面

插件=Go 包,构建=空导入+编译;官方"标准版"只是 modules/standard/imports.go:7-19 的 **13 个空导入**,没有任何特权构建——goreleaser 的 before 钩子(.goreleaser.yml:9-31)同样复制 main.go、`go mod init caddy`、require 固定 tag 后编译。**官方版与你的定制版在构建机制上完全等价**——插件分发的民主化。

## 5.2 caddytest:进程内真服务器

测试桩自己空导入 modules/standard(caddytest.go:31)并**以进程内方式起真服务器**(直接调 caddycmd.Main(),:291-299),经管理 API POST /load 下发配置(:178)再轮询 DeepEqual 确认(:250-257);断言是 curl 式一行调用(AssertGetResponse :546)。规模:129 个 _test.go、39 个表驱动、**241 个 Caddyfile 黄金文件**(integration/caddyfile_adapt_test.go:43,以 `----------` 切分,期望段非 JSON 时反用作错误断言)、7 个 gofuzz 目标。CI:GitHub 矩阵只跑 `-short`(:137 自跳过),真集成在自备 IBM Z s390x 上跑(ci.yml:155-214,continue-on-error);lint 三件套(golangci/govulncheck/dependency-review)+OpenSSF Scorecard 周检+Actions 全 pin SHA。

## 5.3 发布与安全:验证签发的 tag

goreleaser 发布:tag 必须 **SSH 验签且 commit 与提案 PR 一致**,否则流水线**删 tag 中止**(release.yml:110-115,:239-256);产物带 cosign 签名+SBOM+sha512+可重建 buildable-artifact;**无 CHANGELOG 文件**,changelog 由 conventional commit 正则过滤生成(.goreleaser.yml:207-216)。默认安全清单(逐项见各章):自动 HTTPS+重定向(autohttps.go:240-244)、admin 锁 localhost:2019(admin.go:1453)+Origin 校验(:873-886)、**反代默认信任零个代理**(reverseproxy.go:141-147)、On-Demand 强制 ask(ondemand.go:39-46);SECURITY.md 窄 scope+强制 AI 披露(:14-30,:39)。依赖哲学:"不得导出依赖类型"+build tags 裁剪 nobadger/nomysql/nopgx(CONTRIBUTING.md:175;ci.yml:16);文档在 website 分仓(:150);**AGENTS.md 229 行 AI 编码守则**(:5)。

## 5.4 与前作对照及设计动机

| | Caddy | Git(卷一 07) | zstd(卷二) | curl(卷三) |
|---|---|---|---|---|
| 构建 | xcaddy(Go 原生) | 手写 Makefile 矩阵 | 多构建联邦 | autotools/cmake |
| 测试 | 进程内真服务器 | shell 端到端 | decodecorpus 反证法 | 8 周节奏 |
| 发布 | tag 验签+cosign | 邮件补丁 | 年度慢发布 | 8 周一版 |

1. **xcaddy 的插件经济学**:Go 模块生态让"插件"退化为"依赖"——C 编译期插件(nginx)与动态库(无)的两难在 Go 消失;
2. **caddytest 的进程内哲学**:不起进程、直接调 Main()——测试速度与真实性的平衡点与 FFmpeg FATE/Git bats 各占一端;
3. **tag 验签删 tag**(:110-115):供应链安全的自动化执行——验证失败不警告而是**主动删除**,纪律的物理化;
4. **默认安全清单作为产品**:自动 HTTPS/localhost admin/零信任 XFF——每个默认值都省掉一次真实事故;
5. **AGENTS.md 229 行**:AI 编码时代的项目守则——开源工程的新图层。

## 5.5 FAQ

**Q1:xcaddy 和标准版的区别?**
机制等价(:7-19):标准版=固定的一组空导入。

**Q2:caddytest 怎么做到又快又真?**
进程内调 Main()(:291-299):真启动、真端口,但无子进程开销。

**Q3:241 个黄金文件怎么组织?**
Caddyfile 段+期望 JSON 段以 `----------` 切分(:43):适配器回归的一文件多案例。

**Q4:tag 为什么会被流水线删掉?**
(:110-115):验签失败/与提案不符——发布产物的来源必须可追溯。

**Q5:为什么没有 CHANGELOG 文件?**
从 conventional commit 生成(:207-216):单一事实源。

**Q6:Caddy 的依赖哲学?**
stdlib 优先+"不得导出依赖类型"+build tags 裁剪(:175):依赖是 ABI 的一部分。

**Q7:AGENTS.md 是什么?**
AI 编码助手的项目守则(:5,229 行):给 AI 的贡献规范与人类同等地位。

**Q8:默认信任零个代理会不会太保守?**
(:141-147):显式配 trusted_proxies 的成本远低于 XFF 伪造事故——保守是产品。

**Q9:fuzz 有几个目标?**
7 个 gofuzz(dvyukov 风格):配置解析与处理器为主。

**Q10:文档在哪?**
website 分仓(:150):文档与代码的版本解耦。
