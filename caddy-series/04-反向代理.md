# 第 04 章 · 反向代理:负载均衡、健康检查与 XFF 信任链

> 基线:commit `56e3a88`。行号以 modules/caddyhttp/reverseproxy/ 为准(reverseproxy.go 很大,函数级定位)。

## 4.0 全景:一次反向代理请求

```
请求 → 路由命中 reverseproxy handler(:485-597 ServeHTTP+重试循环 :562-587)
  → proxyLoopIteration(:603-730):Select 选 upstream → fillDialInfo
     → 改写(XFF 注入 addForwardedHeaders :889-986)→ 转发 → 响应回流
  → 失败 → tryAgain(:1342-1416)判定 → 换 upstream 重试
```

**默认策略 random**(非轮询,Provision 兜底填 RandomSelection{} :380-382);12 种策略均为独立模块,统一于 9 行 Selector 接口(:1690-1692)。least_conn 数的是**活动请求数**而非连接(selectionpolicies.go:282-308,注释 :263-268);哈希类(ip/uri/cookie)全走 **Rendezvous/HRW 哈希**(:860-886);cookie 粘性用 HMAC-SHA256 恒时比较(:678-732,:794-801)。

## 4.1 重试语义:哪个错误换 upstream

`tryAgain`(:1342-1416):**DialError 永远可重试**(连接未建立=请求未送达上游);连接后错误**默认只有 GET 重试**,其余须 retry_match 显式授权——幂等性假设显式化;retry_match 的响应评估在 reverseProxy 内(:1132-1150)。statusError 错误→状态码映射 502/504/499(:1616-1645)。

## 4.2 健康检查:主动与被动的数据结构

- **主动**:后台 ticker(默认 interval 30s/timeout 5s/passes=fails=1,healthchecks.go:201-219),判定 doActiveHealthCheck(:391-581);恢复=连续 passes 次成功+CAS setHealthy+Emit 事件(:497-505);状态 per-handler 隔离;
- **被动**:三处记账——roundtrip 失败(:720-722)、unhealthy_status(:1095-1099)、unhealthy_latency(:1102-1105);生效条件 Fails()<MaxFails(hosts.go:86-108),**须 fail_duration>0 否则 no-op**;**纠偏:衰减是每个失败独立定时遗忘(+1 后 FailDuration 再 -1,:587-640),不是指数惩罚**;
- 被动状态全局共享于 UsagePool、**跨配置重载保留**(hosts.go:316);主动状态 per-handler。熔断器只有接口无内置实现(:109,:263-266)。

## 4.3 XFF 信任链与转发细节

**两层判定**:server 层 determineTrustedProxy(server.go:1413-1461)+handler 层 trusted_proxies CIDR(:319-335,:931-938)。不可信时客户端带来的 X-Forwarded-For/Proto/Host **被丢弃**,以直连 IP 重建(:944-955);unix socket 与 RemoteAddr 解析失败直接删头防伪造(:895-921)——**默认信任零个代理**(reverseproxy.go:141-147)。SSE/流式:flush_interval 命中即 -1(streaming.go:243-281);websocket:入站 h2/h3 降级(:499-514),出站 101 双向拷贝+ hijack(streaming.go:60-239);transport 默认 keepalive 30s/2m/32、拨号 3s、versions 1.1+2、h2c(httptransport.go:185-187,:208-226,:536-551)。

## 4.4 设计动机

1. **XFF 默认零信任**:伪造 X-Forwarded-For 是反代生态最常见的安全事故——**默认丢弃+显式声明可信 CIDR** 是安全默认的标本(对照 01 章 admin 锁 localhost);
2. **重试的幂等性显式化**:只有 GET 默认重试(:1342-1416)——把 HTTP 语义(非幂等方法不可盲重)写进代码;
3. **策略即模块**:12 种 LB 策略是独立模块(9 行接口)——自定义策略与内置同权;
4. **主动+被动互补**:主动发现死 upstream(免用户请求踩雷),被动发现"活着但坏了"(主动检查探测不到的应用层故障)——两者缺一不可。

## 4.5 FAQ

**Q1:默认负载均衡是什么?**
random(:380-382):无状态、无排序偏差;要粘性用 cookie 策略(HMAC 恒时比较)。

**Q2:least_conn 数的是什么?**
活动请求数(:282-308),不是 TCP 连接数。

**Q3:POST 请求失败会换 upstream 重试吗?**
默认不会(:1342-1416):非幂等;retry_match 显式授权才重试。

**Q4:被动健康检查不生效?**
fail_duration>0 才启用(:86-108):默认 no-op。

**Q5:健康状态的衰减是指数吗?**
不是:每个失败独立定时遗忘(:587-640)——纠偏常见误解。

**Q6:XFF 为什么默认丢弃?**
(:944-955):不可信来源的头可伪造——显式配 trusted_proxies 才信。

**Q7:SSE 转发会缓冲吗?**
flush_interval 命中 SSE 即 -1(:243-281):逐块直通。

**Q8:websocket 经 Caddy 代理可用吗?**
可用:101 升级双向拷贝+ hijack(:60-239);入站 h2 会降级(:499-514)。

**Q9:上游 502/504 怎么映射?**
statusError 映射(:1616-1645):拨号失败 502、超时 504、客户端取消 499。

**Q10:熔断器有内置吗?**
只有接口(:109):策略留给用户实现。

## 4.6 小结与深挖方向

本章结论:**反代="策略即模块+重试幂等显式化+主动被动双健康检查+XFF 零信任"**。深挖:

1. Rendezvous 哈希(:860-886)在 upstream 增减时的迁移率;
2. tryAgain(:1342-1416)对幂等方法清单的可配置性;
3. 被动遗忘定时器(:587-640)在高失败率的抖动;
4. h2→h1 降级(:499-514)的流式语义损失;
5. UsagePool 全局被动状态(:316)在多租户的隔离边界。
