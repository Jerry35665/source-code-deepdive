# 《Kafka 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》的第六卷。全部结论来自对 Kafka 4.5.0-SNAPSHOT(commit `f6149f1c`,2026-09-05)源码的逐行阅读,每处关键论断标注 `文件:行号`。

## 这卷写给谁

用过 Kafka、想理解"消息从 send() 到被 poll() 中间发生了什么"的后端工程师;正在做事件流/队列系统选型或自研的人。需要 Java 阅读能力;Scala 部分(broker core)本卷只覆盖主干。

## 为什么选 Kafka

1. **流式数据的事实标准**,且 4.x 是历史性版本:ZooKeeper 移除、GroupCoordinator Java 重写、KIP-848 新消费协议落地——读它等于读"一个十年系统如何自我更换引擎";
2. **"日志即一切"的极致样本**:生产者累加器、broker 存储、消费位移、KRaft 元数据,全是同一种数据结构的不同投影;
3. **与卷四(raft)构成对照**:两套分布式系统对同一批问题(选举、复制、成员变更)的两种工程答案。

## 环境准备

```bash
git clone https://github.com/apache/kafka.git && git checkout f6149f1c

# KRaft 模式快速启动(JDK17)
KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"
bin/kafka-storage.sh format -t $KAFKA_CLUSTER_ID -c config/kraft/server.properties
bin/kafka-server-start.sh config/kraft/server.properties

# 与源码互动
bin/kafka-console-producer.sh --bootstrap-server :9092 --topic t
bin/kafka-consumer-groups.sh --bootstrap-server :9092 --describe --group g
```

## 三种用法

1. **系统通读**(约 5-6 小时):01 全景 → 02 生产者 → 03 消费者 → 04 存储 → 05 网络与 KRaft → 06 总结;
2. **生产排障**:各章 FAQ(约 80 条)——"no live upstreams"式的 no live Kafka 疑问:OutOfOrderSequence、rebalance 风暴、HW 截断、max_fails 放大;
3. **对照设计**:与《etcd/raft 卷》并读第 04、05 章——同一批分布式问题的两种工程答案。

## 统一约定

- **行号即凭证**:基于 4.5.0-SNAPSHOT;演进极快,以函数名检索定位新版本;
- **勘误显式**:KRaft 元数据日志 4.5 已换底 UnifiedLog(KafkaRaftLog)、SocketServer 壳化迁移、clients 侧无 POCH 机制;
- **三代共存**:classic/cooperative/KIP-848 的协议对照表在第 03 章。
