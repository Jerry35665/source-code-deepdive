# 第 01 章 · 全景与代码地图:多模块的 Java 巨兽

> 基线:Kafka 4.5.0-SNAPSHOT,commit `f6149f1c`(2026-09-05)。

## 1.1 一组数字认识这个项目

| 指标 | 数值 |
|---|---|
| 版本线 | 4.5.0-SNAPSHOT(KRaft 时代,ZK 已移除) |
| 最大文件 | GroupMetadataManager.java 10,073 行 |
| 关键模块规模 | core(Scala/Java 混合)、clients(纯 Java)、storage、group-coordinator、metadata(KRaft) |
| 构建体系 | Gradle + Java 17 |
| 许可证 | Apache-2.0 |

**与前几卷对照**:Kafka 是系列第一个 Scala/Java 混合项目,也是模块化最彻底的(顶层十余个 Gradle 子模块)。它的独特之处:**整个系统建立在同一种数据结构上——追加日志**,客户端、broker、协调器、KRaft 控制器全部是"日志的生产者/消费者"。

## 1.2 顶层结构

```
kafka/
├── clients/            纯 Java 客户端(producer/consumer/admin/network)
├── core/               broker 核心(Scala 为主:KafkaApis、ReplicaManager、log cleaner)
├── storage/            日志存储的 Java 化抽取(UnifiedLog/LogSegment/索引)
├── group-coordinator/  消费组协调的 Java 重写(GroupMetadataManager 10073 行)
├── share-coordinator/  KIP-932 共享组协调
├── metadata/           KRaft:QuorumController、元数据日志、scram
├── server/             broker 网络层(Processor/SocketServer)与 share 分区
├── server-common/      Purgatory(DelayedOperation)等公共件
└── transaction-coordinator/  事务协调器
```

**演进地层**:4.x 完成了三件大事——ZooKeeper 移除(KRaft 独立共识)、GroupCoordinator 从 Scala 重写为 Java(+KIP-848)、日志存储从 core 抽取为纯 Java 的 storage 模块。读代码时要习惯"同一概念有三代实现残留"。

## 1.4 一条主线串起全部文件

```
producer:send → accumulator → Sender → NetworkClient ─┐
                                                       ▼
broker:SocketServer → KafkaApis.handleProduceRequest
    → ReplicaManager.appendRecords → UnifiedLog.append → LogSegment(mmap 索引)
    → DelayedProduce(Purgatory 等待 acks=all)→ HW 推进 → follower fetch
                                                       ▼
consumer:poll → FetchSession → UnifiedLog.read(索引定位)→ FetchBuffer
metadata:QuorumController(KRaft:raft/ 模块 KafkaRaftClient)→ KafkaMetadataLog → 分区分发
```

**勘误性事实**:KRaft 用的是 raft/ 模块里**独立实现的 Raft**(KafkaRaftClient,单线程 poll 驱动,非 etcd 式通用库);而其元数据日志在 4.5 已重构为 `raft/internals/KafkaRaftLog.java`——**底座换成了标准 UnifiedLog**,复用数据路径的段管理/恢复/索引/清理全部工程积累。"日志即一切"在此完成闭环。

## 1.5 阅读路线

1. **数据主线**(推荐):02 生产者 → 04 日志存储 → 03 消费者。跟着一条消息从客户端到磁盘再到消费者;
2. **一致性主线**:04(HW/leader epoch)→ 05(KRaft/QuorumController)。对照《etcd/raft 卷》——Kafka 的 controller 是 KRaft 化的 Raft,而分区层有自己的 HW 机制(非 Raft);
3. **运维主线**:各章 FAQ(约 80 条)——幂等重试、rebalance 抖动、HW 截断、日志清理。
