# 第 01 章 · 全景与架构:单写者、只读 mmap 与双 meta 原子性

> 基线:commit `fd01fc79`(boltdb/bolt 归档版 master)。核心:db.go / tx.go / doc.go。

## 1.0 全景:一张图看懂 BoltDB

```
            bolt.db 单文件(初始 4 页由 init() 写死,db.go:343-387)
 p0 META0(txid=0) ◄┐ db.meta():取 txid 较大且 validate 通过的一份;
 p1 META1(txid=1) ◄┘ 两份同时坏才打不开(db.go:282-292, 803-824)
 p2 FREELIST(每 commit 整页重写,tx.go:176-186)
 p3 根 bucket 的 B+tree 根页 → p4..N branch/leaf(大值接 overflow 连续页)

 读路径:用户代码 ──PROT_READ mmap──► 页指针直读(零拷贝,事务内有效)
 写路径:堆上 node/脏页 ──commit──► WriteAt 新位置 ──fdatasync──► 翻转 meta
 锁三件:rwlock(全局单写)/ metalock(txs 注册+rwtx 挂载)/ mmaplock(防 remap 踩读)
```

纠偏:写**不是**原地改 mmap——映射是 PROT_READ,写映射区直接 SEGV(bolt_unix.go:50; db.go:100),写事务在堆上做 CoW 脏页、commit 时 `WriteAt` 到新位置,旧页原样留给读事务(tx.go:474-517);"freelist 打开时全库扫描重建"也是误传——它是持久化页,Open 直接读入(db.go:236-237)。全库非测试代码约 3,953 行,核心五件套 db/bucket/tx/node/cursor 加 page/freelist 共约 4,000 行。

## 1.1 平台层:锁、mmap、fdatasync 三处硬差异

Unix 用 `syscall.Flock`,非阻塞失败后每 50ms 重试直至超时 ErrTimeout(bolt_unix.go:14-40);Solaris 例外走 fcntl 记录锁。**Windows 必须另立 `.lock` 文件**做 LockFileEx(注释:进程无法对同一文件共享独占锁,WriteTo 需要),且 Truncate 职责挪进 mmap 流程(bolt_windows.go:51-59, 98-130; db.go:875-880 因此跳过)。mmap 一律 PROT_READ + `madvise(MADV_RANDOM)`(bolt_unix.go:48-65)。OpenBSD 无统一缓冲缓存,fdatasync 退化为 `msync(MS_INVALIDATE)`,并有 `IgnoreNoSync` 强制忽略 NoSync(db.go:26-30; bolt_openbsd.go:14-27)。maxMapSize:32 位平台 2GB,64 位 256TB(bolt_386.go:4; bolt_amd64.go:4);ARM32 在 init 时探测非对齐访问得到 brokenUnaligned,读值前先克隆对齐(bucket.go:135-139)。

## 1.2 Open():六步,没有"预热读事务"

`Open()`(db.go:150-241):开文件(O_CREATE/ReadOnly 决定读写模式)→ flock(读写独占/只读共享,防两进程各自写 meta 损库)→ 空文件则 `init()` 写 4 页,否则读首页 0x1000 字节探测 pageSize、校验失败退回 OS 页大小(db.go:204-219)→ 建 pagePool → `mmap(InitialMmapSize)` → **直接从 mmap 读 freelist**。本 commit 的 Open **不创建任何 Tx**,"Open 预热读事务"的说法不成立(db.go:230-240)。mmap 大小从 32KB 倍增到 1GB、之后按 1GB 步进(db.go:308-340);remap 前先对写事务根 node 做 `dereference()` 防悬挂指针(db.go:266-269);meta0/meta1 校验**只有双双失败才报错**(db.go:282-292)。

## 1.3 事务双通道:读=拷 64 字节,写=全局单飞

读通道 `beginTx`:按 metalock→mmaplock 顺序加锁(写事务同序防死锁),把 tx 挂进 `db.txs` 即完事——**快照就是拷贝一份 64 字节 meta 结构**(tx.go:49-50),并持有 mmaplock 读锁到 Close,阻止 remap(db.go:466-502)。写通道 `beginRWTx`:先抢全局 `rwlock`(每库同时仅一个写事务),挂 `db.rwtx`,再取所有存活读事务的最小 txid、`freelist.release(minid-1)` 把不再被引用的 pending 页转正(db.go:504-542)。写事务 init 时 txid 自增,这就是"未来"的事务号(tx.go:58-61);meta 写到 p0 还是 p1 由 `p.id = pgid(m.txid % 2)` 奇偶决定(db.go:1008)——这套"双 meta+奇偶翻转+FNV-64a 校验"就是**无 WAL 的崩溃安全来源**:commit 没走到写 meta 那步,旧 meta 依然完整有效(doc.go:8-11)。

## 1.4 Commit 骨架:两次 fdatasync

```
rebalance(删后重平衡) → spill(拆分+写脏页) → 重写 freelist 页 → grow
 → 脏页按 pgid 排序 WriteAt → fdatasync① → writeMeta(txid%2) → fdatasync② → OnCommit
```

(tx.go:144-236;两次 fdatasync 分别在 tx.go:520-524 与 557-561,文件增长另有 file.Sync,db.go:881-883。)NoSync 可跳过(OpenBSD 上被 IgnoreNoSync 强制恢复)。读事务从不 commit——`View` 结束执行的是 Rollback(db.go:636);托管 `Update`/`View` 里手动 Commit/Rollback 直接 panic(db.go:581-641)。rollback 时写事务清 pending 并从盘 reload freelist(tx.go:249-258)。

## 1.5 bucket:递归 B+tree,子桶是父桶的一个 value

bucket 磁盘表示只有 16 字节 `{root pgid, sequence}`(bucket.go:56-59);子 bucket 以带 bucketLeafFlag 元素的 value 存在父叶子里,`root==0` 表示 inline(整棵子树紧凑排在头之后,阈值 pageSize/4 且不得含子桶,bucket.go:151-153, 586-613)。读事务打开子桶**零拷贝**:直接把 value 字节指针 cast 成 `*bucket`;写事务才复制(bucket.go:130-156)。Get 对 bucket 型 key 返回 nil(bucket.go:270-272)。定位差异:SQLite 是带 journal/WAL 的通用 SQL 栈;BoltDB 读优化——页即磁盘格式、mmap 即页缓存;LSM 写优化但读有放大;BoltDB 代价是写放大:每 commit 重写脏路径整条分支+freelist 页+两次 fsync。

## 1.6 设计动机

1. 纯 Go、单文件、可整体序列化的嵌入式事务 KV,蓝本是 LMDB(doc.go:1-13);
2. 只读 mmap 让应用层"不可能写坏库",越界写直接 panic(doc.go:33-36);
3. 无恢复逻辑:未完成事务崩溃后自然消失,靠双 meta 校验代替 WAL(doc.go:9-11);
4. 读快照成本极低(一次 64 字节拷贝),读者永不见半成品(tx.go:49-50);
5. 全局单写者把并发推理简化到一把 rwlock(db.go:118, 512);
6. allocate 复用 pagePool、按 16MB 批量扩容摊薄 truncate/fsync 成本(db.go:36, 92-95, 830-834)。

## 1.7 FAQ

**Q1:Get 返回的 []byte 能存到事务外吗?**
不能,它指向 mmap,事务结束或 remap 后失效(doc.go:38-40; db.go:266-269)。

**Q2:为什么只能一个写事务?**
rwlock 全局互斥,跨进程还有 flock(db.go:118, 512)。

**Q3:写 meta0 还是 meta1?**
`p.id = txid % 2`,奇偶交替(db.go:1008)。

**Q4:进程崩溃会损坏数据吗?**
未写 meta 则旧 meta 有效,等价自动回滚;单份 meta 坏可用另一份恢复(db.go:282-292)。

**Q5:读事务会阻塞写事务吗?**
只在 mmap 需 remap(文件涨过 datasz)时阻塞;InitialMmapSize 设够大可避免(db.go:245-247, 911-919)。

**Q6:小 bucket 也占一页吗?**
不,inline 进父桶 value,阈值 pageSize/4(bucket.go:611-613)。

**Q7:为什么库文件只涨不缩?**
pending 页等读事务退出才能回收;长期不关的读事务让写者只能追加(tx.go:20-23)。

**Q8:一次 commit 几次 fsync?**
至少两次:脏页后、meta 后各一次(tx.go:520-524, 557-561)。

**Q9:Windows 上锁怎么实现?**
独立 `.lock` 文件 + LockFileEx,funlock 时删除(bolt_windows.go:51-59, 89-94)。

**Q10:NoSync 在所有平台都生效吗?**
OpenBSD 上被 IgnoreNoSync 强制忽略(db.go:26-30)。
