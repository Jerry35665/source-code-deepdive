## 6.1 README:告别信即维护状态

README 自报 1.2.1,定位"LMDB 启发的纯 Go KV,给不需要完整数据库服务器的项目"(README.md:1-7);Project Status 宣称 stable、API/文件格式冻结、1TB 生产规模(README.md:18-22)。作者 Ben Johnson 的告别信宣布项目"complete",理由是维护开源数据库"简单改动也需要数小时的仔细测试",并把用户明确指向 CoreOS 的 bbolt 分叉(README.md:26-39)——"已归档"是仓库层面事实,README 原文没有这个词。README 末尾列了 50+ 使用方:Consul、InfluxDB、bleve、btcwallet、SeaweedFS、Storm 等(README.md:881-935)。

## 6.2 doc.go 是规格书

44 行包注释逐条对应实现:全可串行化 ACID+无锁 MVCC 单写者(doc.go:2-4 ↔ db.go:510-512);零拷贝 B+tree(doc.go:8);崩溃无需恢复(doc.go:9-11 ↔ db.go:285-292);LMDB 血统(doc.go:13);数据文件只读映射、应用写它会 SEGV(doc.go:33-36 ↔ db.go:100);键值仅事务期内有效(doc.go:38-40)。与 LMDB 的官方分歧:LMDB 要手动指定 mmap 上限而 Bolt 自动增量重映射(README.md:764-767);对 LSM 的选型建议原文:"随机写 >10,000 w/s 或机械盘选 LevelDB,读多/范围扫描选 Bolt"(README.md:733-744)。

## 6.3 QuickDB:影子模型即判据

simulation_test 的正确性判据是纯内存 map 版 Bolt(QuickDB,simulation_test.go:198-206):每个写事务从 `versions[txid-1].Copy()` 起步、提交前写回 `versions[txid]`;读者随机取键路径逐层下钻,`b.Get()` 与 `qdb.Get()` 不一致即 panic("value mismatch")(:125-157)。Makefile 的 `race` 目标专门只跑 TestSimulate_100op/1000op 加 `-race`(Makefile:7-8)。纠偏:不存在独立的 forward/backward 兼容测试集,兼容仅靠 magic 0xED0CDAED+version=2 的单点校验(db.go:24, 982-992)。

## 6.4 cmd/bolt:能解剖"打不开的库"的裸页工具

八个子命令(main.go:97-119)。亮点两个:`page` 绕过 bolt.Open 直接 os.Open 裸读页字节,所以能检查损坏文件(main.go:461, 1359;注释自曝 ReadPageSize "not transactionally safe",:1399);`compact` 把源库以 **0444 只读**打开、按 64KB 分批提交到新库,完成后打印 gain 倍数(main.go:1589, 1563, 1614)。纠偏:本版没有 keys/get 子命令(易与 bbolt 生态工具混淆,main.go:97-143)。

## 6.5 错误面与三大运维陷阱

Put 的校验链就是 KV 级错误面:ErrTxClosed→ErrTxNotWritable→ErrKeyRequired→ErrKeyTooLarge→ErrValueTooLarge 依次短路(bucket.go:286-296)。运维三陷阱(README 原文有据):文件**只增不减**,删大数据只进 freelist 不还磁盘(README.md:819-824);数据文件绑定端序,不能跨大小端机器拷(README.md:814-817,与第 02 章"无序列化层"互证);mmap 高内存占用是正常的(README.md:805-812)。另有注释与实现矛盾一处:Timeout 注释称"only available on Darwin and Linux"(db.go:897-898),但 Windows/Solaris 同样实现了 ErrTimeout 路径(bolt_windows.go:68; bolt_unix_solaris.go:22)。

## 6.6 设计动机

1. **简单高于性能**:API 只有关读写值,拒绝一切可能损坏库的操作(README.md:9-11, 760-762);
2. **用元数据设计消灭恢复流程**:双 meta+校验和+两阶段提交,崩溃即回滚无需恢复代码(doc.go:9-11);
3. **测试即规格**:随机化黑盒测试写进 Project Status,QuickDB 模型比对是主判据(README.md:19-20);
4. **完工即封版**:格式/API 冻结后停止维护,把演进交给分叉——对抗"必改核心"的维护黑洞(README.md:26-39);
5. **零依赖单文件分发**:无第三方 import,go get 连 CLI 一起装(README.md:78-85)。

## 6.7 FAQ

**Q1:崩溃后为什么不需要恢复日志?**
双 meta+两阶段提交使未提交数据天然不可见(README.md:869-875)。

**Q2:删掉一大半数据文件会变小吗?**
不会,空间只进 freelist 复用(README.md:819-824)。

**Q3:bolt check 查什么?**
双引用/可达已释放/unreachable unfreed/越界四类(tx.go:383-445)。

**Q4:compact 动原库吗?**
不动,源库 0444 只读打开(cmd/bolt/main.go:1589)。

**Q5:打开被占用的库会怎样?**
默认永久等锁,传 Options.Timeout 才超时 ErrTimeout(db.go:924-927)。

**Q6:NoSync 跳过了什么?**
write 与 writeMeta 各自的 fdatasync;OpenBSD 上被强制无视(tx.go:520-524, 557-561)。

**Q7:etcd 用的是这个库吗?**
etcd 经 bbolt 间接使用 Bolt 格式;README 列表未直接点名 etcd(通识,未核实源码)。

**Q8:bbolt 加了什么?**
NoFreelistSync/Mlock/Unsafe/库内 Compact 等方向(通识,未核实源码);本版可对照的痛点是 freelist 每事务整页重写与双 fdatasync。

**Q9:测试怎么保证"结束时库是好的"?**
包装的 Close() 隐式跑 MustCheck,有错 panic 并 dump 现场(db_test.go:1381-1393)。

**Q10:页面命令为什么能看损坏的库?**
page/dump 绕过包 API 裸读页字节(main.go:461, 1359)。
