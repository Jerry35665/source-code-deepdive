# 第 01 章 · 全景架构:pool、set、drive 三级拓扑

> 基线:commit `7aac2a2`。行号以 cmd/ 为准(主代码几乎全在 cmd/,单 package 巨石)。

## 1.0 全景:三级拓扑与四种部署模式

```
pool(扩容单元)→ set(纠删组,2-16 盘)→ drive(单盘)
四种模式(cmd/setup-type.go:23-38):ErasureSD(单机单盘)/Erasure(单机多盘)/DistErasure(分布式)
64 盘 = 4 set × 16(set 数量最少的自动推导,endpoint-ellipses.go:71-90;注释见 :278)
```

set 尺寸自动推导:总盘数 GCD→可整除候选→**按 set 数量最少**选(endpoint-ellipses.go:71-90);可用 MINIO_ERASURE_SET_DRIVE_COUNT 覆盖(:323)。每个 endpoint 打上 (pool,set,disk) 坐标(endpoint.go:1002-1006);分布式判定在 :1140-1147。启动:newObjectLayer = newErasureServerPools(server-main.go:1199-1201;erasure-server-pool.go:78)。

**9000 一个端口承载四类流量**:S3 API + /minio/storage(盘 RPC)+ /minio/peer(控制面)+ /minio/grid/v1 与 /minio/grid/lock/v1(两条 WebSocket grid,04 章)。

## 1.1 XL 磁盘布局:对象名的字面目录

```
盘 → format.json + .minio.sys/{tmp/.trash, multipart, buckets, config}
   → 桶目录(bucket=getVolDir,xl-storage.go:787-793)
   → 对象名字面目录(不哈希分桶!常见误传已澄清,A 报告专节)
      → xl.meta(元数据,≤128KiB 小对象内联数据 :60)
      → 每版本 UUID DataDir/part.N(分片,xl-storage.go:2366)
```

**对象名不做哈希分桶**——桶下直接按对象名的字面目录层级存(哈希只用于 data-scanner 的分摊);写入走 .minio.sys/tmp 再**原子 rename 提交**(系列模式 4);分片在 set 内按对象名 CRC 的 hashOrder 排列——**让首数据分片散盘**(02 章)。

## 1.2 命名空间锁

本地/分布式锁二选一(namespace-lock.go:231-242);分布式锁 internal/dsync/drwmutex.go:219-231:quorum=N/2 起步、**写锁相等时 +1 防脑裂**;锁为 **1 分钟租约**后台回收(lock-rest-server.go:158-190)——04 章展开。

## 1.3 设计动机

1. **为什么纠删码而非三副本**:对象存储的容量经济性(EC N/2 可用 vs 副本 3× 空间)+盘级并行——代价是读放大与修复复杂(02 章);
2. **为什么对象名字面目录**:S3 语义的对象名可含 `/`(伪目录),字面映射让 mc/ls 可直接对应;哈希分桶(常见误传)会破坏这种对应;
3. **为什么单二进制内嵌全部**:S3 API+盘 RPC+控制面+grid 同端口——部署单元只有一个进程;
4. **set 内 2-16 盘**:纠删码的工程边界(太少无冗余意义,太多重构成本高)——规范写死(cmd/endpoint-ellipses.go:48)。

## 1.4 FAQ

**Q1:对象名会变成哈希目录吗?**
不会:桶下字面目录(A 报告专节澄清);哈希只在 scanner 分摊与 set 选择。

**Q2:64 盘怎么分组?**
GCD 推导选 set 数最少:4 set×16(:71-90);可环境变量强制。

**Q3:一个小文件占一个盘目录吗?**
≤128KiB 内联进 xl.meta(:60)——小对象零额外分片文件。

**Q4:9000 端口的四类流量怎么分?**
路径区分:S3 API/盘 RPC/peer 控制面/两条 grid WebSocket(01.0)。

**Q5:锁的租约是多久?**
1 分钟,后台回收(:158-190);失去 quorum 触发回调(04 章)。

**Q6:扩容(pool)后旧对象会迁移吗?**
不会:pool 按对象已有位置或剩余空间选(:637-657)——新旧数据隔离。

**Q7:set 选择为什么只用对象名?**
(:692-698):同名对象恒同 set(纠删组的完整性);bucket 不参与。

**Q8:quorum 等待发生在启动的哪一步?**
prepare-storage(:239):等足够盘 online 才成组。

**Q9:单机单盘模式的代码路径?**
ErasureSD(:23-38):同一 XL 后端,退化 set=1。

**Q10:format.json 是什么?**
盘的身份与 set 布局声明(format-erasure.go:120):多盘成组的契约。
