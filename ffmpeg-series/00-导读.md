# 《FFmpeg 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》第二系列的首卷。全部结论来自对 FFmpeg master(commit `9f63b36a`,2026-09-04)源码的逐行阅读,每处关键论断标注 `文件:行号`。

## 这卷写给谁

有 3-5 年后端经验、**不需要音视频背景**的工程师——本卷从"什么是 packet/frame"讲起,所有多媒体概念在机制描述中自足解释。如果你做过 Web 服务器、数据库代理或消息队列,本卷的框架层会非常熟悉:FFmpeg 本质上是一台"格式无关的数据搬运与变换机"。

## 为什么选 FFmpeg

1. **多媒体行业地基**:B 站/抖音/Zoom/直播/视频会议的每一帧都经过它;AI 生成视频时代,转码/处理管线需求同步爆炸;
2. **C 语言框架设计的百科全书**:回调表、引用计数、探测机制、时间戳有理数——每个模式都有独立的教学价值;
3. **解读空窗**:现有内容以 2015 年前的旧版 API 教程为主,当前架构无系统性逐模块深读。

## 三种用法

1. **系统通读**:首卷 01→06(核心框架),第二卷 07→14(子系统纵深);
2. **运维/开发对照**:AVIO 超时 → 02 章;decoding error → 03 章;filter graph 语法 → 04 章;faststart → 05 章;
3. **自研引擎**:02(avio 抽象)+ 03(send/receive)+ 04(activate 调度)是可照抄的工程蓝图。

## 统一约定

- **行号即凭证**:基于 master 9f63b36a;
- **零音视频前置**:所有概念(packet/frame/codec/demux/mux/filter/PTS/DTS)在首次出现时解释;
- **与第一系列对照**:avio vs Redis/Nginx 事件抽象;RV 语义 vs K8s;引脚计数 vs SQLite/LevelDB。
