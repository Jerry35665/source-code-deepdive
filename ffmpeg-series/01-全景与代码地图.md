**与前几卷对照**:FFmpeg 的独特之处在于它的**广度**——不是做好一件事,而是"支持一切格式"。代码量 150 万行是系列之最,但核心框架层(avio/demux/mux/decode/encode/filter)只有约 2 万行。剩余的 148 万行是具体编解码器实现(500+)、封装格式解析器(200+)与汇编优化(SIMD)。

## 1.2 六库分层架构

```
           应用程序
              │
    ┌─────────┴──────────┐
    │  libavformat        │  封装/解封装(容器格式: MP4/TS/MKV/FLV...)
    │  avio.c / demux.c   │  I/O 抽象 / 解复用框架
    │  mux.c / mov.c      │  交织算法 / MP4 muxer(12526 行)
    └─────────┬──────────┘
              │ AVPacket(压缩数据)
    ┌─────────┴──────────┐
    │  libavcodec         │  编解码(H.264/HEVC/AAC/Opus... 500+)
    │  decode.c / encode.c│  解码/编码框架
    │  bsf.c              │  位流滤镜(packet 级变换)
    └─────────┬──────────┘
              │ AVFrame(原始帧)
    ┌─────────┴──────────┐
    │  libavfilter        │  滤镜图(scale/overlay/rotate... 500+)
    │  avfilter.c          │  activate 调度
    │  framesync.c         │  多输入同步
    └─────────┬──────────┘
              │
    ┌─────────┴──────────────────────┐
    │  libswscale    视频缩放/色彩空间  │
    │  libswresample 音频重采样        │
    └─────────┬──────────────────────┘
              │
    ┌─────────┴──────────┐
    │  libavutil          │  基础工具(mem/log/rational/error)
    │  hwcontext.c        │  硬件加速抽象
    └────────────────────┘
```

**数据类型三件套**:AVPacket(压缩后的数据包)→ AVFrame(解码后的原始帧)→ AVPacket(编码后的数据包)。整个 FFmpeg 就是这三种形态之间的搬运与变换。
