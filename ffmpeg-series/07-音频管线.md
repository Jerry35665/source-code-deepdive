# 第 07 章 · 音频管线:重采样、格式转换与编解码

> 基线:commit `9f63b36a`。行号以 libswresample/、libavutil/、libavcodec/ 为准。

## 7.0 数字音频三参数与管线全景

一段数字音频由三个正交参数描述:

- **采样率**:CD 44100 Hz,视频工业 48000 Hz,语音 16000 Hz;
- **位深/格式**:12 种 AVSampleFormat(u8/s16/s32/s64/flt/dbl × packed/planar);
- **声道布局**:mono/stereo/5.1/7.1(或自定义)。

任何两个音频片段几乎总会在三参数上不一致。FFmpeg 音频管线 = 三个操作:

1. **格式转换**(audioconvert.c):逐样本算术/移位;
2. **重采样**(resample.c):多相 FIR 滤波改变采样率;
3. **声道混音**(rematrix.c):输出声道 = 输入声道的加权和。

由 `SwrContext` 编排成固定流水线,libavfilter 的 `aresample` 再包成滤镜图节点。

## 7.1 swresample:内部一律 planar

`swr_init()`(swresample.c:156-406)是理解全库的钥匙,四个决策:

**(a) 重采样引擎**:SWR_ENGINE_SWR(自家)或 SWR_ENGINE_SOXR(libsoxr);两者实现同一个 8 函数接口 `struct Resampler`——教科书式算子抽象层。

**(b) 内部采样格式**:**内部一律 planar**——SIMD 按声道整段搬运、混音按平面遍历缓存友好。规则:输入输出都 ≤16bit 且不改采样率 → S16P;否则 ≤3 字节 → S16P;≤4 字节 → FLTP;再不然 DBLP。

**(c) rematrix 判定**:布局不同/音量≠1/自定义矩阵才需要混音;`AV_CHANNEL_ORDER_UNSPEC` 且声道数不匹配直接报错——**混音必须知道每个声道的空间语义**。

**(d) 流水线缓冲**:无重采样+无混音+无 channel_map+无抖动 → 直通转换器;否则 in_convert → resample/rematrix → out_convert。

### 重采样流水线

```
in(packed/planar) → in_convert(格式+选道) → postin
  → resample(多相FIR) 或 rematrix(矩阵混音) → midbuf
  → rematrix 或 resample(顺序由启发式决定) → preout
  → out_convert(int_fmt → 输出格式) → out
```

典型配置(如 s16p→fltp 同采样率)下 5 级流水线实际只执行首尾两次转换,中间全部**指针别名**。

## 7.2 重采样引擎:双相位多相滤波

- **1024 相位**(phase_shift=10)+ Kaiser 加窗 sinc;`exact_rational` 默认开——48000→44100 恰为 147:160,用 160 个精确相位**零相位误差**;
- **`swr_set_compensation` 直接修改多相步进 dst_incr**(resample.c:328-347)——音频能被"无损拉伸追钟"的数据结构根源;SOXR 引擎不支持 compensation(直播跟钟场景不可用);
- 内部 PTS 时间基 = 1/(in_rate×out_rate)(swresample.c:780,939);aresample 滤镜输出 time_base 为 1/out_rate。

## 7.3 AAC/Opus 解码器概览

- **AAC**:AAC 解码器在 `libavcodec/aac/` 子目录;HE-AAC v2 靠 FIL 元素里的 PS 在解码中途把单声道流重配为立体声(aacdec.c:2050-2068)——**解码即含声道变换**;
- **Opus**:SILK 核心输出 8/12/16 kHz,**每个流内嵌 SwrContext 升到 48 kHz**(opus/dec.c:48、193-216)——解码器内嵌重采样器的实证。

## 7.4 FAQ

**Q1:planar 和 packed 的区别?**
packed = 所有声道交错存储(如 s16: LRLRLR);planar = 每声道连续存储(如 s16p: LLLLL + RRRRR)。FFmpeg 内部一律 planar(SIMD 友好),对外接口支持两种。

**Q2:为什么音频 PTS 精度要求比视频高?**
视频 PTS 精度到 1/90000 秒够用;音频 PTS 以样本为 tick(1/48000 秒),且重采样改变样本计数、引入群延迟,误差会累积为可闻的音画不同步。

**Q3:SOXR 更好为什么不是默认?**
SOXR 不支持 `swr_set_compensation`(直播跟钟必须的功能);且自家 SWR 引擎在 exact_rational 下已足够精确。

**Q4:什么情况不需要重采样?**
输入输出采样率相同、格式相同、布局相同——swr_init 检测后分配直通转换器,零处理。

## 7.5 小结与深挖方向

本章结论:**音频管线 = "planar 内部格式 + 多相 FIR + rematrix 矩阵 + 补偿追钟"**;AAC/Opus 证明"解码即含重采样"的行业现实。深挖:

1. `av_reduce` 连分数逼近在 44.1↔48 时的收敛步数;
2. dither(噪声整形)对 16bit 输出质量的量化影响;
3. rematrix 的 7.1→5.1 下混系数与 ITU-R BS.775 的关系;
4. Opus SILK→CELT 模式切换时的 SwrContext 重配置。
