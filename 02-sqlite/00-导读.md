# 《SQLite 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》的第二卷。全部结论来自对 SQLite 3.54.0(2026-08-27 trunk,git 镜像 commit `492e7fc0` / Fossil `5251f4d7`)源码的逐行阅读,每处关键论断标注 `文件:行号`,可对照源码验证。

## 这卷写给谁

有 1-5 年后端经验、用过 SQLite(或任何 SQL 数据库)、想理解"一个数据库引擎到底由什么组成"的工程师。不需要 C 语言专精,但需要一点耐心——本卷的文件引用密度比卷一更高,因为 SQLite 的注释本身就是第一手文档,行号让你能直达。

## 环境准备

```bash
git clone https://github.com/sqlite/sqlite.git
cd sqlite && git checkout 492e7fc0        # 与本卷行号一致的快照

# 构建(经典 configure 路线)
./configure && make sqlite3               # 或用 autoconf/ 下的 amalgamation 包

# 与源码互动的三把钥匙
./sqlite3 :memory: "EXPLAIN SELECT 1;"     # 看字节码(第 08 章)
./sqlite3 :memory: "EXPLAIN QUERY PLAN SELECT * FROM t WHERE a=1;"  # 看计划(第 07 章)
./test/testrunner.tcl mdevtest             # 跑开发者测试集(第 09 章)
```

没有环境也可以读:所有代码片段 ≤15 行,GitHub 网页版按 `文件名 + 行号` 直接跳转。注意 **amalgamation(sqlite3.c)不在仓库里**——它由 `tool/mksqlite3c.tcl` 在发布时生成;读源码请读 `src/` 分文件版本。

## 三种用法

1. **系统通读**(约 7-9 小时):01 全景 → 02 执行框架 → 03/04 存储层 → 05 记录格式 → 06/07 编译器 → 08 VDBE → 09 工程文化;
2. **面试冲刺**:各章"设计动机"与"FAQ"(全卷约 90 条)——B-tree 平衡条件、WAL 提交点、亲和性三种转换强度、束搜索代价公式都是高频误区;
3. **对照排障**:SQLITE_BUSY → 第 04 章锁五态清单;查询计划不如预期 → 第 07 章 TUNING 公式;文件损坏 → 第 03 章防御判定;内存压缩 → 第 05 章 serial type。

## 本卷的四个统一约定

- **行号即凭证**:全部基于 3.54.0 trunk 快照;与旧资料冲突处显式标注(record.c 已消亡、聚合子查询不再扁平化、优化器无计划缓存);
- **与卷一互为镜像**:章节刻意安排了对照——Redis 的 ae 事件循环 vs SQLite 的巨型 switch,Redis 的渐进式 rehash vs SQLite 的惰性页解析,Redis 的 backlog 引用计数 vs SQLite 的 WAL 帧校验和链;
- **代价公式给原文**:第 07 章的全部 TUNING 魔数(3.0×N、25 行、1.25 次、÷8)附代码出处,可直接用于讲解;
- **结论可复算**:记录格式示例逐字节验算(第 05 章)、EXPLAIN 输出实际生成(第 08 章)、"百万用例"的量级推导(第 09 章)。
