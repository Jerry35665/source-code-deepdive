# 第 04 章 · 集群与网关:无共识协议的扇出网络

> 基线:commit `8f3f31b0`。核心文件 server/route.go(3362 行)与 server/gateway.go(3426 行)。

## 4.0 全景:兴趣传播与消息路径

```
订阅传播:S3 客户端 SUB foo → updateRouteSubscriptionMap 在 acc.rm 计数
  → 仅 0→1/N→0 边沿向所有 route 广播 RS+ <account> <subject>(route.go:2609-2622)
  → S1/S2 把远端兴趣插入各自 acc.sl —— 每个节点的 sublist 是"全局兴趣的投影"
消息:S1 PUB foo → 本地匹配命中"ROUTER 类型的兴趣条目"→ RMSG 发给 S3
  → S3 processInboundRoutedMsg 二次匹配本地 sublist 才投递(route.go:497-501)
网关:跨域按账号域聚合(pasi 计数,first/last 才发 RS±);出站前 gatewayInterest 三层否决
```

不变式:**消息永远跟着"本地匹配+按需转发"走:匹配不到就转发订阅状态,匹配得到才转发消息**。SUB 是低频事件,MSG 是高频事件——把订阅当全网收敛的控制面,把消息当只在有订阅者方向流动的数据面。

## 4.1 ROUTE:复用客户端协议的信令通道

route 连接用同一文本协议骨架+集群私有操作:RS+/RS-(远端兴趣)、LS+/LS-(leaf 集群兴趣)、A+/A-(账号级)。三个关键设计:①**去 sid 化**——客户端 SUB 的 sid 不跨网,传播的是聚合兴趣(计数收敛),连接级语义各服务器自行消化;②**边沿触发**——只有 0→1 与 N→0 产生协议流量,稳态信令接近零;③**入口过滤**——从 route 收到的兴趣只进本地 sublist 匹配,不再广播回其他 route(route.go:2553-2565),从根上斩断兴趣回声。新 route 接入时全量灌入(sendSubsToRoute 逐账号拼 RS+ 批量帧)——**重连即追赶:不需要日志,只需要快照**。

权限是兴趣流的第二道闸:canImport 决定要不要把兴趣发出去,canExport 决定要不要登记对端兴趣——被剪的方向连 RS+ 都不存在,带宽为零。

## 4.2 gossip 建网与防环

显式 `routes:` 永久重试;INFO gossip 把新邻居转发给所有已知远端,收到第三方 INFO 的服务器主动去连(全互联由此长出)。防环三招:ID 自检、solicited 升级仲裁(双向同时拨号时保留一条)、0-100ms 随机抖动;DNS 解析的多 IP 随机挑一个并剔除本机接口地址表 routesToSelf 防自连。cluster 名冲突用**字典序仲裁**——字符串比较而非选举,"无共识但可运行"的气质。

## 4.3 网关:跨域账号聚合

route=集群内 subject 级全量兴趣;gateway=跨集群域,每对域每服务器仅 1 条出站连接,对端入口收到后借集群内 route 二次扇出——兴趣视图只存在于"入口对"上,避免 N×M 爆炸。聚合:pasi 计数把集群内 N 份订阅折叠成 first/last 两条 RS±,账号整体无兴趣降级为一条 A-。跨域 request-reply 用 `$GNR.<cluster hash>...` 前缀把回复定向回源集群。**interest-only 现状**:route 天然只有显式兴趣一条路(无乐观模式);gateway 名义默认 Optimistic,但 2.9.0 起 INFO 携带 GatewayIOM,连接建立即全账号切 InterestOnly(gateway.go:552-558,1236-1245)——"先洪泛再学习"的窗口被实践证伪。例外:队列兴趣无论模式总是即时带权重登记(漏发一条整个队列空转)。

## 4.4 无共识的一致性论证

没有共识协议、没有选主;Raft 只在 JetStream。语义如实:**at-most-once**——消息只在"此刻有连接且有兴趣"时投递,无兴趣即丢(route.go:497-501 注释自称这就是"扇出的规模感");分区期间无缓冲无重放,重连只同步"现在"的兴趣;订阅视图最终一致(RS- 黑名单、2s 近期订阅过期、lws 去重)。脑裂两侧各自服务本地客户端,不阻断不去重。这些是有意取舍:扇出网络把"不丢"的义务上移给 JetStream/应用层——共识能保证"状态一致",对"消息必达"没帮助却引入多数派延迟。

## 4.5 设计动机

1. **传播兴趣而非消息**:SUB 低频 MSG 高频,源端按对端兴趣投影过滤,跨网流量从 O(消息总量) 压到 O(有订阅者的方向);
2. **边沿触发**:计数账本 acc.rm/lws 让稳态信令为零;
3. **网关按账号聚合**:跨域链路少而贵,pasi 把 N 份订阅折叠成 2 条边沿信令;
4. **防环靠启发式**:坏情形只是断掉多余连接重试,比引入 leader 简单得多;
5. **复用客户端协议**:telnet 可调试、INFO 字段可向后兼容增删、滚动升级可协商。

## 4.6 FAQ

**Q1:集群一致性是什么级别?**
订阅视图最终一致;消息 at-most-once(无缓冲无重放);共识只在 JetStream。

**Q2:脑裂会怎样?**
两侧继续服务本地客户端,互不感知;恢复后全量重放兴趣对齐,窗口内消息不补发。

**Q3:每对服务器几条 route?**
默认 3 条按账号 FNV 哈希分片,两端独立计算一致落点(const.go:158-159)。

**Q4:客户端 SUB 的 sid 会传播吗?**
不会:跨网传播的是去 sid 的聚合兴趣,连接级语义本地消化。

**Q5:gateway 乐观模式还在吗?**
名义在,实际 2.9.0 起 GatewayIOM 立即全账号切 interest-only;阈值 1000 路径仅剩历史意义。

**Q6:队列订阅为什么例外?**
队列消息投给任一成员即成功,漏发即空转且负反馈无法弥补——总是即时带权重登记。

**Q7:跨域回复怎么找到源集群?**
$GNR.<cluster hash>.<server hash>.<subject> 前缀定向映射,带 TTL 清理。

**Q8:重复拨号会建两条连接吗?**
handleDuplicateRoute 保留一条给另一条 retry 标记+随机抖动。

**Q9:权限怎么参与集群?**
canImport/canExport 双向剪枝兴趣流——被剪方向连 RS+ 都不发。

**Q10:cluster 名冲突怎么办?**
字典序大者胜,断开其他 route 重建(route.go:583-595)——字符串仲裁而非选举。

## 4.7 小结与深挖方向

本章结论:**集群="边沿触发的兴趣投影+账号聚合+启发式防环,承诺必达上移给 JetStream"**。深挖:

1. per-account route 池与 noPool 协商降级(route.go:2162-2192);
2. leafnode hub-spoke 兴趣语义与 gateway 联动;
3. compression s2 协商在 route INFO 的交集算法;
4. $GNR 映射表 TTL 与 shouldMapReplyForGatewaySend 的判定;
5. 动态 cluster 名仲裁在网络来回窗口内的最坏情形分析。
