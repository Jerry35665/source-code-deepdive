# 第 10 章 · 可观测性:监控端点、$SYS 事件与运维面(卷二)

> 基线:commit `8f3f31b0`。核心:server/monitor.go(4383 行)与 events.go(3389 行)。三条通道:HTTP 快照(拉)、$SYS 事件流(推)、JS advisory(业务层)。

## 10.0 全景:三通道与端点地图

```
通道一 HTTP :8222(拉,快照):/varz /connz /routez /gatewayz /leafz /subsz
  /accountz /accstatz /jsz /healthz /ipqueuesz /raftz /stacksz /debug/vars
通道二 $SYS(推,时间序列):$SYS.ACCOUNT.*.CONNECT/DISCONNECT、$SYS.SERVER.*.STATSZ
  (周期广播)/LAMEDUCK/SHUTDOWN、$SYS.REQ.SERVER.<id>.*(请求-应答)
通道三 JS advisory:$JS.EVENT.ADVISORY.*、JS 资源拒绝错误
三通道共用同一批 *z() 快照函数——$SYS.REQ...CONNZ 就是 Connz() 的远调用封装
```

## 10.1 监控端点细读

**/varz** 是全服务器仪表盘:静态配置+运行计数+质量指标(SlowConsumers/StaleConnections/StalledClients)+每端点命中计数(监控自身也被监控)。锁顺序讲究:varzMu 串行化并发请求→服务端锁内只做增量更新→**锁外 marshal**——监控大响应永不持全局锁。**/connz**:分页(默认 1024)+六过滤器,数据三路(open/closed 环形缓冲默认 1 万条/按账号);rtt 为空会现场发 RTT ping 探测(首次查再查才有)。**/routez** 全程持写锁——与 connz 读锁策略形成对照,大规模下频繁拉会与路由写入竞争。**/healthz** 分层:裸探针=进程活;js-enabled-only=JS 就绪;默认全量逐账号逐流校验。**/stacksz 故意不取任何锁**——"即便某处死锁也能拿到全 goroutine 栈",这是线上死锁排查的最后手段。**没有原生 /metrics**:Prometheus 依赖外部导出器翻译 JSON(如实)。

## 10.2 $SYS 事件全景

事件开关=系统账号;Connect/Disconnect 是"计费级"事件(负载字段级:ClientInfo 含 start/lang/jwt/issuer_key/kind/nonce…,Disconnect 附 sent/received 分源统计与 reason 全表);STATZ 心跳**从 250ms 起倍增退避**到目标值(启动期快速收敛,稳态降开销),1s 限速防连发,单机无订阅者整条不发;AccountNumConns 变化即发、无变化 30s 心跳。lameduck 事件发完不关 sendq("还有工作要迁移");shutdown 是"最后遗言"(发完置 sendq=nil)。集群成员把对方静默退出视为孤儿,按 5×心跳周期兜底检测。claim 更新:`$SYS.REQ.ACCOUNT.<pubkey>.CLAIMS.UPDATE` 热更账号配置无需重启。

## 10.3 运维动作与消费

监控查询表 monSrvc 每个同时挂两个主题:`$SYS.REQ.SERVER.<id>.<NAME>`(定点)与 `...PING.<NAME>`(广播全集群);应答按请求头 Accept-Encoding 支持 s2/snappy/gzip 压缩。动作类只有四个:KICK(断指定连接)/LDM(优雅断)/RELOAD/$SYS.DEBUG.SUBSCRIBERS;pprof 无 HTTP 端点,经 PROFILEZ 系统请求(cpu 0-15s 异步采样)。消费:全局事件流需系统账号凭据订阅 `$SYS.>`;普通账号靠自动注入的账号钳制 import 只能自查询——**可观测性粒度与多租户隔离用同一套 import 机制表达**。SLI 建议:slow consumers 速率上升(订阅侧过载第一信号)、stalled/stale、JS 内存拒绝、meta 积压。

## 10.4 设计动机

1. **HTTP 与 $SYS 双通道**:拉与推共用同一批快照函数,一套语义两种交付,避免双实现漂移;
2. **分页而非全量**:快照接口的背压——监控查询不该比业务流量更贵(TODO 自认 offset 分页弱点);
3. **statsz 退避+限速+兴趣检查**:组播式集群视图,空闲单机零成本;
4. **监控与故障态解耦**:stacksz 不取锁、varz 锁外 marshal、lameduck 不关 sendq——任何故障态下仍可用;
5. **pprof 内嵌**:对集群所有节点同时采 CPU profile 成为一条广播;攻击面收敛进系统账号权限;
6. **系统账号为唯一权限边界**:普通账号自动注入账号钳制 import 自查询,无需独立监控 RBAC。

## 10.5 FAQ

**Q1:监控端点有哪些?**
14 个:/varz /connz /routez /gatewayz /leafz /subsz /accountz /accstatz /jsz /healthz /ipqueuesz /raftz /stacksz /debug/vars。

**Q2:/routez 为什么慢?**
全程持 s.mu 写锁遍历(要填权限/压缩/账号名);大规模下与路由写入竞争。

**Q3:/connz 的 rtt 为什么可能是空?**
首次查询会现场发 RTT ping 探测,再查才有值。

**Q4:死锁了怎么取栈?**
/stacksz 不取任何锁,runtime.Stack 指数扩容缓冲。

**Q5:statsz 频率?**
启动 250ms 起倍增至目标值;1s 限速;无订阅者整条不发。

**Q6:普通账号能查自己的连接吗?**
能:自动注入的 service import 把 $SYS.REQ.SERVER.PING.CONNZ 映射到账号钳制主题。

**Q7:能远程采 CPU profile 吗?**
能:$SYS.REQ.SERVER.PING.PROFILEZ 广播,cpu 时长 0-15s,异步执行。

**Q8:有 Prometheus 端点吗?**
没有原生 /metrics(如实);外部导出器翻译 JSON。

**Q9:closed 连接能查吗?**
能:state=closed 走环形缓冲(默认 1 万条),sort=reason 直接回答"为何掉线"。

**Q10:订阅谁会收到某主题?**
/subsz?test=<字面量主题> 返回匹配的订阅清单(要求合法字面量主题)。
