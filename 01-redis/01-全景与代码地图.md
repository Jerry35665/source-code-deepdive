## 1.4 deps/:Redis 的"哲学声明"

```
deps/jemalloc     分配器(碎片统计与 defrag 依赖其扩展 API)
deps/lua          内嵌 Lua 解释器(5.1,带补丁)
deps/hiredis      C 客户端库(哨兵与集群工具复用)
deps/hdr_histogram 命令延迟直方图
deps/linenoise    交互式 CLI 行编辑
deps/fast_float / fpconv  高性能数字转换
```

两大特点:**依赖极少**(无 autotools 之外的构建依赖,全部源码内嵌、可离线编译)与**核心代码不依赖任何网络库**(网络栈自己写)。这是"单文件可携带"工程哲学的延续——Redis 曾长期标榜"3 万行核心"时代攒下的零依赖习惯。

## 1.5 测试体系:212 个 .tcl 在测什么

tests/ 目录分四层:`unit/`(每模块单元测试,如 `unit/type/zset.tcl`)、`integration/`(复制/持久化/阻塞场景)、`cluster/`(集群与哨兵,用 `instances.tcl` 起多进程拓扑)、`support/`(辅助)。运行入口 `./runtest [--cluster] [--sentinel]`,单测可 `--single unit/type/zset` 精确执行。

本卷各章的结论都可在对应测试中找到"官方承诺"的行为描述——例如第 03 章 SCAN 的"至少一次"保证对应 `unit/scan.tcl`,第 06 章 AOF 截断容忍对应 `integration/aof.tcl`。**读源码遇到不确定的语义,先找对应测试,再看实现**——这是 Redis 维护者自己的工作流(测试即规格)。

## 1.6 三条阅读路线

按目标选路线,每条都以第 02 章的启动流程为起点:

1. **性能路线**(偏面试与调优):main() → aeMain → readQueryFromClient → processCommand → call → 各 t_*.c 的编码切换 → evict.c/expire.c。对应本卷 02→03→04→08 章;
2. **可靠路线**(偏架构与 SRE):initServer → rdbSaveBackground → flushAppendOnlyFile → bio → replicationCron → 哨兵/集群状态机。对应 02→06→07 章;
3. **演进路线**(偏维护者视角):git log 单文件(如 `git log --oneline src/evict.c`)+ 本卷各章"8.x 动向"小节——观察 kvobj、estore、rdb-channel、ebuckets 这些正在发生的改造,理解大版本是如何从 unstable 长出来的。
