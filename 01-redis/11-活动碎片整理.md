# 第 11 章 · 活动碎片整理:内存的在线整容

> 基线:commit `e8726d1`。行号以 src/defrag.c、src/zmalloc.c、src/server.c 为准。卷一 08 章讲了内存策略(淘汰=减法)——本章讲"整理":**在不停服的前提下把分散的对象搬回紧凑位置**。

## 11.0 全景:Stage 框架与主循环

```
defrag 拆成一串可中断 stage(defragStageFn,src/defrag.c:48-56)
  由独立时间事件 activeDefragTimeProc 泵动(src/defrag.c:1632-1690)
beginDefragCycle 注册:每 db 的 keys/expires/subexpires 三 stage(:1723-1745)
  + pubsub 两 kvstore(:1747-1757)+ Lua 脚本(:1759)+ module 全局(:1761-1773)
游标推进:defragStageKvstoreHelper(:1245-1294)三级游标
  — LUT 整理(kvstoreDictLUTDefrag)→逐非空 slot→逐 bucket 复用 dictScan 反向游标
限流:每 16 迭代/512 hits/64 scanned 才查一次时钟(:1266-1271)
```

**relocate 三步**(:151-182):`je_get_defrag_hint` 问 jemalloc 分配提示→`zmalloc_no_tcache` 新块+memcpy→`zfree_no_tcache` 旧块——no-tcache 防止旧块从 tcache 立即"发还"给自己。**微观判据**:`usage*curslabs <= curregs+curregs/8`(12.5% 松弛,jemalloc_internal_inlines_c.h:384)。**宏观碎片率**:`frag_pct=frag_smallbins/allocated*100`(defrag.c:1070);逐 bin 统计 `frag+=(nregs*curslabs-curregs)*reg_size`(zmalloc.c:782)。

## 11.1 引用更新:容器内指针的改写

relocate 后所有引用必须改写——这是 defrag 的真正难点:db 双表(keys+expires)双写(kvstoreDictFindLink/SetAtLink :957-977);dict 桶链直接 `*bucketref=newde`(dict.c:1373-1402);zset 用**指针比较**定位节点(避开 use-after-free 的 sdscmp,:409-416),zslUpdateNode 修各层 forward/backward/tail(:377-391);带 TTL 的 hfield 走 ebuckets 阶段(defrag.c:263-278);pubsub channel(refcount=dictSize+1)搬完遍历各 client 字典(:1089-1117);stream NACK 双向指针+raxInsert 顶替(:872-885)。**每一种容器的引用形态都要专门的改写代码**——defrag 的实现成本是 O(容器种类)。

## 11.2 大对象、节奏与触发

超 active-defrag-max-scan-fields(1000)的大对象记键名进 defrag_later(:563-571),defragLaterStep 延后消化(:1158-1196);list 用 quicklist bookmark "_AD" 续位(:581-613),stream/ebuckets 用 static 缓冲 raxSeek(">=",next) 续位(:795-806)。**CPU 占空比**:`D=P*W/(100-P)`(defrag.c:1583),duty 基准 500us(:27),单次上限 10 倍 5ms(:1594-1599);**自适应降速**:decay_rate 每轮 ×0.9,命中率<1% 且碎片变化<2% 才降(:1490-1507)。**触发**:serverCron→databasesCron→activeDefragCycle(server.c:1544/:1200/:1212);默认关(config.c:3112),cycle-min=1/cycle-max=25(:3190-3191)、threshold 10/100(:3192-3193)、ignore-bytes=100MB(:3257);**非 jemalloc 编译直接报错**(config.c:2341-2349)。**子进程暂停**:bgsave/AOF 期间 timer 轮询 100ms 不干活(:1646-1650)——防 CoW 放大。

## 11.3 与卷一 08 对照及设计动机

| | 淘汰(08 章) | defrag(本章) |
|---|---|---|
| 目标 | 内存超限(减法) | 碎片率(整理) |
| 手段 | 丢数据 | 搬数据 |
| 代价 | 数据损失 | CPU+带宽 |

1. **为什么不用重启解决**:在线性要求(缓存/队列不能停)——defrag 是"在线性"的代价;
2. **为什么耦合 jemalloc**:分配器的 slab 布局知识(哪个块可搬/搬去哪)只有分配器知道——**分配器耦合的取舍**(非 jemalloc 禁用);
3. **占空比公式** `D=P*W/(100-P)`:把"碎片整理占 CPU P%"变成可配置的 SLO——与 16 章 VACUUM 的 spread 同族;
4. **子进程期间暂停**:CoW 会把 defrag 的"移动"放大为双倍内存——与 08 章呼应。

## 11.4 FAQ

**Q1:activedefrag 默认开吗?**
默认关(config.c:3112):且需 jemalloc 编译(非 jemalloc CONFIG SET 直接报错 :2341-2349)。

**Q2:碎片率怎么算的?**
(:1070):frag_smallbins/allocated——逐 bin 的(nregs×slabs−实reg)聚合。

**Q3:为什么用 zmalloc_no_tcache?**
(:151-182):tcache 会让旧块立即被"发还"给自己——relocate 失效。

**Q4:defrag 会移动大对象吗?**
>1000 字段的大对象延后到 defrag_later(:563-571)逐个消化,带续位游标。

**Q5:bgsave 时 defrag 还跑吗?**
暂停(:1646-1650):防 CoW 放大——牺牲整理进度保 fork 速度。

**Q6:CPU 上限怎么配?**
active-defrag-cycle-min/max(1-25%)(:3190-3191):线性插值到当前碎片率。

**Q7:命中率<1% 会怎样?**
自适应降速 decay ×0.9(:1490-1507):搬家无收益时停止白干。

**Q8:引用更新漏了会怎样?**
悬垂指针崩溃:每容器类型的改写代码是 defrag 的正确性关键(:409-416 等)。

**Q9:模块数据能整理吗?**
能:module 全局 stage(:1761-1773)+模块的 defrag 回调。

**Q10:什么碎片率该开 defrag?**
threshold 10/100(:3192-3193)+ignore-bytes 100MB(:3257):默认对大实例保守。

## 11.5 小结与深挖方向

本章结论:**defrag="Stage 可中断框架+jemalloc 提示 relocate+全容器引用改写+占空比 SLO"**。深挖:

1. 12.5% 松弛判据(inl :384)的jemalloc size class 映射;
2. quicklist bookmark "_AD"(:581-613)的持久化与断点续整;

4. 自适应降速(:1490-1507)在碎片率缓升场景的滞后;
