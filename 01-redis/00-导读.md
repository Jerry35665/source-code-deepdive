# 《Redis 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》的第一卷。全部结论来自对 Redis unstable 分支 commit `e8726d18`(2025-09-15)源码的逐行阅读,每处关键论断都标注 `文件:行号`,可对照源码验证。

## 这卷写给谁

有 1-5 年后端经验、用过 Redis、想把"知道"升级为"确定"的工程师。不要求 C 语言功底到能写内核,但要求能看懂结构体、指针和函数指针。每章独立成篇,可跳跃阅读;但第 02 章是所有章的坐标系,建议先读。

## 环境准备

```bash
# 获取与本文行号一致的源码
git clone https://github.com/redis/redis.git
cd redis && git checkout e8726d18   # unstable 分支该 commit

# 构建(Linux/macOS;Windows 建议 WSL2 或只读不跑)
make -j                              # 默认 jemalloc 构建
./src/redis-server &                 # 起一个默认实例
./src/redis-cli monitor              # 另开终端看实时命令流

# 跑测试(验证本卷结论的最快方式)
./runtest --single unit/type/zset
```

没有环境也可以读:本卷所有代码片段都控制在 15 行内并标注位置,GitHub 网页版直接搜索 `文件名 + 行号` 即可跳转。

## 三种用法

1. **系统通读**(约 6-8 小时):01 全景 → 02 启动 → 03/04 数据 → 05 事件 → 06/07 持久化与高可用 → 08 内存。读完你将拥有一张完整的"16 万行地图";
2. **面试冲刺**(每章末 FAQ,共约 80 条):直接读各章"设计动机"与"FAQ"两节,再回源码验证存疑处;
3. **对照排障**(按问题索引):生产问题 → 定位章节——延迟毛刺看 05(写直出与缓冲区)、内存膨胀看 03/04(编码阈值)与 06(fork COW)、故障转移看 07、过期/淘汰看 08。

## 本卷的三个统一约定

- **行号即凭证**:所有 `文件:行号` 基于上述 commit;行号会随版本漂移,函数名不会——用函数名检索即可定位到新版本;
- **8.x 动向单独标注**:unstable 分支有多处与旧资料冲突的演进(io_threads 重写、SDS 类型选择修正、backlog 块链表化、ebuckets、kvobj),各章均已显式指出"哪些流行说法已过时";
- **结论可复算**:SCAN 渐进式 rehash 的数值演算(第 03 章)、16384 slot 的带宽推导(第 07 章)、LFU 饱和曲线(第 08 章)都给了可手工验算的过程,不信就动手算。
