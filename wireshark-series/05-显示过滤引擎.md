# 第 05 章 · 显示过滤引擎 dfilter:编译一次、每包解释的字节码 VM

> 基线:tag `v4.7.3`(commit `f6e0bf22`)。核心:epan/dfilter/(grammar.lemon / scanner.l / semcheck.c / gencode.c / dfvm.c)与 epan/ftypes/。

## 5.0 全景:两阶段结构

```
【编译期:每条过滤器一次】                        【执行期:每包一次】
 "ip.src==10.0.0.1 && len(tcp.payload)>0"
   │ 宏文本展开(嵌套≤23)                        epan_dissect_run → proto_tree
   ▼                                            (prime:只记 interesting_fields)
 dfilter_compile_full(dfilter.c:605)            dfilter_apply_edt = dfvm_apply(df, tree)
   ├ flex scanner.l + lemon grammar.lemon            │
   │  → stnode 语法树                                ▼
   ├ dfw_semcheck:类型检查/常量转 fvalue        dfvm_apply_full 主循环(dfvm.c:1591)
   └ dfw_gencode → 49 种 DFVM 指令 + 寄存器数       READ_TREE(树→寄存器)→ ANY_EQ 等
                                                    → IF_FALSE_GOTO → RETURN(accum)
```

纠偏:本版 **没有 PEER 指令**(dfvm.h:77-127 共 49 个 opcode 中无此名),同名多字段靠 `hfinfo->same_name_next` 链遍历(dfvm.c:956-959);`ftype_t` 也已无 `how_is_equal`/`convert` 回调——4.x 重构后统一为 `compare` 三态回调派生 `fvalue_eq` 等全部比较(ftypes.c:1290-1301)。引用 3.x 旧文献的这两处说法均已失效。

## 5.1 编译四级流水

`dfilter_compile_full` → `dfwork_parse`(flex 取 token 喂 lemon 生成的 `Dfilter()`,输入结束喂 0 复位,dfilter.c:398-463)→ `dfw_semcheck`(TRY/CATCH(TypeError) 包住递归类型检查,semcheck.c:2227-2281)→ `dfw_gencode`(先造 RETURN 骨架再递归填指令,gencode.c:908-921)。语法文件是 grammar.lemon(`%name Dfilter`)+ scanner.l,构建调 `tools/lemon`(epan/dfilter/CMakeLists.txt:63-93)。装配把 insns/interesting_fields/references 搬进 `dfilter_t` 并按 `next_register` 分配寄存器组(dfilter.c:493-524);**空过滤器编译成功返回 NULL**,语义即"显示全部帧"(dfilter.c:546-554)。

## 5.2 DFVM:寄存器=多值单元格

49 个 opcode 分七组:分支 4、读 6、装载 1、谓词 16(ALL/ANY × EQ/NE/GT/GE/LT/LE/CONTAINS/MATCHES)、集合 7、算术 9、调用 3(dfvm.h:77-127);参数是 11 种 tagged union(dfvm.h:30-42)。寄存器 `df_cell_t` 本体是 GPtrArray,装"该字段在本包的所有出现值"(dfilter-int.h:31-33)——量词内建于指令选择:`==` 编译为 **ANY_EQ**、`!=` 为 **ALL_NE**、`===` 才是 ALL_EQ(scanner.l:180-189);ALL/ANY 共用双循环,空集时 ALL 为真、ANY 为假(dfvm.c:1047-1068)。主循环单遍 + 布尔累加器 accum + goto 分支(dfvm.c:1604-1818);`optimize()` 很弱,只做三种跳转改写,无常量折叠(gencode.c:866-902)。

## 5.3 求值对象是树,不是字节

纠偏:常规字段从树的 `field_info->value` 取**已解码 fvalue**(dfvm.c:905-916),不是原始字节;两种例外——`@field` raw 语法走 tvb 原始字节(dfvm.c:787-816),`vals()` 现场生成显示标签。性能支点是 **prime 机制**:编译期把引用字段登记进 interesting_fields(gencode.c:204-210),`dfilter_prime_proto_tree` 逐个 `proto_tree_prime_with_hfid`,告知 dissector 本包只需记录这些字段——"仅过滤"场景树可只含所需项(dfilter.c:711-719; epan.c:846-851)。`read_tree` 还有本包缓存:寄存器非空即跳过重读(dfvm.c:922-962)。每包调用点:tshark 读过滤与显示过滤(tshark.c:3543-3570, 3587)、着色规则(color_filters.c:605)、tap(tap.c:372)、自定义列(proto.c:7920)。

## 5.4 切片、集合与层语法

`ip.src[0:4]` 全路径:语法 `slice ::= entity [range]`(grammar.lemon:488)→ drange 五种形式 `[i:j]/[i-j]/[i]/[:j]/[i:]`(drange.c:56-62)→ `check_slice` 校验 ftype_can_slice(semcheck.c:1707)→ `DFVM_SLICE`(gencode.c:264)→ `fvalue_slice` 分流 string/bytes(dfvm.c:1273)。层语法 `tcp.payload#[0]` 用 `#` 触发 LAYER 扫描态(scanner.l:224-233),运行期按 `proto_layer_num` 过滤、负偏移按倒数换算(dfvm.c:752-785)。集合 `tcp.port in {80,443,1..5}` 不占寄存器:逐元素 SET_ADD(区间 SET_ADD_RANGE)压 set_stack,一条 SET_ANY_IN 判定,SET_CLEAR 清栈(gencode.c:456-509)。

## 5.5 函数与宏:len() 不是函数调用

内置 13 函数(dfunctions.c:670-689)中 **len/vals 的 func 指针为 NULL**:gencode 特判,`len()` 编译成专用 `DFVM_LENGTH` 指令(gencode.c:353-356; dfvm.c:1298-1316),`vals()` 退化为字段 value-string 读取(gencode.c:358-363);其余走 CALL_FUNCTION+参数栈(gencode.c:365-401)。宏是**编译前纯文本替换**,状态机扫描 `$name(args)`,嵌套上限 23 层,定义由 UAT 管理(dfilter.c:631; dfilter-macro.c:651-657)。`${ip.src}` 引用走第三条路:dissect 后一次性把值快照进 references(按层排序),执行期 `READ_REFERENCE` 绝不回查树(dfilter.c:857-920; dfvm.c:1004-1038)。

## 5.6 设计动机

1. **编译一次、每包解释**:字符串只解析一次,每包成本=读树+寄存器运算;
2. **寄存器=多值单元格**:量词内建于指令,ALL/ANY 单一实现(dfvm.c:1047-1068);
3. **prime 协议**:把"需要哪些字段"反向喂给 dissector,免建全树(dfilter.c:711-719);
4. **三态比较+类型方法表**:新 ftype 填一张 ftype_t 即自动参与全部 49 指令(ftypes-int.h:126-216);
5. **引用快照**:着色/引用跨阶段稳定取值,执行期零树查询(dfilter.c:857-920);
6. **lemon 单例+喂 0 复位**:高频重编译零分配(dfilter.c:113, 463)。

## 5.7 FAQ

**Q1:过滤器何时变成可执行物?**
编译期一次产出指令数组,每包只跑 dfvm_apply(dfilter.c:605; dfvm.c:1591)。

**Q2:`ip.src[0:4]` 与 `ip.src#[0]` 区别?**
前者字节切片(DFVM_SLICE),后者选第 N 协议层(READ_TREE_R)。

**Q3:字段值从哪来?**
树的 finfo->value;仅 @raw 与 vals 变体转原始字节/标签(dfvm.c:905-928)。

**Q4:过滤为什么快?**
prime 让树只含所需字段(dfiter.c:711-719)。

**Q5:`==` 和 `===` 差别?**
ANY_EQ 任一匹配即真;ALL_EQ 要求全部相等(scanner.l:180-189)。

**Q6:未知字段名哪一步报错?**
语法归约时 resolve_unparsed 查注册表(grammar.lemon:31-40)。

**Q7:空过滤器算错误吗?**
不算,返回 NULL dfilter_t,显示全部帧(dfilter.c:546-554)。

**Q8:宏能嵌套多深?**
23 层,超出报 too much nesting(dfilter-macro.c:566 附近)。

**Q9:opts() 优化有多强?**
只做三种跳转改写,无常量折叠/死码清除(gencode.c:866-902)。

**Q10:第三方能加函数吗?**
df_func_register 动态注册,dfilter 插件统一 init(dfunctions.c:719-741)。

## 5.8 小结与深挖方向

本章结论:**dfilter=flex+lemon 编译→49 指令字节码→每包从(瘦身的)树读值解释执行**。深挖:

1. optimize() 三种跳转改写对 -Y 吞吐的实测收益(gencode.c:855-905);
2. `#` 层语法的 proto_layer_num 分配规则与负偏移换算(dfvm.c:752-785);
3. fvalue_eq 错误路径(-res)在 ALL/ANY 双循环中的短路传播(ftypes.c:1290-1301);
4. DF_SAVE_TREE 语法树字符串在 GUI 诊断中的复用(dfilter.c:655-691);
5. dfilter-translator 把显示过滤翻译为 BPF 捕获过滤的能力边界(dfilter-translator.c)。
