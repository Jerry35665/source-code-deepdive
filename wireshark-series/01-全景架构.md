# 第 01 章 · 全景与架构:三库、多前端与一个特权子进程

> 基线:tag `v4.7.3`(commit `f6e0bf22`,同一提交并发 Stratoshark 0.10.3,双 tag 指向同点)。核心:顶层 CMakeLists.txt / epan / wiretap / dumpcap.c。

## 1.0 全景:数据流与进程边界

```
                        网卡 NIC(libpcap/npcap,外部依赖)
                             │
┌── dumpcap(唯一持特权者;只链 writecap+wsutil+libpcap,CMakeLists.txt:3870-3879)──┐
│  capture_loop:pcap_activate → BPF → ringbuffer 分文件 → writecap 写临时文件      │
└──────┬──────────────────────────────────────────────┬──────────────────────────┘
       │ 控制面:同步管道 'F'/'P'/'D'/'E' 单字符消息      │ 数据面:临时 pcap/pcapng 文件
       │ (capture/sync_pipe.h:47-62)                  │ (doc/README.capture:72-77)
┌── 前端:wireshark(Qt) / tshark / strato ── wiretap 读文件 ───────────────────────┐
│  epan_dissect_run → dissect_record → 帧/协议 dissector 链(epan/packet.c:760,990) │
│  → proto_tree 字段树 → dfilter 显示过滤 → 着色 → Qt/文本/JSON 输出                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

纠偏:本 tag 已**无 GTK 前端**(ui/ 下仅 cli/qt/stratoshark 等,ls 核实);libwireshark 实为 epan target 的 OUTPUT_NAME(epan/CMakeLists.txt:287-289);wiretap 实际注册 **102** 种捕获文件类型子类型(非传闻的 190——`wtap_register_file_type_subtype` 全部调用逐一去重计数,file_access.c:1174 注册函数定义),epan/dissectors 下恰好 **1700** 个 packet-*.c。

## 1.1 三大库与依赖方向

epan/wiretap/wsutil 三动态库分别定义于 epan/CMakeLists.txt:265、wiretap/CMakeLists.txt:182、wsutil/CMakeLists.txt:384(纠偏:全仓不存在 `SetLibraryProperties`,实为 add_library+set_target_properties)。epan 由 crypt/dfilter/dissectors/ftypes/wslua 等对象库拼装(epan/CMakeLists.txt:265-278),PRIVATE 依赖 wiretap、PUBLIC 依赖 wsutil(:293-298)。抓包能力是构建期显式条件:`ENABLE_PCAP` 关闭时 dumpcap 不建、产品退化为纯离线分析器(CMakeLists.txt:3952-3955)。

## 1.2 为什么抓包必须单独一个 dumpcap

官方动机原文:"capture process has been isolated in dumpcap; this simple program is less likely to contain security holes and is thus safer to run as root"(README.md:67-72)——特权最小化;性能动机是两任务模型:捕获要防丢包、解析显示可能很慢,父子进程互不阻塞(doc/README.capture:59-63)。dumpcap 的链接表就是其"小"的证明:writecap+wsutil_static+libpcap,**不链 epan/wiretap**,纯采集器零解析能力(CMakeLists.txt:3870-3879);权限上六种运行场景统一收口为"打开 pcap 后立即弃权"(dumpcap.c:5346-5419)。Linux 授权安装期二选一:setuid 位或 `setcap cap_net_raw,cap_net_admin+ep`(CMakeLists.txt:3897-3915)。

## 1.3 前端同构:tshark 与 GUI 没有区别

GUI 点开始 → `capture_start`(ui/qt/wireshark_main_window_slots.cpp:955)→ `sync_pipe_start`(ui/capture.c:128);tshark 实时抓包同样直接调 `sync_pipe_start`(tshark.c:3065)——三前端完全同构,共用 ui/capchild/caputils 静态库。数据回读:前端收到 'P' 后批量 `wtap_read` 临时文件,先做轻量计数(capture dissector,ui/capture.c:514-527)再完整解析 `epan_dissect_run → dissect_record`(epan/epan_dissect.c:755-764)。

## 1.4 版本、构建与程序家族

版本不走 project(VERSION):`PROJECT_MAJOR/MINOR/PATCH_VERSION` 在 CMakeLists.txt:162-172 set 拼装,注入 ws_version.h.in:6-8;同处定义 Stratoshark 0.10.x(:174-177)。程序家族:wireshark/stratoshark(Qt 双 GUI)、tshark/strato(命令行,strato.c 自述改编自 tshark.c:3-5)、tfshark(实验)、rawshark(文件/管道抽字段)、sharkd(守护进程)、dumpcap、editcap/mergecap/text2pcap/capinfos/captype/randpkt/reordercap 等(CMakeLists.txt:3303-4013);extcap 外置采集 11 个(androiddump/sshdump/ciscodump…);插件仓内 27 个(epan 14/codecs 11/wiretap 1/ui 1)。Windows 抓包驱动版本钉死:Npcap 1.88、USBPcap 1.5.4.0(CMakeLists.txt:354, 366)。

## 1.5 设计动机

1. **特权最小化**:高风险面缩到一个"简单程序",解析器漏洞波及不到 root(README.md:72);
2. **防丢包**:采集与显示解耦,慢 UI 不堵内核到盘的热路径(doc/README.capture:61-63);
3. **面分离**:控制消息与包载荷走不同通道,管道只传元信息(sync_pipe.h:47-62);
4. **代码复用**:三前端共享 ui 库与 epan 引擎(CMakeLists.txt:3277-3291, 3573-3583, 3611-3621);
5. **引擎可插拔**:对象库拼装+运行时插件+extcap 外进程三层扩展(epan/CMakeLists.txt:265-278);
6. **单仓多产品**:Wireshark 与 Stratoshark 同仓同提交发布,共享 epan/wiretap 与 app/ "应用风味"抽象。

## 1.6 FAQ

**Q1:epan 含抓包能力吗?**
不含,抓包全在 dumpcap;epan 的 capture_dissectors 只是对原始字节做轻量计数(epan/capture_dissectors.h:38)。

**Q2:libwireshark 对应哪个 target?**
epan,OUTPUT_NAME "wireshark"+PREFIX "lib"(epan/CMakeLists.txt:287-289)。

**Q3:tshark 抓包和 GUI 有何不同?**
没有不同,同样 sync_pipe_start 拉起 dumpcap(tshark.c:3065)。

**Q4:dumpcap 与前端传包数据吗?**
不传,数据走临时文件,管道只传控制消息。

**Q5:版本号定义在哪?**
CMakeLists.txt:162-177 set 拼装,project() 无 VERSION 关键字。

**Q6:dumpcap 何时放手特权?**
pcap 打开成功后立即丢弃全部特权/能力(dumpcap.c:5356-5360)。

**Q7:有多少协议与文件格式?**
1700 个 packet-*.c;wiretap 注册 102 种文件类型子类型(本 tag 去重实测)。

**Q8:Stratoshark 是本仓的吗?**
是,strato.c 改编自 tshark.c,双 tag 同点发布。

**Q9:没有 libpcap 能构建吗?**
能,产品退化为纯离线分析器(CMakeLists.txt:3952-3955)。

**Q10:libpcap 在仓里吗?**
只有头文件垫片(libpcap/ 目录),实现是外部依赖。

## 1.7 小结与深挖方向

本章结论:**Wireshark=epan 解析引擎+wiretap 文件库+wsutil 工具层+多前端同构+特权隔离的 dumpcap,控制面/数据面分离**。深挖:

1. dissector 注册与 call_dissector_work 分发链(epan/packet.c:990);
2. dfilter 编译-执行管线与按需建树优化(tshark.c:3264-3299);
3. dumpcap 的 ringbuffer 分文件与 pcapio 写盘(writecap/pcapio.c);
4. 同步管道协议全集与 Windows 差异(doc/README.capture:90-92);
5. sharkd JSON 服务与 fuzzshark 质量体系(fuzz/fuzzshark.c)。
