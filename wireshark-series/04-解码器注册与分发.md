# 第 04 章 · 解码器注册与分发:生成的函数表、双槽 Decode As 与七级瀑布

> 基线:tag `v4.7.3`(commit `f6e0bf22`)。核心:epan/packet.c / epan/register.c / epan/conversation.c / packet-tcp.c。

## 4.0 全景:一条 TCP 包的七级瀑布

```
 eth → frame → ip.proto 表:dissector_try_uint("ip.proto",6)(packet.c:1743)
      → dissect_tcp(packet-tcp.c:8847,can_desegment=2 当可重组,:9857)
      → decode_tcp_ports(:8394)七级瀑布:
  ① conversation 命中 → ② 被 Decode As 改过的端口(dissector_is_uint_changed)
  → ③ 启发式(可选先试)→ ④ server(SYN 观测)→ ⑤ low → ⑥ high
  → ⑦ 启发式 → 全拒绝则 data 兜底(:8426-8573)
  子 dissector 不够吃 → 置 desegment_len → desegment_tcp 重组后重调(:4950)
```

纠偏:`proto_reg_handoff_tcp` 在 packet-tcp.c:11529,**完全不注册 tcp.port**——全仓 32 处 `dissector_add_uint("tcp.port")` 分散在 23 个应用 dissector 里,端口注册权早已下放;TCP 入口函数是 `dissect_tcp` 而非旧资料里的 `tcp_dissect`。

## 4.1 注册:构建期生成的函数表

1,700 个 packet-*.c 的注册入口不是运行期发现,而是 `tools/make-regs.py` 用正则在**构建期**扫描生成 `dissector_reg_proto[]/dissector_reg_handoff[]` 两个数组(make-regs.py:44-46, 60-71),启动时 `epan_init → proto_init` 顺序遍历调用(register.c:99-103; proto.c:656)。注册与 handoff 刻意分两批:先全员自我声明(协议/字段/表),再全员互挂钩件——消除跨文件初始化顺序问题(proto.c:651-683);插件 dlopen 后 `plugin_register` 自登记,插进同一时序的固定槽位(wsutil/plugins.c:196-233)。带进度回调时 worker 在独立线程、主线程每 150ms 上报当前协议名,支撑 GUI 启动进度条(register.c:28, 74-89)。

## 4.2 三件套与五类表

`proto_register_protocol` 用三张哈希保证全名/短名/过滤名全局唯一,重复即 REPORT_DISSECTOR_BUG(proto.c:8620-8666);`register_dissector` 重名直接 ws_error 终止进程(packet.c:3615-3619);`register_dissector_table` 按键型建表,uint 表用 `g_direct_hash`(端口值即键,packet.c:2793-2806),另有 string/GUID/none/自定义哈希五类。每个槽位是 `dtbl_entry{initial, current}` **双句柄**(packet.c:1212-1215)——这是整个 "Decode As" 体系的地基:用户覆盖只改 current(packet.c:1672),reset 拨回 initial,`dissector_is_uint_changed` 以 `current != initial` 判定被改端口并让 TCP 分发"用户指定优先"(packet.c:1727-1736 → packet-tcp.c:8439)。持久化是 profile 下 `decode_as_entries` 纯文本(四段 CSV),启动时重放 change;纠偏:packet.c:80-83 注释称其为 UAT,实现并非 UAT 框架,而是经 read_prefs_file 解析(decode_as.c:294-298)。

## 4.3 启发式:后注册先试,命中冒泡

`heur_dissector_add` 用 `g_slist_prepend` **头插**(packet.c:3031)——后注册者先试;`dissector_try_heuristic` 命中后把 entry 摘下拼到队首,越常用越靠前(packet.c:3180-3184)。候选先查协议启用与单项开关,先 add_layer 再调解析器,返回 0 或没画节点则回滚层号(packet.c:3148-3172)。纠偏:"按注册顺序匹配"的说法需要纠正为"逆注册序+频率冒泡"。

## 4.4 分发簿记:call_dissector_work 与单跳授权

`dissector_try_uint_with_data` = 一次哈希查 current + 保存/恢复 `pinfo->match_uint` + `call_dissector_work`;查表失败或句柄为 NULL 返回 0,不自动兜底(packet.c:1743-1797)。`call_dissector_work` 是跨层环境管理:协议未启用直接返回、**can_desegment 逐层递减**、压栈/出栈 current_proto 与 layers、子解析器零消费/零绘制时回滚层(packet.c:990-1088)。can_desegment 是"2→1→0 的单跳授权":只有紧贴 TCP 的第一层子 dissector 能请求重组,`saved_can_desegment` 给 SOCKS 类代理留恢复口(packet.c:1016-1029)。TCP 要求"拒绝即不许请求重组",违者 DISSECTOR_ASSERT(packet-tcp.c:8562-8570)。

## 4.5 conversation:通配查找与按帧号选句柄

会话键是 `conversation_element_t` 数组(CE_ADDRESS/CE_PORT/CE_TYPE),按通配形态分多张 wmem_map:exact_addr_port/exact_addr/no_addr2/no_port2/no_addr2_or_port2/id(conversation.c:135-209)。`find_conversation` 先正反双向 exact(反方向命中且 conv_index 更大者胜,取更新的会话),再逐级放宽通配(conversation.c:1876-1922)。会话不直接存 dissector,而是带一棵按帧号组织的 `dissector_tree`:`wmem_tree_lookup32_le` 取"该帧时点生效"的句柄——天然支持"从某帧起换 dissector"(conversation.c:2806-2827)。TCP 的分析状态 tcpd 挂在会话 proto_data 上,按地址比较区分 fwd/rev 流(packet-tcp.c:2193-2253)。

## 4.6 设计动机

1. **构建期注册表**:无 dlopen 扫描无反射,链接器顺带完成漏注册检查(make-regs.py:50-51);
2. **双槽 Decode As**:默认分发永不丢失,用户覆盖可逆叠加(packet.c:1212-1215);
3. **can_desegment 递减**:重组门票只发给直接挂 TCP 者,防深层滥用(packet.c:1016-1029);
4. **启发式头插+冒泡**:注册序/频率/禁用统一在一条 GSList,常见协议近 O(1)(packet.c:3031, 3180);
5. **两阶段注册**:先声明后互挂,插件共享同一时序(proto.c:651-683);
6. **会话键 element 化**:一套键 API 覆盖四元组/双地址/单端口/纯 ID 全形态(conversation.c:222-233)。

## 4.7 FAQ

**Q1:1700 个 dissector 谁来注册?**
make-regs.py 构建期生成数组,启动顺序遍历(register.c:99-103)。

**Q2:重名注册会怎样?**
ws_error 终止进程(packet.c:3615-3619)。

**Q3:Decode As 到底改了什么?**
只换 dtbl_entry->current,initial 永不覆盖(packet.c:1672)。

**Q4:Decode As 规则存哪?**
profile 的 decode_as_entries 文件,四段 CSV,启动重放(decode_as.c:203-243)。

**Q5:启发式匹配顺序?**
后注册先试+命中冒泡,禁用项跳过(packet.c:3031, 3180-3184)。

**Q6:子 dissector 怎么要更多数据?**
置 desegment_len/offset,TCP 凑齐后用合成 TVB 重调(packet-tcp.c:5509-5518)。

**Q7:深层解析器能要重组吗?**
不能,can_desegment 逐层递减,只有第一层有门票(packet.c:1028-1029)。

**Q8:TCP 先试哪个端口?**
会话→被改端口→(可选启发式)→server→low→high→启发式→data(packet-tcp.c:8426-8573)。

**Q9:会话从某帧起换协议怎么做?**
dissector_tree 按帧号 lookup32_le,天然支持(conversation.c:2815)。

**Q10:插件和内置注册时序有差别吗?**
插件 dlopen 自登记,但与内置一样走 protocols→handoffs 两阶段槽位(proto.c:659-683)。

## 4.8 小结与深挖方向

本章结论:**分发网=构建期函数表+三层哈希+双槽 Decode As+启发式冒泡+会话旁路,重组授权逐层递减**。深挖:

1. desegment_tcp 的 MSP 状态机与 fragment_add 交互(packet-tcp.c:4969, 5393-5442);
2. conversation_element_t 新旧 API 并存的迁移成本(conversation.c:170-209);
3. postdissector 尾部二次解析与首遍 prime(packet.c:164-171, 622-627);
4. register_depend_dissector 依赖图反哺协议禁用提示(packet.c:2419-2423);
5. pino 伪协议在 TCP 选项上的应用(packet-tcp.c:11326; proto.c:8671-8684)。
