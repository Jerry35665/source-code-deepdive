# 第 03 章 · 字节码与解释器:四段帧与 computed-goto

> 基线:commit `04be246`。行号以 quickjs.c 的 JS_CallInternal(:17746-22130,约 4400 行)与 quickjs-opcode.h 为准。

## 3.0 全景:一次函数调用的执行旅程

```
JS_CallInternal(:17746)
  → js_check_stack_overflow(C 栈检查 :17837)
  → 一块 C 栈 alloca 分四段(:17834-17868):
      arg_buf(参数补齐;参数够时零拷贝借用调用方 argv :17828/:17841)
      var_buf(局部,全初始化 undefined :17860)
      stack_buf(表达式栈,深度=编译期上界,运行期不逐指令查界)
      var_refs[](闭包槽,全 NULL :17864)
  → DIRECT_DISPATCH:SWITCH(pc)=goto *dispatch_table[*pc++](computed-goto,:17767-17785)
  → 逐指令执行 → return 收栈
```

JS 栈帧 JSStackFrame(:407-420)只是挂链节点(错误栈/调试用);真正的执行状态在 alloca 的四段里。生成器/async 的等价四段布局**搬进堆上** JSAsyncFunctionState 尾部(:784-795),重入走 :17790-17810 的 GENERATOR 分支——**帧即数据,暂停=把帧从栈搬到堆**。

## 3.1 操作码体系:X-macro 与 SHORT_OPCODES

quickjs-opcode.h 的 X-macro 一表三用(枚举/名表/格式);正式码 178 条+临时码 19 条+**SHORT_OPCODES 66 条**(:289-362:push_0..7/get_loc0..3/goto8·16/call0..3)。SHORT_OPCODES 是省内存的变长编码:pass3 按跳距/槽号降级(quickjs.c:35075-35088);临时码与正式码编号重叠是有意的复用(:1133-1134)。JSFunctionBytecode(:685-724)自指针布局(:36135-36244),序列化时 atom→索引回填、大端机逐指令字节交换、BC_VERSION=5(:37717-37761/:38615-38671/:37505)。

## 3.2 闭包:JSVarRef 的双态生命周期

JSVarRef(:450-464)是"指向栈"或"自持值"的双态:closure 创建时 get_var_ref 惰性建"指向栈"的 ref(:16997-17054,:17521-17543);**帧退出 close_var_refs 把值抄进 ref 自身**(detach);let 块退出走 OP_close_loc(:18768)提前 detach。GC 标记:attached var_ref 只标宿主帧(仅 async 堆帧),detached 标 *pvalue(:6625-6638;async 帧扫 arg_buf..cur_sp :6654)——**栈上的值不归 GC 管,归帧管**。

## 3.3 异常:栈扫描而非异常表

异常=全局 rt->current_exception;`OP_catch` 把目标 pc 偏移压栈为 JS_TAG_CATCH_OFFSET=5 哨兵(:18926,quickjs.h:91)。exception: 标签(:20662)从 sp 向栈底扫描:释放沿途值,遇非零哨兵则压回异常值 goto restart 进 catch(:20674-20687),零值哨兵则 JS_IteratorClose(...,TRUE)(:20676-20681);扫到栈底返回 JS_EXCEPTION 由上一帧继续扫——**无异常表、正常路径零开销,回退=C 递归展开+逐帧扫描**。finally 用 OP_gosub(压 INT 返回地址 :18931)→OP_ret(校验 INT tag 与字节码界 :18941-18957)模拟子例程;空 finally 在 pass2 被删(:34304-34319);源码自注 INT tag 有伪造风险(:18935 XXX)——**诚实的技术债标注**。

## 3.4 调用与数值快路径

OP_call 系(:18182-18238):实参躺在调用方栈顶(call_argv=sp-argc),OP_tail_call 拿到返回值直接 goto done;**尾调用改写在 pass3 匹配 call+return**(:34941-34957)。数值:OP_add/OP_mul 的 int 快路径(:19696/:19830):int64 中转,`(int)r!=r` 溢出转 double,mul 特判 -0。promise_reaction_job 是微任务本体(:53386-53426),rt->job_list FIFO,undefined resolve 函数是 await 免分配优化(:2263-2330)。

## 3.5 设计动机

1. **栈机+computed-goto**:栈机的指令编码最省(SHORT_OPCODES 直接吃这个红利),goto 表让 dispatch 零比较——对照寄存器机(LuaJIT)需要更宽编码;
2. **运行期不逐指令查栈界**:栈深上界在编译期算好(compute_stack_size :35753,上限 JS_STACK_SIZE_MAX=65534 :211)——把安全检查从热路径挪到编译期;
3. **异常用栈扫描**:免异常表(省内存),赌异常路径罕见——与 02 章"报错即停"同族;
4. **帧即数据**:生成器/async 与普通调用共用四段布局,暂停=搬迁——一个抽象覆盖三种执行模型;
5. **INT tag 的诚实**(:18935):已知可伪造仍标注 XXX——技术债显式化。

## 3.6 FAQ

**Q1:QuickJS 是栈机还是寄存器机?**
栈机(OP_* 对 stack_buf 操作):编码省、简单;寄存器机的收益要 JIT 才兑现。

**Q2:为什么 JS 栈不逐指令查界?**
编译期 compute_stack_size 算出每函数上界(:35753),alloca 一次到位——热路径零检查。

**Q3:C 栈溢出怎么防?**
js_check_stack_overflow(__builtin_frame_address 对 rt->stack_limit,:2040-2063)——JS 深递归最终是 C 栈深递归。

**Q4:闭包变量什么时候进堆?**
帧退出 close_var_refs 时 detach(:17521-17543);let 块走 OP_close_loc(:18768)提前——**值搬家而非指针重写**。

**Q5:异常为什么不用表?**
栈扫描(:20662-20687)省异常表内存;代价是异常路径 O(栈深)——赌异常少。

**Q6:finally 怎么实现?**
OP_gosub/OP_ret 模拟子例程(:18931/:18941):INT tag 校验防跳飞,自注有伪造面(:18935)。

**Q7:async/await 的暂停点是什么?**
OP_yield/await 返回 int+保存 cur_pc/cur_sp(:20694-20697);恢复在 js_async_function_resume(:21238),await 值写回 cur_sp[-1](:21313)。

**Q8:尾调用优化在哪?**
pass3 匹配 call+return 改写 OP_tail_call(:34941-34957):不是规范要求,是免费的优化。

**Q9:pc2line 是什么?**
行号差分编码(:673-676),find_line_num(:7435)解码——错误栈的行号来源。

**Q10:字节码能序列化复用吗?**
能:JS_WriteObject/ReadObject(atom 回填+字节交换 :37717-38671,BC_VERSION=5)——qjsc 的根基(F 章)。
