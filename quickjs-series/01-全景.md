## 1.1 双层运行时:JSRuntime 与 JSContext

JSRuntime(quickjs.c:319-391)持有堆:atom 表(:323-329)、gc_obj_list(:337)、job_list(:366)、shape_hash(:386-389)、malloc 统计;JSContext(:514-559)持有 realm:5 个预置 shape(:522-526)、class_proto[](:528)、eval_internal 函数指针(:555)。**realm 切换就是 `ctx = b->realm` 一行**(:17871)。对照 V8 isolate/context:概念同构,粒度小三个数量级。JS_NewContext(:2627-2650)挂 11 个 JS_AddIntrinsic*(可裁剪:JS_NewContextRaw+按需 AddIntrinsic,quickjs.h:397-410);JS_FreeRuntime(:2405)收尾断言只剩内置 atom(:2477)。

## 1.2 JSValue:NaN-boxing 只给 32 位平台

纠偏常识:**只有 32 位平台启用 NaN-boxing**(quickjs.h:63-65);64 位是 16 字节 struct{union u; int64_t tag}(:229-232)。NaN-boxing 的位级(:145-214):uint64_t 一体,tag=高 32 位(**负 tag=带引用计数的指针**,正 tag=INT0…FLOAT64);double 裸存位型+`JS_FLOAT64_TAG_ADDEND=0x7ff80000-JS_TAG_FIRST+1` 补偿(:160),float64 用无符号区间判定(:191);NaN 归一(:184-185)。`JS_VALUE_HAS_REF_COUNT` 一次无符号比较(:287)。**值即字,免解引用**——解释器快的第一性。

## 1.3 JSShape:同 layout 结果集的共享

JSShape(:974-988):is_hashed+hash+变长尾(hash_table+JSShapeProperty);JSShapeProperty 只有 hash_next:26+flags:6+atom(:968-972),**值存在对象侧 prop[] 平行下标**(JSObject :990-1077:shape :1013/prop :1014)。共享=GC 对象+refcount+runtime 级 shape_hash 表(初始 16 桶 :5132,乘数 0x9e370001 :5145);转移复用 find_hashed_shape_prop(:5533,逐 prop 全比);refcount>1 时写时复制 js_clone_shape(:9223-9233)。与 V8 hidden class 的差异:无 transition tree,只做"同 layout 共享"——**省内存不追热路径**(04 章展开)。对象创建 JS_NewObjectFromShape(:5613);数组 fast_array 旁路(:1003+,:1050-1072),溢出转慢路径(:9244)。

## 1.4 atom 与内存分配

atom(原子字符串)体系(:2868-3814):小整数 atom 免分配(JS_ATOM_TAG_INT :2870),242 个内置 atom(quickjs-atom.h X-macro)由 JS_InitAtoms(:3078)初始 512 桶、2 倍 rehash(:2875);内置 atom 常量永不回收(:2877-2884)。分配器:2026-06 新增**小块 arena**(8 字节 JSMallocBlockHeader+4096B 页+31 尺寸类 :241-317,Changelog 称快 11%);默认 malloc 用 _msize/malloc_usable_size(:2139-2150);JS_SetMemoryLimit(:2221)。GC 触发 js_trigger_gc(:1780)是 malloc 字节数阈值(×1.5 递增)——04 章展开。

## 1.5 设计动机

1. **为什么不用 JIT**:内存目标(百 KB 级)+启动目标(<300μs runtime 生命周期,doc/quickjs.texi:31-38)+单人维护——解释器+直出字节码是约束下的最优;test262 "nearly 100%" 证明正确性不靠 JIT;
2. **为什么 shape 共享还是要做**:属性是 JS 最大的内存消费者,同 layout 共享在无 JIT 前提下依然是数倍的内存差;
3. **零依赖的纪律**:连大数库(libbf)与浮点打印(Gay dtoa)都移除/自写——**依赖最小化的极端执行**;
4. **单文件的城市规划**:6 万行按行号分区,Bellard 用注释与顺序维持可读性——"文件内分区"是另一种模块化。

## 1.6 FAQ

**Q1:64 位平台为什么不用 NaN-boxing?**
16 字节 struct 让 tag 独立、免位操作;NaN-boxing 的收益(8 字节值)在 64 位需牺牲 double 精度或复杂编码(:63-65)。

**Q2:JSShape 和 V8 hidden class 一样吗?**
共享思想同,机制不同:无 transition tree,只有"同 layout 结果集"哈希共享(:5533)。

**Q3:内置对象能裁剪吗?**
能:JS_NewContextRaw+按需 JS_AddIntrinsic*(quickjs.h:397-410)——嵌入式按需组装。

**Q4:atom 会泄漏吗?**
不会:引用计数+空闲链复用(:3306);内置 atom 永生(:2877-2884)。

**Q5:一个 runtime 多个 context 干什么用?**
多 realm 隔离全局对象(沙箱/iframe 场景);堆与 GC 共享。

**Q6:test262 通过率真的接近 100%?**
doc 自称;已知失败仅 58 行清单(test262_errors.txt)——固定 commit 测试(F 章工程)。

**Q7:arena 分配器管什么?**
小块(16-512B)对象:31 尺寸类+4096B 页(:241-317);大对象走系统 malloc。

**Q8:GC 什么时候触发?**
malloc 字节数阈值×1.5(js_trigger_gc :1780-1796):不是对象计数。

**Q9:能限制内存和 CPU 吗?**
内存 JS_SetMemoryLimit(:2221);CPU 用 JS_SetInterruptHandler(每 10000 分支检查,:512)——F 章。

**Q10:quickjs 和 quickjs-ng 什么关系?**
社区分叉(ng 主打兼容与活跃维护);本卷基于 Bellard 原版(:04be246)。
