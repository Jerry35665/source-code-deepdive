# 第 06 章 · 内置库与工程:宿主义务与单人纪律(卷末)

> 基线:commit `04be246`(VERSION 2026-06-04)。行号以 quickjs-libc.c、qjs.c、qjsc.c、quickjs.c 的 BigInt 区为准。两处重要勘误:本 commit **无 libbf.c**(2025-04-26 移除 bignum 扩展,BigInt 内置化,Changelog:17-19);dtoa.c 是 Bellard 自写的 "Tiny float64 printing and parsing library"(dtoa.c:3-4),不是 Gay 的 dtoa。

## 6.0 全景:嵌入 JS 的宿主义务

```
qjs.c:453-536 就是嵌入说明书:
JS_NewRuntime → JS_SetMemoryLimit/MaxStackSize(:463-466)
  → js_std_init_handlers(:4133-4163,timers/信号/端口/SAB 回调)
  → ModuleLoaderFunc2 → rejection tracker → JS_NewContext(或 Raw+裁剪)
  → std/os 注册(:107-117) → 跑脚本 → js_std_loop(:4292-4312) → 全套释放
```

**setTimeout 只挂链表**(quickjs-libc.c:2175-2201),唯一驱动点是 js_os_poll 的 poll(2)/WaitForMultipleObjects(:2547-2657/:2422-2513),循环空则退出——**为什么必须手动 js_std_loop**:QuickJS 不带事件循环,定时器/IO 是宿主的义务,libc 只提供"义务的参考实现"。未处理 rejection 致命 exit(1)(:4275-4288,2025-04 起收紧)。模块加载器直接按名 load,无路径搜索;`.so` 走 dlopen(:519,:684-735)。

## 6.1 worker:零共享堆的消息模型

每 worker 线程独立 JS_NewRuntime(:3626)——**零共享堆**;postMessage 用 JS_WriteObject2(SAB|REFERENCE)序列化(:3797-3799)+malloc 拷贝(:3809);**SharedArrayBuffer 是唯一按引用物**,靠 JSSABHeader 原子引用计数(:3492-3519);管道=mutex 队列+waker(pipe 自唤醒 :2306-2315/CreateEvent :2282-2286),使 worker 消息能进同一个 poll;禁止嵌套 worker(:3713-3716)。

## 6.2 BigInt:libbf 移除后的内置实现

libbf 时代结束(2025-04):BigInt 现为 quickjs.c 内置,"optimized for small numbers"——**补码 limb 结构+1MB 规模上限**(:490-502,:11266);short-BigInt 内联进 JSValue(quickjs.h:93);除法用 **Knuth D 算法**(clz 归一化+试商,:11880-11979;:11489-11556)。移除 libbf 的动机链:BigFloat/BigDecimal 两个未定提案+数十 KB 依赖 vs 实际需求——**砍掉未标准化的部分,保留已标准化的**。dtoa.c 自写补位:精确最短打印(:3-4)。

## 6.3 qjs/qjsc:REPL 与快启动

qjs REPL:行编辑/着色/持久历史(repl.js:78 历史仅内存态)。**qjsc 把 JS 预编译成 C 字节数组**(JS_WriteObject→C 数组,qjsc.c:193,:179-209)+生成上下文工厂与 main 模板(:794-861,:373-389);产物启动只走 js_std_eval_binary 的 ReadObject(quickjs-libc.c:4353-4384)——**跳过解析的快启动链路**;REPL 本身就是 qjsc_repl 字节码(qjs.c:522-524)——自举。

## 6.5 与前作对照与设计动机

| | quickjs-libc | node | 定位 |
|---|---|---|---|
| 事件循环 | 宿主手动 js_std_loop | 内置 libuv | 参考实现 vs 平台 |
| worker | 独立 runtime+消息 | worker_threads | 零共享 vs 共享堆 |
| 模块 | 按名 load+dlopen | 完整解析器 | 嵌入面最小 |

1. **libc 是示例而非标准**:宿主按需抄——QuickJS 把"JS 引擎"与"运行时"的边界画得极清(对照 node 把两者焊死);
2. **libbf 之死**:未标准化提案的维护成本>价值——砍;BigInt 内置化后 short-BigInt 内联值——**依赖最小化与性能同向**;
3. **qjsc 的自举**:REPL 自己就是编译产物——工具链吃自己的狗粮;
4. **单人纪律**:每版 Changelog 可读、WERROR、test262 固定 commit——**单人项目靠制度而非团队**。

## 6.6 FAQ

**Q1:为什么 setTimeout 不自动跑?**
QuickJS 无内置循环:setTimeout 只挂链表(:2175-2201),js_std_loop(:4292-4312)是宿主义务。

**Q2:worker 之间能共享对象吗?**
不能:独立 runtime+序列化传递(:3626,:3797);唯一例外 SAB(按引用+原子计数 :3492)。

**Q3:BigInt 还能用 BigFloat 吗?**
不能:2025-04 移除(Changelog:17-19);只保留标准 BigInt(内置 Knuth D,:11880)。

**Q4:qjsc 产物怎么快?**
跳过解析直接 ReadObject(:4353-4384):解析成本一次性付在编译期。

**Q5:模块能从网络加载吗?**
宿主自定:默认按名 load(:684-735),LoaderFunc2 是注入点。

**Q6:脚本死循环怎么防?**
JS_SetInterruptHandler 每 10000 分支(:512):宿主决定超时策略。

**Q7:内存超限的行为?**
malloc 失败直接抛 OOM(:1845-1860):不重试不 GC(04 章)。

**Q8:test262 已知失败 58 行是什么?**
test262_errors.txt 的白名单:固定 commit 下的人工清单(F 章文化)。

**Q9:能静态链接进 iOS 吗?**
能:零依赖+可裁剪 intrinsics(quickjs.h:397-410);libc 的平台分支按需编译。

**Q10:Bellard 还维护吗?**
活跃:2026-06 仍在发版(arena malloc 快 11%):单人+制度。
