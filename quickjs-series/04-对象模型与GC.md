# 第 04 章 · 对象模型与 GC:shape 共享与三遍清环

> 基线:commit `04be246`。行号以 quickjs.c 的 Shape 区(:5119-5610)、对象区、GC 区(:6508-6850)为准。

## 4.0 全景:属性读写决策树与 GC 两层

```
JS_GetPropertyInternal:fast_array? → int 索引直读 u.array.u.values[:9043-9083]
                       → shape 查 atom → prop[] 下标取值
                       → 沿 shape->proto 原型链(:8355 每步 p=p->shape->proto)
                       → exotic 特化(String/TypedArray/Proxy/Arguments)
GC 两层:引用计数为主(确定性析构)+ 三遍 cycle removal 兜底(处理环)
```

**GC 头寄生 malloc 头**:ref_count/mark/gc_obj_type 全在 8 字节 JSMallocBlockHeader(:270-280),JSGCObjectHeader 只剩 list_head(:435);quickjs.h:99-102 注释"must match JSMallocBlockHeader"——**一个头服务两个子系统**。引用计数归零不立即 free:进 gc_zero_ref_count_list 统一析构(:6471-6484)。

## 4.1 shape:共享是"结果集哈希"而非 transition 树

`find_hashed_shape_prop`(:5533-5564):先比 32 位累积 hash(shape_hash 多项式,kernel 乘数 0x9e370001 :5145),再比 proto、prop_count,**最后逐项比对全部 atom/flags**(:5549-5558)——哈希只是预筛。加属性总入口 add_property(:9179-9239)三分支:

1. 表里有"同前缀+新属性"的 shape→直接 dup 复用(:9208-9222);
2. 共享中(ref_count≠1)→js_clone_shape(:5268-5292),克隆体挂回表(:9229-9230);
3. 独占未哈希→原地 add_shape_property(:5469-5510,"摘表→扩容→新 hash 重挂")。

改/删已有属性走 js_shape_prepare_update(:10302-10327):共享则克隆**不挂表**(退化 layout 不值得复用),独占则摘表置 is_hashed=FALSE。原型指针存 shape->proto(:985)。**与 V8 hidden class 的本质差异:无 transition tree、无 IC、无热路径优化——纯内存经济**。

## 4.2 fast_array:紧凑数组的进出

数组默认 fast_array:int 索引直读 u.array.u.values[idx](:9043-9083);**length 是 prop[0]+JS_PROP_LENGTH flag**(:5664-5671),写分发(:9714-9717)→set_array_length(:9433-9521);快路追加 add_fast_array_element(:9542-9570)同步拨 length,门槛 can_extend_fast_array(:9935)。**稀疏化(convert_fast_array_to_array :9244-9286)**的触发:删非末尾元素(:9389)、CreateProperty(:10160)、DefineProperty(:10586)、arguments 重定义(:16140)——一旦慢路径永不回快(单向门)。TypedArray:OOB 读 undefined(:8304-8307)、写静默丢弃但**仍做数值转换**(:9763);detach 统一 `u.array.count=0,u.ptr=NULL`(:57044-57045):所有界检查自然失败。Proxy 全套 12 个 exotic 方法(:51437-51449),handler 未定义时原样转发 target(:50822-50823),并做 target 不变量校验(:50836-50854)。

## 4.3 GC 三遍:cycle removal 的不变式

`JS_RunGCInternal`(:6815-6833)=可选弱引用清理(:6510)+三遍:

1. **gc_decref**(:6697):沿全部父子边各减 1,归零者移 tmp_obj_list;不变式:第一遍后 ref_count==堆外引用数,**有 assert(ref_count>0) 不会为负**(:6689);
2. **gc_scan**(:6736):从外部可存活者增计恢复,从 0→1 者搬回 gc_obj_list 实现可达性传递;再对 tmp 里的死人对孩子只增不减以平衡(:6731-6734);
3. **gc_free_cycles**(:6756):REMOVE_CYCLES 相位整体析构;finalizer 里可见僵尸(free_mark,:6347/:6840),weakref_count≠0 的壳保留(:6803-6806)。

**触发**:js_trigger_gc(:1780-1793)是 **malloc 字节数**阈值(malloc_size>threshold 后重置为 ×1.5 :1795-1796),初始 256KB(:2083),唯一调用点 JS_NewObjectFromShape:5619。**无 GC-on-OOM**:malloc 失败直接 JS_ThrowOutOfMemory(:1845-1860),不重试不触发 GC——嵌入式任务的确定性优先。

## 4.4 与 V8 对照及设计动机

| | quickjs | V8 |
|---|---|---|
| 属性 | shape 共享+prop 数组 | hidden class+IC+transition tree |
| GC | 引用计数+全停三遍清环 | 增量+并发标记-清除+分代 |
| 触发 | malloc 字节阈值 | 分配速率/堆占比 |

1. **引用计数为主**:finalizer 确定性(嵌入式资源管理)+实现简单;环是它的阿喀琉斯之踵——三遍清环是补丁而非体系;
2. **全停赌短任务**:嵌入式场景任务毫秒级,停顿无感——约束决定 GC 形态;
3. **shape 只做内存经济**:无 IC/无 transition tree 是"解释器足够快"的推论——与 01 章"不做 JIT"一条线;
4. **单向门稀疏化**(:9244):回快路径需要重整数组的复杂度不值——单向设计消灭状态振荡。

## 4.5 FAQ

**Q1:循环引用会泄漏吗?**
不会:三遍清环(:6815-6833)专门处理;但清环是全停的。

**Q2:为什么归零不立刻 free?**
统一析构防 finalizer 重入(gc_zero_ref_count_list :6471-6484)。

**Q3:加属性一定触发 shape 查找吗?**
三分支(:9179-9239):复用/克隆/原地——独占且未哈希时零查找。

**Q4:数组的 length 是普通属性吗?**
是 prop[0]+flag(:5664-5671):语义特殊但存储普通——统一与特化的平衡。

**Q5:稀疏化后还能回 fast_array 吗?**
不能,单向门(:9244):消灭状态振荡。

**Q6:GC 会因为 OOM 自动跑吗?**
不会(:1845-1860):直接抛错——确定性优先于自救。

**Q7:finalizer 在 GC 里什么时机执行?**
REMOVE_CYCLES 相位(:6756)与引用计数归零统一析构(:6471);注意僵尸可见性(:6347)。

**Q8:Proxy 的不变量校验在哪?**
(:50836-50854):转发的合法性由 target 校验兜底。

**Q9:TypedArray 写越界会怎样?**
静默丢弃但做数值转换(:9763):规范语义的副作用面。

**Q10:JS_FreeRuntime 为什么断言两次?**
(:2464-2465):gc_obj_list/weakref_list 必须空——运行时退出的正确性锚点。

## 4.6 小结与深挖方向

本章结论:**对象模型="shape 结果集共享+fast_array 单向门+引用计数+三遍清环"**;一切为内存与确定性让路。深挖:

1. find_hashed_shape_prop 逐项比对(:5549-5558)在大对象的成本;
2. gc_scan 的可达性传递(:6736)在深环网络的栈深;
3. malloc 阈值 GC(:1780)与 JS_SetMemoryLimit 的相互作用;
4. fast_array 稀疏化的四个触发点(:9389 等)的真实分布;
5. finalizer 僵尸可见性(:6347)对 WeakRef 语义的影响。
