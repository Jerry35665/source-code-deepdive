## 12.1 config_dump 与 clusters

config_dump 不持有任何配置:ConfigTracker 是"回调表+弱所有权 EntryOwner"(组件析构即注销)——clusters/listeners/routes/secrets/bootstrap 五键各组件构造时注册;组装时现算现发,`MessageUtil::redact` 抹敏感字段。难点是 FieldMask 穿透 Any:资源内容包在 google.protobuf.Any 里,拆成"外层 mask+内层 mask"对 Any 做 unpack→trim→pack。include_eds 是唯一伪注册(endpoint 现算 ClusterLoadAssignment)。/clusters 的 json 版把健康位结构化为 HostHealthStatus,用 HEALTH_FLAG_ENUM_VALUES 宏逐位调用——**新增健康位必须同步出现在 admin 输出**。

## 12.2 stats prometheus 化三步

①Sanitize:指标名 `[^a-zA-Z0-9_]` 替换 `_`,label 值转义;②名字映射:自定义指标不加前缀原样暴露(首字符数字则整个丢弃),普通指标统一加 `envoy_` 前缀;③双格式:按 Accept 头协商 text 或 protobuf delimited;histogram 支持 cumulative/summary/prometheusnative 三模式(per-host 指标绕过 ThreadLocalStore 单独成组)。

## 12.3 安全面与 readiness

危险端点的防线是把"危险"编码进数据结构:mutates_server_state_ 的 handler 强制 POST 否则 405,/help 自动标注;addStreamingHandler 拒绝 prefix 含 `&"'<>?:` 的注册(防扩展 XSS 注入)。**admin 走 nullOverloadManager**——过载时 /server_info、/healthcheck/fail、/quitquitquit 必须可用,给运维留带外通道;代价是 admin 自身无背压(TODO 承认)。/ready 状态机极薄:Init::Manager 三态→PRE_INITIALIZING/INITIALIZING,Initialized 后按 healthcheckFailed 分 DRAINING/LIVE——**对 LB 而言"主动声明不健康"与"正在排水"语义等价**,k8s readinessProbe 无需理解 Envoy 内部。优雅 drain 与 lifecycle 三段(Startup/PostInit/ShutdownExit)是 wasm 等有状态扩展的最后清理通道。

## 12.4 扩展生态盘点(目录即分类)

filters/http 约 90 个(router/rbac/jwt_authn/ext_authz/lua/wasm/oauth2/ext_proc/cache…);filters/network 约 26 个(tcp_proxy/HCM/redis/thrift/dubbo/generic_proxy…);clusters(eds/strict_dns/logical_dns/dynamic_forward_proxy/aggregate…)、load_balancing_policies(RR/least_request/ring_hash/maglev/subset…)、health_checkers、access_loggers、stat_sinks、tracers(zipkin/datadog/otel/skywalking…)、transport_sockets、wasm_runtime 四运行时、config_subscription 三种 xDS 订阅、resource_monitors、formatters、matching 族……**目录层级=工厂 category=配置注入点**,三者对齐让"新扩展放哪、注册哪个 factory、bootstrap 怎么写"成为同一个问题。总注册表 331 条可被下游 @envoy_build_config 覆盖;metadata status 如实统计:stable 184/alpha 127/wip 39,无 deprecated(下线 API 走 envoy_deprecated_ 注解)。**contrib 分仓**:38 个第三方依赖/无安全加固承诺的扩展物理隔离,主仓库不依赖。

## 12.5 设计动机

1. **config_dump 走注册而非集中 dump**:配置所有权分散在组件;回调表+弱所有权让"谁能提供谁注册",dump 永远现算;
2. **危险端点显式**:编码进数据结构,分发器机械强制 POST、审计工具可静态枚举写端点;
3. **目录即分类**:目录层级/工厂 category/配置注入点三者对齐,331 条扩展不与管理复杂度同涨;
4. **metadata status 必填**:成熟度预期与 security_posture("敢不敢面对不可信流量")变成机器可查字段;
5. **contrib 分仓**:核心最小可信集与长尾适配各自演进;
6. **admin 豁免过载**:比"更高阈值"更可靠——极端过载下带外通道仍可能被波及。

## 12.6 FAQ

**Q1:config_dump 能过滤吗?**
能:?resource/?mask(FieldMask 穿透 Any)/?name_regex/?include_eds 四参数。

**Q2:/ready 返回 503 的条件?**
非 LIVE(PRE_INITIALIZING/INITIALIZING/DRAINING)一律 503;DRAINING 唯一触发是 /healthcheck/fail。

**Q3:prometheus 指标名规则?**
sanitize 后普通指标加 envoy_ 前缀;自定义指标原样暴露但首字符不能是数字。

**Q4:过载时 admin 还能用吗?**
能:admin 显式走 null overload manager,还可 ignore_global_conn_limit。

**Q5:扩展能裁剪吗?**
能:extensions_build_config.bzl 331 条,下游 @envoy_build_config 覆盖;3 条必须扩展。

**Q6:扩展的成熟度在哪查?**
extensions_metadata.yaml 的 status(stable 184/alpha 127/wip 39)与 security_posture 五值。

**Q7:contrib 里有什么?**
38 个:第三方 SDK 依赖(golang/mysql/kafka/rocketmq/sip/postgres)、硬件加速(qat)等;独立分仓与 metadata。

**Q8:危险端点需要 POST 吗?**
需要:mutates_server_state 的 handler 非 POST 一律 405;是否留痕取决于是否配了 admin.access_log。

**Q9:wasm 扩展的"最后清理"在哪?**
lifecycle 的 ShutdownExit 阶段:server 等全部 completion 回调完成才退出。

**Q10:全系列怎么读?**
运维排障线 C2→F→F2;控制面接力线 B→F→F2;扩展开发线 B2→F→F2(卷一/卷二报告编号)。
