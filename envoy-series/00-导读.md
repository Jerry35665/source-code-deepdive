## 定位与三大纠偏

Envoy 是 C++ 写的**面向控制面编程的 L7 数据平面**:单进程多线程 + xDS 动态配置 + filter 扩展体系。一句话对比:Nginx 是多进程+静态配置的 Web 代理,Caddy 是自动 HTTPS 的站点服务器,Envoy 是给 Mesh 控制面当执行器的代理。

**三大纠偏**(与流行认知相反):

1. **"Envoy 是多线程所以有锁竞争"——错**。连接一经 accept 终身固定 worker,配置对象经 ThreadLocal slot 每线程一份私有副本(thread_local_impl.cc:124-136),稳态数据路径零锁;唯一的全局临界区是 main 线程的配置单点写;
2. **"hot restart 等于 reload"——不完全**。它靠共享内存+domain socket 传 fd 做**进程接力**(换二进制用),日常配置变更的正确路径是 xDS 热更新,根本不碰进程生命周期;
3. **"admin 是独立系统线程"——错**。它是 main 线程 event loop 上一组独立的 listener+HCM(admin.cc:54-77),自带假 overload manager(admin.cc:117),与 worker 隔离但同在主循环。
