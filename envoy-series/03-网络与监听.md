# 第 03 章 · 网络与监听:从 accept 到 connection 的管线

> 基线:tag v1.39.1。核心目录 source/common/network/ 与 source/common/listener_manager/。

## 3.0 全景:一次 TCP 连接的完整路径

```
main:LDS→ListenerImpl→createListenSocketFactory(reuse_port 分叉,listener_impl.cc:122-141)
  →doFinalPreWorkerInit:listen(backlog=128)+STATE_LISTENING 选项(:208-244)
  →addListenerToWorker ×N ──post──▶ worker:ConnectionHandlerImpl::addListener(:40)
     →ActiveTcpListener:TcpListenerImpl 注册 Level 触发 Read 事件(tcp_listener_impl.cc:163-171)
worker event loop:TcpListenerImpl::onSocketEvent(:63)批量 accept
  →三道闸:全局连接上限/LoadShed 伯努利/listener open_connections
  →ActiveTcpListener::onAccept→onAcceptWorker(balancer 可跨线程 post)
  →ActiveTcpSocket:listener filters(tls_inspector/original_dst/proxy_proto)可 StopIteration 等数据
  →findFilterChain:dport→dip(LcTrie)→SNI→transport_proto→ALPN→src 漏斗(filter_chain_manager_impl.cc:550-583)
  →ServerConnectionImpl+L4 filter 链定型——此后这条连接的管线不可更换
```

## 3.1 socket 创建:reuse_port 的分叉与克隆

`BindType` 由 bind_to_port 与 reuse_port 组合(listener_manager_impl.cc:1264-1268)。**NoReusePort=所有 worker 共享一个 dup 的 fd**(单 accept 队列,epoll 唤醒竞争);**ReusePort=N 个独立 bind 的 fd**(内核按哈希分流,零竞争)。`listen()` 刻意推迟到 worker 启动前(listener_impl.cc:208-244)。两个必须记住的连锁规则:更新监听若与 draining 监听同地址则**克隆其 socket factory 而非重新 bind**(:1254-1258);reuse_port 不能热改(:581-584)——因为 REUSEPORT 的每个 socket 有独立内核 accept 队列,关队列会 RST 排队连接(listener_impl.cc:152-165 长注释)。热重启时 fd 优先从父进程继承(duplicateParentListenSocket)。

## 3.2 accept 三道闸

`onSocketEvent` 是批量 accept(上限 max_connections_to_accept_per_socket_event):①全局连接上限(rejectCxOverGlobalLimit,优先 OverloadManager 资源,回退 runtime key+进程级原子计数)→直接 close 计 downstream_global_cx_overflow;②LoadShedPoint 或伯努利采样拒绝(RejectIncomingConnections 动作);③listener 级 `envoy.resource_limits.listener.<name>.connection_limit` 计 downstream_cx_overflow(tcp_listener_impl.cc:63-145)。accept 后连接仍可能换 worker:balancer 可 post 到别的线程;use_original_dst 命中也会移交——但一旦落定,终身固定。

## 3.3 listener filters 与 filter chain 定型

ActiveTcpSocket 是"已 accept 未成 connection"的中间态:listener filters 逐个推进,StopIteration 时用 ListenerFilterBuffer 阻塞式 peek 等更多数据(active_tcp_socket.cc:124-186);15s 超时默认放弃,可配 continue 兜底。SNI/ALPN/原始目的地在这阶段采集,正是 findFilterChain 的输入——漏斗顺序 dport→dip(LcTrie)→SNI→传输协议→ALPN→源,全部落空回退 default_filter_chain。**chain 与 filter 实例在连接建立时刻定型,之后不可更换**;配置变更只影响新连接,存量连接走 chain 级 drain。

## 3.4 ConnectionImpl:水位线背压与五种 close

读写缓冲各带水位线,`low=high/2` 滞回(watermark_buffer.cc:127-129),阈值=per_connection_buffer_limit_bytes(默认 1MiB)。**读侧**越 high→`readDisable(true)` 摘掉 epoll Read 位,背压落在内核接收队列(connection_impl.cc:504-525);**写侧**越 high→计数归一后向 filter 链广播 onAboveWriteBufferHighWatermark,由 HCM 沿 L7 上传(:703-709)。没有自定义背压消息——这就是 TCP 滑动窗口思想在用户态的延伸。

close 五型(connection.h:80-89):NoFlush(仍尽力写一次再关)/FlushWrite/FlushWriteAndDelay(delayed close 状态机:写完即关或写完再等 delayed_close_timeout)/Abort/AbortReset(一个字节不写)。RST 检测在读写两条路径均有特判。

## 3.5 三态迁移与 in-place 更新

warming→active→draining:本地初始化完成后 onListenerWarmed **先对新 worker 上线新的,再 drain 旧的**(listener_manager_impl.cc:865-897)——零中断窗口。drain 依次 stopListener 停 accept(并关 socket 让内核 accept 队列快速失败)→存量连接广播 onDrain→超时后 removeListener。**in-place filter chain 更新**:判定"除 chain 外完全一致且 reuse_port 未变"(listener_impl.cc:1146-1181),命中则网络侧动作只剩"worker 原地换 config 指针+消失的 chain 走 drain"——socket/listener 零重建,`listener_in_place_updated`++。

## 3.6 设计动机

1. **per-worker 独立 accept**:reuse_port 下每 worker 独立内核队列,无惊群零竞争;代价是"队列隔离"引出的克隆与不可热改规则;
2. **水位线而非背压消息**:生产者消费者同线程,两个阈值事件足够;low=high/2 防抖;
3. **chain 建立时定型**:匹配输入(SNI/ALPN)只在 listener filter 阶段可测;定型后数据路径零查表;
4. **overflow 直接拒**:把排队交还内核 backlog,把拒绝变成可观测计数;
5. **三态+in-place**:warming 消除切换窗口,in-place 把 diff 收敛到 chain 层。

## 3.7 FAQ

**Q1:accept 在 main 线程吗?**
不:main 只建 socket 和 listen;accept 事件在每个 worker 自己的 dispatcher 上。

**Q2:水位线会丢数据吗?**
不会:读侧只摘 epoll Read 位,已缓冲数据照常推进;写侧只广播信号。

**Q3:一条连接能换 worker 吗?**
accept 后、定型前可以(balancer/original_dst);落定后终身固定。

**Q4:找不到 filter chain 会怎样?**
no_filter_chain_match++ 并关连接;配了 default_filter_chain 则兜底。

**Q5:listener filters 超时会怎样?**
默认关连接;continue_on_listener_filters_timeout=true 则放行继续。

**Q6:SNI/ALPN 怎么采到的?**
tls_inspector listener filter 在 ActiveTcpSocket 阶段 peek 字节。

**Q7:reuse_port 能运行时改吗?**
不能:独立内核队列会因关闭而 RST 排队连接(listener_impl.cc:152-165)。

**Q8:UDP 呢?**
独立路径:UdpListenerImpl 批量收包(recvmmsg/GRO)+ per-worker UdpListenerWorkerRouter 固定四元组会话。

**Q9:socket 选项为什么建模成三态?**
同一选项在 PREBIND/BOUND/LISTENING 语义不同;状态化让"创建于 main、生效于 worker 前后"由框架保证。

**Q10:downstream_cx_overflow 和 global 的区别?**
listener 级限额 vs 进程级全局上限,分别在 ActiveTcpListener 与 TcpListenerImpl 两层闸门。

## 3.8 小结与深挖方向
