# 第 05 章 · 集群与负载均衡:从 EDS 到 host 选择的完整链路

> 基线:tag v1.39.1。核心目录 source/common/upstream/ 与 source/extensions/load_balancing_policies/。

## 5.0 全景:ClusterManager 到 HealthyHost

```
CDS/静态 → ClusterManagerImpl(addOrUpdateCluster:727)
  ├ active_clusters_ / warming_clusters_(hash 相同 NOP;不同则 warming)
  │   postThreadLocalClusterUpdate ── tls_.runOnAllThreads(:1177-1296)
  ▼
ThreadLocalClusterManagerImpl(每 worker 一份)
  ├ ClusterEntry{ 本线程 PrioritySet 副本 + lb_ = lb_factory_->create()(:1910-1921) }
  ├ host_http_conn_pool_map_:Host→ConnPools(★连接池挂在 host 上,h:765)
  ▼ chooseHost(:2131)→ override → lb_->chooseHost
PrioritySet:host_sets_[priority] → HostSet{hosts/healthy/degraded/excluded + per-locality}
  → choosePriority(healthy/degraded 两轮,按健康度×overprovisioning 1.4 溢出)
  → panic?(健康+降级 < 50% → 全视作健康)→ zone 路由/加权 → LB 算法 → Host
```

## 5.1 per-thread 视图:零锁选择的代价

主线程集群的 PrioritySet 是权威副本;worker 通过 `tls_.runOnAllThreads` 广播重建自己的 TLS 副本,LB 的轮转指针/EDF 堆/zone 状态全部线程私有(cluster_manager_impl.cc:1910-1921)。三条细则:①host 移除必须**全量广播完整列表**——worker 拿 HostSharedPtr 作 map key,漏一条就泄漏(:601-612);②纯健康/权重/元数据变更可进 1000ms 合并窗口(:614-724);③判死额外 post 健康失败触发连接池 drain。**host 复用**:EDS 按地址字符串匹配新旧 host,地址不变⇒对象不变⇒在途连接/健康状态/统计连续(upstream_impl.cc:2366-2509)——这是 EDS 能以秒级频率推送的工程前提。

## 5.2 priority、panic 与 zone 路由

**priority spill**:100 份流量按"可用度=健康占比×1.4"自上而下分配,P0 吃不完溢出到 P1(load_balancer_impl.cc:38-96)。**panic**:某 priority 健康+降级 < 50%(默认阈值,runtime 可调)即全体视作健康;全部 priority panic 时按总 host 数重分;`fail_traffic_on_panic` 可选干净拒绝(:677-692,335-376)。panic 的哲学:绝大多数后端"看起来坏"更可能是探测误报,全打 0 容量比打散全集群更糟。**zone 路由**:本 locality 占比≥上游则 Direct 全直连,否则按 residual_capacity 比例外溢;locality 加权则走 EDF 调度器(:513-835)。

## 5.3 LB 家族:EDF 支与 thread-aware 支

**EDF 支(per-thread)**:RoundRobin(deadline=now+1/weight 的 O(log n) 加权轮转,edf_scheduler.h:60)、LeastRequest(weight/(active+1)^bias;无权重时 N_CHOICES 即 power-of-two choices 随机抽 N 个取最闲,或 FULL_SCAN+蓄水池采样)、Random。**thread-aware 支(hash 类)**:主线程 refresh() 构建不可变状态,worker 读锁换指针;RingHash(ketama 二分查环)、Maglev(查表 O(1),三档实现按规模选择)、bounded-load(hash 过载时随机跳跃换 host)。**Subset LB** 包裹任意内层 LB:先按 metadata 选桶再选 host,四级 fallback 到 panic_mode_subset。

## 5.4 健康检查:主动合成探针 + 被动真实流量

主动 HC:每 host 一个 session,阈值翻转(成功需连续 healthy_threshold 次;网络类失败立即计入),interval 派生含 no_traffic_interval(60s)与 edge interval(health_checker_base_impl.cc:295-417);HTTP 检查器复用完整 upstream 栈,`x-envoy-immediate-health-check-fail` 头可立即排除。**outlier 纯被动**:连续 5xx(默认 5)或周期成功率低于"均值-标准差×因子"即逐出;`max_ejection_percent` 默认 10% 限幅+指数退避回归(outlier_detection_impl.cc:776-910)。二者收敛到同一 health_flags_ 位与同一套 healthy/degraded 分区——被动判据是真实流量,主动判据覆盖无流量 host,互补而非冗余。

## 5.5 连接池:per-host、per-thread、per-hash-key

池挂在每 worker 的 `host_http_conn_pool_map_`,二次键含 upstream protocol/socket options/SNI——不同选项的连接不串池(cluster_manager_impl.cc:2035-2088)。统一建连公式 `(pending+active+anticipated)*ratio > capacity+active`(conn_pool_base.cc:94-114):HTTP/1 容量恒 1(退化成固定连接排队),HTTP/2/3 容量=并发流上限(SETTINGS/GOAWAY 动态增减)——协议差异沉入容量语义,排队/断路器/preconnect 只写一遍。断路器满但池空仍保底建一条,防 pending 流被排到永远无法服务的 host(:205-209)。HTTP/3 与 HTTP/2 可组 ConnectivityGrid 做 ALPN 竞速 failover。

## 5.6 设计动机

1. **per-thread 视图**:LB 是最热路径,任何锁被 N worker 放大;权威副本+全量广播+本地重建换零锁;
2. **priority+locality 两层正交**:priority 编码故障域切换(秒级主机抖动 vs 分钟级 AZ 故障),locality 编码正常态摆放;
3. **panic 50%**:把可用性从 0 拉回非零,用户在"脏转发"与"干净拒绝"间选择;
4. **outlier 被动**:真实流量才反映应用层质量;探测流量在大规模下本身是负担;
5. **池 per-host**:握手成本/流上限是物理连接属性,天然绑定 (host,protocol,options) 四元组。

## 5.7 FAQ

**Q1:EDS 推送会重置健康状态吗?**
不会:地址匹配复用 Host 对象,健康检查状态随之迁移(upstream_impl.cc:2496-2509)。

**Q2:panic 阈值能关吗?**
能:healthy_panic_threshold: 0;配 fail_traffic_on_panic 则宁可拒绝。

**Q3:LeastRequest 的 power-of-two 是什么?**
随机抽 choice_count_ 个 host 取 active 最少——O(1) 近似全局最少。

**Q4:RingHash 和 Maglev 怎么选?**
RingHash 一致性好但查找 O(log n);Maglev 查表 O(1)、内存换时间。

**Q5:最多逐出多少 host?**
max_ejection_percent 默认 10%;always_eject_one 可保底踢一个。

**Q6:连接池为什么不在 cluster 上?**
物理连接绑定 (host,协议,options);host 移除→drain 该 host 的池,语义天然清晰。

**Q7:HTTP/1 的池和 HTTP/2 的池差别?**
同一套代码:HTTP/1 容量恒 1,HTTP/2 容量=并发流上限;排队逻辑共享。

**Q8:preconnect 什么时候建连?**
peekahead_ratio>1 时 newStream 前驱动,最多预选 3 个池,先 LB peekAnotherHost。

**Q9:warming 期间的集群接流量吗?**
不接:路由仍引用旧 active;新集群独立预热到 EDS/HC 就绪。

**Q10:纯健康状态变化会立刻广播吗?**
进 1000ms 合并窗口;host 增删则立即全量广播。
