# 第 06 章 · 热重启、Admin 与工程文化

> 基线:tag v1.39.1。核心目录 source/server/ 与 source/exe/。

## 6.0 全景:三通道进程接力

```
父进程 epoch N                          子进程 epoch N+1
  │ ①共享内存 shm_open /envoy_shared_memory_{base_id×10}
  │   仅锁+标志位(SharedMemory 结构,version=11),不含 stats 数据
  │ ②控制通道:AF_UNIX SOCK_DGRAM 迷你 RPC(长度前缀+protobuf)
  │   kPassListenSocket(SCM_RIGHTS 传 fd)/kStats/kDrainListeners/kShutdownAdmin/kTerminate
  │ ③UDP 透传通道:父把收到的 UDP/QUIC 包原样转给子
  时间线:子 attach 校验 version → 要 fd(t2)→ worker 起来后 drainParentListeners(t3)
        → drain-time-s(默认 600s)概率渐进关连接 → parent-shutdown-time-s(900s)到期
        → 子发 kTerminate → 父 kill 自己(SIGTERM)
```

本体的文件布局:协议骨架在 hot_restarting_{base,child,parent}.cc,粘合层 hot_restart_impl.cc,禁用时的桩是 HotRestartNopImpl(hot_restart_nop_impl.h:16-44)。同址最多 3 个 Envoy 共存,第 3 个顶掉最老的父(hot_restarting_base.cc:35-38)。

## 6.1 共享内存刻意做小与 stats 重放

共享内存不是 stats 大表,而是几十字节的锁+标志结构(hot_restart_impl.h:30-36);attach 时严格校验 version=11,不兼容直接 RELEASE_ASSERT 快速失败——**不兼容就走全量重启的版本契约**。初始化竞态用共享内存原子位兜底;日志锁 PTHREAD_MUTEX_ROBUST+EOWNERDEAD 恢复,父进程暴死不把锁带进坟墓;`prctl(PR_SET_PDEATHSIG)` 保证无孤儿(:107-110)。

**stats 走 RPC 重放而非共享内存**:父导出 protobuf(只导 used 的 gauge 与 latch>0 的 counter 增量,动态 stat 段以 span 区间随行),子经 StatMerger 按每进程私有 SymbolTable 重放(stat_merger.cc:22-75);gauge 三种合并语义(Accumulate/NeverImport/Uninitialized),`server.hot_restart_generation` 在交接时保留父贡献。

## 6.2 fd 交接与"谁管 listener"

子创建 listener socket 时先向父要:duplicateParentListenSocket 按地址匹配,父校验 worker_index 后用 SCM_RIGHTS 复制对应 worker 的 fd(hot_restarting_parent.cc:150-171);找不到则子自行 bind。**非 reuse-port**:同一时刻 fd 只在父或子手里,交接零丢包;**reuse-port**:父子各自 bind,内核分流——此时 LDS 更新可跳过地址重复检查,且子启动时向父发 kShutdownAdmin 继承 `enable_reuse_port_default`(#17259 的默认值切换过渡协议)。drain 节奏:`drainClose` 按 elapsed/drain_timeout 概率渐进关连接(drain_manager_impl.cc:75-98)。

## 6.3 Admin、GuardDog 与 OverloadManager

Admin 是 main 线程 event loop 上的独立 listener+HCM(admin.cc:54-77),自带假 overload manager 与 ignore_global_conn_limit——**控制面比数据面活得久**:worker 全卡死时 /server_info 仍可用。端点=构造函数里一张 handlers_ 表(/clusters /config_dump /stats /server_info,admin.cc:127-280);/server_info 呈现 hot_restart_version(`{11}.{sizeof(SharedMemory)}`)、INITIALIZING 位与双 uptime(本 epoch vs 全部 epoch)。

**GuardDog 宁杀勿挂**:独立线程(名 `dog:{dispatcher}`),周期取所有阈值最小值;分级 miss 200ms/megamiss 1s/kill(默认关,可加抖动)/multikill(多线程同卡判全局死锁);kill 先向卡死线程发终止信号,5s 不退则 PANIC 自爆留全量 backtrace(guarddog_impl.cc:143-172,abort_action.cc:38-50)。**OverloadManager 集中采样、分布式执行**:主线程定时器采样资源压力→Threshold/Scaled 触发器→thread-local 广播+回调,各组件在自己的 dispatcher 上注册动作(accept 闸门见 03 章)。

## 6.4 工程文化

扩展以 header-only Registry 静态自注册(REGISTER_FACTORY,按名查找不允许重名),config 一律 `MessageUtil::downcastAndValidate`+生成的 pb.validate 启动期强校验——**配置错误在启动即死**;元数据集中在 extensions_metadata.yaml。CI 是 checks 模型,format 失败是最常见拒因;测试金字塔:test/common 440 个单测、test/integration 96 个真网络集成,AGENTS.md 明文要求新代码 100% 覆盖、单测 hermetic。季度发布,changelogs/ 保留 1.0.0 起每个版本。本仓已有 AGENTS.md,要求提交 PR 必须披露 AI 使用且提交者完全理解所提交代码(AGENTS.md:18-20)。VERSION.txt(1.39.1)与 API_VERSION.txt(3.0.0)解耦——xDS API 演进不绑定代理发版。

## 6.5 设计动机

1. **fork 新进程而非线程内重启**:进程是唯一的全量内存回收边界;旧泄漏随旧进程消亡;
2. **domain socket 传 fd**:SCM_RIGHTS 是唯一能原样移交"已 bind 的 listen socket 所有权"(保留 accept 队列)的机制;
3. **stats 走重放**:全名字符串表会侵蚀符号化收益;dynamic spans 精确保留动态段语义;
4. **GuardDog 宁杀勿挂**:无声挂死拿不到现场;自爆留 backtrace,由外层 restarter 拉起新 epoch;
5. **admin 与 worker 隔离**:控制面必须在数据面降级/死锁时仍可应答。

## 6.6 FAQ

**Q1:热重启期间会断流吗?**
不:fd 原样移交保留 accept 队列;reuse-port 模式则父子并行分流。

**Q2:新旧版本协议不兼容怎么办?**
version 校验失败直接快速失败,走全量重启——明确的版本隔离契约。

**Q3:drain 是立即断连接吗?**
不是:按 elapsed/drain_timeout 概率渐进关闭;600s 默认可调。

**Q4:stats 在共享内存里吗?**
不在(老资料过时):只放锁+标志;stats 经 protobuf 导出+SymbolTable 重放。

**Q5:worker 死循环了会怎样?**
GuardDog miss/megamiss 计数;配 kill 则 5s 不退 PANIC 自爆留现场。

**Q6:admin 会被过载降级影响吗?**
不会:自带 null overload manager,可 ignore_global_conn_limit。

**Q7:配置错误会运行期才炸吗?**
不会:pb.validate 启动期强校验,错误配置启动即死。

**Q8:扩展怎么注册?**
REGISTER_FACTORY 静态自注册;启动日志打印全部静态链接扩展。

**Q9:同机器能跑几个 Envoy 同端口?**
最多 3 个 epoch 共存;第 3 个启动顶掉最老的父。

**Q10:QUIC 热重启怎么办?**
父把收到的 UDP 包经 _udp 通道原样转发给子直到 drain 完成;worker 数变化会失败(注释坦承)。
