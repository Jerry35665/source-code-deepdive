# 《Nginx 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》的第五卷。全部结论来自对 Nginx 1.31.5 主干(commit `231a60ee`,2026-09-02)源码的逐行阅读,每处关键论断标注 `文件:行号`。

## 这卷写给谁

读过《Redis 卷》、想知道"比 Redis 更复杂的 C 语言事件驱动系统长什么样"的工程师;Nginx 运维与模块开发者;任何要设计高性能网络服务的人。需要能读 C;不要求读过 Nginx 文档——本卷的视角是"文档背后源码真正做了什么"。

## 为什么选 Nginx

1. **事件驱动架构的另一极**:与 Redis 的 ae 库互为镜像——同为 Reactor,但多进程 vs 单线程、红黑树定时器 vs 链表、accept 锁 vs 无惊群问题,每处差异都是"数量级与约束决定设计"的教案;
2. **HTTP 框架的教科书**:配置期压平的阶段引擎、单向过滤器链、返回值路由器——理解它就读懂了 OpenResty/Envoy/Kong 等一众后继者的设计原型;
3. **生产工程文化的样本**:池化世界观、常数 4 哲学、诚实的历史包袱、手写 configure。

## 环境准备

```bash
git clone https://github.com/nginx/nginx.git && git checkout 231a60ee

# 构建(最简)
auto/configure --with-http_stub_status_module && make -j

# 与源码互动的两把钥匙
objs/nginx -V                                  # 看编译期模块表(ngx_modules)
error_log  logs/error.log debug;               # debug 级日志 + debug_connection
```

注意:本卷基于主干(1.31.x 开发线),与 stable 分支(1.28.x)可能有细微行号偏移;函数名与逻辑稳定。

## 三种用法

1. **系统通读**(约 5-6 小时):01 全景 → 02 进程 → 03 事件 → 04 HTTP → 05 upstream → 06/07 基建与文化;
2. **运维深挖**:各章 FAQ(约 85 条)——reload 永不致命的机制、平滑升级 fd 接力、"no live upstreams" 的三种根因、max_fails 的 worker 放大效应;
3. **模块开发**:第 06 章(内存池/buf)+ 第 07 章(模块注册)+ 第 04 章(filter 链与 last_buf 陷阱)。

## 本卷的统一约定

- **行号即凭证**:基于主干 commit `231a60ee`;
- **与 Redis 卷对照贯穿全卷**:ae vs ngx_event、SIGALRM vs find_timer、accept 锁三代演进 vs Redis 无此问题——每章对照点显式标注;
- **行为细节给源码证据**:文档没写的(SIGTERM 退避绞杀、init_master 死回调、X-Accel 后 keepalive 失效)全部以行号背书。
