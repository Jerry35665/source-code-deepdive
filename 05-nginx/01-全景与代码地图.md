## 1.2 顶层结构

```
nginx/
├── src/
│   ├── core/     基建:cycle、内存池、slab、字符串、buf/chain、配置解析、
│   │             模块系统、hash/rbtree/array、日志、resolver、connection
│   ├── event/    事件核心 + modules/(epoll/kqueue/select/eventport)
│   ├── http/     HTTP 框架:请求生命周期、11 阶段、filter 链、upstream、
│   │             modules/(proxy/gzip/rewrite/static/...)、v2/v3/
│   ├── stream/   TCP/UDP 反代(与 http 同构的四层版本)
│   ├── mail/     邮件代理(pop3/imap/smtp)
│   ├── os/       平台层:unix/(process/process_cycle/channel/...)
│   └── misc/
├── auto/         构建体系(configure/modules/feature 探测)
└── docs/         changes.xml(版本史的 XML 源)
```

**读法提示**:core 与 event 是理解一切的地基(本卷第 02、03、06、07 章);http 的模块组织高度同构(读懂 proxy 就懂 fastcgi/uwsgi);stream 是 http 的精简镜像。

## 1.4 一条主线串起全部文件

```
启动:main → init_cycle(事务式)→ master(sigsuspend)→ fork workers
每 worker:init_process → 事件循环(process_events_and_timers)
    accept → ngx_http_init_connection → create_request(池)
    → 11 阶段引擎 → content handler(proxy → upstream 状态机)
    → 过滤器链 → write filter → socket
    → finalize → keepalive/close → 池销毁
```

**三条贯穿性的语言**:① buf/chain 双坐标(第 06 章)是所有 IO 路径的通货;② 函数指针换挡(事件 actions、upstream 状态机、checker)是所有状态机的统一写法;③ pool 生命周期(第 06 章)是所有内存的归宿。

## 1.5 阅读路线

1. **IO 主线**(推荐):02 进程 → 03 事件 → 04 HTTP → 05 upstream。跟着一条请求从字节到字节;
2. **基建主线**:06 内存池 → 07 模块 → 02 → 03。适合要写 Nginx 模块的读者;
3. **对照主线**:与 Redis 卷并读——ae vs ngx_event、serverCron vs master 信号机、replication vs upstream(每章对照点已标注)。
