# 第 01 章 · 全景与代码地图:2.6 万行的教科书

> 基线:LevelDB 1.23,commit `7ee830d0`(2026-03-10 镜像)。

## 1.1 一组数字认识这个项目

| 指标 | 数值 |
|---|---|
| 核心代码行数(不含 third_party) | 25,764 |
| 最大源文件 | db_impl.cc 1,579 / version_set.cc 1,569 |
| 测试文件(*_test.cc) | 30 个 |
| 强制第三方依赖 | **0**(crc32c/snappy/zstd/tcmalloc 全部可选探测) |
| 许可证 | BSD-3 |
| 官方实现文档 | doc/impl.md(作者亲写的维护者笔记) |

**与前两卷对照**:Redis 17 万行、SQLite 22 万行、LevelDB 2.6 万行——但它覆盖了存储引擎的完整骨架(MemTable、WAL、SSTable、版本管理、compaction、bloom)。**行数最少、密度最高**,这就是"教科书"的含义:每一行都在讲原理,没有一行在处理历史包袱(2011 年诞生、无遗留格式)。

## 1.2 顶层目录

```
leveldb/
├── db/          数据库核心:db_impl、version_set、memtable、skiplist、
│                log(WAL)、write_batch、db_iter、table_cache、repair
├── table/       SSTable 层:format、block、table_builder、merger、
│                filter_block、two_level_iterator、iterator 基类
├── util/        基础设施:arena、cache、bloom、coding、crc32c、hash、
│                env( posix/windows )、options、status 相关
├── include/     公共接口:slice、status、options、iterator、cache、
│                comparator、filter_policy、env、db、write_batch
├── port/        平台移植层(port.h + 生成的 port_config.h)
├── helpers/     memenv(内存 Env)等辅助
├── doc/         index.md(用户手册)、impl.md(维护者笔记)、
│                table_format.md / log_format.md(格式规范)
├── issues/      按 issue 编号命名的回归测试
├── benchmarks/  db_bench(官方压测工具)
└── third_party/ 仅 googletest 与 benchmark(只进测试 target)
```

分层的 clean 程度是它的招牌:**include/ 只暴露 11 个头文件**,port/ 收敛所有平台差异,util/ 无一依赖 db/table——依赖方向严格单向向下。

## 1.4 一条主线串起全部文件

```
Put ──► write_batch ──► log_writer(WAL) ──► memtable(skiplist/arena)
                                                │ 写满冻结
                                                ▼
Get ──► memtable.Get ──► version_set.Get ──► table_cache ──► table
        (LookupKey)      (Version 层级)                        (block/filter)
                                                │ 后台 compaction
                                                ▼
                          version_set(PickCompaction/InstallResults)
```

dbformat 的 InternalKey 编码是贯穿一切的"通用语":memtable 排序、SSTable 排序、compaction 归并、Get 短路,全部用同一套比较器。**读懂第 03 章的 3.3 节,其余章节的排序逻辑都不必再解释**。

## 1.5 三条阅读路线

1. **写路径优先**(推荐):02 执行框架 → 03 内存组件 → 08 WAL 与恢复 → 04 SSTable → 06 版本 → 07 compaction。跟着一条 Put 从内存走到磁盘再被合并;
2. **读路径优先**:02 → 03(LookupKey)→ 04(block 格式)→ 05 bloom → 06(Version::Get)→ 07(DBIter)。跟着一条 Get 走完全部层次;
3. **接口优先**(架构视角):09(接口哲学)→ 01 → 任意。先理解 Slice/Status/Iterator 三大抽象,再看实现如何被它们约束。

## 1.6 与 RocksDB 的关系(一句提醒)

本卷基于原版 LevelDB 1.23;RocksDB 是它 2013 年的 fork,此后演进出 WriteThread 流水线、VersionBuilder 增量、多级 L0、column family 等。读 LevelDB 的价值在于**看到这些复杂度出现之前的清晰形态**——每个 RocksDB 概念都能在这里找到它的朴素起源(各章深挖方向已标注对照点)。
