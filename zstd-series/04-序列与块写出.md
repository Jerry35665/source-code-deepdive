# 第 04 章 · 序列与块写出:两遍管道

> 基线:commit `d79e723`。行号以 lib/compress/zstd_compress.c、zstd_compress_sequences.c、zstd_compress_literals.c、zstd_compress_internal.h 为准。03 章讲"怎么找匹配",本章讲"找到之后怎么写进块"。

## 4.0 全景:seqStore 到块字节的管道

```
SeqStore_t(中间表示:SeqDef{offBase, litLength, mlBase},internal.h:85-89)
   → ZSTD_compressBlock_internal(c:4410)
   → ZSTD_entropyCompressSeqStore_internal(c:2915):
       第一遍:直方图统计 + 四态选型 + 建表 + 写表头
       第二遍:ZSTD_encodeSequences 冻结表后写位流
```

**为什么必须两遍**:FSE/Huffman 表头物理上位于位流之前,而表头大小与选型取决于整块统计——先统计后编码。offBase 是求和类型(:744-748):1-3=repcode 引用,≥4=真偏移+3。`ZSTD_seqToCodes`(:2721-2747):ofCode=highbit32(offBase),U16 超长靠 longLengthPos 补偿。

## 4.1 三表决策:四选一的代价比较

`ZSTD_selectEncodingType`(zstd_compress_sequences.c:156-235):LL/ML/OF 三张表各自独立四选一——

- **单符号**→set_rle(:166;nbSeq≤2 例外选 basic :168-174);
- **快档**(strategy<lazy):上块表 valid 且 nbSeq<1000→**repeat**(:187-191);样本太少或分布太平→**basic**(预定义表,:192-203);
- **慢档**:交叉熵(basicCost :139)vs 旧表代价(repeatCost :104,概率 0 即不可用)vs 自建表 NCount×8+理想熵(compressedCost :206-209)**三者取小**。

AccuracyLog:`FSE_optimalTableLog`=log2(srcSize)-2 封顶;低概率 -1 表示要求 nbSeq≥2048(:57-64)。**repeat 是跨块状态的红利**:表不重传,块间一致性由 D 端同款状态机保证(05 章)。

## 4.2 字面量编码:三型与 4 流切分

字面量段三型(Raw/RLE/Compressed)+3/4/5 字节头(2-2-10-10/14-14/18-18 的位数分配,zstd_compress_literals.c:140,:187-201,:209-232);Huffman 4 流均分切分点+6 字节跳转表 LE16 回填(huf_compress.c:1165-1198;singleStream=srcSize<256,literals.c:142)。**块级字面量决策**(zstd_compress.c:3660-3764):63 字节门槛、(srcSize>>7)+4 的估算、set_repeat 条件——字面量段的选型与序列段同族但独立。

## 4.3 序列写出:倒序的镜像艺术

`ZSTD_encodeSequences_body` **倒序循环**(intentional underflow,zstd_compress_sequences.c:333-369)——镜像解码顺序:解码端从最后状态往回走(02 章 LIFO),编码端必须按解码的逆序写位流。seqHead 一个字节装三张表的类型:`(LLtype<<6)+(Offtype<<4)+(MLtype<<2)`(:2996,c:2996)。块循环的 lastBlock 判定 `lastFrameChunk & (blockSize==remaining)`(c:4646);三输出路径(Raw/RLE/Compressed)@4664-4689。**跨块状态=熵表+rep 的双缓冲交换**(仅压缩块确认,c:3634-3640);块分裂 rep 对账 dRep/cRep(:4097-4125);nbSeq==0 的块把旧 FSE 表当 repeat 拷走保状态一致(:2982-2986)。

## 4.4 字典的进入方式

字典通过 `ZSTD_resetCCtx_byCopyingCDict` 拷入**整套熵表+rep 状态**(c:2510)——首个数据块即可用 repeat 模式(表已在字典里):小数据压缩的胜负手(06 章展开训练)。

## 4.5 超级块:reversed 的扩展位

超级块(PG19?不对——zstd v1.5.6 稳定,zstd.h:415 参数 130):子块布局+**熵表只写一次、后续子块全 repeat**(zstd_compress_superblock.c:505-638,入口 :665-688);契约失败退 Raw 块。**仅 targetCBlockSize 参数启用**——默认关闭,报告如实标注两处解码器兼容性 workaround(seq≤1.3.4/1.4.0)。

## 4.6 与 deflate 对照及设计动机

deflate 的 dynamic huffman 每块重建表(表头+数据同块);zstd 把"表"升级为**可跨块 repeat 的状态**+三表分治(LL/ML/Off)+FSE 分数比特。设计动机:①两遍管道是表头前置的物理必然——**先有统计才有表,先有表才有位流**;②预定义表(basic)让小数据免传表;③AccuracyLog 是精度预算:表头成本 vs 编码收益的每一 bit 都要过秤;④超级块是"repeat 极致化"的实验位,默认关闭体现工程克制。

## 4.7 FAQ

**Q1:为什么不能一遍完成?**
表头物理前置+选型依赖整块统计(:2915-3031):两遍是格式决定的。

**Q2:repeat 模式什么时候失效?**
概率 0(repeatCost :104)或快档 nbSeq≥1000(:187-191)——状态一致性优先于收益。

**Q3:字面量 4 流怎么切?**
四等分+跳转表回填(:1165-1198);<256 字节走单流(literals.c:142)。

**Q4:offBase 为什么 ≥4 才是真偏移?**
1-3 留给 repcode 槽(:744-748):真偏移要+3 写入。

**Q5:超级块默认开吗?**
不开:仅 targetCBlockSize(:415,参数 130)启用;兼容 workaround 如实标注。

**Q6:nbSeq=0 的块有意义吗?**
纯字面量块;但仍要拷走旧表保 repeat 状态(:2982-2986)——状态机的纪律。

**Q7:序列头一个字节装得下三张表的类型?**
每表 2bit+2bit 保留(:2996):类型只有 4 种(RLE/basic/compressed/repeat)。

**Q8:为什么 encodeSequences 要倒序?**
解码从最后状态回溯(02 章 LIFO):编码必须按解码逆序写(:333-369)。

**Q9:字典为什么能让首块就 repeat?**
CDict 拷入整套熵表+rep(c:2510):字典自带"上一块"。

**Q10:块最多多少序列?**
128KiB 块×平均匹配长:数千级;nbSeq 字段 16 位+扩展位。

## 4.8 小结与深挖方向

本章结论:**写出="两遍管道(格式必然)+三表四选一(代价取小)+repeat 跨块状态+倒序镜像"**。深挖:

1. selectEncodingType 三代价(:139/:104/:206-209)的期望误差;
2. 字面量 63 字节门槛(:3660)的经验来源;
3. 超级块兼容 workaround 的两处历史(seq≤1.3.4/1.4.0);
4. longLengthPos 补偿(:2721-2747)的触发频率;
5. rep 对账 dRep/cRep(:4097-4125)在块分裂的正确性论证。
