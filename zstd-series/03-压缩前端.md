# 第 03 章 · 压缩前端:策略族谱系与 repcode

> 基线:commit `d79e723`。行号以 lib/compress/clevels.h、zstd_fast.c、zstd_double_fast.c、zstd_lazy.c、zstd_opt.c、zstd_ldm.c、zstd_compress_internal.h 为准。zstd 的速度/比率权衡由策略族实现——**22 个级别不是 22 种算法,是一张参数表驱动的 8 种策略**。

## 3.0 全景:策略族谱系

```
速度 <<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<< 比率
fast   dfast  greedy lazy  lazy2  btlazy2 btopt  btultra2
L1-2   L3-4   L5     L6-7  L8-12  L13-15  L16-17 L18-22
单hash  双hash  链d0   链d1  链d2   二叉树  DP     DP+两遍
```

级别=纯数据:clevels.h:26-51 四张表(按源大小分档)×23 行 7 元组 {windowLog,chainLog,hashLog,searchLog,minMatch,targetLength,strategy};负级别走 row 0,`targetLength=-level` 作跳跃步长(zstd_compress.c:8305-8310)。**分发表驱动**:`ZSTD_selectBlockCompressor` 是 [dictMode][strategy] 的函数指针表(zstd_compress.c:3099-3143),row matchfinder 另一张表(:3150-3171),由 ZSTD_buildSeqStore(:3292-3455)统一调用。窗口双缓冲:ZSTD_window_update 不连续时把旧前缀降级 extDict(internal.h:1395-1396)。

## 3.1 fast/dfast:单双 hash 的速度极

**fast**(zstd_fast.c):单 hash 表直出匹配;`stepSize = TL + !TL + 1`(:200)——targetLength 直接变跳跃步长;hash 流水线注释 :144-189;mls 4-7 × cmov/branch 特化 4 份(:425-479,cmov 条件 windowLog<19 :449)。**dfast**(zstd_double_fast.c):hashLong(8B)+hashSmall(=chainTable,mlsB)双表(:110-112):8 字节命中长匹配(:206-211)、4 字节保底(:220)、`_search_next_long` 反超(:253-273)——长匹配优先,短匹配兜底。**repcode 在快路径的作用**:所有策略入口先试 rep、出口连吃"立即 rep"(fast :275/:410、dfast :190/:308)。

## 3.2 lazy 族:hash chain 与二叉树

hash chain:`NEXT_IN_CHAIN`(zstd_lazy.c:626)把同槽候选串成链,插入 :632-657,搜索预算 `1<<searchLog`(:689)。**lazy 的本质是"再往前看一步"**:gain 公式 `ml2*4 - highbit32(offBase) > ml*4 - highbit32(offBase) + 4`(:1699-1706)——新匹配增益超过一个 cost 位就换;depth 0/1/2=greedy/lazy/lazy2(:1832/:1876/:1920);lazySkipping=8(:20/:1667)。**DUBT 隐式二叉树**:`bt[2*(idx&btMask)]`,btLog=chainLog-1(:259-261;zstd_opt.c:452-453),惰性批量排序协议(:276-307)——btlazy2 用树把"链上查找"变"对数查找"。

## 3.3 btopt 族:最优解析与价格模型

btopt/btultra 是**最优解析(optimal parse)**:价格模型用定点 1/256 bit(zstd_opt.c:25-36),`ZSTD_getMatchPrice` 对长距离惩罚 offCode≥20 加 2bit/档(:340-341);opt[] 数组前向刷价(:1200-1338)+`_shortestPath` 回溯(:1340-1429);**rep 三元组嵌入每个 DP 状态**(:1254-1261)——状态不只记位置还记三个 rep 槽;btopt 有剪枝(:1268/:1334)。**btultra2 的两遍扫描**:首块 ZSTD_initStats_ultra 只收统计(:1476-1499),注释明说"2x CPU 换 ~0.5%"(:1516-1523)——**最贵级别买最准的统计**。

## 3.4 repcode:压缩率的秘密武器

`ZSTD_updateRep`(internal.h:839-857):offBase>3 是真偏移→三槽顺移(LRU);1-3 是 repcode→`repCode-1+ll0` 换算后"**使用即前置**"。三个"最近偏移"槽让重复偏移的编码成本摊薄到 1-2 bit(offBase=1-3 直接引用槽)。03 章 opt 的 DP 状态嵌入 rep、04 章序列编码的 rep记账——**repcode 贯穿前端与后端**。

## 3.5 LDM:长距离匹配

`strategy>=btopt && windowLog>=27` 自动启用(zstd_compress.c:289-293):gear hash 切分内容定锚+XXH64 校验+分桶轮转(zstd_ldm.c:190-208,:395-400,:428-466)——大文件(虚拟机镜像/日志)的长重复由"锚点采样"解决,不进主 match finder 的热路径。

## 3.6 与前作对照及设计动机

deflate 只有 greedy+lazy 一种策略对(参数只有 level/window);zstd 把"策略×参数"做成数据表。与 FFmpeg clevels? 与 PG clevels? 与卷内对照:**clevels.h 之于 zstd = FFmpeg 的 clevels 类似物(15 章提及的级别表)+ PG 的 cost GUC(11 章)——"级别即数据"**。设计动机:①按块选策略(局部负载自适);②参数硬编码不做成配置文件:调参是发布行为,不是用户行为;③repcode 的三槽是 LZ77 感知 locality 的最小充分状态。

## 3.7 FAQ

**Q1:级别 19 和 22 差在哪?**
同策略 btultra2,参数不同:TL 256-999(:26-51)与搜索深度;22 更慢更省。

**Q2:为什么 fast 的 step=targetLength?**
跳步大小即"平均匹配间隔预期"(:200):大 TL=大步=快但漏匹配。

**Q3:hash chain 和 binary tree 怎么选?**
btlazy2 起用树(:259-261):树查找 O(log) 但插入贵——链适合浅搜索,树适合深搜索。

**Q4:lazy 的"gain 公式"在算什么?**
(:1699-1706)多找一步的增益是否超过 1 个 cost 位——lazy2 就是多步重复此判定。

**Q5:btultra2 为什么要两遍?**
首遍只收统计建更准的价格表(:1476-1499):2x CPU 换 ~0.5% 比率(:1516-1523)——官方注释原话。

**Q6:repcode 只有三槽,第 4 个最近偏移呢?**
丢进普通 offset 编码(代价高);三槽是"收益/状态"的折中(:839-857)。

**Q7:LDM 什么时候自动开?**
strategy≥btopt 且 windowLog≥27(:289-293):大窗口+贵策略才值得。

**Q8:负级别(-1~-19)是什么?**
row 0 参数+targetLength=-level 作步长(:8305-8310):"只求快"的正式接口。

**Q9:extDict 是什么?**
窗口滚动时旧数据不在连续缓冲:匹配引用降级为"双缓冲寻址"(internal.h:1395-1396)。

**Q10:row matchfinder 是什么?**
(:3150-3171 另一张表)SIMD 整行比较的 hash(tagTable 8 位标签,zstd_lazy.c:1185 起):lazy 族的速度变体。
