# 《Kubernetes 卷》导读:如何使用本卷

> 本卷是《源码深读 · 系统开源项目解读系列》的第七卷。全部结论来自对 Kubernetes master(commit `517a94ff`,2026-09-04)源码的逐行阅读,每处关键论断标注 `文件:行号`。

## 这卷写给谁

用过 Kubernetes(kubectl/Deployment/Service)、想知道"声明式背后到底是谁在干活"的后端/平台工程师;要开发 Operator 或自定义调度器的开发者。需要 Go 阅读能力;不需要读过 K8s 文档全集——本卷只讲机制,不讲用法。

## 为什么选 Kubernetes

1. **云原生时代的"操作系统内核"**,也是本系列规模最大的项目(核心抽样 66 万行);
2. **声明式 API 与控制循环的发明地**(虽继承自 Google Borg):理解本卷的 informer/reconcile 模式,就理解了 Operator、Argo、Crossplane 等整个生态;
3. **工程模式的宝库**:staging 模块化、代码生成器、feature gate、API 兼容性管理——大型 Go 项目的组织范本。

## 环境准备

```bash
git clone https://github.com/kubernetes/kubernetes.git && git checkout 517a94ff

# 本地跑控制面(kind 是最简单的方式)
kind create cluster --image kindest/node:v1.34.0

# 与源码互动的三把钥匙
kubectl get pod pod-name -o yaml --show-managed-fields   # 看 managedFields(第 02 章)
kubectl get --raw /api/v1/pods?watch=1                    # 直观看 watch 事件流
kubectl describe pod pod-name                             # 看 events(决策树的输出)
```

## 三种用法

1. **系统通读**(约 5-6 小时):01 全景 → 02 API 服务器 → 03 控制器 → 04 调度器 → 05 kubelet → 06 总结;
2. **Operator 开发者**:第 03 章逐字读(informer/workqueue 的每处防御都是你框架里的坑);
3. **排障对照**:Pod Pending → 04 章;Pod 反复重启 → 05 章;API 409/410 → 02 章;控制器卡死 → 03 章。
