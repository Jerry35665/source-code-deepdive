# 第 28 章 · 聚合引擎:四路分发、延迟合并与状态导出

> 基线:commit `7e886f44`。核心:src/execution/operator/aggregate/(physical_hash_aggregate.cpp / physical_perfecthash_aggregate.cpp / physical_ungrouped_aggregate.cpp)与 src/execution/radix_partitioned_hashtable.cpp。

## 28.0 全景:计划期四路分发

```
 plan_aggregate.cpp:278-310 选择顺序即优先级:
 ① 无分组且单 grouping set        → PhysicalUngroupedAggregate
 ② 单值分区+全聚合有 cluster_update → PhysicalPartitionedAggregate
 ③ 整数键+min/max 统计+位宽和≤阈值+无 DISTINCT → PhysicalPerfectHashAggregate
 ④ 兜底(GROUPING SETS/DISTINCT/任意键) → PhysicalHashAggregate
 ORDER BY 聚合在进物理算子前已被 BindSortedAggregate 改写(plan_aggregate.cpp:320-327)
```

纠偏:分组键执行期**不序列化**——GAHT 行布局=组列+hash+对齐的聚合状态,键匹配靠盐值过滤+RowMatcher 逐列比较(aggregate_hashtable.cpp:866-882);与 join HT 共享 ht_entry_t 盐值指针表(ht_entry.hpp:18-24)。

## 28.1 哈希聚合:合并被推迟到 source 阶段

纠偏:sink 的 Finalize **只**把 uncombined_data 切成 AggregatePartition[] 并标 READY_TO_FINALIZE;真正的状态 combine(逐 chunk 重探测+CombineStates)发生在下游 GetData 领取的 **FINALIZE 任务**里(radix_partitioned_hashtable.cpp:965-1039, 1231-1307)——"Combine 完成合并"是旧图景;单线程且未 abandon 时整个合并直接跳过(:1002-1028)。DISTINCT finalize 是独立事件流:去重表结果回灌主 HT 后再插常规 finalize 事件(physical_hash_aggregate.cpp:814-836);输入相同的 DISTINCT 聚合共享一张去重表(distinct_aggregate_data.cpp:120-170)。有 filter 时**不能**跳过常规 sink(:98-111)。

## 28.2 GAHT 内部:盐值探测与自适应

探测结构是 ht_entry_t 指针表(高 16 位盐值),线性探测、容量恒为 2 的幂、负载因子 1.5 触发倍增,初始容量 2×STANDARD_VECTOR_SIZE(aggregate_hashtable.hpp:87; aggregate_hashtable.cpp:226-229);每线程一张 GAHT,radix 位宽由 RadixHTConfig 全局同步,满时 Abandon/Repartition/导出状态三选一(radix_partitioned_hashtable.cpp:314-411, 824-878)。状态导出/导入支撑外存。GROUPING() 值按 grouping_set 预计算;空 grouping set 伪造 TINYINT 常量组(:46-63, 28-31)。

## 28.3 Perfect Hash 与 sorted aggregate

Perfect hash 的触发判据:整数组键+min/max 统计+位宽和 ≤ perfect_ht_threshold——**默认 12,设置描述写 "bytes" 但按 bit 比较**(plan_aggregate.cpp:228-237; settings.hpp:2059-2070);纠偏:运行时统计错误导致组 ID 越界时**直接抛 InvalidInputException 而非回退**哈希聚合(perfect_aggregate_hashtable.cpp:146-153),且线程间合并在全局 mutex 下串行(physical_perfecthash_aggregate.cpp:166-169)。`string_agg ... ORDER BY` 是**计划期改写**:注入 sorted-aggregate 包装器(链表缓冲+整体排序)接管,string_agg 状态只有字符串缓冲三元组;排序键冗余时 ORDER BY 被直接删除(sorted_aggregate_function.cpp:209, 580-585)。

## 28.4 设计动机

1. **延迟合并**:FINALIZE 任务化让合并可并行领用,不再阻塞 pipeline 收尾(radix_partitioned_hashtable.cpp:1231-1307);
2. **四路分发**:按统计与键形态递进,最便宜的路径优先(plan_aggregate.cpp:278-310);
3. **盐值指针表复用**:聚合与 join 共享同一 ht_entry_t 设计,调优经验互通(ht_entry.hpp:18-24);
4. **计划期改写 ORDER BY 聚合**:sorted-aggregate 包装器让执行骨架零改动(sorted_aggregate_function.cpp:209);
5. **group_validity 计划期判定**:键列必非 NULL 时省 validity 位(plan_aggregate.cpp:269-276);
6. **状态导出/导入**:聚合状态是字节,外存与重分布皆可承接(radix_partitioned_hashtable.cpp:824-878)。

## 28.5 FAQ

**Q1:聚合有几种物理算子?**
四种:ungrouped/partitioned/perfect-hash/hash,按优先级分发(plan_aggregate.cpp:278-310)。

**Q2:Combine 完成状态合并吗?**
不,真正的合并推迟到 source 阶段领取的 FINALIZE 任务(radix_partitioned_hashtable.cpp:1231-1307)。

**Q3:perfect hash 的阈值是多少?**
默认 12,单位是 bit 而非文档写的 bytes(settings.hpp:2059-2070)。

**Q4:perfect hash 统计错了会回退吗?**
不会,直接抛 InvalidInputException(perfect_aggregate_hashtable.cpp:146-153)。

**Q5:分组键要序列化吗?**
不,行内存原始列值+RowMatcher 逐列比较(aggregate_hashtable.cpp:866-882)。

**Q6:DISTINCT 聚合怎么执行?**
每个去重输入独立一张去重 HT,finalize 时回灌主 HT(physical_hash_aggregate.cpp:814-836)。

**Q7:string_agg 的 ORDER BY 在哪排序?**
计划期注入 sorted-aggregate 包装器,链表缓冲+整体排序(sorted_aggregate_function.cpp:209)。

**Q8:负载因子多少触发扩容?**
1.5;容量恒为 2 的幂(aggregate_hashtable.hpp:87)。

**Q9:空表聚合输出什么?**
无分组时输出一行(逐聚合 initialize+finalize);有分组集输出 NULL 组(radix_partitioned_hashtable.cpp:1390-1426)。

**Q10:GROUPING() 怎么算?**
按 grouping_set 是否含该列预计算常量(:46-63)。
