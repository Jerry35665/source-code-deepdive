# 第 18 章 · 扩展体系与多端工具:双轨加载与 MbedTLS 签名

> 基线:commit `7e886f44`。核心:src/main/extension/(6 个 .cpp 共 3,513 行)、extension/ 内嵌扩展、tools/。

## 18.0 全景:静态注册表 + 动态 dlopen 双轨

```
 LOAD <name>
   ├ 静态短路:查 DBConfig::linked_extensions(生成代码只发清单,Load 是手写查表)
   │   extension_helper.cpp:95-107——注释:为"扩展自带一份 DuckDB 拷贝"的嵌套场景避免 ODR
   └ 动态轨:搜索目录(SET extension_directory → 配置列表 → ~/.duckdb/extensions)
       → <版本>/<平台>/<名>.duckdb_extension → 512B footer 校验(平台/版本/ABI)
       → 两层 SHA-256(MbedTLS,1MB 分块并行)→ 试受信公钥(core 20 把/community 19 把)
       → dlopen(RTLD_NOW|RTLD_LOCAL)→ 入口 <名>_duckdb_cpp_init / _init_c_api[_v2]
```

纠偏:网上常见"生成代码直接调 Load 函数"的描述对本 commit 不成立——生成的代码**只发布清单到 linked_extensions**,真正的 Load 是手写查表,为的是嵌套 DuckDB 场景能读宿主注册表(config.hpp:286; extension_helper.cpp:95-107)。

## 18.1 内嵌扩展与三层内建函数

`extension/` 内嵌 10 个目录:core_functions(约 3.3 万行)/parquet(2.7 万)/json(1.3 万)/icu(4.7 万)/tpch/tpcds/autocomplete/demo_capi/loader/delta(只剩 README 占位——已迁出主仓的证据)。internal_extensions[] 表 31 项:前 9 项可静态链入(core_functions/icu/excel/parquet/tpch/tpcds/httpfs/json/autocomplete——注意 excel 与 httpfs 源码已不在仓,只留旗标),其余 22 项(spatial/iceberg/vss/ducklake 等)只能动态加载(extension_helper.cpp:121-152)。纠偏:**内建函数有三层**——引擎固有列表(function_list.cpp 约 225 项)在 DuckCatalog::Initialize 恒注册,即使 core_functions 不链接(duck_catalog.cpp:38-43);core_functions 约 386 项是第二层;第三层是 EXTENSION_FUNCTIONS[] 约 1,400 行生成映射注册的**占位函数**,bind 时才触发 autoload 并重绑定(built_in_functions.cpp:102-176)——"用到即加载"的机制底座。

## 18.2 动态加载细节:签名与信任分流

footer 512 字节由 8 个 32 字节字段倒序组成(magic/平台/duckdb 版本/扩展版本/ABI 类型,extension_load.cpp:331-371)。签名:**两层 SHA-256**——内容按 1MB 分块(8KB 步长)并行哈希再拼接总哈希,密码学原语是 **MbedTLS 而非 OpenSSL**(:247-302)。信任键按仓库来源分流:核心仓 20 把内置公钥、community 仓 19 把;**裸 LOAD(无 FROM)把来源强制压回 core/community 键**,防止借用户自建仓的键载入原生代码(:944-960);.info 安装信息文件记录来源仓库,FROM 加载核对一致性防"借名加载"(:604-624)。两条白名单互不相同:自动安装 auto_install 仅 10 项,自动加载 AUTOLOADABLE_EXTENSIONS 有 26 项(:169-183; extension_entries.hpp:1544-1548);autoload/autoinstall 默认构建期决定,发行版 Makefile 显式开启(Makefile:464)。

## 18.3 tools/ 已瘦身与多端分工

纠偏:本 commit 的 tools/ 只剩五个目录——cpp(新句柄式 C++ API 约 1.15 万行)、shell(约 1.75 万行,主文件 3,682 行)、sqllogic(仅 pytest 辅助)、swift(打包)、utils;**python/jdbc/odbc/r/node 绑定全部不在仓库**。C API(约 2.0 万行,v1+v2)在 src/main/capi/。发行版默认链接 icu/json/parquet/autocomplete(core_functions 经 core.cmake 一并载入),tpcds/tpch 标 DONT_LINK——构建但不链,运行时走动态轨(bundled_extensions.cmake:17-26)。

## 18.4 设计动机

1. **注册表而非生成调用**:嵌套 DuckDB(扩展自带引擎拷贝)能识别宿主已链扩展,避免 ODR 违例(extension_helper.cpp:18-20 注释原文);
2. **占位函数autoload**:函数在 catalog 里"可见",bind 时才加载,SQL 兼容性与按需安装兼得(built_in_functions.cpp:102-176);
3. **两层哈希并行化**:1MB 分块让大扩展文件签名验证可并行(extension_load.cpp:258-282);
4. **键来源分流**:裸 LOAD 强制 core/community 键,封堵"重定向目录借键"攻击面(:944-960);
5. **DONT_LINK 构建**:基准类扩展构建验证但不进发行二进制,控制体积(bundled_extensions.cmake:17-26);
6. **别名表集中**:http/s3→httpfs 等 10 条别名一处维护(extension_alias.cpp:6-17)。

## 18.5 FAQ

**Q1:静态扩展怎么被找到?**
查 DBConfig::linked_extensions 注册表,生成代码只发清单(extension_helper.cpp:95-107)。

**Q2:LOAD json 会重新加载吗?**
json 已静态链入,静态短路直接调注册的 load 函数。

**Q3:扩展签名用什么库?**
MbedTLS(非 OpenSSL),两层 SHA-256(extension_load.cpp:14, 247-302)。

**Q4:裸 LOAD 用户仓库的扩展行吗?**
不行,强制 core/community 键并给专门错误(:944-960, 653-663)。

**Q5:函数还没加载就能 SELECT 吗?**
能,EXTENSION_FUNCTIONS 占位在 bind 时触发 autoload(built_in_functions.cpp:102-176)。

**Q6:Python 绑定在本仓吗?**
不在,tools/ 只剩 cpp/shell/sqllogic/swift/utils。

**Q7:自动安装白名单多大?**
10 项;自动加载白名单 26 项,两表互不相同(extension_helper.cpp:169-183)。

**Q8:扩展文件尾是什么?**
512 字节 footer:magic/平台/版本/ABI 八字段倒序(extension.hpp:45-46)。

**Q9:入口符号有几种?**
C++ `<名>_duckdb_cpp_init`、C ABI V1 `_init_c_api`、V2 `_init_c_api_v2`(extension_load.cpp:817-903)。

**Q10:delta 扩展源码在哪?**
已迁出主仓,extension/delta 只剩 README 占位。
