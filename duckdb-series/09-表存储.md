# 第 09 章 · 表存储:RowGroup、段与扫描路径

> 基线:commit `7e886f44`。核心:src/storage/table/ 目录。

## 9.0 全景:RowGroup 内部的列段布局

```
RowGroup(DEFAULT_ROW_GROUP_SIZE=122880 行 = 60×2048 vector,storage_info.hpp:26)
├ ColumnData c0(INT)
│   ├ 段A PERSISTENT:DataPointer{block_id+offset+压缩类型+统计} ← 段的身份只有几十字节
│   ├ 段B TRANSIENT:未压缩内存块,可追加
│   └ validity 子列:独立位图段(数据段压缩自带 null 语义时 checkpoint 退化 COMPRESSION_EMPTY)
├ ColumnData c1(VARCHAR)
│   ├ 段P dict_fsst:[header][字典][FSST符号表][串长][索引] 四区相向生长
│   └ 段Q TRANSIENT:块内字典(串从块尾向下生长),超长串写溢出块留 12B marker(负偏移标识)
├ RowVersionManager(每 2048 行一条版本信息;checkpoint 序列化为 deletes_pointers)
└ UpdateSegment:UpdateNode→每 vector 一条 UpdateInfo,元组id+新值内联在 undo buffer
```

## 9.1 写入:永远不压缩

append 链:RowGroupCollection::InitializeAppend→RowGroup::Append 逐列下发→ColumnData::AppendData。行组封满→finalize 开新组;段满→归并段统计开新段。**transient 段尺寸策略**:首段极小、逐段翻倍、1024 字节以上对齐"2 的幂−块头"、上限块大小——冷表省内存,热表很快收敛到整块(column_data.cpp:793-835)。压缩函数固定 COMPRESSION_UNCOMPRESSED:**写入路径永远不压缩,压缩只发生在 checkpoint**。

## 9.2 读取:压缩函数多态 + 两级 zonemap

ColumnSegment 不认识压缩格式,一切转发给段自带的 CompressionFunction 函数表(init_scan/scan/filter/fetch_row,column_segment.cpp:137-190)——**读哪个解压器由段元数据决定,调用方无感**。过滤下推两级:行组级 zonemap 砍掉整组(FILTER_ALWAYS_FALSE 直接跳过 122880 行);段级 zonemap 快进游标,活下来的 vector 再走段级 filter。并行以行组为单位原子认领,`batch_index` 保有序输出;预取把本区间要读的块组成 run(≤32MB)一次大读,行组尾部注定被 zonemap 裁掉的 vector 不预取。

## 9.3 checkpoint:按行组并行重写 + 元数据复用

RowGroupCollection::Checkpoint 为每个行组排任务;RowGroup::WriteToDisk 先试省事——**无变化且支持复用直接返回 REUSE_EXISTING_ROW_GROUP_METADATA**,列粒度再分 FULLY_CHECKPOINT/PARTIALLY_REUSE(row_group.cpp:1634-1677)。真正要写的列走 ColumnDataCheckpointer:重扫描整行组,候选压缩算法各跑 analyze 计分,**分数(预估字节数)最小者胜出**后重写新块;无变更的列零拷贝只重发 DataPointer。产物 RowGroupPointer(row_start/count/各列指针/删除指针)写进表数据元数据流,catalog 侧只落 table_pointer+total_rows。统计在行组/段级维护、上卷为 TableStatistics——优化器拿到的 zonemap 就是这些 min-max。

## 9.4 DELETE/UPDATE 是"旁路"

基线段不可变:DELETE 只在 RowVersionManager 打标记,行数据一字节不动;UPDATE 新值写进 UpdateSegment 的 UpdateInfo 链(每 vector 一条,元组 id+新值内联),分配走事务 undo buffer——回滚=链回退,提交=版本号翻转,与卷一 MVCC 闭环衔接。checkpoint 时增量要么合并重写进新段,要么随元数据复用保留。

## 9.5 设计动机

1. **122880=60 vector**:足够大让 zonemap/压缩发挥价值,足够小让多线程负载均衡;必须整除 vector 才能无拷贝切片;
2. **persistent/transient 双形态**:append 只碰无锁内存块,压缩成本推迟到 checkpoint 一次性摊销;持久段身份压成几十字节 DataPointer,重启不必碰数据块;
3. **按列段为压缩单元**:每段独立携带压缩类型与统计,冷热混合共存于一个行组,新格式可渐进混存;
4. **统计行组/段级**:裁剪分层(整组→段→vector 内 filter),统计同地存储同地更新,无需独立索引;
5. **update/delete 走旁路**:基线不可变,扫描零锁;增量小且按 vector 对齐,checkpoint 批量合并;
6. **元数据复用做到列级**:典型负载"追加新行组、老组纹丝不动",checkpoint 成本∝变化量而非表大小。

## 9.6 FAQ

**Q1:行组为什么是 122880?**
60 个 vector;可配置但必须被 vector 大小整除(storage_manager.cpp:463-474)。

**Q2:列段和块什么关系?**
段上限=块大小;一行组的每列约切 60 个段(每段 vector 整数倍)。

**Q3:打开库会加载所有数据吗?**
不会:行组按需反序列化,列扫描到才加载(row_group.hpp:302-319)。

**Q4:新写入压缩吗?**
不:固定 uncompressed,压缩只在 checkpoint 的竞分后重写。

**Q5:字符串超长怎么办?**
写独立溢出块,段内字典区留 12B (block_id,offset) marker,行索引存负偏移。

**Q6:validity 段什么时候消失?**
数据段压缩自带 null 语义(dict_fsst 等)时 checkpoint 直接换 COMPRESSION_EMPTY 一块不落。

**Q7:UPDATE 改了哪里?**
基线不动:新值进 UpdateInfo 链(undo buffer),checkpoint 时合并。

**Q8:checkpoint 会重写没变的行组吗?**
不:REUSE/PARTIALLY_REUSE 只重写涉及指针,未变列连元数据块都不动。

**Q9:点查路径?**
RowGroup::Fetch 先做可见性过滤再 FetchRow(column_segment.cpp:185-190)。

**Q10:删除多的行组 checkpoint 会靠前吗?**
RowGroupReorderer 可按删除率重排 checkpoint 顺序为 vacuum 腾空间(row_group_reorderer.hpp:25)。
