# 第 25 章 · 窗口函数执行:双身份算子与五级聚合器阶梯

> 基线:commit `7e886f44`。核心:src/execution/operator/aggregate/physical_window.cpp 与 src/function/window/(18 个文件)。纠偏:窗口执行器不在 src/execution/ 下,而在 src/function/window/。

## 25.0 全景:sink 排序 + source 六阶段

```
 PhysicalWindow 既是 Sink 又是 Source(必须看到完整分区才能求值):
 Sink:按分区键 radix 哈希进 SortStrategy 四策略(HashedSort/FullSort/
      PartitionedSort/NaturalSort,sort_strategy.cpp:35-49),MemoryTag=WINDOW
 Source 六阶段任务状态机:SORT → MATERIALIZE → MASK → SINK → FINALIZE → GETDATA
   MASK 并行算两张 ValidityMask:partition_mask(新分区首行)/order_mask(新 peer 组首行)
 输出保序:有分区 NO_ORDER / 无分区无排序 INSERTION_ORDER / 否则 FIXED_ORDER
   并行输出靠 batch_index 归并(physical_window.cpp:1111-1124)
```

纠偏:**order-dependent 只在裸 `OVER()`(无 PARTITION BY 且无 ORDER BY)时为真**(physical_window.cpp:271-273),此时才关 ParallelSink;带 ORDER BY 的窗口 sink 反而可乱序并行——顺序由 source 端每 hash group 内重建。

## 25.1 执行器家族:两个类+回调注入

纠偏:执行器工厂只有两分支——`WindowExecutor`/`WindowAggregateExecutor`(physical_window.cpp:288-298);lead/lag/rank 的差异全部由 `WindowFunction` 回调(bounds/canstream/sink/finalize/evaluate)注入(window_function.hpp:108,137)。row_number 只需 PARTITION_BEGIN/END 边界;rank 是边界减法+NextRank 增量维护(window_rank_function.cpp:182-247)。**lead/lag 默认是 O(1) cursor 移位**,只有 IGNORE NULLS/非常量偏移/arg_orders/framing 才升级为 TokenTree+IndexTree 的 O(n log n) 论文算法(window_value_function.cpp:638-700);arg_orders 恰是分区排序前缀时两棵树直接省掉(:258-272)。

## 25.2 聚合窗口:五级阶梯

聚合窗口按 **Distinct→Constant→Custom→SegmentTree→Naive** 固定阶梯选择增量结构(window_aggregate_function.cpp:60-85);进入前 `SimplifyWindowedAggregate` 先剥修饰符(DISTINCT 可清则清、arg_orders 可清则清,:33-53)。SegmentTree 即 Leis 论文的增量树;Distinct 是 merge sort tree(注释引 ACM 论文);**EXCLUDE 不是行过滤**——是把帧切成最多 3 个有序子帧,段树用左右两份状态 combine(window_aggregator.hpp:32-81; window_segment_tree.cpp:447-468)。

## 25.3 规划期三分法与分组

规划期把窗口表达式分三类:streaming(可流式函数,如 row_number 常量向量递增)/partitioned(分区键全为单值常量,下推)/blocking;streaming 存在时 partitioned 全部降级 blocking(plan_window.cpp:41-59)。同组条件:分区等价 + ORDER BY 构成已有排序的**公共前缀**——`RANK() OVER (ORDER BY a)` 与 `SUM(x) OVER (ORDER BY a,b)` 会被拆成两个算子(:110-140);同组内相等且非 volatile 的表达式直接 CSE 复用列(:120-131)。

## 25.4 设计动机

1. **无独立排序算子**:sort 内嵌为 SortStrategy,省一次全量物化(physical_window.cpp:312-314);
2. **MASK 并行**:分区/peer 边界位图先算好,SINK/FINALIZE 阶段零比较(physical_window.cpp:556-577);
3. **回调注入**:函数差异全部在 WindowFunction 回调,Executor 不改(window_function.hpp:108);
4. **阶梯式增量结构**:按准入条件从 O(1) 到段树逐级升级,最贵路径最少用(window_aggregate_function.cpp:60-85);
5. **batch_index 归并**:并行 sink+保序输出两全(batch_base+块号,:1049);
6. **前缀共享分组**:共享排序前缀的窗口共用一个算子一次排序(plan_window.cpp:110-140)。

## 25.5 FAQ

**Q1:窗口排序是独立算子吗?**
不是,PhysicalWindow 内嵌 SortStrategy 四策略。

**Q2:什么情况窗口不能并行 sink?**
裸 OVER() 无分区无排序时(order-dependent)(physical_window.cpp:271-273)。

**Q3:lead/lag 是 O(n log n) 吗?**
默认 O(1) 移位;IGNORE NULLS 等复杂情况才走 TokenTree(window_value_function.cpp:695-700)。

**Q4:EXCLUDE 怎么实现?**
帧切成最多 3 个子帧分别聚合再 combine(window_aggregator.hpp:32-81)。

**Q5:聚合窗口用普通 AggregateFunction 吗?**
用,但按五级阶梯选增量结构,Naive 兜底(window_aggregate_function.cpp:60-85)。

**Q6:两个窗口表达式会共用排序吗?**
分区等价且 ORDER BY 是公共前缀才共用,否则拆算子(plan_window.cpp:110-140)。

**Q7:MASK 阶段算什么?**
partition_mask/order_mask 两张边界位图,后续阶段免比较(physical_window.cpp:556-577)。

**Q8:rank 怎么算?**
边界减法:帧内 (frame_peer_begin-frame_begin)+1(window_rank_function.cpp:182-193)。

**Q9:DENSE_RANK 支持参数排序吗?**
不支持 can_order_by(function/window/README.md:54)。

**Q10:窗口算子能流式吗?**
可流式函数(streaming)单独一类,其余 blocking/streaming 三分法(plan_window.cpp:41-59)。
