# 第 11 章 · 列存压缩算法族

> 基线:commit `7e886f44`。核心:src/storage/compression/ 目录。

## 11.0 全景:analyze→竞分→压缩 三阶段

```
内存段永远未压缩;checkpoint(行组重写)时:
 ① analyze:每个候选算法 init_analyze→逐 vector analyze(可提前出局)
 ② choose :final_analyze 返回"预估存储字节数",最小者胜出(force_compression 可覆盖)
 ③ compress:init_compression→逐 vector compress→finalize,段满换块落盘
段头布局通法:数据从头向后、元数据/字典从块尾向前生长,flush 时 memmove 压实
16 种 CompressionType:UNCOMPRESSED/RLE/BITPACKING/FSST/CHIMP/PATAS/ALP/ALPRD/
 ZSTD/ROARING/DICT_FSST…(CONSTANT/EMPTY 为 internal only 不进候选)
```

## 11.1 竞分:分数即预估字节数

打分口径各家用越来越贵的估法换准确度:定长=`sizeof(T)×count`;RLE=`(2+sizeof(T))×run 数`;bitpacking 用空 Writer **空转演练**累计 total_size;字典带 1.2 倍惩罚;FSST 最豪横——**真的建一次编码器试压缩**再采样外推;ZSTD=总串长/2 加惩罚;ALP 采样 8×32 个值试压 top-K 组合。框架把"是否划算"交给数据回答,新算法无痛加入候选表(compression_config.cpp:17-35)。

## 11.2 算法精读

- **Bitpacking**(整型通才,唯一带 FOR):每 2048 值一组四选一——CONSTANT/CONSTANT_DELTA/DELTA_FOR/FOR,位宽比较取 delta 位宽与 FOR 位宽的小者(bitpacking.cpp:273-301);元数据 (mode,offset) 打包成一个 u32 从块尾生长。
- **RLE**:值/计数双区;扫描亮点——**整个段的所有 run 只跑一次过滤**,结果缓存 matching_runs 位图,后续 vector 只查位图(rle.cpp:545-568);整 vector 落在单 run 内直接输出 CONSTANT_VECTOR。
- **dict_fsst**(v1.3 起字符串默认):一份数据三形态自适应——字典去重累计达 4096 字节阈值时决定是否对**字典本身**做 FSST;DICTIONARY(低基数,无符号表)/DICT_FSST(字典 FSST+串长位压缩+索引位压缩)/FSST_ONLY(全唯一省索引)三模式(dict_fsst/compression.cpp:34-52)。老 Dictionary/FSST 在 v1.3 目标下弃用仅保留读。
- **ALP/ALPRD**(现役浮点):ALP 把浮点按 (exponent,factor) "切割"成整数落入 FOR+位压缩,每 1024 值一组,v1.5 起压缩不划算的 vector 可回退未压缩(哨兵 0xFF);ALPRD 处理切不动的值:左右拆分+8 项小字典。**Chimp/Patas 已退役**(analyze 直接返回 nullptr),只留读路径。
- **ZSTD**:每 2048 值一块可跨块溢出;非内存库、v1.2+。
- **Roaring**:validity/BOOL 的容器压缩。

## 11.3 不解压过滤:四家特权

实现 filter 的只有 **RLE、dict_fsst、Constant、Empty**:RLE 把过滤对象从 N 行缩到 run 数;dict_fsst 对字典(≤基数项)做一次 FilterSelection,数据页只查位图(NULL 槽惰性求值);Constant 用 zone map 直接清零 selection;Empty 是空操作。其余算法退化为扫描后过滤。收益=提前剪掉的行数×上游算子成本——这些算法的压缩表示本身就是高阶摘要,过滤它们少一至两个数量级的比较。

## 11.4 设计动机

1. **竞分而非固定选择**:压缩率强依赖数据分布,同列不同段最优算法不同;分数即预估字节数;
2. **checkpoint 才压缩**:内存段要支持高频追加与回滚,变长布局无法就地追加;行组粒度重写让 analyze 看到完整数据;
3. **FSST 配字典**:FSST 不做去重,每段一张符号表的固定开销在低基数列不划算;dict_fsst 一份数据三形态;
4. **ALP 替代 Chimp/Patas**:预测编码解压必须顺序重放无法随机访问;ALP 落入成熟 FOR 路径天然随机访问且不划算可回退;
5. **相向生长+压实**:压缩过程无需预知最终大小;不值得压实就不压实(块×4/5 阈值);
6. **按存储版本门控**:读路径永不下线,写路径按目标版本收敛——兼容性与格式演进兼得。

## 11.5 FAQ

**Q1:为什么内存里的段不压缩?**
要支持高频追加与事务回滚;压缩推迟到 checkpoint 摊销。

**Q2:Bitpacking 的四种模式怎么选?**
按位宽:min-max 差与 delta 差的 MinimumBitWidth 取小(bitpacking.cpp:273-301)。

**Q3:字典压缩的 NULL 怎么处理?**
索引 0 保留给 NULL;dict_fsst 过滤时 NULL 槽惰性求值。

**Q4:Chimp 还能用吗?**
只能读旧库:analyze 已返回 nullptr,compress 抛 deprecated。

**Q5:哪些算法能不解压过滤?**
RLE/dict_fsst/Constant/Empty 四家;其余扫描后过滤。

**Q6:损坏文件会怎样?**
CompressionSegmentReader 带边界校验,统一抛 DataCorruptionException。

**Q7:validity 段也压缩吗?**
独立压缩;主算法自带 null 语义时直接 COMPRESSION_EMPTY。

**Q8:ZSTD 为什么限制字符串?**
当前实现只注册 VARCHAR 且非内存库(zstd.cpp:1082-1084)。

**Q9:force_compression 有什么用?**
调试/对比:清掉其他候选只留目标算法+UNCOMPRESSED 兜底。

**Q10:dict_fsst 的三模式何时确定?**
压缩中动态:字典累计 4096 字节阈值时决策(dict_fsst/compression.cpp:34-52)。

## 11.6 小结与深挖方向
