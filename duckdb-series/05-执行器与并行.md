# 第 05 章 · 执行器与并行:push-based pipeline 与线程调度

> 基线:commit `7e886f44`。核心目录 src/parallel/ 与 src/execution/。

## 5.0 全景:计划如何被切块并行

```
SELECT region,sum(amount) FROM orders GROUP BY region;
 Pipeline P1: TABLE_SCAN(source)→[filter]→ HASH_AGGREGATE(sink)
 Pipeline P2: HASH_AGGREGATE(source,物化后的HT)→ RESULT_SINK(sink)
 衔接:不靠数据队列,靠事件图——"我的 EXECUTE 依赖你的 COMPLETE"
      (pipeline_schedule.cpp:196-206:依赖在对方 sink Finalize 后才算满足)
线程池(每库一个,默认=核数):T0..Tn 各领 PipelineTask,各建 PipelineExecutor,
各自写 LocalSinkState → 全员 Combine → 单线程 Finalize → P2 调度
```

切块规则只有三条(physical_operator.cpp:245-275):叶子非 sink→当 source;**IsSink()→自己是上一段的 source、同时为子计划开新 MetaPipeline 并当子段 sink**;其余→挂 operator 向孩子递归。断点必落在"看完全部输入才能产出"的算子(聚合/排序/hash join build/结果收集器)。HashJoin 覆写:build 侧开子 MetaPipeline,build 喂得饱全部线程时依赖递归传播避免广度优先(physical_join.cpp:47-57)。

## 5.1 push 主循环

每条 pipeline 的每个并行任务持一个 PipelineExecutor,构造时预分配算子链每级中间 chunk 与 per-thread OperatorState(pipeline_executor.cpp:57-75)。常规路径:source 拉一个 chunk(FetchFromSource),`ExecutePushInternal` 沿链推入 sink(pipeline_executor.cpp:558-610);算子返回 HAVE_MORE_OUTPUT 时下标压入 `in_process_operators` 栈,下轮从栈顶恢复——这是**仅存的迭代器残留**,跨算子 pull 已不存在(:723-734 注释举例 join 剩余 tuples 必须先吐完)。sink 返回 BLOCKED 时任务整体泊车,恢复后断点续推(:612-647)。

收尾分两级:每线程 `Combine` 把 LocalSinkState 并入 Global(pipeline_executor.cpp:685-721);全局 `Finalize` 由 FINISH 事件触发、单线程(如物化聚合 HT)。含 DISTINCT 聚合时插入两级 finalize 事件(先并 distinct radix 表再常规 finalize,physical_hash_aggregate.cpp:584-689)。

## 5.2 Event/Task/线程池

每条 pipeline 展开五阶段:INITIALIZE→EXECUTE→PREPARE_FINISH→FINISH→COMPLETE(pipeline_schedule.cpp:108-120)。Event 是最小同步单元:FinishTask 原子递增,最后一个任务完成即 Finish 并通知父事件,依赖计数归零才 Schedule(event.cpp:14-64)。线程池**每数据库一个** TaskScheduler:worker 在 ExecuteForever 等信号量(空闲 0.5s 顺手 flush 分配器)、出队执行;TASK_BLOCKED 的任务 Deschedule 挂起待回调(task_scheduler.cpp:160-214)。任务队列按 producer token 隔离——一条查询的任务只被它自己及空闲 worker 消费;客户端线程也能 WorkOnTasks 认领,无空闲 worker 时仍能推进(executor.cpp:328-342)。

## 5.3 并行度:协商 + 动态领批

全局线程数默认核数,Linux 上被 SLURM/cgroup 配额修正(config.cpp:648-665),`SET threads` 覆盖。单 pipeline 并行度由 `TryGetMaxThreads` 协商:sink→source→逐算子的 MaxThreads 逐级收窄(pipeline.cpp:118-157);任一环节不支持并行则整条退化为单任务。扫描侧**持锁动态领批**:local state 在 AssignTask 里领一段 chunk 区间并分配递增 batch_index(physical_column_data_scan.cpp:112-128)——慢线程不拖累整体,倾斜自动再平衡;batch_index 兼做保序归并的键。

## 5.4 算子侧:Sink/Combine/Finalize 三相

并发约定写在头文件(physical_operator.hpp:200-215):Sink 可多线程并发(注意锁 Global);Combine 在单线程完成自己部分后调;Finalize 全 barrier 后单线程每 pipeline 一次。PhysicalHashAggregate:Sink 把聚合子列**按引用**装进线程局部 radix 分区;Combine 合局部 HT;Finalize 单线程物化;随后作为下条 pipeline 的 source,按 HT 分区数给并行度、原子 state_index 动态分工(physical_hash_aggregate.cpp:503-860)。PhysicalHashJoin:build 侧独立 pipeline,默认超 100 万行(PARALLEL_CONSTRUCT_THRESHOLD)才并行构造全局 HT,key 倾斜回退单线程(physical_hash_join.cpp:840-872);probe 用共享 HT 当中间算子。

## 5.5 设计动机

1. **push-based**:避免每算子实现可重入迭代器;sink 是天然汇聚点,多线程各推局部状态即可;
2. **按 sink 断开**:阻塞边界显式化为事件依赖,段内任意并行、段间一个 Finalize 栅栏,无需跨段数据队列与反压协议;
3. **local/global 分离**:并发面压到最小,还给内存规划明确挂点(PrepareFinalize 上报);
4. **finalize 单独成阶段**:缩短临界区,允许插入多级事件与兄弟 pipeline 的内存排序约束;
5. **动态领批**:抗倾斜;batch_index 兼顾乱序容忍与保序。

## 5.6 FAQ

**Q1:join build 为什么先于 probe?**
probe 需要 HT:build 侧 Finalize 完成(事件 COMPLETE)后 probe 的 EXECUTE 才被调度。

**Q2:线程数怎么定?**
默认核数,容器里按 cgroup/SLURM 修正(config.cpp:648-665)。

**Q3:结果怎么保序?**
ORDER BY 计划走 SOURCE_ORDERED 收集器且 sink 强制单线程;并行流靠 batch_index 归并(physical_result_collector.cpp:23-37)。

**Q4:一个 chunk 在算子间会拷贝吗?**
尽量引用传递;窄化场景由 CachingPhysicalOperator 合并小 chunk(physical_operator.cpp:352-434)。

**Q5:出错时正在跑的任务怎么办?**
PushError 置中断并解除泊车,CancelTasks 排干(executor.cpp:555-564,278-326)。

**Q6:聚合 HT 会被扫两次吗?**
不是:P1 写 HT(sink),P2 把 HT 当 source 并行读——同一对象两种角色。

**Q7:小查询会起多线程吗?**
不一定:TryGetMaxThreads 协商失败或基数小时退单任务。

**Q8:流式结果背压怎么处理?**
producer 任务泊车(parked producer),消费端取数唤醒(physical_result_sink.cpp:254-260)。

**Q9:partial 任务的粒度?**
PROCESS_PARTIAL 每次最多 50 chunk,未完重新排队(pipeline.hpp:49)。

**Q10:算子能拒绝并行吗?**
能:ParallelSource/ParallelSink 任一为假即整条单任务(pipeline.cpp:118-128)。
