## 0. 总览:一次 checkpoint 中的三阶段选型与压缩

DuckDB 的内存内 segment 始终以未压缩形态追加;只有在 checkpoint(行组重写)时才做"分析→竞分→压缩"。整体流水线(`src/storage/table/column_data_checkpointer.cpp`):

```
 RowGroup 的内存 segments
        │ ColumnDataCheckpointer::Checkpoint()          checkpointer.cpp:411
        ├─ 无任何变更? ──► 只写元数据,旧块原样保留            checkpointer.cpp:421-432
        ▼ WriteToDisk()                                  checkpointer.cpp:310
 ┌───────────────────────────────────────────────────────────────┐
 │ ① analyze  : 对每个候选算法 init_analyze → 逐 vector analyze;  │
 │              算法可提前返回 false 出局                          │
 │ ② choose   : final_analyze 返回"预估字节数",最小者胜出          │
 │              (可被 force_compression 设置强行指定)              │
 │ ③ compress : init_compression → 逐 vector compress →           │
 │              compress_finalize,段满即换段落盘                   │
 └───────────────────────────────────────────────────────────────┘
        ▼
 每列得到若干"压缩段"(一列可混用同算法的多个 256KB 块),
 validity 单独压缩;若主算法自带 validity(如 dict_fsst)则 validity 段写 COMPRESSION_EMPTY
```

各算法的段头布局(压缩后的一个 block 内,均以"数据从头向后、元数据/字典从块尾向前生长,flush 时 memmove 压实"为通法):

```
RLE:        [rle_count_offset:u64][value T × n ......][run_count u16 × n]     rle.cpp:124,206
Bitpacking: [header:u64=metadata_end][grp0|grp1|...][metaN-1 ... meta0]      bitpacking.cpp:532-556
            meta = (mode<<24)|offset,每 2048 值一个组,组内 32 值一个算法块     bitpacking.cpp:28-49
Dictionary: [header:20B][selection buffer 位压缩][index buffer u32×k][字典串]  dictionary/common.hpp:10-16
dict_fsst:  [header][字典串][FSST 符号表?][串长 位压缩][字典索引 位压缩]        dict_fsst/compression.cpp:100-110
FSST:       [header:16B][索引位压缩][压缩串字典][FSST 符号表]                  common/fsst.hpp:22-29
ALP:        [metadata_pointer:u32][vector 数据 ...][反向偏移表]               alp_scan.hpp:99-108
ZSTD:       [vector 元数据表][lengths u32[]|压缩数据](可溢出到额外块)         zstd.cpp:17-36
```

## 1. 框架:CompressionFunction 函数表

每个算法 × 物理类型实例化出一个 `CompressionFunction`,本质是一张 C 函数指针表(`src/include/duckdb/function/compression_function.hpp:208-231`):

- **analyze 三件套**:`init_analyze / analyze / final_analyze`(compression_function.hpp:139-141)。注释明确三步协议:analyze 返回 false 即出局,final_analyze 返回分数,"ideally this is the exact number of bytes"(compression_function.hpp:245-249)。
- **compress 三件套**:`init_compression / compress / compress_finalize`(compression_function.hpp:146-149)。
- **扫描族**:`init_scan / scan_vector / scan_partial / select / filter / fetch_row / skip / init_prefetch`(compression_function.hpp:154-176)。
- **可选扩展**:`init_segment/init_append/append/...`(未压缩段就地追加,compression_function.hpp:181-187)、`serialize_state/deserialize_state/visit_block_ids`(ZSTD 等溢出块元数据,compression_function.hpp:193-197)、`get_segment_info`(PRAGMA storage_info,compression_function.hpp:203)。
- `validity` 字段:`REQUIRES_VALIDITY` 或 `NO_VALIDITY_REQUIRED`(compression_function.hpp:312),dict_fsst 设为后者(dict_fsst.cpp:283)。

`CompressionType` 全列表(`src/include/duckdb/common/enums/compression_type.hpp:19-37`,共 16 项):

| 枚举 | 一句话 |
|---|---|
| AUTO(0) | 占位:由竞分决定,非真实算法 |
| UNCOMPRESSED(1) | 定长/字符串/validity 的原样存储,兜底选项 |
| CONSTANT(2) | internal only:整段单值,值取自 min 统计 |

| CHIMP(8) / PATAS(9) | 浮点预测压缩,均已退役,仅保留读路径 |

注册表与候选过滤在 `src/function/compression_config.cpp:17-35`(14 个方法入口)与 `compression_config.cpp:114-132`:CONSTANT/EMPTY 不进入候选(`EmitCompressionFunction` 对其返回 false),它们只由系统内部产生。构造时按 19 种物理类型逐一生成函数表(compression_config.cpp:86-112)。

## 2. 选型:ColumnDataCheckpointer 的 analyze 竞分

`DetectBestCompressionMethod`(`src/storage/table/column_data_checkpointer.cpp:172-271`)是选型核心:

1. 若设置了 `force_compression`,先清掉其他候选只留目标算法与 UNCOMPRESSED 兜底(checkpointer.cpp:117-152)。
2. `InitAnalyze` 对每个候选调用 `init_analyze`——它可以返回 nullptr 直接弃权(如老版本目标下的 dict_fsst,dict_fsst.cpp:71-79)。
3. `ScanSegments` 逐 vector 喂给所有存活候选;`analyze` 返回 false 就把 state 置空出局(checkpointer.cpp:194-211)。
4. 打分与比较(checkpointer.cpp:226-254):

```cpp
auto score = function->final_analyze(*state);
//! The finalize method can return this value ... to indicate it should not be used.
if (score == DConstants::INVALID_INDEX) {
    continue;
}
if (score < best_score || forced_method_found) {
    compression_idx = j;
    best_score = score;
    chosen_state = std::move(state);
}
```

各家打分口径(全部是"预估存储字节数",越小越好):定长未压缩就是 `sizeof(T)*count`(fixed_size_uncompressed.cpp:37-40);RLE 是 `(2+sizeof(T))*seen_count`(rle.cpp:114-118);bitpacking 在 analyze 时用空 Writer 演练 Flush 累计 `total_size`(bitpacking.cpp:380-387);字典用 `RequiredSpace × 1.2 压缩比惩罚`(dictionary_compression.cpp:85-98,比例常量在 dictionary/common.hpp:20);FSST 真的试压缩采样串再外推(fsst.cpp:150-204);ZSTD 用 `总串长/2` 加惩罚(zstd.cpp:191-208);ALP 对采样向量试压缩逐 vector 累加(alp_analyze.hpp:153-183)。

两个细节:主算法声明 `NO_VALIDITY_REQUIRED`(dict_fsst)时,validity 段直接改用 COMPRESSION_EMPTY 省掉一个空段(checkpointer.cpp:301-321);若所有候选都被淘汰则抛 FatalException(checkpointer.cpp:258-261)。

### 3.1 Uncompressed(constant 之外的三种形态)

`UncompressedFun::GetFunction` 按物理类型分发:定长类型走 `FixedSizeUncompressed`,BIT 走 `ValidityUncompressed`,VARCHAR 走 `StringUncompressed`(uncompressed.cpp:6-31)。

- 定长:analyze 得分即 `sizeof(T)*count`;扫描是纯 `memcpy`/零拷贝——`FixedSizeScan` 直接把 `reader.GetArraySlice<T>` 的视图 `SetData` 进结果向量,连拷贝都省了(fixed_size_uncompressed.cpp:177-186)。它还是唯一保留 `append` 函数族的算法(fixed_size_uncompressed.cpp:280-288),内存段追加复用同一条路径。
- 字符串:块内是 `[长度偏移 i32×n][串数据]`,偏移为负表示大串溢出到其他块,负偏移长度用 `std::abs` 差分求出(string_uncompressed.cpp:92-113);打分 `count*4 + 总串长 + 溢出标记`(string_uncompressed.cpp:60-63);头部仅 8 字节 DICTIONARY_HEADER_SIZE(上卷 E1 详述,string_uncompressed.hpp:53-59)。
- validity:纯位图扫描,`AlignedScan/UnalignedScan` 处理非对齐段首(validity_uncompressed.cpp:238,454,639)。

### 3.2 Constant 与 Empty(退化段)

- CONSTANT 是 internal only,函数表里 analyze/compress 全为 nullptr(numeric_constant.cpp:335-340):段值直接从段统计的 min 读出并输出 CONSTANT_VECTOR(numeric_constant.cpp:242-250)。
- COMPRESSION_EMPTY 的压缩态只累计 count 与非空数,最终 flush 一个 **0 字节段**(empty_validity.hpp:53-74);扫描/过滤/fetch 全是空操作(empty_validity.hpp:78-99)——"这段什么都不存"本身就是信息。

### 3.3 RLE

计数 `rle_count_t = uint16_t`(rle.cpp:15),因此一个行程最多 65535 值,`RLEState::Update` 对 2^16 恰好重复的边界做了 `last_seen_count=0` 特判(rle.cpp:44-83)。analyze 用同一个 `RLEState` 空转统计 `seen_count`,得分 `(2+sizeof(T))*seen_count`(rle.cpp:114-118)。

压缩时值与计数先分区写:`values` 从 header 后向后、`run_counts` 预留在 `max_rle_count` 之后(rle.cpp:165-172);`FlushSegment` 把计数 memmove 紧贴值区、对齐,并把 `rle_count_offset(u64)` 存进段头(rle.cpp:192-209)。

扫描侧的亮点:
- 若当前 vector 整段落在单个 run 内,直接输出 CONSTANT_VECTOR 而非逐值填充(rle.cpp:421-448);
- `RLEFilter` 对**整个段的所有 run 只跑一次过滤**,结果缓存进 `matching_runs` 位图,后续 vector 只查位图(rle.cpp:545-568):

```cpp
if (!scan_state.matching_runs) {
    // we haven't applied the filter yet
    // apply the filter to all RLE values at once
    auto total_run_count = scan_state.layout.ValidateAllRuns();
    ...
    ColumnSegment::FilterSelection(run_matches, run_vector, filter_state, total_run_count,
                                   scan_state.matching_run_count);
```

- 读盘时按段内 `segment_count` 逐 run 校验(run_count 超出剩余行数即 DataCorruptionException,rle.cpp:301-313)。
- 点查 `RLEFetchRow` 不建索引:临时构造扫描状态 `Skip(row_index)` 后取当前 run 值(rle.cpp:649-661),`RLESelect` 同理依赖 selection 有序的前提,乱序直接抛 InternalException(rle.cpp:520-524)。
- BOOL 类型的 RLE 显式把 filter 置空(rle.cpp:678-682);LIST 走 uint64 且不写统计(rle.cpp:707-708)。

### 3.4 Bitpacking

组参数:算法块 32 值(common/bitpacking.hpp:29),元数据组 `BITPACKING_METADATA_GROUP_SIZE = max(STANDARD_VECTOR_SIZE,2048)`(bitpacking.cpp:28),段头 8 字节(common/bitpacking.hpp:30)。这是唯一带 **FOR 编码** 的整型通才:每个元数据组在 Flush 时四选一(bitpacking.cpp:252-314):

1. 全 NULL 或 max==min → CONSTANT(只存 1 值);
2. delta 为常数 → CONSTANT_DELTA(存 frame + 步长);
3. delta 位宽 < FOR 位宽 → DELTA_FOR(frame + width + delta_offset + 位压缩 delta);
4. 否则 → FOR(minimum 作 frame,width 位压缩)。

位宽选择即 `MinimumBitWidth(min_max_diff)` 与 `MinimumBitWidth(min_max_delta_diff)` 的比较,取小者(bitpacking.cpp:273-301)。元数据 `(mode,offset)` 编码为一个 u32,`mode<<24 | offset`(bitpacking.cpp:37-49),从块尾向下生长(bitpacking.cpp:475-479),flush 时压实并把总偏移存段头(bitpacking.cpp:553-555)。

analyze 阶段同样空转演练;若 `类型大小×2048×2 > 块大小` 直接出局(bitpacking.cpp:361-368)。扫描时整组解到 `decompression_buffer[2048]`,仅当对齐整算法块时才直接解进结果向量(bitpacking.cpp:1038-1047);DELTA_FOR 跳读必须顺序重放 delta(bitpacking.cpp:926-951)。点查 `BitpackingFetchRow` 用 `Skip(row_index)` 定位组后按模式取值:CONSTANT 取常量、CONSTANT_DELTA 用 `constant*offset+frame` 乘法、FOR/DELTA_FOR 解一个算法块再加 frame/delta_offset(bitpacking.cpp:1098-1127)。**无 filter/select**:函数表止步于 fetch_row/skip(bitpacking.cpp:1167-1175)。hugeint/uhugeint 由 `bitpacking_hugeint.cpp` 提供跨 32 位字的位级 Unpack 特化(bitpacking_hugeint.cpp:10-60)。

### 3.5 Dictionary 与 FSST / Dict_FSST(字符串三连)

老版 Dictionary 段布局见源码顶部 ASCII 注释(dictionary_compression.cpp:14-44):`[header][selection buffer][index buffer][字典串]`,字典串从块尾向下生长,索引 0 保留给 NULL(dictionary/compression.cpp:26-27),新词 `next_width = MinimumBitWidth(index_buffer.size())` 逐步加宽(dictionary/compression.cpp:100-103);Finalize 时位压缩 selection buffer、写 index buffer 与宽度、memmove 字典压实(dictionary/compression.cpp:115-170)。大串(≥块限制)直接让 analyze 出局(dictionary/common.hpp:45-48)。

FSST(v1.3 前的字符串压缩冠军)analyze 最"豪横":以 25% 概率采样(fsst.cpp:38,120),`final_analyze` **真的建一次 FSST 编码器并试压缩**,估算每段一个符号表的摊销后再乘 1.2 惩罚(fsst.cpp:150-204);符号表 `duckdb_fsst_decoder_t` 按段存储(fsst.cpp:352-356),段头 16 字节(common/fsst.hpp:22-29)。底层实现在 `third_party/fsst/libfsst.cpp`,接口 `duckdb_fsst_create/duckdb_fsst_compress`(third_party/fsst/fsst.h:108,154)。

dict_fsst(v1.3 起的默认,dict_fsst.cpp:71-79 版本门控)统一了两者:段布局为 `[header][字典][符号表?][串长位压缩][索引位压缩]`(dict_fsst/compression.cpp:100-110),段头含 `mode` 字段(common.hpp:20-27)。三种模式在压缩中动态决定:字典去重累计达 `DICTIONARY_ENCODE_THRESHOLD = 4096` 字节时决定是否对字典做 FSST 编码(dict_fsst/compression.cpp:34-52):

```cpp
static DictFSSTMode ConvertToMode(DictionaryAppendState &state) {
    switch (state) {
    case DictionaryAppendState::ENCODED:          return DictFSSTMode::DICT_FSST;
    case DictionaryAppendState::REGULAR:
    case DictionaryAppendState::NOT_ENCODED:      return DictFSSTMode::DICTIONARY;
    case DictionaryAppendState::ENCODED_ALL_UNIQUE: return DictFSSTMode::FSST_ONLY;
```

- DICTIONARY:字典原样存,退化为老字典编码(无符号表,dict_fsst/compression.cpp:75-77);
- DICT_FSST:字典串 FSST 压缩,另存串长位压缩数组与符号表;
- FSST_ONLY:全唯一时连索引都省掉(`dictionary_indices_space == 0`,dict_fsst/compression.cpp:69-71)。
- analyze 侧:单串超过 `STRING_SIZE_LIMIT=16384`(common.hpp:41)出局;FSST 最坏情形按 2 倍膨胀预留(analyze.cpp:8-13,66-74);打分粗暴地取 `total_string_length/2`(analyze.cpp:80-82)。
- 扫描时 `duckdb_fsst_import` 载入符号表(dict_fsst/decompression.cpp:87-90),短串直接在栈上解码,长串走 StringVector 分配器(decompression.cpp:34-36);整 vector 可解成 DictionaryVector 复用(dict_fsst.cpp:136-141)。

### 3.6 ZSTD

仅 VARCHAR(zstd.cpp:1082-1084),每 2048 值一块(`ZSTD_VECTOR_SIZE`,zstd.cpp:42),块内 `[page_id/page_offset/uncompressed_size/compressed_size 的 vector 元数据表][lengths+压缩数据]`,放不下可溢出到额外块并由 `visit_block_ids` 跟踪(zstd.cpp:17-36,94-98)。打分 = `总串长/2` + 长度数组 + 元数据,再乘平均串长是否过阈值的惩罚(不过阈值罚 1000 倍,"仍然可以被强制使用",zstd.cpp:191-208)。内存库禁用、v1.2.0 前禁用(zstd.cpp:144-151)。

### 3.7 Chimp / Patas(已退役)与 ALP / ALPRD(现役浮点)

**Chimp 与 Patas 的 analyze 已被砍**:`ChimpInitAnalyze`/`PatasInitAnalyze` 直接 `return nullptr`(chimp_analyze.hpp:18-21;patas_analyze.hpp:21-25),compress 路径抛 "has been deprecated"(chimp_compress.hpp:24-39)。它们只保留读路径以兼容旧库:Chimp 每 1024 值一组,`[flag 流][leading-zero 块][packed data]` 元数据自块尾反向读取(chimp.hpp:32-36;chimp_scan.hpp:184-201);Patas 函数表仍注册 float/double(patas.cpp:16-33)。

**ALP** 是现役 double/浮点压缩:把浮点按 `(exponent, factor)` "切割"成整数,每 1024 值一个 vector,异常值例外。采样参数写死在常量里——每行组采 8 个 vector、每 vector 采 32 值(alp_constants.hpp:28-31);`FindTopKCombinations` 找 top-K 组合并对完整采样向量试压缩估大小(alp_analyze.hpp:153-163);当压缩不划算时,**从 v1.5 起允许该 vector 回退未压缩存储**——exponent 写入哨兵 `UNCOMPRESSED_MODE_SENTINEL = 0xFF`(alp_constants.hpp:36-37;alp_scan.hpp:204)。段布局为 `[metadata_pointer][vector 数据...][反向偏移表]`,每个 vector 的元数据含 exponent/factor/异常数/FOR/bit_width(alp_scan.hpp:70-84)。

**ALPRD** 处理难切割的浮点:值拆左右两半,左半用 ≤8 项的小字典(`MAX_DICTIONARY_BIT_WIDTH = 3`,alprd_constants.hpp:27-28),右半位压缩,异常表修正;函数表与 ALP 同构,仅 float/double(alprd.cpp:57-79)。

### 3.8 Roaring(validity/BOOL)

 roaring 把 validity 位图转成 bool 向量后按 roaring 容器压缩:analyze 统计 zero/one/run/array/bitset 容器数与每段占用(roaring/analyze.cpp:100-122),BIT 与 BOOL 两条特化路径(roaring/common.cpp:320-345)。它同样没有 filter/select。

## 4. filter 下推:谁能"不解压就过滤"

实现 `filter` 函数指针的只有四家(全仓 grep `\.filter = `):**RLE、dict_fsst、Constant、Empty**;bitpacking/ALP/ALPRD/roaring/zstd/未压缩族均无,由上层退化为"扫描后过滤"(dict_fsst.cpp:236-237 的 fallback 即此形态)。

- **RLE**:过滤对象是 run 值数组(基数远小于行数),结果缓存 `matching_runs` 一次算全程(rle.cpp:545-612);带既有 selection 时走逐行合并的慢路径(rle.cpp:613-637)。
- **dict_fsst**:对字典(≤ dict_count 项)做一次 `FilterSelection`,行通过 `dict_sel` 查 `filter_result` 位图;槽 0 是 NULL,仅当确有行引用它才惰性求值 NULL 过滤(dict_fsst.cpp:184-232)——字符串比较发生在**未解压**的字典向量上(FSST 模式下字典已是解压后的原文字典,`AllowDictionaryScan` 保证)。
- **Constant**:利用段统计判定 `filters_nulls/filters_valid_values`,直接 `sel_count = 0` 或保持常量输出,完全不解压(numeric_constant.cpp:296-320);NULL 语义由表达式分析静态判定(numeric_constant.cpp:31-69)。
- **Empty**:filter 为空操作——全 NULL 或全非 NULL 段的正确性由 zone map 统计保证(empty_validity.hpp:96-99)。

## 5. 压缩段扫描基础设施

上层扫描器对压缩段是无感的:它只调用函数表里的 `init_scan → scan_vector/scan_partial/select/filter/fetch_row`。一次典型顺序扫描的时间线:

```
ColumnScanner                     压缩段(block 已 pin 为 BufferHandle)
     │ init_scan ────────────────► 构造 XxxScanState:解析段头/元数据表,全部过校验
     │ scan_vector(count=2048) ──► 按算法解压/物化一个 vector
     │        │                       ├─ 常量段: SetVectorType(CONSTANT_VECTOR)
     │        │                       ├─ 字典段: 输出 DictionaryVector + sel
     │        │                       └─ 其他:   解压缓冲 → memcpy/直解
     │ filter(可选) ─────────────► RLE/dict_fsst/constant 在压缩表示上剪枝
     │ skip(n) ──────────────────► RLE 沿 run、BP 跨组直达、ZSTD 空操作
     ▼ 重复直到段尾
```

`CompressionSegmentReader`(src/include/duckdb/storage/compression/compression_segment_reader.hpp:24)是本代重写引入的**带边界检查的非拥有视图**:`Read/Get/GetArray/GetArraySlice/ReadSubReader` 全部走 `CheckForwardRead/CheckRange/CheckArray`(compression_segment_reader.hpp:207-226),配合各算法的 `ThrowXxxCorrupted` DataCorruptionException(rle.cpp:248-259、bitpacking.cpp:51-82、alprd.cpp:8-54),把"损坏文件"从越界读变成受控异常。

每个算法的扫描状态都持有 pin 住的 `BufferHandle` + 一块**解压缓冲**:

- Bitpacking:`T decompression_buffer[2048]`(bitpacking.cpp:727),整组解压后 memcpy 切片,对齐时直解进结果(bitpacking.cpp:1038-1047);
- ALP:`decoded_values/exceptions/for_encoded[1024]` 三个栈上缓冲(alp_scan.hpp:64-78);
- RLE:校验后的 `values/run_counts` 视图(rle.cpp:327-340);
- 字符串族:`CompressedStringScanState` 可把一整个 vector 解成 **DictionaryVector**(去重后 1024 行引用同一字典向量,dictionary/decompression.cpp:183;dictionary_compression.cpp:140-144)。

"跳过"语义按算法能力分层:RLE 沿 run 前进(rle.cpp:358-374),Bitpacking 非增量模式可跨组直达(bitpacking.cpp:880-908),ZSTD 的 skip 干脆是 NO OP(zstd.cpp:87-89,依赖上层按 vector 对齐)。

## 6. 设计动机

1. **为什么 analyze 竞分而非固定选择**:压缩率强依赖数据分布,同一列不同段的最优算法不同;框架把"是否划算"交给数据本身回答——分数即预估字节数(compression_function.hpp:245-249),各家用越来越贵的估法换取准确度:RLE 数行程、bitpacking 空转演练、FSST 真试压缩+25% 采样外推(fsst.cpp:150-204)、ALP 采样 top-K 组合试压(alp_analyze.hpp:157-163)。竞分让新算法可以无痛加入候选表(compression_config.cpp:17-35)。
2. **为什么 checkpoint 才压缩**:内存中的 segment 要支持高频追加与事务回滚,压缩格式的变长布局无法就地追加;行组粒度重写让 analyze 能看到完整数据再决策,且压缩成本摊销到 checkpoint 一次性付出。无变更时直接保留旧块只写元数据(checkpointer.cpp:421-432),避免无谓重压。
3. **为什么 FSST 要配字典(dict_fsst)**:FSST 擅长压串内容但不做去重,每段一个符号表的固定开销在低基数列上不划算;老 FSST 每串一条索引 + 每段一张表(fsst.cpp:199-201)。dict_fsst 保留字典去重(索引位压缩仅 `log2(基数)` 位),达到 4096 字节阈值才决定是否对**字典本身**做 FSST(dict_fsst/compression.cpp:34-52);全唯一时退化 FSST_ONLY 省掉索引(dict_fsst/compression.cpp:69-71),低基数时退化纯 DICTIONARY 省掉符号表——一份数据三种形态自适应。
4. **为什么 ALP 替代 Chimp/Patas**:Chimp/Patas 的预测编码对标预测无误时近乎零成本,但解压必须顺序重放、无法随机访问,官方最终将其 analyze 置空退役(chimp_analyze.hpp:18-21);ALP 把浮点"切割"成整数后落入成熟的 FOR+位压缩路径,天然支持按 1024-vector 随机访问,且 v1.5 起对不划算的 vector 回退未压缩(alp_scan.hpp:204),压缩不了也不亏。ALPRD 用左右拆分+8 项小字典兜住 ALP 切不动的值(alprd_constants.hpp:27-28)。
5. **为什么支持不解压过滤**:过滤下推的收益 = 提前剪掉的行数 × 上游算子成本。RLE 把过滤对象从 N 行缩到 seen_count 个 run 且结果跨 vector 复用(rle.cpp:545-568);dict_fsst 缩到 dict_count 个字典项(dict_fsst.cpp:184-203);Constant 干脆用 zone map 语义直接清零 selection(numeric_constant.cpp:303-318)。这些算法的"压缩表示本身就是高阶摘要",过滤它们比解压后过滤少一至两个数量级的比较次数。
6. **为什么数据/元数据相向生长、flush 时压实**:块内数据从头向后、元数据/字典从块尾向前,压缩过程中无需预知最终大小;flush 时 `memmove` 压实并对齐,把段尾空洞还给下一个段(统一模式见 rle.cpp:192-209、bitpacking.cpp:532-556、dictionary/compression.cpp:157-169)。`GetCompactionFlushLimit = 块大小×4/5`(compression_info.hpp:22-24)决定"不值得压实就不压实"。
7. **为什么算法按存储版本门控**:dict_fsst≥v1.3(dict_fsst.cpp:71-79)、zstd≥v1.2(zstd.cpp:148-151)、老字典/FSST 在 v1.3 目标下弃用(dictionary_compression.cpp:70-78;fsst.cpp:99-107)。读路径永不下线(旧文件可读),写路径按目标版本收敛,兼顾兼容性与格式演进。
