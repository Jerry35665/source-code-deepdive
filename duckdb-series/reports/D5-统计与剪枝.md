# 报告 D5 · 统计传播与 zone map 剪枝(DuckDB 卷四)

> 基线:7e886f44——DuckDB 用同一套 `BaseStatistics` 贯穿优化器(统计传播删恒真/恒假、收紧 min/max、反哺执行器)与执行层(row group/segment 两层 zone map 剪枝 + join build 侧注入的运行时动态过滤),本报告核实这条"统计在优化与执行之间联动链"的全部关键源码。

## 1. 总览:同一套统计,两条消费链路

统计系统的类型中枢是 `StatisticsType`,共 8 类,嵌套类型(STRUCT/LIST/ARRAY)靠子统计递归表达:

```cpp
// src/include/duckdb/storage/statistics/base_statistics.hpp:38-47
enum class StatisticsType : uint8_t {
    NUMERIC_STATS, STRING_STATS, LIST_STATS, STRUCT_STATS,
    BASE_STATS, ARRAY_STATS, GEOMETRY_STATS, VARIANT_STATS
};
// base_statistics.hpp:165-189:字段只有 type、has_null、has_no_null、
// distinct_count、stats_union(numeric/string/geometry/variant 四选一)、
// extra_data、child_stats(unsafe_unique_array<BaseStatistics>)
```

两条消费链路共享这套对象:

- ①优化期:`StatisticsPropagator` 在逻辑计划上传播(卷一 D 篇只给了 45 pass 总览,本卷展开联动细节);
- ②执行期:存储层用逐 row group、逐 segment 的统计做 zone map 剪枝(卷二 09 讲 append/checkpoint 写入端如何生成 `SegmentStatistics`,本卷只讲查询期消费端)。

优化器拿到的列统计是"全表合并值"的拷贝,而非任一 row group 的值:

- `DuckTableEntry::GetStatistics` 转 `DataTable::GetStatistics`(src/storage/data_table.cpp:1560-1565,内部 `row_groups->CopyStats(column_id)`);
- 基础表扫描函数挂接 `scan_function.statistics_extended = TableScanStatistics`(src/function/table/table_scan.cpp:1150;实现 :992-1007,rowid/row number/生成列返回 nullptr);
- distinct 统计独立存放:`DataTable::SetDistinct`(data_table.cpp:1567-1570)。

传播有两个入口:主入口走优化器流程的 STATISTICS_PROPAGATION pass;副入口 `FilterStatisticsOptimizer` 以 `FILTER_SIMPLIFICATION` 模式运行,专门简化跨多表 binding 的 filter 并据此重跑 filter pushdown(src/optimizer/filter_statistics.cpp:37-75;模式枚举见 src/include/duckdb/optimizer/statistics_propagator.hpp:30)。

## 2. BaseStatistics 类型体系:有效位、min/max、截断字符串与递归子统计

数值统计核心是 `NumericStatsData{has_min, has_max, min, max}`,min/max 存在 `NumericValueUnion` 中(src/include/duckdb/storage/statistics/numeric_stats.hpp:24-33);`CheckZonemap(stats, comparison_type, constants)` 直接对常量与 [min,max] 做区间判定(numeric_stats.hpp:73-74)。字符串统计没有"contains 位图",实际字段是截断 min/max + unicode 标志 + 三种长度统计:

```cpp
// src/include/duckdb/storage/statistics/string_stats.hpp:26-34,56-59
enum class StringStatsType {
    NO_STATS, EMPTY_STATS, EXACT_STATS, TRUNCATED_STATS
};
struct StringStatsData {
    constexpr static uint32_t CURRENT_MAX_STRING_MINMAX_SIZE = 12;  // min/max 最多存 12 字节
    string_t min;      // 依 min_type 可能被截断
    string_t max;      // 依 max_type 可能被截断
    bool has_unicode;  // 是否可能含 unicode
    // has_max/min_string_length、total_string_length(总字节数)亦有
    StringStatsType min_type;
    StringStatsType max_type;
};
```

嵌套类型的组织方式:

- `StructStats::GetChildStats(stats, i)` 按子列下标取统计(src/include/duckdb/storage/statistics/struct_stats.hpp:28-32);
- `PushdownExtract` 支持对 struct 子列直接下推抽取(struct_stats.hpp:45-46;消费见 src/storage/table/column_data.cpp:515-523,`StorageIndex::IsPushdownExtract` 时抽子统计再检查);
- `ListStats` 只有单一子统计(list_stats.hpp:27-29),list_entry_t 的 min/max 更新被显式置空(base_statistics.hpp:191-193);
- 没有 JSON 统计类型;最新增的类型是 VARIANT 统计,携带 shredding 状态(src/include/duckdb/storage/statistics/variant_stats.hpp:14-26)。

有效位状态机 `StatsInfo`(base_statistics.hpp:30-36)是 Filter 收紧的主要落点:普通比较可断言列不再含 NULL(propagate_filter.cpp:51-56);空值性经 `CombineValidity`/`CopyValidity` 在表达式推导中传播(base_statistics.hpp:106-107)。struct 的第一"子列"即 validity 统计的挂靠处:validity 的 zone 检查走 `child_states[0]`(column_data.cpp:57)。

## 3. statistics_propagator:入口、statistics_map 与 Filter 收紧

主入口在优化器流程中段:STATISTICS_PROPAGATION pass 构造 propagator 并 `PropagateStatistics(plan)`(src/optimizer/optimizer.cpp:457-463;若计划含 DML CTE 则整体跳过,:456)。产出的 statistics_map 随后被复用:MultiStageAggregateRewriter 与 ProjectionPlacement(optimizer.cpp:465-478),删除过表达式则重跑 UNUSED_COLUMNS(optimizer.cpp:494-499)。传播按算子类型分发(statistics_propagator.cpp:47-104,未覆盖的类型走默认 `PropagateChildren`),每个实现都先递归子节点再处理本节点——所谓"自底向上"实为后序遍历,statistics_map(`column_binding_map_t<unique_ptr<BaseStatistics>>`,statistics_propagator.hpp:155)自叶向根累积。Filter 收紧的核心规则:

```cpp
// src/optimizer/statistics/operator/propagate_filter.cpp:51-86(X </> / = 常量)
if (!IsCompareDistinct(comparison_type))
    stats.Set(StatsInfo::CANNOT_HAVE_NULL_VALUES);   // 普通比较 ⇒ 列不再含 NULL
if (!stats.GetType().IsNumeric()) return;            // 非(57-59 行)数值列直接放弃
if (!NumericStats::HasMinMax(stats)) return;
// ... switch:
case COMPARE_LESSTHAN / LESSTHANOREQUALTO:
    NumericStats::SetMax(stats, constant);           // X < C ⇒ max 收到 C
case COMPARE_GREATERTHAN / GREATERTHANOREQUALTO:
    NumericStats::SetMin(stats, constant);           // X > C ⇒ min 收到 C
case COMPARE_EQUAL:
    NumericStats::SetMin(stats, constant);           // X = C ⇒ min=max=C
    NumericStats::SetMax(stats, constant);
```

两列比较同样交叉收紧:`i < j` 且 i:[-50,250]、j:[-100,100] ⇒ i.max 收到 100、j.min 收到 -50(propagate_filter.cpp:105-125,源码含同一数值示例的注释);`i = j` 取两侧更紧的边界(:138-156)。收紧只改优化器内存中的统计副本,绝不写回存储。对计划的改写只有四类:Filter 条件删除/换 EmptyResult(本节)、join 恒真/恒假改写(第 4 节)、Get 上过滤器删除/降级(第 4 节)、join 派生 filter(第 4 节)。判定用的五态分类:

```cpp
// src/optimizer/statistics/operator/propagate_filter.cpp:231-247
FilterPropagateResult StatisticsPropagator::ClassifyFilter(Expression &condition) {
    if (ExpressionIsConstant(condition, Value::BOOLEAN(true)))
        return FILTER_ALWAYS_TRUE;
    if (ExpressionIsConstantOrNull(condition, Value::BOOLEAN(true)))
        return FILTER_TRUE_OR_NULL;
    if (ExpressionIsConstant(condition, Value::BOOLEAN(false)))
        return FILTER_ALWAYS_FALSE;
    else if (ExpressionIsConstantOrNull(condition, Value::BOOLEAN(false)))
        return FILTER_FALSE_OR_NULL;
    return NO_PRUNING_POSSIBLE;
}
```

基数为传播的另一产物:join/cross product 取乘积且用 hugeint 防溢出、估算基数取 max(propagate_join.cpp:209-228),union 取加法(statistics_propagator.hpp:116-117),集合操作与 positional join 取最大(propagate_join.cpp:293-301、313-321)。

## 4. Join / Aggregate / Get 的代表性推导

Join:每条比较条件先对左右表达式统计做 `PropagateComparison` 区间判定,恒假按 join 类型改写(SEMI/INNER→EmptyResult、ANTI→保留一侧、LEFT→右子树置空、RIGHT→左子树置空,src/optimizer/statistics/operator/propagate_join.cpp:16-47),恒真则删条件或把比较 join 降级为 cross product(:49-81;ASOF join 的不等式条件恒真时必须保留,:119-129)。条件统计还被存进 JoinCondition 供执行期完美哈希 join 复用:

```cpp
// src/optimizer/statistics/operator/propagate_join.cpp:101-104
auto prune_result = PropagateComparison(*stats_left, *stats_right, condition.GetComparisonType());
// Add stats to logical_join for perfect hash join
condition.SetLeftStats(stats_left->ToUnique());
condition.SetRightStats(stats_right->ToUnique());
// 消费端:src/execution/operator/join/physical_hash_join.cpp:275-286
// CanDoPerfectHashJoin 要求单条件、右统计为整数且 HasMinMax,
// 用 right_stats 的 min/max 判定键值域是否连续可枚举
```

更激进的是 `CreateFilterFromJoinStats`:INNER/SEMI join 收紧后,若某侧是整数列引用且 min/max 变紧,直接给该侧子树插入派生 LogicalFilter(如 `col >= min_after`),并立即用 FilterPushdown 压到扫描上(propagate_join.cpp:164-184、348-392;仅限整数 :352-353,压完后还会重传播表达式 :391)。

Aggregate:`TryExecuteAggregates` 对无 group 且聚合全为 count_star/min/max 的查询,直接用列统计答案替换为常量(src/optimizer/statistics/operator/propagate_aggregate.cpp:176-223,入口 :537)。min/max 比较器按类型分派——字符串用 StringStats、数值/时间戳用 NumericStats(:75-82);投影链上仅允许安全的整型宽化 cast(:84-93)。

Get:把每列统计装入 statistics_map 后(propagate_get.cpp:164-177),对已挂在 LogicalGet 上的 table_filters 逐一分类处理:

```cpp
// src/optimizer/statistics/operator/propagate_get.cpp:199-226(节选)
case FilterPropagateResult::FILTER_ALWAYS_TRUE:
    get.table_filters.RemoveFilterByColumnIndex(table_filter_column);  // 恒真: 删
    break;
case FilterPropagateResult::FILTER_TRUE_OR_NULL:
    // 降级为 IS NOT NULL 过滤器(:211-214)
    get.table_filters.SetFilterByColumnIndex(table_filter_column,
        make_uniq<ExpressionFilter>(CreateNullCheckExpression(...IS_NOT_NULL)));
    break;
case FILTER_FALSE_OR_NULL: case FILTER_ALWAYS_FALSE:
    ReplaceWithEmptyResult(node_ptr);                                  // 恒假: 空结果
    return make_uniq<NodeStatistics>(0U, 0U);
default:
    UpdateFilterStatistics(stats, filter);                             // 其余: 收紧统计
```

外连接会把可置 NULL 侧全部列统计标记 `CAN_HAVE_NULL_VALUES`(propagate_join.cpp:243-289;positional join 双侧同,:327-343),这是其后 NULL 语义推导的基础。

## 5. zone map 执行期剪枝:row group 与 segment 两层

PhysicalTableScan 自己不做剪枝——它只在构造全局源状态时把 `TableFilterSet` 原样传给 table function(src/execution/operator/scan/physical_table_scan.cpp:41-47),真正的判断全在存储层。第一层在 row group 粒度:`RowGroup::InitializeScanInternal` 开头即 `CheckZonemap`,不过关该 row group 整个跳过(src/storage/table/row_group.cpp:385-389)。`RowGroup::CheckZonemap` 先处理多列 filter(复制各列统计后 `CheckExpressionStatistics` 整体判定,rowid 列用平凡区间统计替代,row_group.cpp:741-777;rowid 无 zonemap 但可造 [beg,end) 平凡统计,:730-735),再对单列 filter 逐个判定:

```cpp
// src/storage/table/row_group.cpp:792-805(row group 级判定)
prune_result = GetColumn(base_column_index).CheckZonemap(context, base_column_index, filter);
if (prune_result == FILTER_ALWAYS_FALSE || prune_result == FILTER_FALSE_OR_NULL)
    return false;                                    // 整个 row group 跳过
if (ExpressionFilter::IsRootNonSelectivityOptionalFilter(filter))
    filters.SetFilterAlwaysTrue(i);                  // 仅服务 row group 级,此后不再检查
else if (prune_result == FILTER_ALWAYS_TRUE)
    filters.SetFilterAlwaysTrue(i);                  // 记住恒真,后续向量不再重复检查
// 进入新 row group 时先 filters.CheckAllFilters() 复位(:781)
```

第二层在 segment(zone,数万行)粒度,发生在每个向量边界:

```cpp
// src/storage/table/row_group.cpp:810-849(CheckZonemapSegments 节选)
auto prune_result = column_data.CheckZonemap(state.column_scans[column_idx], filter, current_segment);
if (prune_result != FILTER_ALWAYS_FALSE && prune_result != FILTER_FALSE_OR_NULL)
    continue;
// ...
idx_t target_vector_index = target_row / STANDARD_VECTOR_SIZE;
if (!target_vector_index_max.IsValid() || target_vector_index_max.GetIndex() < target_vector_index)
    target_vector_index_max = target_vector_index;   // 推进到越界 segment 之后的向量
```

调用点在 `RowGroup::PrepareScan` 循环里 `if (!CheckZonemapSegments(state)) continue;`(row_group.cpp:956)。类型分派最终落到数值/字符串区间模板:数值版逐常量判定 EQUAL/GT/LT 等 6 种比较(numeric_stats.cpp:159-227,入口 :248-252 先查 HasMinMax);字符串版处理截断边界的 `\0` 补位技巧——截断 min "bbbbbbbbbbbb" 配 min_string_length=13 且常量恰等于该前缀时,下界视为 `min+'\0'` 转 EXACT(string_stats.cpp:712-722;截断统计只比前缀字节,CompareStringStats :728-733)。segment 级检查还会叠加未提交 updates 的统计,结论冲突即放弃剪枝(column_data.cpp:453-465;GetUpdateStatistics :295-299)。另有 `PrefetchRowCount` 用 `ColumnData::ZonemapScanEnd` 收缩预取行数(row_group.cpp:895-905;column_data.cpp:476-507,注意 :501-503 "vector 只能整段跳过"的 2048 对齐约束)。与卷二 09 的分工边界:append 侧 `FlushSegmentStats`/segment 定稿(segment_statistics.hpp:18-21;column_data.cpp:569-660),本卷全部是查询期只读消费。

## 6. 动态过滤:build 侧 min/max、bloom、IN 与 TopN 边界的运行时下推

动态过滤分两段。规划段:`JoinFilterPushdownOptimizer::GenerateJoinFilters` 遍历比较 join 的 eq/ineq 条件(:326-343),在 build 侧键上生成 min/max 聚合(:386-403),递归 probe 侧找可达 LogicalGet 并挂 `dynamic_filters`(shared_ptr<DynamicTableFilterSet>,src/include/duckdb/planner/operator/logical_get.hpp:63;注入 src/optimizer/join_filter_pushdown_optimizer.cpp:358-372;即使无目标也保留聚合以支持完美哈希 join,:374-384)。

执行段:hash join build 完成时发布——min==max 发单侧比较过滤(FinalizeFilters 中 `Value::NotDistinctFrom(min_val,max_val)` 分支,src/execution/operator/join/physical_hash_join.cpp:1752-1765),否则发范围对;bloom/prefix-range 要等 build 全部完成才能构造,先 `DeferRuntimeFilter` 再由 `PublishDeferredRuntimeFilters` 统一推入(physical_hash_join.cpp:1141-1145、1519-1547);IN 过滤直接扫 build 侧键列去重生成,含 NULL 或稠密区间则放弃(:1605-1655,稠密/空判定 :1645-1648)。三者的启用门槛是 `CanUseInFilter`/`CanUseBloomFilter`/`CanUsePrefixRangeFilter`(:1295-1355)。

```cpp
// src/planner/filter/table_filter_dynamic_function.cpp:140-158(统计剪枝回调)
FilterPropagateResult DynamicFilterScalarFun::FilterPrune(const FunctionStatisticsPruneInput &input) {
    lock_guard<mutex> lock(data.filter_data->lock);
    if (!data.filter_data->initialized) return NO_PRUNING_POSSIBLE;   // 未定不剪
    return DynamicFilterData::CheckStatistics(*column_stats,
        data.filter_data->comparison_type, data.filter_data->constant);  // → Numeric/String::CheckZonemap
}
// :106-127 DynamicFilterSelect:未初始化时 SetAllTrueSelection 全放行(:111-113)
// CheckStatistics 分派:数值/varchar → Numeric/StringStats::CheckZonemap(:47-71)
```

关键机制有三:

1. 运行时过滤器统一表达为 `ExpressionFilter` 内嵌的内部标量函数 `__internal_tablefilter_dynamic` / `__internal_tablefilter_bloom_filter` 等(src/include/duckdb/planner/filter/table_filter_functions.hpp:19-59、264-270;工厂 :72-78),共享状态 `DynamicFilterData{comparison_type, constant, atomic<bool> initialized}`(table_filter_dynamic_function.cpp:19-21);
2. 扫描端在 `TableScanGlobalSourceState` 构造时把动态过滤与静态 table_filters 合并快照(physical_table_scan.cpp:37-39;`GetFinalTableFilters` 合并逻辑 src/planner/table_filter_set.cpp:526-549;logical_get→physical 的传递 src/execution/physical_plan/plan_get.cpp:210);
3. 因过滤器内容运行期可变,segment 级检查对动态过滤永不置 `segment_checked`,每个 segment 都要重判(column_data.cpp:442-445;可见性量测 :363-364)。

另两个易漏点:

- hash join 每轮开始会 `ClearFilters` 清掉上一轮(如递归 CTE 重执行)残留的过滤器(physical_hash_join.cpp:288-298);
- TopN 优化器把第 N 个排序键值作为动态边界(共享 `DynamicFilterData`)直接推进 LogicalGet 的 table_filters,`LIMIT N + ORDER BY k` 由此转为扫描端剪枝(src/optimizer/topn_optimizer.cpp:121、140、153;NULLS FIRST 时包一层 OR IS NULL,:141-149)。

动态过滤与静态过滤的语义差异:它们都包在 OptionalFilter 里,只作性能提示不承担正确性(table_filter_functions.hpp:67-78),所以 `IsRootNonSelectivityOptionalFilter` 的恒真缓存只用于 row group 级检查(row_group.cpp:798-800)。

## 7. 纠偏清单(以本 commit 源码为准)

以下各条修正系列前文或常见二手资料的表述:

1. "字符串统计含 contains 位图"——不存在。字符串统计是截断 min/max(≤12 字节,EXACT/TRUNCATED 两态)+ has_unicode + max/min/total_string_length(string_stats.hpp:26-63);全 statistics 目录 grep "contains" 仅命中 geometry 注释。
2. "JSON 统计"——不存在 JSON_STATS;StatisticsType 新成员是 VARIANT_STATS(base_statistics.hpp:38-47),带 shredding 状态(variant_stats.hpp:14-26)。JSON 列在本 commit 以 VARCHAR 语义走字符串 min/max。
3. "uncompressed_string_segment 的 CheckZonemap"——该文件已不存在;字符串非压缩实现为 src/storage/compression/string_uncompressed.cpp,zone map 检查入口只在 RowGroup/ColumnData(row_group.cpp:738、column_data.cpp:433),不在 segment 编码层。
4. "DynamicFilter 是 TableFilter 子类"——已过时:`LegacyDynamicFilter` 标注 DEPRECATED 仅为反序列化保留(src/include/duckdb/planner/filter/dynamic_filter.hpp:22-23);ConstantFilter/InFilter/NullFilter/ConjunctionFilter 同样全部 legacy 化(constant_filter.hpp:17、in_filter.hpp:16、null_filter.hpp:15-29、conjunction_filter.hpp:16-41),运行时统一为 ExpressionFilter;`TableFilterType` 枚举的 LEGACY_* 项即此迁移的化石层(table_filter.hpp:22-34)。
5. "统计传播自底向上修改计划"——遍历确为子先父后,但统计流向是叶→根的 map 累加(statistics_propagator.cpp:39-45);计划改写只有删条件/换 EmptyResult/插派生 filter 三类,min/max 收紧永远只作用于优化器内存副本,不写回存储。
6. "执行期剪枝发生在 PhysicalTableScan"——扫描算子只透传 filters(physical_table_scan.cpp:41-47);两层剪枝都在存储层 row_group.cpp/column_data.cpp。

## 9. 设计动机

- 一套 `BaseStatistics` 同时服务优化器估算与执行器剪枝,避免"目录统计"与"存储统计"两套模型互译;base 层只存有效位与 distinct,类型细节全部下沉到 NumericStats/StringStats 等命名空间(base_statistics.hpp:64-189;data_table.cpp:1560-1565 仅是 CopyStats)。
- 过滤器表达式化(ExpressionFilter)让任意复合谓词都能参与统计剪枝:新增内部函数即新增过滤器类型,不再为每种谓词维护一个 C++ 子类与配套 CheckStatistics(table_filter.hpp:22-34;expression_filter.hpp:47-56)。
- 动态过滤把"join 实际数据分布"这一运行时信息回灌给存储层,而统计检查(FilterPrune)与行选择(Select)回调分离,使同一对象既能剪 zone 又能滤行(table_filter_dynamic_function.cpp:106-158)。
- 两层剪枝(row group 粗筛 + segment 细筛)匹配两级物理粒度,恒真判定被 `SetFilterAlwaysTrue` 缓存、进入新 row group 才复位,避免逐向量重复求值(row_group.cpp:781、798-805)。
- 正确性显式兜底:updates 统计与 segment 统计结论不一致时放弃剪枝(column_data.cpp:453-465);动态过滤未初始化时不剪也不杀(table_filter_dynamic_function.cpp:111-113、149-151);运行时过滤包 OptionalFilter 不承担正确性(table_filter_functions.hpp:67-78)。
- join 条件统计在优化器算一次、执行期直接复用于完美哈希 join,避免重复值域分析(propagate_join.cpp:102-104;physical_hash_join.cpp:275-286)。
- 基数估算按算子语义取不同合并律(join 乘、union 加、集合操作/positional 取大),并用 hugeint 防乘法溢出(propagate_join.cpp:209-228、293-301)。

## 10. FAQ 候选

- statistics_map 的 key 是什么?——`ColumnBinding(table_index, projection_index)`,Get 与 Projection 各自插入(propagate_get.cpp:175-177;propagate_projection.cpp:17-22)。
- FILTER_SIMPLIFICATION 与 FULL 两种模式差别?——前者只由 FilterStatisticsOptimizer 用于跨表 filter 简化(filter_statistics.cpp:60),FULL 走主流程并顺带触发压缩物化(statistics_propagator.cpp:106-111)。
- 恒假 filter 如何改写计划?——整棵子树换成 LogicalEmptyResult,基数记 0(propagate_filter.cpp:343-348;propagate_get.cpp:217-221)。
- 外连接如何污染统计?——LEFT/RIGHT/FULL/SINGLE 把可置 NULL 侧全部列统计标记 CAN_HAVE_NULL_VALUES(propagate_join.cpp:243-289)。
- min/max 收紧只对数值列吗?——UpdateFilterStatistics 明确跳过非数值(propagate_filter.cpp:57-59),但 join 恒真/恒假判定与 min/max 聚合替换支持字符串区间(propagate_comparison.cpp:11-25;propagate_aggregate.cpp:75-82)。
- 什么样的聚合可以不扫表?——无 group、聚合无 filter、全为 count_star/min/max 且底层列有对应统计时替换为常量(propagate_aggregate.cpp:176-223)。
- row group 没被剪掉,segment 级还有机会吗?——有,每个向量边界重新 CheckZonemapSegments,可整段跳过越界 segment(row_group.cpp:956、810-849)。
- 动态过滤在 build 未完成时会不会误杀 probe 数据?——不会,未初始化时 Select 全放行、FilterPrune 返回不可剪(table_filter_dynamic_function.cpp:111-113、149-151)。
- 未提交的事务更新会破坏 zone map 剪枝吗?——CheckZonemap 把 updates 统计与 segment 统计合并判定,不一致即不剪(column_data.cpp:453-465)。
- 动态过滤为什么包 OptionalFilter?——它只是性能提示不承担正确性,执行不生效也放行(table_filter_functions.hpp:67-71;row_group.cpp:798-800 因此只用于 row group 级恒真缓存)。

## 12. 正文蒸馏要点

1. 统计类型共 8 类,嵌套类型靠 child_stats 递归;无 JSON 统计,VARIANT 统计带 shredding 状态(base_statistics.hpp:38-47、188;variant_stats.hpp:14-26)。
2. 字符串统计 = 截断 min/max(≤12 字节,EXACT/TRUNCATED 两态)+ unicode + 三种长度,无 contains 位图(string_stats.hpp:26-63、34)。
3. 统计传播入口在 optimizer.cpp:457-463(含 DML CTE 则跳过),statistics_map 按 ColumnBinding 累积、自叶向根(statistics_propagator.hpp:155)。
4. Filter 收紧规则:X<C 收 max、X>C 收 min、X=C 收成点;普通比较断言列非 NULL,仅对有 min/max 的数值列生效(propagate_filter.cpp:65-86、51-63)。
5. 两列比较可交叉收紧并连锁推证:`i=j AND i=k` 在 j、k 区间不相交时可静态证假(propagate_filter.cpp:105-156;propagate_join.cpp:147-158 注释)。
6. 恒假→LogicalEmptyResult、恒真→删条件,Get 上的 TRUE_OR_NULL filter 降级为 IS NOT NULL(propagate_filter.cpp:337-348;propagate_get.cpp:199-215)。
7. join 条件统计写入 JoinCondition,执行期直接用于完美哈希 join 的整数键值域判定(propagate_join.cpp:102-104;physical_hash_join.cpp:275-286)。
8. CreateFilterFromJoinStats 把 join 收紧结果物化为子树上的派生 filter 并再次 pushdown,仅限整数列(propagate_join.cpp:348-392)。
9. 无 group 的 count_star/min/max 聚合可直接用统计答案替换整棵子树(propagate_aggregate.cpp:176-223、537)。
10. zone map 剪枝两层都在存储层:row group 级 CheckZonemap(row_group.cpp:387、738-808)与 segment 级 CheckZonemapSegments(row_group.cpp:956、810-849),扫描算子只透传 filters(physical_table_scan.cpp:41-47)。
11. 数值 zone 判定是 6 种比较的区间模板并支持多常量;字符串有截断 min+'\0' 的边界技巧(numeric_stats.cpp:159-227;string_stats.cpp:712-722)。
12. 动态过滤 = ExpressionFilter 内嵌 `__internal_tablefilter_*` 内部函数 + 共享 DynamicFilterData,build 完成时发布、扫描 gstate 构造时快照、对动态过滤 segment 结论永不缓存(physical_hash_join.cpp:1141-1145、1519-1547;physical_table_scan.cpp:37-39;column_data.cpp:442-445)。
13. 经典 TableFilter 子类(Constant/In/Null/Conjunction/Dynamic/Bloom/PrefixRange)全部 DEPRECATED,统一为 ExpressionFilter,枚举保留 LEGACY_* 仅为序列化兼容(table_filter.hpp:22-34;constant_filter.hpp:17;dynamic_filter.hpp:22-23)。
