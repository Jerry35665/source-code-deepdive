# 报告 B3 · 表达式执行与标量函数机器(DuckDB 卷三)

> 基线:7e886f44428e90c8379d4d34e2afb866108ff079 —— 表达式执行只有 8 个绑定类分发点,比较与 CAST 均已"函数化";所有标量函数统一为 `scalar_function_t(DataChunk&,…)` 单轨回调,重载解析靠隐式 cast 代价求和 + TEMPLATE 类型推导,热路径由 ScalarExecutor 按"常量/平坦输入 profile"编译期特化。

## 1. 执行入口:8 类分发与 SelectionVector 透传

ExpressionExecutor 构造时把表达式挂进列表并逐个初始化状态树:`AddExpression` 为每条表达式建一个 `ExpressionExecutorState`,`Initialize` 递归构建 `root_state`,随后 `state->Verify()`(src/execution/expression_executor.cpp:67-83)。状态树按表达式类型分流——`InitializeState` 的 switch 与执行 switch 完全同构,只有 8 个绑定类:BOUND_REF / BOUND_CASE / BOUND_CONJUNCTION / BOUND_CONSTANT / BOUND_FUNCTION / BOUND_LAMBDA / BOUND_OPERATOR / BOUND_PARAMETER(expression_executor.cpp:232-254, 279-306)。比较与 CAST 在本 commit 都已是 BoundFunctionExpression(见 §7 纠偏 1、纠偏 7)。注意 DEBUG 构建下执行前还要断言:复用的结果向量若是 FLAT,其 validity 必须全 valid,防止上一 chunk 的脏掩码泄漏(expression_executor.cpp:258-269)。

入口有三种粒度:

```cpp
// src/execution/expression_executor.cpp:85-95(多列)
void ExpressionExecutor::Execute(DataChunk *input, DataChunk &result) {
    SetChunk(input);
    D_ASSERT(expressions.size() == result.ColumnCount());
    for (idx_t i = 0; i < expressions.size(); i++) {
        ExecuteExpression(i, result.data[i]);
    }
    result.SetChildCardinality(input ? input->size() : 1);
    result.Verify(context);
}
```

带 SelectionVector 的入口 `ExecuteExpression(input, result, sel, count)` 把 sel 原样递给根表达式(expression_executor.cpp:102-109);顶层 `ExecuteExpression(idx_t, Vector&)` 则传 `sel=nullptr`(136-140)。Select 一族是过滤专用:`SelectExpression` 支持 true_sel/false_sel 双向输出(120-129);`Select` 的 switch 只给 BOUND_CONJUNCTION 与 BOUND_FUNCTION 定制路径,其余走 `DefaultSelect`——先在栈上物化 `bool intermediate_bools[STANDARD_VECTOR_SIZE]`,再 `ToUnifiedFormat` 扫一遍生成 sel,validity 可证无 NULL 时走 `NO_NULL` 模板消掉判空(expression_executor.cpp:315-331, 374-394, DefaultSelectLoop 在 333-356)。STANDARD_VECTOR_SIZE 默认 2048(src/include/duckdb/common/vector_size.hpp:16-21)。物理过滤器正是消费方:`state.executor.SelectExpression(input, state.sel)`(src/execution/operator/filter/physical_filter.cpp:54)。

执行后统一收尾:除 BOUND_REF 外 `FlatVector::SetSize(result, count)`,因为 BOUND_REF 直接共享源 chunk 缓冲区不能 resize;随后 `Verify(expr, result, count)` 可按 DebugVectorVerification 开关做字典化/VARIANT 往返等压力测试(expression_executor.cpp:307-312, 168-230)。单值求值入口 `EvaluateScalar` 就是"造 executor、跑 count 行、取第 0 行"(142-155),它是优化器常量折叠的引擎。

三个"叶子"类几乎零成本:REF 收到 sel 就 `result.Slice(chunk->data[expr.Index()], *sel, count)`,没有就零拷贝 `Reference`(src/execution/expression_executor/execute_reference.cpp:13-23);CONSTANT `result.Reference(expr.GetValue(), count)` 造常量向量(execute_constant.cpp:14-18);PARAMETER 引用 `ParameterData()->GetValue()`(execute_parameter.cpp:14-20)。相应地,`ExpressionState::AddChild` 对这三个类不初始化子状态(`initialize.push_back(false)`),`Finalize` 只为有子节点的表达式分配 intermediate_chunk(src/execution/expression_executor_state.cpp:10-26)。

## 3. 重载解析:隐式 cast 代价 + TEMPLATE 推导

解析分两步。第一步选 overload:`FunctionOverloads::Cost` 先查参数个数(min/max,varargs 放开上限),再对每个实参求 `ImplicitCastCost` 并求和;含 UNKNOWN(未定参数)则整体 cost=0;任意一参不可隐式 cast 即出局(src/function/function_binder.cpp:83-176, 96-125)。`ImplicitCastCost` 有 context 时走 `CastFunctionSet::ImplicitCastCost`(可含扩展注册的 cast),否则退回内建 `CastRules::ImplicitCast`(74-81)。平票产生候选集,最终抛"Could not choose a best candidate function"(238-286, 288-309);多候选且含 UNKNOWN 则抛 `ParameterNotResolvedException`(311-334)。

代价表 `TargetTypeCost` 是一张偏序表(src/function/cast_rules.cpp:9-52):BIGINT=101 < INTEGER=102 < HUGEINT=103 < DOUBLE=104 < DECIMAL=105 < BIGNUM=106;TIMESTAMP 系 119-124;VARCHAR=149;嵌套类型 160;TEMPLATE=1000000。特例规则:STRING_LITERAL→VARCHAR cost 1、→其他合法类型 cost 20(402-413);INTEGER_LITERAL 能装进目标整型时给 `TargetTypeCost-90`(414-430)——这就是 `2.5 + 3` 不必显式 cast、且整数字面量偏好 BIGINT 的原因。LIST/ARRAY/STRUCT/UNION 的代价递归到子类型,同别名约束 `from.GetAlias() != to.GetAlias()` 直接 -1(432-441, 519-583)。第二步 `CastToFunctionArguments` 逐 child `RequiresCast`,判 `DIFFERENT_TYPES` 时插入 `BoundCastExpression::AddCastToType`,STRING_LITERAL/INTEGER_LITERAL 若从 bind 回调漏出直接 InternalException(function_binder.cpp:496-512, 541-573)。

本 commit 还引入 C++ 风格的 TEMPLATE 类型:`ResolveTemplateTypes` 从 children 递归推导(`InferTemplateType` 深入 LIST/MAP/STRUCT 子类型),冲突时用 `LogicalType::TryGetMaxLogicalType` 单化并记录推导链,失败即 BinderException;bind 回调结束后 `CheckTemplateTypesResolved` 兜底校验(function_binder.cpp:780-907, 930-976)。另有两处"bind 期执行":对 DEFAULT_NULL_HANDLING 函数,任一 child 可折叠求值为 NULL,整个函数直接替换成类型正确的 NULL 常量(function_binder.cpp:619-652);`bind_expression` 回调可让函数在绑定期直接产出一个替代表达式(1168-1191)。命名参数、默认值与隐式参数名(如 struct_pack)也在这一层解析:`ResolveArguments` 把命名实参重排进签名槽位、缺失槽填默认值常量(982-1086)。

## 4. 一元/二元模板与 ScalarExecutor:constant 折叠路径 vs 向量路径

热循环引擎是 `ScalarExecutor`(src/include/duckdb/common/vector_operations/scalar_executor.hpp:31),Unary/Binary/Ternary Executor 只是它的薄外观。它先对全部输入做 `InputProfile` 采样(src/include/duckdb/common/vector_operations/scalar_executor.hpp:34-40):

```cpp

struct InputProfile {
    uint64_t constant_mask = 0;            // 每位标记该输入是否常量(≤64 输入)
    bool all_constant = true;
    bool all_flat_or_constant = true;
    bool any_constant_null = false;
};
```

然后三路分发(scalar_executor.hpp:374-450):

- **全常量**:`ExecuteConstant` 只算第 0 行,结果置 CONSTANT_VECTOR(190-205)——执行期的"constant 折叠路径"。它与优化器把整棵可折叠子树换成 BoundConstantExpression 的 `ConstantFoldingRule` 是两回事:后者在计划期用 `ExpressionExecutor::TryEvaluateScalar` 求值后直接替换表达式(src/optimizer/rule/constant_folding.cpp:11-42;expression_executor.cpp:157-166);
- **全平坦/常量混合**:按 `constant_mask` switch(0..6,最多 3 输入)进 `ExecuteFlat<CONSTANT_MASK>`,常量输入经 `InputIndex` 编译期折叠为读下标 0(62-69);validity 按 64 位 entry 批判——AllValid entry 跳过判空、NoneValid 直接跳过 64 行(157-188);若任一常量输入为 NULL,整个结果向量直接置 NULL(386-394);
- **其他(字典/压缩等)**:`ExecuteGeneric` 走 `ToUnifiedFormat` 逐行,二输入时可再按"selection 有无"switch 出 4 份特化(329-372, 215-327)。

Select 侧的入口同样先采样 profile,再按 true_sel/false_sel 组合选 Sink(`StaticSelectionSink<has_true, has_false>` vs 运行时 `RuntimeSelectionSink`,452-561),Specialize 输出数量后再进 `SelectInternal`(801-874)。

`ExecuteFlat` 的核心循环(常量掩码实例化为 2,即右参是常量):


模板生成的另一面是 lambda 操作数:`UnaryExecutor::Execute(input, result, count, fun)` 若 lambda 返回 `optional<RESULT_TYPE>` 则自动获得"返回 nullopt 即置 NULL"能力(src/include/duckdb/common/vector_operations/unary_executor.hpp:155-162;对应 `UnaryLambdaWrapper` 30-44);`UnaryExecutor::ExecuteString` 把结果字符串堆 `StringVector::GetStringHeap(result)` 传给操作符(171-175);`UnaryExecutor::Select` 走同一 ScalarExecutor 的 Select 引擎(198-205)。UnaryExecutor 还自带一层字典优化:输入是字典向量且 `字典大小*2 <= count` 时,直接对字典本体执行再把结果包成 `result.Dictionary(...)`(123-140,`DICTIONARY_THRESHOLD = 2`)。Select 侧同样特化:`SelectFlatLoop` 的 NoneValid entry 一次性把 64 行扔进 false_sel(scalar_executor.hpp:596-598);`BinarySelectAdapter::OperationNoNull` 用 `ComparisonSelectComplement` 把 `<` 折叠为 `!(right>left)`、`<=` 折叠为 `!(left>=right)` 等(src/include/duckdb/common/vector_operations/binary_executor.hpp:105-122)。所有特化均受 `DUCKDB_SMALLER_BINARY(...)` 编译开关裁剪以控制二进制体积(unary_executor.hpp:93-116 的 ExecutePolicy/SelectPolicy)。

## 5. vector_operations 关键件:AND/OR 三值逻辑、IS NULL、CASE、比较

**AND/OR 的 Execute 是全量物化**:`VectorOperations::And/Or` 双常量输入产常量结果(22-36),否则基于 `Values<uint8_t>()` 条目循环调 `TernaryAnd/TernaryOr::Operation`,不传播 selection vector(src/common/vector_operations/boolean_operators.cpp:16-62,169-187)。三值逻辑显式编码,注释即规格(64-81):AND 中"FALSE AND NULL = FALSE、NULL AND NULL = NULL",实现为"bool 返回值=是否为 NULL"的双出口约定:

```cpp
// src/common/vector_operations/boolean_operators.cpp:86-108(节选)
static bool Operation(bool left, bool right, bool left_null, bool right_null, bool &result) {
    if (left_null && right_null) {
        return true;                 // 结果 NULL
    } else if (left_null) {
        result = right;
        return right;                // right=false → FALSE;right=true → NULL
    } else if (right_null) {
        result = left;
        return left;
    } else {
        result = left && right;
        return false;
    }
}
```

OR 对称实现(111-158);两侧均无 NULL 时走 `SimpleOperation` 快路径(57-61);布尔按 uint8 读避免 gunk bool(38-39)。

真正的短路在 `ExpressionExecutor::Select(BoundConjunctionExpression)`:AND 链每轮把存活行收进 true_sel,后续子谓词只扫 `current_sel=true_sel`,行数逐级收缩,`current_count==0` 提前退出;求值顺序由 `AdaptiveFilter::GetPermutation()` 按运行耗时动态冒泡重排(src/execution/expression_executor/execute_conjunction.cpp:66-105, 93-101;src/execution/adaptive_filter.cpp:108+)。OR 对偶:每轮后 `current_sel=false_sel` 只追非通过行,结束 `true_sel->Sort(result_count)` 保持行号有序(execute_conjunction.cpp:106-145)。Execute 路径(物化)则首孩子 Reference、后续逐个 `VectorOperations::And/Or` 合并,不短路(33-59)。

**IS NULL**:常量输入直接产常量布尔;否则扫 validity mask 写 `entries.IsValid(i)`(src/common/vector_operations/null_operations.cpp:13-38),由 OPERATOR 分发调用(OPERATOR_NOT/IS_NULL/IS_NOT_NULL,src/execution/expression_executor/execute_operator.cpp:161-181)。

**CASE**:状态里预置 true_sel/false_sel 两个 STANDARD_VECTOR_SIZE 选择向量(src/execution/expression_executor/execute_case.cpp:12-19)。循环每个 WHEN:先 `Select(when_expr)` 划分行集,`then_expr` 只对 tcount 行求值进中间向量,再 `FillSwitch` 按 sel 散写进结果(45-70);第一个 WHEN 全真可整体短路只执行 THEN(58-62);全假直通 ELSE(76-89);结尾统一 `result.Slice(*sel, count)` 恢复外层行集(90-92)。`TemplatedFillLoop` 分常量(写 `*data` 到各 sel 位置)与条目两条路(95-123);VARCHAR 分支额外 `StringVector::AddHeapReference(result, vector)` 防悬垂(189-192);STRUCT 递归 Flatten 后逐子列 Fill,LIST 先 `ListVector::Append` 子数据再给偏移量补 `+= offset`(193-226)。

**比较**:比较在本 commit 是标量函数——`GetComparisonFunctionInternal` 注册 ANY/ANY + BOOLEAN 的 `ComparisonFunction<TYPE>`,`SetSelectCallback(ComparisonSelect<TYPE>)`,IS DISTINCT FROM 系列标 `SPECIAL_HANDLING`(src/function/scalar/comparison/comparison.cpp:82-97)。Select 版实现在 execute_comparison.cpp:`TryPrimitiveSelectOperation` 按物理类型 switch 到 `BinaryExecutor::Select<T,T,OP>`,顺带把 NULL 行标进可选 null_mask(18-102);不支持的类型退到 `ComparatorSelectOperation`——先 `ComparatorFill` 产 int8 三元 {-1,0,1} 再按谓词分流,统一把 NULL 归入 false_sel(104-143)。`<` 与 `<=` 翻转操作数复用 `>`/`>=` 实现(194-216);布尔版 `Equals` 对 NaN 相等特判(src/common/vector_operations/comparison_operators.cpp:22-38)。物化版三参包装(如 `VectorOperations::Equals(left,right,result)`)走 `TryPrimitiveComparisonExecute` / `ComparatorToBoolean`(comparison_operators.cpp:216-224)。

**IN/COALESCE/TRY**(BOUND_OPERATOR,execute_operator.cpp):IN 是"左孩子求值一次,逐 RHS child `VectorOperations::Equals` 再 OR",NOT IN 末尾 `Not`(20-64);COALESCE 用交替的 sel_a/sel_b 缩小剩余行,非空行 `FillSwitch` 定点写入,余下置 NULL(65-111);TRY 先整体向量化执行,抛执行错误后逐行重试,重试前必须 `ResetDictionaryStates()` 清掉字典缓存(112-160)。

## 7. 纠偏(以 7e886f44 源码为准)

1. **"执行器直接执行 BoundColumnRefExpression"** —— 错。分发表中没有 BOUND_COLUMN_REF:计划期 `ColumnBindingResolver::VisitReplace(BoundColumnRefExpression&)` 把它替换为携带物理列下标的 `BoundReferenceExpression`(src/execution/column_binding_resolver.cpp:224-248),执行器只认 BOUND_REF(expression_executor.cpp:280-282)。
2. **"RegularFunction vs VectorizedFunction 双轨分发"** —— 不存在。本 commit 无 `vectorized_function_t`/`standard_function_t`/`RegularFunction` 符号(全仓 grep 为空),唯一执行形态是 `scalar_function_t(DataChunk&,ExpressionState&,Vector&)`(scalar_function.hpp:133),逐行 lambda 只是模板包装的便捷入口(scalar_function.hpp:450-466)。
3. **"隐式 cast 代价模型入口叫 CostFunction"** —— 现名 `CastRules::ImplicitCast`(cast_rules.cpp:385)与 `CastFunctionSet::ImplicitCastCost`(src/include/duckdb/function/cast/cast_function_set.hpp:56-60),解析时由 `FunctionOverloads::Cost` 求和(function_binder.cpp:83-176);`TargetTypeCost` 的 BIGINT(101)<INTEGER(102) 偏好保留(cast_rules.cpp:11-14)。
4. **"AND/OR 在 boolean_operators.cpp 里做 sel 短路"** —— 该文件的三值逻辑全量物化、无 selection vector(§5);短路只在 conjunction 的 Select 路径(execute_conjunction.cpp:66-145),且 Execute 路径(33-59)与 And/Or 一样不短路;"true/false 常量短路"实际发生在两个层面:bind 期 NULL 常量折叠(function_binder.cpp:619-652)与 ScalarExecutor 的 any_constant_null 整体置 NULL(scalar_executor.hpp:386-394)。
5. **"templated_column_operators 生成循环"** —— 该文件已不存在;统一循环引擎为 `ScalarExecutor` + Policy(scalar_executor.hpp:31;unary_executor.hpp:93-116),Unary/Binary/Ternary Executor 是按 `DUCKDB_SMALLER_BINARY` 可裁薄的外观。
6. **"pragma_version 提供函数计数"** —— `PragmaVersion` 只回 `SELECT * FROM pragma_version();`(pragma_queries.cpp:145-147);逐 overload 的计数/枚举在 `duckdb_functions()` 表函数(duckdb_functions.cpp:141)。
7. **"CAST 是独立表达式节点走专属执行分支"** —— 执行器无 BOUND_CAST 分支;`BoundCastExpression::AddCastToType` 产出的实际是 `__cast` 标量函数的 BoundFunctionExpression(src/function/scalar/operator/cast.cpp:170-200),cast 逻辑经 `CastFunctionSet::GetCastFunction` 查表执行(src/common/vector_operations/vector_cast.cpp:9-20);TRY_CAST 与可抛 cast 还会在反序列化时动态 `SetErrorMode(CAN_THROW_RUNTIME_ERROR)`(cast.cpp:145-149)。

## 8. 设计动机

- **编译期铺开物理类型、运行期零虚调用**:bind 期把 LogicalType 定到唯一 overload 并把 `BinaryFunction<T,…>` 函数指针固化(arithmetic.cpp:34-72, 1091+),热循环内只剩模板直调与取下标,连"哪个输入是常量"都在编译期折进 `InputIndex` 的模板参数(scalar_executor.hpp:62-69)。
- **SelectionVector 全程透传 = 过滤先行**:AND/OR 链、CASE、COALESCE、比较 Select 都以"行号集合收缩"推进,使 late materialization 之下后续算子只碰存活行(物理过滤器见 physical_filter.cpp:54)。
- **常量的三级利用**:bind 期 NULL 子表达式整体折叠(function_binder.cpp:619-652)→ 执行期 all_constant 只算 1 行且结果 `FlattenAndSetConstant`(execute_function.cpp:225-253)→ 优化器 ConstantFoldingRule 把任意可折叠子树换成 BoundConstantExpression(constant_folding.cpp:28-42)。
- **字典列的 O(count)→O(dict)**:函数态只对存储字典执行一次并把结果包成可复用 dictionary 向量,用 20000 大小上限与 50% chunk 填充率防低选择率劣化;完成后按字典 id 缓存(execute_function.cpp:49-132)。
- **三值逻辑显式编码而非哨兵值**:ValidityMask + TernaryAnd/Or 的 9 格真值表直接写成注释与代码互证(boolean_operators.cpp:64-158),避免魔法值、与 SQL 语义逐条对齐。
- **一个 ScalarFunction 描述全部生命周期**:execute/select/statistics/to_string/serialize/filter_prune/init_local_state 回调合一(scalar_function.hpp:174-207),避免计划期与执行期两套注册 API 漂移;不可抛函数的守卫统一在 `Execute`/`Select` 外壳(scalar_function.hpp:315-340)。
- **体积-性能可调**:所有模板特化挂在 `DUCKDB_SMALLER_BINARY` 开关上,嵌入式构建可放弃热路径特化换二进制尺寸(unary_executor.hpp:94-116;execute_comparison.cpp:23-25)。

## 9. FAQ 候选

1. ExpressionExecutor 认几个表达式类?——8 个(REF/CASE/CONJUNCTION/CONSTANT/FUNCTION/LAMBDA/OPERATOR/PARAMETER,expression_executor.cpp:234-253),比较与 CAST 均以函数形态落入 BOUND_FUNCTION。
2. 顶层入口的 sel 是什么?——`ExecuteExpression(idx_t, Vector&)` 传 nullptr(expression_executor.cpp:136-140),由各子表达式自行决定是否用增量 sel(`FlatVector::IncrementalSelectionVector`,expression_executor.cpp:386-388)。
3. 常量折叠发生在哪?——优化器 ConstantFoldingRule 借 `ExpressionExecutor::TryEvaluateScalar` 求值后替换为 BoundConstantExpression(constant_folding.cpp:34-42),执行器自身不折叠、只负责"全常量输入算 1 行"。
4. 函数如何声明"绝不会抛错"?——默认 CANNOT_ERROR,违者重抛为 InternalException(`ThrowNonFallibleFunctionError`,scalar_function.hpp:315-327),可能抛错的函数必须 `SetFallible()`。
5. Select 回调的价值是什么?——免掉"先物化布尔向量再扫一遍"的双重遍历,谓词直接产出 true/false sel 并在 AND 链上逐级收缩行数。
6. 为什么 random() 不享受常量优化?——VOLATILE 函数强制 `all_constant=false`,每行都算(execute_function.cpp:206-210)。
7. 默认 NULL 语义由谁保证?——引擎:常量 NULL 实参直接短路返回 NULL(execute_function.cpp:218-221),标 SPECIAL_HANDLING 的函数(如 IS DISTINCT FROM)例外(comparison.cpp:93-96)。
8. AND 的子谓词顺序会变吗?——会,AdaptiveFilter 按累计耗时对 permutation 做冒泡式重排(execute_conjunction.cpp:83-84;adaptive_filter.cpp:108+)。
9. CASE 的字符串结果为何要 AddHeapReference?——FillSwitch 按位拷贝 string_t 头,必须让结果向量引用源堆以延寿(execute_case.cpp:189-192)。
10. 内建函数总数从哪查?——`duckdb_functions()` 表函数逐 overload 输出,计数=每个 catalog 条目 `functions.Size()`(duckdb_functions.cpp:141-143)。
11. lambda 参数占位向量是什么?——BOUND_LAMBDA 执行时只写一个常量占位 0,真正求值由宿主函数对 body 另行执行(execute_lambda.cpp:14-21)。
12. TRY 如何避免字典缓存污染逐行重试?——重试前 `ResetDictionaryStates()` 清空缓存的输出字典(execute_operator.cpp:141-143;execute_function.cpp:124-132)。

## 正文蒸馏要点

1. 执行分发只有 8 个绑定类;比较/CAST 都是 BoundFunctionExpression,执行器没有它们的专属分支(expression_executor.cpp:279-306;cast.cpp:186-200)。
2. BOUND_REF 是纯零拷贝节点:有 sel 就 Slice,没 sel 就 Reference 整列;且是唯一不被 SetSize 的结果(execute_reference.cpp:13-23;expression_executor.cpp:307-311)。
3. 标量函数单轨化:`scalar_function_t(DataChunk&,…)` 一统天下,select/statistics/bind/init_local_state 等是可选叠加回调(scalar_function.hpp:133-144,174-207)。
4. 重载解析=逐参隐式 cast 代价求和取最小;代价表 BIGINT=101<INTEGER=102<…<VARCHAR=149,整数字面量有 -90 优惠、字符串字面量 cost 1/20(function_binder.cpp:83-176;cast_rules.cpp:9-52,402-430)。
5. ScalarExecutor 按 InputProfile(constant_mask/all_flat_or_constant/any_constant_null)三路特化:全常量算 1 行、平坦混合编译期折叠常量下标、其余走 UnifiedVectorFormat(scalar_executor.hpp:34-40,374-450)。
6. 过滤主路径是 Select 而非 Execute:AND/OR 链行号集合逐级收缩、顺序由 AdaptiveFilter 运行时重排;And/Or 向量操作本身只做全量三值逻辑(execute_conjunction.cpp:66-145;boolean_operators.cpp:16-62)。
7. CASE 靠预置 true/false 选择向量分段执行 then/else 并用 FillSwitch 定点散写;LIST 需要偏移补偿、VARCHAR 需要堆引用、第一个 WHEN 全真可整体短路(execute_case.cpp:34-93,189-226)。
8. 比较的 Select 版按物理类型特化到 BinaryExecutor::Select,`<`/`<=` 翻转操作数复用 `>`/`>=` 实现,退路是 int8 三元比较 ComparatorFill(execute_comparison.cpp:18-143,194-216)。
9. NULL 语义三层兜底:bind 期 NULL 实参折叠整函数、执行期常量 NULL 短路、VERIFY_FUNCTIONS 模式校验"NULL 进非 NULL 出"报 InternalException(function_binder.cpp:619-652;execute_function.cpp:218-221,148-181)。
10. 内建函数是生成器产出的静态表 + 统一 catalog 注册;`duckdb_functions()` 逐 overload 输出且 FunctionCount=functions.Size()(function_list.cpp:86-289;register_function_list.cpp:54-96;duckdb_functions.cpp:141-143)。
11. 字符串在执行面"看得见":结果写进向量私有 StringHeap(EmptyString+Finalize),散写路径必须 AddHeapReference(caseconvert.cpp:19-29,86-96;execute_case.cpp:189-192)。
12. 绑定期状态树为每个有子节点的表达式预分配 intermediate_chunk,REF/CONSTANT/PARAMETER 跳过初始化;函数执行前 Reset 复用,孩子结果按位写入(execute_function.cpp:201-204;expression_executor_state.cpp:10-26)。
