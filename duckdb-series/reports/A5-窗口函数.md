# 报告 A5 · 窗口函数执行(DuckDB 卷四)

> 基线:7e886f44(duckdb,commit "Added connection_progress_get to the capi v2 #25681")。一句话总结:窗口函数没有独立排序算子——`PhysicalWindow` 自身先作为 sink 把数据按分区键 radix 哈希进 `SortStrategy`(HashedSort/FullSort/PartitionedSort/NaturalSort 四策略),再作为 source 以 SORT→MATERIALIZE→MASK→SINK→FINALIZE→GETDATA 六阶段任务状态机逐分区完成排序、边界位图、表达式物化、聚合器构建与分帧求值;执行器家族只有 `WindowExecutor`/`WindowAggregateExecutor` 两个类,lead/lag/rank 等差异全部通过 `WindowFunction` 回调注入,聚合窗口则按 Distinct→Constant→Custom→SegmentTree→Naive 阶梯选择增量数据结构。

## 1. 算子定位:规划期的三分法与分组

窗口函数在物理规划阶段(`LogicalWindow` → `CreatePlan`)被分为三类,并按"共享分区 + 排序前缀"分组串联(src/execution/physical_plan/plan_window.cpp:31-66):

```cpp
// src/execution/physical_plan/plan_window.cpp:41-47
if (enable_optimizer && PhysicalStreamingWindow::IsStreamingFunction(context, wexpr)) {
    streaming_windows.push_back(expr_idx);
} else if (!wexpr.Partitions().empty() &&
           HasSingleValuePartitions(context, wexpr.Partitions(), plan, partition_columns)) {
    partitioned_windows.push_back(expr_idx);
} else {
    blocking_windows.push_back(expr_idx);
}
```

- **流式优先**:一旦存在可流式函数,partitioned 全部降级为 blocking,`special_windows` 指向流式组(plan_window.cpp:54-59)。
- **分区列下推**:分区键为单值常量(如 `OVER (PARTITION BY 'A')`)时,`HasSingleValuePartitions` 把分区列挂到 `partition_info`,走 `PhysicalWindow(…, partitions)` 构造(plan_window.cpp:174-180;physical_window.cpp:282-286, 317-323)。
- **分组规则**:分区等价(`PartitionsAreEquivalent`)是硬条件,不满足即拆新组;`ORDER BY` 必须构成组内已有排序的公共前缀(`GetSharedOrders`),否则同样拆出(plan_window.cpp:110-140)。这意味着 `RANK() OVER (ORDER BY a)` 与 `SUM(x) OVER (ORDER BY a, b)` 会被拆成两个算子——共享的是完整前缀而非任意子集。
- **CSE**:同组内完全相等(`Equals`)且非 volatile 的窗口表达式直接复用列,最终由一层 PhysicalProjection 恢复列序(plan_window.cpp:120-131, 184-203)。
- 头注释明确假设"所有函数共享同一分区与排序"(src/include/duckdb/execution/operator/aggregate/physical_window.hpp:16-17);生成的算子按 `special_count` 决定流式/分区/阻塞三型(plan_window.cpp:163-181)。

## 2. PhysicalWindow:既是 sink 又是 source

窗口求值必须看到完整分区才能开始,所以 `PhysicalWindow` 同时实现 Sink 与 Source 接口(physical_window.hpp:49-89)。Sink 阶段三个方法(Sink/Combine/NextBatch)几乎全部转发给内部的 `SortStrategy`(physical_window.cpp:328-360):

```cpp
// src/execution/operator/aggregate/physical_window.cpp:312-314
sort_strategy = SortStrategy::Factory(client, wexpr.Partitions(), wexpr.OrderBy(),
                                      op.children[0].get().GetTypes(), wexpr.PartitionsStats(),
                                      op.partition_info, op.estimated_cardinality);
strategy_sink = sort_strategy->GetGlobalSinkState(client);
```

`order_idx` 指向 ORDER BY 最多的那个窗口表达式,分区/排序形态、统计信息都取自它(physical_window.cpp:266-279, 302-313)。全局 sink 态持有 executors(每个窗口表达式一个)与共享表达式库 `WindowSharedExpressions`(physical_window.cpp:200-235),并支持迭代重执行:`Reset()` 只重建 sort sink,executors 与共享布局保留(physical_window.cpp:224-234)。

**order-dependent 的真实含义**:仅当某个窗口表达式既无 `PARTITION BY` 又无 `ORDER BY`(裸 `OVER()`)时才置位:

```cpp
// src/execution/operator/aggregate/physical_window.cpp:271-273
if (bound_window.Partitions().empty() && bound_window.OrderBy().empty()) {
    is_order_dependent = true;
}
```

它决定两件事:`ParallelSink() = !is_order_dependent`、`SinkOrderDependent() = is_order_dependent`(physical_window.hpp:83-89)。裸 `OVER()` 的行号语义依赖输入到达顺序(单分区、NaturalSort 不重排),sink 不能乱序并行;反过来,带 `ORDER BY` 的查询会在 source 阶段重建顺序,sink 完全可并行。

输出保序契约:`SourceOrder()` 规定——有分区时 `NO_ORDER`(分区完成顺序未定义)、无分区无排序 `INSERTION_ORDER`、否则 `FIXED_ORDER`(physical_window.cpp:1111-1124);并行输出靠 batch_index 归并,且 `SupportsPartitioning` 只允许单分区场景保序,注释直言"work stealing causes out of order batch numbers"(physical_window.cpp:1101-1109, 1145-1153)。batch_index 由 `batch_base + 块号` 组成(physical_window.cpp:1049)。

## 3. 分区键与排序键:SortStrategy 四策略与边界位图

`SortStrategy::Factory` 按(分区、排序)形态选择四种实现(src/common/sort/sort_strategy.cpp:35-49):分区列下推用 `PartitionedSort`;有分区键用 `HashedSort`;只有 `ORDER BY` 用 `FullSort`;全空用 `NaturalSort`。`HashedSort` 把分区键哈希进 `RadixPartitionedTupleData`(`MemoryTag::WINDOW`,以追加的 hash 列分区,src/common/sort/hashed_sort.cpp:119-125),并按数据量自动扩 radix 位:平均分区超过 `DEFAULT_ROW_GROUP_SIZE` 就 `new_bits += 2`(hashed_sort.cpp:130-145)。本地分区在 combine 前同步到全局位宽(`SyncLocalPartition`),这是 sink 并行的关键(hashed_sort.cpp:168-200)。

Source 端把每个非空 hash bin 包成 `WindowHashGroup`,注释直接给出三种形态(physical_window.cpp:523-526):1 无分区(不排序)、2 单分区(排序无哈希)、3 多分区(排序+哈希)。每组的共享 collection 表达式按 `GetSortedExpressions` 定型(physical_window.cpp:529-535)。

**MASK 阶段**并行计算两张 `ValidityMask`:partition_mask(有效位=新分区首行)与 order_mask(有效位=新 peer 组首行),map 的 key 是"分区列数+排序列数"前缀长度(physical_window.cpp:556-577)。比较由 `WindowDeltaScanner` 驱动:分区变化行对全部 mask 置位,peer 变化再对前缀结构用 `VectorOperations::DistinctFrom` 精确判定(physical_window.cpp:579-670, 196 行定义 scanner)。并行 MASK 要求每任务的 chunk 数与 mask 的 64 位 entry 对齐(`aligned_scale`,即 `BITS_PER_VALUE / STANDARD_VECTOR_SIZE` 向上取整),否则跨线程写同一 word(physical_window.cpp:501-507)。

## 4. WindowExecutor 家族:两个 Executor + 回调注入 + 五种聚合器

执行器工厂只有两分支:

```cpp
// src/execution/operator/aggregate/physical_window.cpp:288-298
static unique_ptr<WindowExecutor> WindowExecutorFactory(BoundWindowExpression &wexpr, ClientContext &client,
                                                        WindowSharedExpressions &shared) {
    if (wexpr.GetExpressionType() == ExpressionType::WINDOW_AGGREGATE) {
        return make_uniq<WindowAggregateExecutor>(wexpr, client, shared);
    } else {
        if (!wexpr.WindowFunction().get()) {
            throw InternalException("Window expression type %s", ExpressionTypeToString(wexpr.GetExpressionType()));
        }
        return make_uniq<WindowExecutor>(wexpr, shared);
    }
}
```

基类构造注册共享表达式(src/function/window/window_executor.cpp:12-34):RANGE 边界列 `RegisterCollection`(求值前整分区物化)、帧边界表达式 `RegisterEvaluate`、函数参数默认 `RegisterEvaluate`——除非函数自带 sharing 回调改写分类。求值统一入口是"先 `UpdateBounds` 再 `EvaluateInternal`"(window_executor.cpp:36-45);Sink/Finalize 都有函数级回调优先、基类兜底的双路径(window_executor.cpp:85-104)。各函数的差异全部由 `WindowFunction` 回调承载(src/include/duckdb/function/window_function.hpp:108, 137):`window_bounds_function_t` 声明需要哪些边界,`window_canstream_function_t` 声明能否流式。典型例子:

- **row_number**:只要 `PARTITION_BEGIN/END`(有 EXCLUDE 时追加帧边界)(src/function/window/window_rownumber_function.cpp:145-152);流式实现是一个常量 1 向量递增(window_rownumber_function.cpp:90-99)。
- **rank/dense_rank/percent_rank/cume_dist**:rank 就是边界减法 `rank = (frame_peer_begin - frame_begin) + 1`(帧内)或 `(peer_begin - partition_begin) + 1`(无帧),跨 chunk 用 `NextRank` 增量维护 `rank/rank_equal`(src/function/window/window_rank_function.cpp:182-193, 225-247);带 arg_orders 时改用 `WindowTokenTree::Rank`(window_rank_function.cpp:222-228)。DENSE_RANK 不支持 `can_order_by`(function/window/README.md:54)。
- **lead/lag**:默认是 cursor 整体移位 O(1);`IGNORE NULLS`、非常量偏移或 arg_orders 使 `can_shift` 为 false 才走树路径(src/function/window/window_value_function.cpp:695-700)。带独立 `ORDER BY` 参数时按注释引用的论文算法四步走(window_value_function.cpp:237-249):

```cpp
// src/function/window/window_value_function.cpp:651-655, 665-671(节选)
// (1) compute the ROW_NUMBER of the own row
frame = FrameBounds(frame_begin[i], MaxValue(frame_end[i], frame_begin[i]));
const auto own_row = glstate.row_tree->Rank(frame.start, frame.end, row_idx) - 1;
// (2) adjust the row number by adding or subtracting an offset
...
// (3) find the row at that offset
const auto nth_index = glstate.value_tree->SelectNth(frames, n);
// (4) evaluate the expression provided to LEAD/LAG on this row.
cursor.CopyCell(0, nth_index.first, result, i);
```

其中 `WindowTokenTree` 是"用整型 token 替代排序键比较"的 merge sort tree(src/include/duckdb/function/window/window_token_tree.hpp:16-18),`WindowIndexTree` 提供 `SelectNth`(src/include/duckdb/function/window/window_index_tree.hpp:37-38)。若 arg_orders 恰是分区排序前缀,两棵树都直接省掉(window_value_function.cpp:258-272)。
- **ntile**:需要分区首尾加帧边界(window_rownumber_function.cpp:239-247);**first/nth_value**:需要帧边界 + arg-order 的 IndexTree(window_value_function.cpp:26-32)。

聚合窗口的策略阶梯(src/function/window/window_aggregate_function.cpp:60-85):

```cpp
// src/function/window/window_aggregate_function.cpp:60-76(节选)
} else if (WindowDistinctAggregator::CanAggregate(wexpr)) {
    // build a merge sort tree; see https://dl.acm.org/doi/pdf/10.1145/3514221.3526184
    aggregator = make_uniq<WindowDistinctAggregator>(wexpr, shared, client);
} else if (WindowConstantAggregator::CanAggregate(wexpr)) {
    aggregator = make_uniq<WindowConstantAggregator>(wexpr, shared, client);
} else if (WindowCustomAggregator::CanAggregate(wexpr, mode)) {
    aggregator = make_uniq<WindowCustomAggregator>(wexpr, shared);
} else if (WindowSegmentTree::CanAggregate(wexpr)) {
    // see http://www.vldb.org/pvldb/vol8/p1058-leis.pdf
    aggregator = make_uniq<WindowSegmentTree>(wexpr, shared);
}
```

进入阶梯前,`SimplifyWindowedAggregate` 先剥修饰符:`DISTINCT` 不影响结果则清除;`arg_orders` 非 order-dependent、或恰为分区排序前缀,则清空(window_aggregate_function.cpp:33-53)。五路策略的准入条件:

- **Naive**(兜底):聚合函数可按 aggregate 方式调用即可,每帧从头聚合(window_naive_aggregator.cpp:377-383;Evaluate 用 `EvaluateSubFrames` 逐子帧调 aggregate_executor,window_naive_aggregator.cpp:223-238)。debug 设置 `DebugWindowModeSetting=SEPARATE` 或关闭优化器时强制 naive(window_aggregate_function.cpp:60-64)。
- **SegmentTree**:无 DISTINCT、无 arg_orders、非 COUNT(*),且函数不能自带 window 回调(window_segment_tree.cpp:13-25);fanout=16 的扁平数组 `levels_flat_native`,按层并行构建(window_segment_tree.cpp:60, 44-52, 377-430)。
- **Custom**:聚合函数自带 `CanWindow()` 回调(如内置 window 化聚合),要求无 arg_orders、无 DISTINCT、`mode < COMBINE`(window_custom_aggregator.cpp:10-28)。`WindowAggregationMode{WINDOW,COMBINE,SEPARATE}` 是 debug 设置,不是运行时自动选择(src/include/duckdb/common/enums/window_aggregation_mode.hpp:10-22)。
- **Constant**:帧整体等于"分区起点到当前 peer 组尾"(标准 RANGE 缺省帧),无 EXCLUDE、无 DISTINCT、有参数(COUNT(*) 让给段树),每分区只聚合一次、结果缓存为向量按分区偏移广播(window_constant_aggregator.cpp:97-133, 31-47)。
- **Distinct**:`DISTINCT` + 无 EXCLUDE + 无 arg_orders,构建 (prev_idx,input_idx) 压缩的 `WindowDistinctSortTree`(window_distinct_aggregator.cpp:20-43)。

FILTER 子句在共享 sink 表达式里物化为布尔列,Sink 时 `SelectExpression` 成 SelectionVector,进入聚合器的 `ValidityArray filter_mask`(window_aggregate_function.cpp:89-92, 111-135, 149-158)。Finalize 时还用边界列统计 `FrameStats`(帧宽上下界,供段树估计叶子范围),`ApplyWindowStats` 按 UNBOUNDED/CURRENT/EXPR 各边界类型收缩统计(window_aggregate_function.cpp:226-252, 163-224)。

## 5. 分帧:8 个边界、三种模式、EXCLUDE 子帧

帧边界是 8 列 UBIGINT 的 bounds chunk(src/include/duckdb/function/window_function.hpp:31-49;window_boundaries_state.cpp:441-442):PARTITION_BEGIN/END、PEER_BEGIN/END、VALID_BEGIN/END、FRAME_BEGIN/END。每个函数用 `window_bounds_function_t` 声明所需子集,`AddImpliedBounds` 补全依赖闭包——如 RANGE 前置边界隐式需要 PEER_BEGIN+VALID_BEGIN/END,EXCLUDE GROUP/TIES 需要 peer 边界,VALID_END 需要 PARTITION_END(src/function/window/window_boundaries_state.cpp:321-417)。`UpdateBounds` 只算声明的列,并处理 `is_jump`(GETDATA 乱序跨行时用 `FindPrevStart` 回退搜索)(window_boundaries_state.cpp:451-492, 460-463)。行内边界值经 `WindowInputExpression` 读取,常量向量走快路径(window_boundaries_state.hpp:24-35)。

三种模式的实现差异全在 FrameBegin/FrameEnd 的 switch(window_boundaries_state.cpp:674-1007):

- **ROWS**:纯算术 `row_idx ± offset`,带 `TryAdd/TrySubtract` 溢出保护,负偏移与 NULL 抛 InvalidInputException(713-747, 880-916);所有结果最后 `ClampFrame` 到分区内(src/include/duckdb/function/window/window_boundaries_state.hpp:83-87)。
- **RANGE**:`FindOrderedRangeBound` 在排好的 order 列上做 `std::lower_bound/upper_bound`(ASC 用 LessThan,DESC 用 GreaterThan),迭代器直接包在 `WindowCursor` 上;并用上一行帧 `prev` 作二分区间收缩提示(185-244):

```cpp
// src/function/window/window_boundaries_state.cpp:239-243
if (FROM) {
    return idx_t(std::lower_bound(begin, end, val, comp));
} else {
    return idx_t(std::upper_bound(begin, end, val, comp));
}
```

NULL 不参与 RANGE 比较:VALID_BEGIN/END 在分区建立时跳过首尾 NULL(612-672);`CURRENT ROW` 在 RANGE/GROUPS 语义下直接引用 PEER_BEGIN/END 向量,零计算(706-711, 869-874)。偏移超出当前值会抛 OutOfRangeException(199, 206)。
- **GROUPS**:偏移语义是"第 n 个 peer 组",用 `FindPrevStart/FindNextStart` 在 order_mask 上数组跳跃(788-832);这两个函数对 `CannotHaveNull` 的 mask 有 O(1) 快路径(14-78)。

**EXCLUDE 语义**不是过滤数据,而是把帧切成有序、不相交的最多 3 个子帧(`WindowExcludeMode{NO_OTHER,CURRENT_ROW,GROUP,TIES}`,src/include/duckdb/parser/expression/window_expression.hpp:34):LEFT(帧首到 peer 首/当前行)、TIES 时单独一个当前行子帧、RIGHT(peer 尾/当前行+1 到帧尾),并保证"左右有序、不相交、start<=end、个数恒定"(src/include/duckdb/function/window/window_aggregator.hpp:32-81)。段树对 EXCLUDE 用左右两份聚合状态分别评估再 `Combine`:CURRENT_ROW 的分割点是 peer 边界,否则是帧边界(window_segment_tree.cpp:447-468)。

## 6. 并行:六阶段任务状态机与流式窗口

每个 hash group 是一个独立状态机 `WindowGroupStage{SORT, MATERIALIZE, MASK, SINK, FINALIZE, GETDATA, DONE}`,阶段推进用原子计数门控(physical_window.cpp:18, 86-130);任务按"阶段为主序"编号——同组内所有线程先做完 SORT 才进 MATERIALIZE(physical_window.cpp:132-149):

```cpp
// src/execution/operator/aggregate/physical_window.cpp:136-144(节选)
const auto group_stage = GetStage();
const auto group_threads = GetThreadCount();
task.stage = WindowGroupStage(next_task / group_threads);
if (task.stage == group_stage) {
    task.thread_idx = next_task % group_threads;
    task.group_idx = group_idx;
    task.begin_idx = task.thread_idx * per_thread;
    task.end_idx = MinValue<idx_t>(task.begin_idx + per_thread, ChunkCount());
```

任务总量 `= 线程数 × 6`;最大分区优先调度,`group_threads = ceil(blocks/per_thread)`,分区间是松耦合的 work-stealing:source 线程在 `active_groups` 里轮询,组完成即从活跃表移除(physical_window.cpp:480-516, 738-744, 928-992)。`MaxThreads() = total_blocks`(physical_window.cpp:445-447)。SINK 阶段把共享表达式物化进每组的 `WindowCollection`(ColumnDataCollection 包装,src/include/duckdb/function/window/window_collection.hpp:19-25)并喂给所有 executor(physical_window.cpp:815-880);SINK→FINALIZE 按块门控而非按行,否则 FINALIZE 会读到其他线程未初始化的 thread_states 条目(physical_window.cpp:107-115)。FINALIZE 先 Combine 集合、再逐函数构建段树/排序树——树构建内部自带跨线程 fan-in(原子 build_level/build_started/build_completed,physical_window.cpp:882-906;window_segment_tree.cpp:377-430)。GETDATA 每线程按块扫回,输出 = 输入列 + 各函数结果列(physical_window.cpp:1045-1088)。

**流式窗口**条件:OVER() 全空、无 arg_orders、无 EXCLUDE;聚合需为"running total"帧(UNBOUNDED PRECEDING..CURRENT ROW ROWS)且聚合函数无状态析构回调(quantiles 这类被排除),普通函数须声明 `CanStream`(src/execution/operator/aggregate/physical_streaming_window.cpp:178-197):

```cpp
// src/execution/operator/aggregate/physical_streaming_window.cpp:185-192(节选)
if (wexpr.GetExpressionType() == ExpressionType::WINDOW_AGGREGATE) {
    // Aggregates with destructors (e.g., quantile) are too slow to repeatedly update/finalize
    if (wexpr.AggregateFunction()->HasStateDestructorCallback()) {
        return false;
    }
    // We can stream aggregates if they are "running totals"
    return wexpr.WindowStart() == WindowBoundary::UNBOUNDED_PRECEDING &&
           wexpr.WindowEnd() == WindowBoundary::CURRENT_ROW_ROWS;
}
```

lead/lag 流式要求 foldable 偏移/默认值,且 `|offset| < MAX_BUFFER = 2048` 行前瞻(physical_streaming_window.cpp:32;window_value_function.cpp:520-533)。流式 API 是"全有或全无":声明 CanStream 就必须提供 state+stream 回调(function/window/README.md:24, 184-192)。

## 7. 纠偏(以 7e886f44 源码为准)

1. **文件位置**:窗口执行器不在 `src/execution/window_executor.cpp`,而在 `src/function/window/window_executor.cpp` 及同目录 18 个文件;`src/execution/operator/aggregate/` 下只有 physical_window.cpp / physical_streaming_window.cpp 两个宿主算子(physical_window.cpp:6-8 的 include 即证)。
2. **"每类函数一个执行器"不成立**:Executor 仅 `WindowExecutor` 与 `WindowAggregateExecutor` 两个(physical_window.cpp:288-298);lead/lag/rank/ntile/first_value 全是同一基类 + `WindowFunction` 回调(bounds/sharing/local/sink/finalize/evaluate/can_stream)注入(window_function.hpp:108-173)。
3. **策略名修正**:不是"Constant/Special/Proable";调试枚举是 `WindowAggregationMode{WINDOW,COMBINE,SEPARATE}`(window_aggregation_mode.hpp:10-22),运行时是五路 if-else 阶梯 Distinct→Constant→Custom→SegmentTree→Naive,固定顺序、先到先得(window_aggregate_function.cpp:60-85)。
4. **order-dependent 常被误读**:带 ORDER BY 的窗口 sink 是可并行的;只有裸 `OVER()`(无分区无排序)才 `is_order_dependent=true` 并关闭 ParallelSink(physical_window.cpp:271-273;physical_window.hpp:83-89)。
5. **"全局排序"不存在**:排序以 hash 分区为单位独立进行,分区间无序;输出保序仅在单分区场景承诺,且依赖 batch_index 归并(physical_window.cpp:1101-1124, 1049)。
6. **EXCLUDE 不做行过滤**:实现为最多 3 个子帧(SubFrames)重排,段树用左右两份状态 combine(window_aggregator.hpp:32-81;window_segment_tree.cpp:447-468)。
7. **lead/lag 并非总是 O(n log n) 树**:默认 `can_shift` 路径是 cursor 移位 O(1),只有 IGNORE NULLS/非常量偏移/arg_orders/framing 才升级(window_value_function.cpp:695-700)。

## 8. 设计动机

1. **分区即并行单元**:每个 hash group 独立状态机+原子计数+任务队列,大组优先、线程数按块数分配,组间以 work-stealing 松耦合,避免组间负载倾斜(physical_window.cpp:480-516, 86-149)。
2. **边界按需计算**:8 种边界由各函数声明子集,`AddImpliedBounds` 求闭包,回避昂贵的 peer/valid 边界全算(window_boundaries_state.cpp:321-417;function/window/README.md:81-102)。
3. **数据结构换时间**:聚合按形态选择增量结构——running total 常量化、一般帧段树(Leis VLDB'15)、DISTINCT merge sort tree(SIGMOD'22),naive 只做兜底(window_aggregate_function.cpp:60-85)。
4. **表达式共享与去重**:`WindowSharedExpressions` 三类注册(sink/collection/evaluate)按表达式去重,volatile 表达式强制独立列(window_shared_expressions.cpp:6-26);plan 层再做窗口 CSE(plan_window.cpp:120-131)。
5. **一次物化多处引用**:排序结果、共享表达式都进 `WindowCollection`,各执行器用 `WindowCursor` 随机读取,避免重复拷贝(physical_window.cpp:529-535;window_collection.hpp:19-25)。
6. **顺序性做成可选契约**:`SourceOrder/SupportsPartitioning/batch_index` 让无分区窗口能给下游交付确定顺序,有分区时坦承无序(physical_window.cpp:1101-1124)。
7. **可扩展**:V2.0 起窗口函数是 catalog 函数类型,扩展可注册新窗口函数与流式实现,内置函数与扩展走同一套 API(function/window/README.md:3-13, 230-241)。

## 9. FAQ 候选

1. PhysicalWindow 为什么既是 sink 又是 source?——窗口函数需整分区就绪后求值,先 sink 进 radix 分区排序存储,再在 source 端按阶段计算(physical_window.cpp:342-349, 1155-1186)。
2. ORDER BY 在哪执行?——在 PhysicalWindow 内部 SortStrategy 的 SORT/MATERIALIZE 阶段,不是独立排序算子(physical_window.cpp:746-783)。
3. 什么窗口能流式?——OVER() 全空、无 arg_orders、无 EXCLUDE,且函数声明 CanStream 或聚合是 running-total 帧(physical_streaming_window.cpp:178-197)。
4. MASK 阶段为什么存在?——把分区/peer 边界预计算成 ValidityMask,求值期 `FindNextStart/FindPrevStart` 在位图上跳跃而非逐行比较(physical_window.cpp:579-671;window_boundaries_state.cpp:14-78)。
5. rank 为什么便宜?——它是 `peer_begin - frame_begin + 1` 的边界减法加跨 chunk 增量,不建任何树(window_rank_function.cpp:225-247)。
6. lead/lag 何时变贵?——IGNORE NULLS、非常量偏移、独立 ORDER BY 参数或帧内 framing 时退化为 TokenTree+IndexTree 的 O(n log n)(window_value_function.cpp:638-700)。
7. DISTINCT SUM() OVER 怎么算?——WindowDistinctAggregator 构建 (prev_idx,input_idx) 压缩 MergeSortTree,排除 EXCLUDE/arg_orders 组合(window_distinct_aggregator.cpp:20-36)。
8. FILTER 子句去哪了?——物化为共享布尔列,Sink 时 SelectExpression 成 SelectionVector,进聚合器 ValidityArray(window_aggregate_function.cpp:89-92, 149-158)。
9. SINK→FINALIZE 为什么按块门控?——按行计数会让 FINALIZE 读到其他线程尚未初始化的 thread_states 条目(physical_window.cpp:107-115)。
10. 多个窗口函数怎么共享工作?——规划期按分区等价+排序公共前缀分组,同组表达式完全一致时 CSE 消除(plan_window.cpp:82-140)。

## 11. 正文蒸馏要点

1. 窗口执行器位于 `src/function/window/`(window_executor.cpp 等),宿主算子只有 PhysicalWindow/PhysicalStreamingWindow;V2.0 起窗口函数是 catalog 函数类型而非枚举特判,扩展与内置走同一 API(function/window/README.md:3-13)。
2. 规划期三分:streaming / partitioned(常量分区下推)/ blocking,且 streaming 优先,partitioned 让位(plan_window.cpp:41-59)。
3. 多个窗口函数按"分区等价 + ORDER BY 公共前缀"分组共享一个 PhysicalWindow,同组完全一致的表达式做 CSE(plan_window.cpp:82-140)。
4. `is_order_dependent` 仅指裸 `OVER()`:此时 sink 必须保序不可并行;带 ORDER BY 反而可乱序 sink,顺序在 source 重建(physical_window.cpp:271-273;physical_window.hpp:83-89)。
5. Sink 阶段全部转发 SortStrategy,四策略按形态选择:PartitionedSort/HashedSort/FullSort/NaturalSort(sort_strategy.cpp:35-49);HashedSort 用 radix 分区并按行组大小自动扩位(hashed_sort.cpp:130-145)。
6. Source 端每 hash group 走 SORT→MATERIALIZE→MASK→SINK→FINALIZE→GETDATA 六阶段,任务按阶段主序分配,SINK→FINALIZE 按块门控(physical_window.cpp:18, 86-149)。
7. MASK 阶段并行构建 partition_mask/order_mask,把"比较出边界"变成"位图上找边界",任务块须与 64 位 mask entry 对齐(physical_window.cpp:501-507, 579-671)。
8. 帧求值基于 8 列 UBIGINT bounds,函数按需声明+依赖闭包补全;is_jump 支持乱序 GETDATA 回退(window_function.hpp:31-49;window_boundaries_state.cpp:321-417, 460-463)。
9. ROWS 是纯算术、RANGE 是 lower/upper_bound 二分(带 prev 提示与 NULL 跳跃)、GROUPS 是 order_mask 上数 peer 组(window_boundaries_state.cpp:674-1007, 185-244, 788-832)。
10. EXCLUDE 实现为最多 3 个有序子帧,段树用左右两份状态 combine(window_aggregator.hpp:32-81;window_segment_tree.cpp:447-468)。
11. 聚合策略阶梯 Distinct(MergeSortTree)→Constant(分区常量化)→Custom(window 回调)→SegmentTree(fanout=16)→Naive 兜底,前置 SimplifyWindowedAggregate 剥离无效 DISTINCT/arg_orders(window_aggregate_function.cpp:33-85)。
12. 流式窗口要求 OVER() 全空且函数声明 CanStream(lead/lag 还要求 foldable 偏移 <2048 行前瞻);row_number 的流式实现是常量向量递增(physical_streaming_window.cpp:178-197;window_rownumber_function.cpp:90-99)。
