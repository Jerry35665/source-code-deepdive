# 报告 F3 · 扩展体系与多端工具(DuckDB 卷三)

> 基线:7e886f44("Added connection_progress_get to the capi v2 (#25681)")。一句话总结:DuckDB 扩展体系是"静态链接注册表 + 动态 dlopen 双轨"加载流水线——静态轨由 CMake 生成代码把扩展清单发布到 `DBConfig::linked_extensions`,动态轨对 `.duckdb_extension` 文件做 MbedTLS SHA-256 双层签名校验后 `dlopen`;所有扩展默认挂到 system catalog 的 `main` schema;本仓库 `tools/` 只剩 cpp/shell/sqllogic/swift/utils 五个目录,python/jdbc/odbc/r 等语言绑定已不在本仓库。

## 1. 目录地图与静态内嵌扩展

扩展体系代码分两条线:`extension/` 放扩展本体(内嵌源码 + 构建脚本),`src/main/extension/` 放加载机制(6 个 .cpp 共 3513 行,`wc -l` 实测)。

- 机制侧六件套:`extension_helper.cpp`(962 行,内嵌清单/白名单/公钥)、`extension_load.cpp`(936 行,dlopen 与签名)、`extension_install.cpp`(659 行,安装目录)、`extension_loader.cpp`(404 行,ExtensionLoader 注册 API)、`extension_alias.cpp`(40 行,别名)、`extension_repository_manager.cpp`(512 行,用户自建仓库)。
- `extension/` 当前内嵌目录(`ls` 实测):autocomplete、core_functions、delta、demo_capi、icu、json、loader、parquet、tpcds、tpch。
- 各扩展一句话:`core_functions` 核心函数库(scalar/aggregate/lambda,约 3.3 万行);`parquet` 列式读写(2.7 万行);`json` JSON 类型/读写/序列化(1.3 万行);`icu` 时区与 collation(4.7 万行,含生成数据);`tpch`/`tpcds` 基准数据生成与查询(tpcds 达 6.9 万行);`autocomplete` shell 补全;`demo_capi` C API 示例;`loader` 仅 dummy 静态扩展样例;`delta` 只剩 README 占位(`extension/delta/README.md`),是"已迁出主仓"的直接证据。
- 官方分类(`extension/README.md:13-24`):in-tree(与引擎同步演进、随主仓 CI)与 out-of-tree(独立仓库、独立 CI,分 DuckDB 托管与外部两种)。

静态扩展的发现**不是**直接调用生成代码,而是查配置里的注册表:

```cpp
// src/main/extension/extension_helper.cpp:95-107
//! Loads an extension that was linked into the binary, via the registry the config carries. This is
//! deliberately not generated code: an extension with its own copy of DuckDB links no generated
//! loader, so a compile-time list would be invisible to it, while the config is data it can read.
ExtensionLoadResult ExtensionHelper::LoadExtension(DuckDB &db, const std::string &extension) {
    auto &config = DBConfig::GetConfig(*db.instance);
    for (auto &linked : config.linked_extensions) {
        if (StringUtil::CIEquals(linked.name, extension)) {
            linked.load(db);
            return ExtensionLoadResult::LOADED_EXTENSION;
        }
    }
    return ExtensionLoadResult::NOT_LOADED;
}
```

核心清单是 `internal_extensions[]` 表(31 项,`src/main/extension/extension_helper.cpp:121-152`),每项 `名字 + 描述 + 是否已链接`:

- 前 9 项带编译期开关、可静态链入:core_functions、icu、excel、parquet、tpch、tpcds、httpfs、json、autocomplete(`extension_helper.cpp:122-130`)。
- 注意:excel 与 httpfs 的源码已不在 `extension/` 下,只留编译旗标与默认 false(`extension_helper.cpp:29-31,45-47`)。
- 其余 22 项(motherduck、mysql_scanner、odbc_scanner、sqlite_scanner、postgres_scanner、inet、spatial、aws、azure、encodings、iceberg、vss、delta、fts、ui、ducklake、quack、vortex、lance、avro、unity_catalog 等)固定 false,只能动态加载(`extension_helper.cpp:131-151`)。

启动时序与构建管线:

- 注册表 `vector<LinkedExtension> linked_extensions` 在 `src/include/duckdb/main/config.hpp:286`;内容由 CMake 生成代码 `ExtensionHelper::RegisterLinkedExtensions` 填充(`extension/generated_extension_loader.cpp.in:11-13`),编译旗标由 `extension/extension_build_tools.cmake:19` 的 `-DDUCKDB_EXTENSION_<NAME>_LINKED=1` 驱动。
- `DatabaseInstance::Initialize` 调 `RegisterLinkedExtensions(config)`(`src/main/database.cpp:311`)→ `DuckDB` 构造函数在 `options.load_extensions` 时调 `LoadAllExtensions` 按注册顺序全部加载(`database.cpp:376-379`、`extension_helper.cpp:109-116`)。
- 发行版默认链哪些?`.github/config/bundled_extensions.cmake:17-26`:链接 icu、json、parquet、autocomplete(core_functions 经 `core.cmake:3` 一并载入),tpcds/tpch 标 `DONT_LINK`——构建但不链,运行时走动态轨。
- 静态 C API 扩展另有专口:`DuckDB::LoadStaticCAPIExtension(V2)`,install mode 记为 `STATICALLY_LINKED`,静态加载时 `get_api` 为 null(直接链符号,不需 vtable)(`src/main/extension/extension_load.cpp:155-187,189-217`)。

## 2. 动态扩展加载:dlopen、签名校验与搜索顺序

`INSTALL/LOAD` SQL 的执行终点是 `PhysicalLoad::GetDataInternal`(`src/execution/operator/helper/physical_load.cpp:73-105`):INSTALL 分支调 `ExtensionHelper::InstallExtension`,INSTALL AND LOAD 紧接着 `LoadExternalExtension`,LOAD 分支带 alias/repository 选项加载,之后 `RefreshSearchPath`。主流程在 `TryInitialLoad`(`extension_load.cpp:455-728`)。

**(1) 搜索顺序**(短名加载,即名字不含 `.`/`/`/`\`,判定在 `extension_load.cpp:755-758`):

```cpp
// src/main/extension/extension_load.cpp:534-568(节选)
// Collect all directories to search for extensions
vector<string> search_directories;
auto custom_extension_directory = Settings::Get<ExtensionDirectorySetting>(db);
if (!custom_extension_directory.empty()) {
    search_directories.push_back(custom_extension_directory);        // ① SET extension_directory
}
if (!db.config.options.extension_directories.empty()) {
    for (const auto &dir : db.config.options.extension_directories) {
        search_directories.push_back(dir);                           // ② 配置的目录列表
    }
}
if (search_directories.empty()) {
    for (const auto &path : ExtensionHelper::DefaultExtensionFolders(fs)) {
        search_directories.push_back(path);                          // ③ 默认 ~/.duckdb/extensions
    }
}
```

- 默认目录:`~\.duckdb\extensions`(Win)或 `~/.duckdb/extensions`,CMake 变量 `DUCKDB_EXTENSION_DIRECTORIES` 可改(`extension_install.cpp:65-95`)。
- 目录内再拼 `<版本|commit>/<平台>/<名>.duckdb_extension`(`extension_load.cpp:519-532`);版本段取 release tag 或 source id(`extension_install.cpp:38-47`),平台段如 `linux_amd64`/`osx_arm64` 由 `src/include/duckdb/common/platform.hpp:37-75` 编译期推断。
- 用户自建仓库的扩展放 `repositories/<名>/` 子目录,必须 `LOAD x FROM <repo>` 才找得到(`extension_load.cpp:468-488,528-530`)。

**(2) 元数据 footer**:扩展文件末尾 512 字节是 footer(`FOOTER_SIZE=512`,`SIGNATURE_SIZE=256`,`src/include/duckdb/main/extension.hpp:45-46`),由 8 个 32 字节字段倒序组成:magic、平台、duckdb 版本或 CAPI 版本、扩展版本、ABI 类型(`extension_load.cpp:331-371`)。后缀不是 `.duckdb_extension` 直接拒绝(`extension_load.cpp:574-579`)。

**(3) 签名校验**:非 `allow_unsigned_extensions` 时执行(`extension_load.cpp:626-663`)。

- 哈希算法:**两层 SHA-256**——对除末尾 256 字节签名外的内容按 1MB 分块(8KB 步长读入)并行哈希,再把块哈希拼接做总哈希(`extension_load.cpp:258-282,284-302`)。
- 密码学原语是 **MbedTLS wrapper,不是 OpenSSL**(`extension_load.cpp:14,247-252`;`third_party/mbedtls`)。
- 逐一试受信公钥验签(`CheckKnownSignatures`,`extension_load.cpp:392-407`);信任键按仓库来源分流(`GetTrustedPublicKeys`,`extension_helper.cpp:905-942`):核心仓 20 把内置公钥、community 仓 19 把社区公钥、用户自建仓只用其登记的键。
- 裸 LOAD(无 FROM)把来源强制压回 core/community 键(`ResolveTrustedSignatureOrigin`,`extension_helper.cpp:944-960`),防止重定向 extension_directory 借用户仓键载入原生代码;用户仓扩展裸 LOAD 会得到专门错误(`extension_load.cpp:653-663`)。
- `.info` 安装信息文件记录来源仓库;FROM 加载核对来源一致性,防止"借名加载"(`extension_load.cpp:604-624`)。

**(4) dlopen 与入口点**:`dlopen(filename, RTLD_NOW | RTLD_LOCAL)`(`extension_load.cpp:694`)。按 ABI 找入口(`extension_load.cpp:817-903`):C++ 扩展 `<名>_duckdb_cpp_init`;C ABI V1 `<名>_init_c_api`;C ABI V2(`<名>_init_c_api_v2`,`C_STRUCT_UNSTABLE` 亦归 V2,`extension_load.cpp:30-40`)。

**(5) 失败兜底**:加载失败且在自动安装白名单时,先 `InstallExtension` 再重试一次(`InitialLoad`,`extension_load.cpp:730-753`)。

两份白名单与默认值:

- 自动安装白名单 `auto_install[]` 仅 10 项(motherduck、postgres/mysql/odbc/sqlite_scanner、delta、iceberg、unity_catalog、ui、ducklake)(`extension_helper.cpp:169-183`)。
- 自动加载白名单 `AUTOLOADABLE_EXTENSIONS` 有 26 项(`src/include/duckdb/main/extension_entries.hpp:1544-1548`)。**两表互不相同**。
- autoload/autoinstall 默认值构建期决定:settings 默认 false(`src/include/duckdb/main/settings.hpp:457-473`),CMake option 默认 FALSE(`CMakeLists.txt:305-306,396-401`);发行版 Makefile 显式 `-DENABLE_EXTENSION_AUTOLOADING=1 -DENABLE_EXTENSION_AUTOINSTALL=1`(`Makefile:464`)。
- 别名表 10 条(http/https/s3→httpfs、md→motherduck、mysql、odbc、postgres、sqlite/sqlite3→sqlite_scanner、uc_catalog→unity_catalog)(`src/main/extension/extension_alias.cpp:6-17`)。
- catalog 查不到条目时的 autoload 入口:`Catalog::TryAutoLoad`(`src/catalog/catalog.cpp:656-671`)。


## 4. Catalog 挂载与函数/宏注册

**CatalogType 全集**(`src/include/duckdb/common/enums/catalog_type.hpp:15-51`):表 1、schema 2、视图 3、索引 4、预编译语句 5、序列 6、collation 7、类型 8、库 9、坐标系 10、触发器 11;函数八类 TABLE 25 / SCALAR 26 / AGGREGATE 27 / PRAGMA 28 / COPY 29 / MACRO 30 / TABLE_MACRO 31 / WINDOW 32;版本标记 DELETED 51 / RENAMED 52;秘密三件套 SECRET 71 / SECRET_TYPE 72 / SECRET_FUNCTION 73;DEPENDENCY 100。基类 `CatalogEntry` 自带 `extension_name` 字段("The name of the extension that registered this entry (empty for core entries)",`src/include/duckdb/catalog/catalog_entry.hpp:36-55`),是扩展产物在 catalog 里的身份标记。

**扩展的落点**:system catalog(名字就叫 "system",`src/include/duckdb/common/constants.hpp:34`)的 main schema(`DEFAULT_SCHEMA "main"`,`constants.hpp:31`)。

```cpp

void ExtensionLoader::RegisterFunction(CreateScalarFunctionInfo function) {
    D_ASSERT(!function.functions.name.empty());
    function.extension_name = GetRegisteredExtensionName();
    if (function.GetQualifiedName().Schema() == DEFAULT_SCHEMA) {
```

- 默认注册 schema 是 main(`src/include/duckdb/main/extension/extension_loader.hpp:36`:`Identifier extension_schema = Identifier::DefaultSchema();`)。
- 冲突策略统一 `ALTER_ON_CONFLICT`(`extension_loader.cpp:132`),重复 LOAD 幂等。
- 想隔离的扩展可调 `UseDedicatedSchemaForExtension`:建 internal schema + 设默认注册 schema + 加搜索路径三步(`extension_loader.cpp:47-56,58-68,86-107`);`pg_catalog` 被禁止占用(`extension_loader.cpp:76-78`)。

- 可注册种类全集:标量/聚合/窗口/表/pragma/copy 函数、宏、collation(同时注册为函数以便序列化)、坐标系、类型、secret、cast、指标(`extension_loader.cpp:122-402`)。

## 7. 设计动机与 FAQ 候选

**设计动机**:

1. **双轨加载,零成本降级**:静态链接得单文件发行版;`DONT_LINK` 的 tpch/tpcds 走动态轨照样可测(`bundled_extensions.cmake:25-26`)。
2. **注册表解耦生成代码**:`linked_extensions` 放 DBConfig 而非编译期符号,嵌套场景(扩展自带一份 DuckDB)也能识别宿主已链扩展,避免 ODR 违例(`extension_load.cpp:779-791`、`extension_helper.cpp:95-97`)。
3. **供应链安全五道闸**:magic footer 自描述 → 两层 SHA-256 → 来源感知信任键 → 裸 LOAD 强制 core/community 键 → `allow_unsigned_extensions` 逃生门(`extension_load.cpp:592-670`)。
4. **占位函数 + autoload 的无感体验**:启动只注册轻量占位,真正调用才安装/加载并重绑定(`built_in_functions.cpp:102-131`)。
5. **catalog 单一登记口**:所有扩展产物都是带 `extension_name` 的 `CatalogEntry`,配合 `ALTER_ON_CONFLICT` 实现幂等、溯源、统一依赖管理(`catalog_entry.hpp:55`、`extension_loader.cpp:132`)。
6. **版本/平台目录隔离**:`<version>/<platform>/` 布局让多版本多平台二进制共存,升级引擎不重装扩展(`extension_install.cpp:49-51`)。
7. **核心瘦身战略**:delta、excel、httpfs 等迁出主仓,`extension/` 仅留与引擎耦合最深的部分(`extension/README.md:13-24`)。

## 8. 正文蒸馏要点

1. 扩展机制代码在 `src/main/extension/`(6 文件 3513 行),扩展本体在 `extension/`(当前 10 个目录,delta 仅剩 README)。
2. `internal_extensions[]` 31 项是总注册表,前 9 项可静态链接;excel/httpfs 仅存旗标、源码已迁出(extension_helper.cpp:121-152)。
3. 静态加载 = CMake 生成 `RegisterLinkedExtensions` 发布清单到 `config.linked_extensions`,`LoadExtension` 手写查表执行 load 函数(database.cpp:311;extension_helper.cpp:98-107)。
4. 启动时 `DuckDB` 构造器按 `load_extensions` 选项把已链扩展按注册顺序全部加载(database.cpp:376-379)。
5. 动态加载搜索顺序:custom_extension_directory → extension_directories → `~/.duckdb/extensions`,再拼 `<版本>/<平台>/<名>.duckdb_extension`(extension_load.cpp:534-568;extension_install.cpp:38-51)。
6. 签名校验是 MbedTLS(非 OpenSSL)SHA-256 两层哈希(1MB 分块),footer 512B/签名 256B;公钥按 core 20 把/community 19 把/用户仓分流(extension_load.cpp:258-282;extension_helper.cpp:458-889)。
7. 裸 LOAD 只信 core/community 键,用户自建仓扩展必须 `LOAD x FROM <repo>`,防目录重定向攻击(extension_helper.cpp:944-960;extension_load.cpp:653-663)。
8. 三个 ABI 入口:`<名>_duckdb_cpp_init` / `<名>_init_c_api` / `<名>_init_c_api_v2`,dlopen 用 `RTLD_NOW|RTLD_LOCAL`(extension_load.cpp:694,817-903)。
9. 扩展产物一律写 system catalog("system")的 main schema;`CatalogEntry.extension_name` 记来源,`ALTER_ON_CONFLICT` 保证幂等(catalog_entry.hpp:55;extension_loader.cpp:132,136-146)。
10. 内建函数三层:引擎固有约 225 项恒注册;core_functions 约 386 项走扩展注册;`EXTENSION_FUNCTIONS[]` 占位函数在 bind 时触发 autoload(register_function_list.cpp:102-105;built_in_functions.cpp:102-176)。
11. `CREATE MACRO` 落为 ScalarMacro/TableMacro 两类 catalog 条目,`CreateMacroInfo.macros` 持有重载向量;扩展亦可注册宏(duck_schema_entry.cpp:240-249;create_macro_info.hpp:24-27)。
12. tools/ 仅 cpp(约 1.15 万行新 C++ API)、shell(约 1.75 万行)、sqllogic(pytest 辅助)、swift(打包)、utils(小工具);Python/JDBC/ODBC/R 绑定不在本仓库,属官方拆仓运营;C API(约 2.0 万行)在 `src/main/capi/`。
