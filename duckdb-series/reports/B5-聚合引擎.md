## 二、哈希聚合全链路:sink→combine→finalize→source

`PhysicalHashAggregate` 本体只存只读计划数据(头注释:physical_hash_aggregate.hpp:59-61);每个 GROUPING SET 一张 `RadixPartitionedHashTable`(构造:src/execution/operator/aggregate/physical_hash_aggregate.cpp:185-188;字段:physical_hash_aggregate.hpp:80-85)。只有 DISTINCT 聚合时可跳过常规 sink:

```cpp
// src/execution/operator/aggregate/physical_hash_aggregate.cpp:98-111
bool PhysicalHashAggregate::CanSkipRegularSink() const {
    if (!filter_indexes.empty()) {
        // If we have filters, we can't skip the regular sink, because we might lose groups otherwise.
        return false;
    }
    if (grouped_aggregate_data.aggregates.empty()) {
        return false;   // 无聚合时必须立刻进主 HT(:104-105)
    }
    if (!non_distinct_filter.empty()) {
        return false;
    }
    return true;
}
```

- DISTINCT finalize 是独立事件流:先 `FinalizeDistinct` 关闭去重表并插入 `HashAggregateDistinctFinalizeEvent`(physical_hash_aggregate.cpp:814-836),其任务把去重后的行回灌主 HT(回灌 :778-807,收尾 combine :810),`FinishEvent` 再插入常规 finalize 事件(:685-689)。

- 行数据在 `PartitionedTupleData`:行布局 = 组列 + hash + 各聚合状态(状态大小 `AlignValue(state_size)`,src/execution/operator/aggregate/aggregate_object.cpp:21-25;布局构造 radix_partitioned_hashtable.cpp:37-43)。**分组键执行期不序列化**:盐值快速过滤后由 `RowMatcher` 逐列比较(aggregate_hashtable.cpp:946-957);序列化只发生在状态导出/溢出(第六节末)。
- 新组在 `radix_bits>=3` 且平均每分区新组 ≤4 时写入**单分区的 `unpartitioned_data`**(aggregate_hashtable.hpp:211;aggregate_hashtable.cpp:914-926)。

## 四、Perfect Hash 聚合:触发与执行

触发判据 `CanUsePerfectHashAggregate`(plan_aggregate.cpp:131-247),须全部满足:单 grouping set 无 GROUPING 函数(:132-134);组键全为 8/16/32/64 位有/无符号整数(:140-153);每列有 min/max 统计,无统计时仅 INT8/16、UINT8/16 可用类型全域兜底(:156-173);单列 range < 2^31(:218-226);无 DISTINCT 且必须有 combine 回调(:239-245)。位宽预算:

```cpp
// src/execution/physical_plan/plan_aggregate.cpp:228-237(节选)
range += 2;   // +1 给 NULL 槽,+1 使闭区间变槽数(:185-188 注释)
idx_t required_bits = RequiredBitsForValue(UnsafeNumericCast<uint32_t>(range));   // :18-25
bits_per_group.push_back(required_bits);
perfect_hash_bits += required_bits;
// check if we have exceeded the bits for the hash
if (perfect_hash_bits > Settings::Get<PerfectHtThresholdSetting>(context)) {
    return false;   // too many bits for perfect hash
}
```

阈值设置 `perfect_ht_threshold` **默认 12**,描述写"Threshold in bytes"但比较对象是 bit 数(src/include/duckdb/main/settings.hpp:2059-2070;比较在 plan_aggregate.cpp:234-237)。执行(src/execution/perfect_aggregate_hashtable.cpp):

```cpp
// src/execution/perfect_aggregate_hashtable.cpp:68-88(节选)
if (group_data.validity.CanHaveNull()) {
    for (idx_t i = 0; i < count; i++) {
        auto index = group_data.sel->get_index(i);
        // NULL groups are considered as "0" in the hash table ... (0 << shift == 0)
        if (group_data.validity.RowIsValid(index)) {
            D_ASSERT(data[index] >= min_val);
            auto adjusted_value = UnsafeNumericCast<uintptr_t>((data[index] - min_val) + 1);
            address_data[i] += adjusted_value << current_shift;
        }
    }
}
```

- 一次性分配 `2^总位宽` 个槽,每槽 `tuple_size` 字节状态,构造时批量 `InitializeStates`(:11-58);组键不存储,由槽位反解(`ReconstructGroupVector`/Scan,:276-341)。
- update 有 clustered 快速路径(组 ID 直接映射状态指针,免散布地址,:174-213),常规路径才换算指针(:146-171)。
- **运行时不回退**:统计错误致组 ID 越界直接抛 `InvalidInputException`(提示 `PRAGMA disable_optimizer`),不退回哈希聚合(:146-153);回退只发生在计划期。
- 线程间合并是**全局限事的**:每线程一张 PerfectAggregateHashTable,Combine 在全局 mutex 下逐槽按 STANDARD_VECTOR_SIZE 批量合并(src/execution/operator/aggregate/physical_perfecthash_aggregate.cpp:163-172,锁在 :168;合并循环 perfect_aggregate_hashtable.cpp:215-249)——该路径的固有并行瓶颈。

## 五、无哈希表的两条专用路径

**ungrouped(无分组)**:全局仅一组聚合状态;每线程一份本地状态,每聚合一个状态缓冲,析构时显式调用 destructor 回调(src/execution/operator/aggregate/physical_ungrouped_aggregate.cpp:45-104,析构 :82-96)。向量化有两条:

```cpp
// src/execution/operator/aggregate/physical_ungrouped_aggregate.cpp:374-394(节选)
void LocalUngroupedAggregateState::Sink(DataChunk &payload_chunk, idx_t payload_idx, idx_t aggr_idx, idx_t count) {
    auto cluster_update = func.GetStateClusterUpdateCallback();
    if (cluster_update) {
        ClusteredAggr clustered;
        clustered.SetSingleRun(state.aggregate_data[aggr_idx].get(), count);   // 单状态批量
        aggr_input_data.clustered = &clustered;
        cluster_update(start_of_input, aggr_input_data, payload_cnt, clustered, count);
    } else {
        auto state_data = FlatVector::Writer<uintptr_t>(repeated_state_vector, count);
        for (idx_t i = 0; i < count; i++) {
            state_data.WriteValue(state_ptr);          // 同一状态指针重复 count 次
        }
        func.GetStateUpdateCallback()(start_of_input, aggr_input_data, payload_cnt, repeated_state_vector, count);
    }
}
```

- Combine 在全局 mutex 下逐聚合调用一次 combine(count=1,`ALLOW_DESTRUCTIVE`)(:132-151);DISTINCT 聚合的常规 combine 被跳过(:135-137),其状态在 distinct finalize 任务里回灌(:553-627、`CombineDistinct` :153-173)。
- finalize 无 DISTINCT 时仅置 finished(:645-656);source 输出一行(:684-705)。FILTER 在 sink 内逐聚合选择后过滤(:224-232)。有 ORDER_DEPENDENT 聚合时该算子声明 `SinkOrderDependent()`(:297-305);物理哈希聚合则恒无序(physical_hash_aggregate.hpp:137-139)。

**partitioned(源已按组列单值分区)**:每组值一个 `GlobalUngroupedAggregateState` 存进 `value_map_t`,同分区值的行直接 update 对应状态,零探测零 HT(物理算子类型 `PARTITIONED_AGGREGATE`:src/execution/operator/aggregate/physical_partitioned_aggregate.cpp:16-29;状态表 :53-56、`GetOrCreatePartition` :60-72;每线程分区切换见 :29-40 的 `current_partition`)。GROUPING SETS、GROUPING 函数、DISTINCT 聚合均不支持(plan_aggregate.cpp:34-43)。

## 七、纠偏清单 · 设计动机 · FAQ 候选 · 深挖方向

### 纠偏(以本 commit 源码为准)

1. "聚合用 radix partitioned 哈希表"不准确:`RadixPartitionedHashTable` 只是编排层,探测结构是每线程一张 GAHT 的单区线性探测指针表;且 radix_bits≥3 时新组可写进单分区 `unpartitioned_data`(aggregate_hashtable.hpp:211、aggregate_hashtable.cpp:914-926)。
2. "perfect hash = 小基数聚合"过粗:精确判据是整数键 + min/max 统计 + 位宽和 ≤12(bit)+ 无 DISTINCT + 有 combine;缺统计时仅 ≤16 位小类型用类型全域兜底(plan_aggregate.cpp:131-247);且运行时统计错误**不回退而是抛错**(perfect_aggregate_hashtable.cpp:146-153)。
3. "Combine 阶段完成状态合并"是旧图景:本 commit 真正的分区合并被推迟到 **source 阶段**的 FINALIZE 任务(每分区一张临时 HT 逐 chunk 合并);sink 的 Finalize 只做分区切分与状态标记(radix_partitioned_hashtable.cpp:965-1039、1158-1186、1231-1307)。
4. "无分组聚合也走哈希表"错:ungrouped 零哈希表,单全局状态 + 每线程状态,mutex 下逐聚合一次 combine(count=1)(physical_ungrouped_aggregate.cpp:132-151)。
5. "string_agg 自己维护排序状态"错:排序由计划期注入的 sorted-aggregate 包装器(链表缓冲+整体排序)实现,string_agg 状态只有字符串缓冲三元组(sorted_aggregate_function.cpp:209、266-282;string_agg.cpp:9-14)。
6. `PhysicalHashAggregate::SinkGroupsOnly` 只有声明、无定义无调用(physical_hash_aggregate.hpp:161-163,全仓 grep 仅此一处),属死声明;"仅 DISTINCT 聚合时跳过常规 sink"由 `CanSkipRegularSink` 实现(physical_hash_aggregate.cpp:98-111)。

### 设计动机(≥5)

1. 每线程私有 HT + 分区对齐合并:探测零锁竞争,combine 只搬行不动状态(radix_partitioned_hashtable.cpp:880-963)。
2. 延迟到 source 的分区合并:内存按"一次一分区"计,天然衔接状态导入/导出;并行度按可驻留分区数计算(MaxThreads,:1044-1064)。
3. HLL 自适应:高唯一率放弃探测(纯追加)、低去重率扩容,把去重成本挪到 source(radix_partitioned_hashtable.cpp:533-571)。
4. perfect hash 用统计信息消除哈希与比较:组键即地址、槽位即组值,键都不用存(perfect_aggregate_hashtable.cpp:63-89、276-341)。
5. 状态内联行布局 + ArenaAllocator:变长状态连续分配、整行可搬移、析构可批量(radix_partitioned_hashtable.cpp:37-43;row_aggregate.cpp:35-50)。
6. DISTINCT 复用通用 radix HT 而非专用结构:sink/combine/finalize 同一套接口直接服务去重表(distinct_aggregate_data.cpp:100-116)。
7. cluster_update/ClusteredAggr:把"每行一个状态地址"退化为"单状态+计数",省散布写(row_aggregate.cpp:52-64;physical_ungrouped_aggregate.cpp:381-386)。

### FAQ 候选(每条一句话)

1. 为什么每线程一张哈希表?——避免共享探测的锁与 cache 争用,线程间只做分区对齐的行搬运。
2. 分组键执行时要序列化吗?——不要;键按行布局内联、RowMatcher 逐列比较,只有状态导出/溢出才序列化。
3. HLL 在聚合里干什么?——估计真实唯一组数,驱动"跳过查找"或"扩大容量"的一次性自适应。
4. perfect hash 的组槽为什么 +2?——非空值偏移 +1 给 NULL 留 0 号槽,再 +1 使闭区间 [min,max] 变槽数(plan_aggregate.cpp:185-188)。
5. count(*) 走哪条回调?——nullary 聚合,状态就是一个 int64 计数(count.cpp:305-306)。
6. DISTINCT 聚合并行吗?——并行;去重表本身是 radix HT,finalize 由多任务扫描回灌主 HT(physical_hash_aggregate.cpp:642-650)。
7. `GROUP BY ()` 怎么实现?——空 grouping set 伪造成 TINYINT 常量单组(radix_partitioned_hashtable.cpp:28-31)。
8. 空表聚合输出什么?——特例路径:初始化状态即 finalize 出一行,NULL 语义由函数 null_handling 定(radix_partitioned_hashtable.cpp:1390-1417)。
9. 完美哈希的 Combine 为什么慢?——全局 mutex 串行逐槽批量合并(physical_perfecthash_aggregate.cpp:166-169)。
10. 聚合状态何时析构?——destructor 回调(自动接线自 OP::Destroy),multi-scan 在全局 sink 析构时、否则 scan 消费行时调用(radix_partitioned_hashtable.cpp:284-312、1339-1341)。

## 八、正文蒸馏要点

1. 聚合物理化四路分发,顺序 ungrouped → partitioned → perfect hash → hash,判定全在计划期一个函数内(plan_aggregate.cpp:278-310)。
2. `RadixPartitionedHashTable` 是编排层而非哈希表本体;探测结构是每线程 GAHT 的盐值线性探测指针表,容量恒为 2 的幂、负载因子 1.5(aggregate_hashtable.hpp:87;aggregate_hashtable.cpp:875-882)。
3. 每行布局 = 组列 + hash + 各聚合状态(状态大小 AlignValue 对齐),分组键执行期不序列化(radix_partitioned_hashtable.cpp:37-43;aggregate_object.cpp:21-25)。
4. Sink 的本地 HT 满时按"多线程 Abandon / 需要时 Repartition / 状态压力导出"三步消化,常规路径每 chunk 只做探测与 update(radix_partitioned_hashtable.cpp:824-878)。
5. Combine 只做分区对齐的行合并;真正的状态合并(FINALIZE 任务)发生在 source 阶段,单线程单 HT 且未 abandon 时合并被整体跳过(radix_partitioned_hashtable.cpp:880-963、1002-1028、1231-1307)。
6. Perfect hash 触发判据是位宽和 ≤ `perfect_ht_threshold`(默认 12,比较单位是 bit 而非设置描述的 byte),运行时越界抛错不回退(plan_aggregate.cpp:228-237;perfect_aggregate_hashtable.cpp:146-153)。
7. Perfect hash 的线程间合并在全局 mutex 下逐槽批量进行,是该路径的并行瓶颈(physical_perfecthash_aggregate.cpp:163-172;perfect_aggregate_hashtable.cpp:215-249)。
8. Ungrouped 聚合无哈希表:每线程每聚合一个状态,combine 在锁下 count=1 调用;向量化靠重复状态指针或 cluster_update 单跑批量(physical_ungrouped_aggregate.cpp:132-151、374-395)。
9. 源已按组列单值分区时走 `PhysicalPartitionedAggregate`:value_map 直达每值状态,零探测(plan_aggregate.cpp:255-263;physical_partitioned_aggregate.cpp:53-72)。
10. DISTINCT 是执行形态而非回调:独立 radix HT 去重 + finalize 回灌主 HT;输入相同的 DISTINCT 聚合共享去重表(physical_hash_aggregate.cpp:154-166、691-812;distinct_aggregate_data.cpp:120-170)。
11. FILTER 两段落地:计划期 filter 列移到投影尾部,执行期 SelectExpression 选行后按过滤地址调用 update(plan_aggregate.cpp:342-348;row_aggregate.cpp:66-77)。
12. ORDER BY 聚合在计划期被替换为链表缓冲+整体排序的包装器,string_agg 等本体不感知排序;排序键可证明冗余时 ORDER BY 直接消除(sorted_aggregate_function.cpp:209、266-282、580-585;string_agg.cpp:9-14)。
