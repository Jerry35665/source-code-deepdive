# 第 27 章 · 统计传播与 zone map 剪枝:一套统计,两条消费链

> 基线:commit `7e886f44`。核心:src/optimizer/statistics/(statistics_propagator.cpp 与 operator 推导)、src/include/duckdb/storage/statistics/、src/storage/table/ 的剪枝消费端。

## 27.0 全景:统计的两条链

```
 BaseStatistics(8 类:NUMERIC/STRING/LIST/STRUCT/BASE/ARRAY/GEOMETRY/VARIANT)
   ①优化期:StatisticsPropagator 后序遍历逻辑计划,statistics_map 自叶向根累积
     Filter 收紧:X<C ⇒ max 收到 C;X=C ⇒ min=max=C;普通比较 ⇒ CANNOT_HAVE_NULL
     五态分类:ALWAYS_TRUE/TRUE_OR_NULL/ALWAYS_FALSE/FALSE_OR_NULL/NO_PRUNING
   ②执行期:zone map 两层剪枝(row_group.cpp)
     row group 级 CheckZonemap(:738-808)+ segment 级 CheckZonemapSegments(:810-849)
 动态过滤:join build 完成发布 → 扫描端 gstate 快照合并 → 运行期标量函数判定
```

纠偏:过滤器体系已**整体重构为表达式化**——ConstantFilter/InFilter/NullFilter/ConjunctionFilter/DynamicFilter/BloomFilter 全部 DEPRECATED(仅为反序列化保留的 Legacy 类型,table_filter.hpp:22-34),运行时统一为 `ExpressionFilter` 内嵌任意 bound 表达式;动态过滤变成内部标量函数 `__internal_tablefilter_dynamic`+共享 `DynamicFilterData{comparison_type, constant, atomic<bool> initialized}`(table_filter_dynamic_function.cpp:19-21, 129-158)。

## 27.1 统计类型的真面目

纠偏:字符串统计**没有 "contains 位图"**——实际是 12 字节截断 min/max+unicode 标志+三种长度统计(string_stats.hpp:26-63);也没有 JSON 统计类型,最新增的是 VARIANT 统计(带 shredding 状态,variant_stats.hpp:14-26)。struct 第一"子列"就是 validity 统计的挂靠处(column_data.cpp:57);ListStats 只有单一子统计,list_entry_t 的 min/max 更新被显式置空(base_statistics.hpp:191-193)。优化器拿到的列统计是**全表合并值**的拷贝(data_table.cpp:1560-1565),distinct 统计独立存放。

## 27.2 zone map 剪枝:两层都在存储层

PhysicalTableScan 只透传 TableFilterSet(physical_table_scan.cpp:41-47);row group 级剪枝在 `RowGroup::CheckZonemap`(row_group.cpp:738-808,InitializeScanInternal 调用),segment 级在每个 2048 行边界 `CheckZonemapSegments`(:810-849)。两个谨慎点:**动态过滤因运行期可变对 segment 结论永不缓存**(column_data.cpp:442-445);未提交 updates 的统计与 segment 统计冲突时放弃剪枝(:453-465)。struct 子列直接下推靠 StorageIndex::IsPushdownExtract 抽子统计(:515-523)。

## 27.3 统计与执行器的反哺链

join 条件统计写入 JoinCondition 后,执行期直接用于完美哈希 join 的整数键值域判定(propagate_join.cpp:102-104 → physical_hash_join.cpp:275-286);运行时过滤器由 hash join build 完成时发布(:1141-1145, 1519-1547)。传播的两个入口:主入口 STATISTICS_PROPAGATION pass(optimizer.cpp:457-463,含 DML CTE 整体跳过);副入口 FilterStatisticsOptimizer 以 FILTER_SIMPLIFICATION 模式跑,专门简化跨 binding 的 filter 并重跑 pushdown(filter_statistics.cpp:37-75)。基数传播:join 取乘积(hugeint 防溢出)、union 取加法、集合操作取最大。

## 27.4 设计动机

1. **一套对象两条链**:优化器收紧的统计与存储 zone map 同构,删恒真/剪枝共享语义(base_statistics.hpp);
2. **表达式化过滤器**:任意 bound 表达式皆可下推,旧七种过滤器类型退役(table_filter.hpp:22-34);
3. **动态过滤不缓存**:运行期可变结论永不写入 segment 缓存,保正确性(column_data.cpp:442-445);
4. **统计只读存储**:收紧只改优化器副本,绝不写回(propagate_filter.cpp);
5. **CANNOT_HAVE_NULL 传播**:普通比较顺带断言非空,validity 剪枝白赚(propagate_filter.cpp:51-56);
6. **DML 跳过传播**:含 DML CTE 的计划整体跳过统计 pass,防改写副作用(optimizer.cpp:456)。

## 27.5 FAQ

**Q1:字符串有 contains 统计吗?**
没有,是 12 字节截断 min/max+长度统计(string_stats.hpp:26-63)。

**Q2:zone map 剪枝在哪层?**
存储层两层:row group 级+segment 级(2048 行);扫描算子只透传过滤器(row_group.cpp:738-849)。

**Q3:InFilter 还在吗?**
DEPRECATED,运行时统一 ExpressionFilter(table_filter.hpp:22-34)。

**Q4:动态过滤会缓存吗?**
对 segment 永不缓存(运行期可变)(column_data.cpp:442-445)。

**Q5:统计会写回存储吗?**
不会,传播只改优化器内存副本。

**Q6:两列比较能互相收紧吗?**
能:i<j 交叉收紧 i.max 与 j.min(propagate_filter.cpp:105-125)。

**Q7:join 统计怎么反哺执行?**
条件统计供完美哈希 join 判定整数键值域(physical_hash_join.cpp:275-286)。

**Q8:validity 统计挂哪?**
struct 的第一个"子列"(child_states[0])(column_data.cpp:57)。

**Q9:DML 计划跑统计传播吗?**
含 DML CTE 整体跳过(optimizer.cpp:456)。

**Q10:基数怎么传播?**
join 乘积(hugeint)、union 加法、集合操作取最大(propagate_join.cpp:209-301)。
