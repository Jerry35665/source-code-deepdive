# 第 04 章 · IO 与视频:imgcodecs、videoio 与后端工厂

> 基线:commit `d3d247f1`。核心:modules/imgcodecs/src/loadsave.cpp 与 modules/videoio/。

## 4.0 全景:两条管线

```
imread("a.png"):读文件头 maxlen 字节→遍历解码器表逐个 checkSignature(前缀 memcmp)
  →命中即 newDecoder→readHeader→calcType(flags 定类型)→readData→EXIF 旋转/缩小收尾
  (读靠内容,不看扩展名——对改名的 raw 文件鲁棒)
VideoCapture::open("f.mp4"):CAP_ANY 按注册序轮询后端
  优先级=1000-i*10:FFMPEG(1000)>GSTREAMER>…>MSMF>DSHOW>V4L2>…>CV_IMAGES>CV_MJPEG
  每后端 createCapture→isOpened?用它:继续下一个(逐后端可归因日志)
imencode(".png",img):写靠扩展名选编码器(findEncoder);params 是 int 键值对向量
```

## 4.1 imgcodecs 细节

编解码器注册表按 HAVE_* 门控装入 14 类 wrapper:libpng 与 libspng 双实现互斥注册(SPNG 优先)、libjpeg-turbo、libwebp、libtiff(多页主力)、OpenEXR(唯一允许非常规通道数的特例)、AVIF/JXL/OpenJPEG、自研 BMP/PNM/HDR/GIF、GDCM(DICOM 只解码)/GDAL(遥感,IMREAD_LOAD_GDAL 旁路签名探测)。IMREAD_* 语义三件事:calcType 类型推导(非 UNCHANGED 未给 ANYDEPTH 强制 8U)、REDUCED 缩小(JPEG 解码器内部直接降采样,其余 resize 收尾)、EXIF 方向旋转。护栏:OPENCV_IO_MAX_IMAGE_* 环境变量默认限 2^30 像素(解压炸弹);imread 失败返回空 Mat 不抛异常——**二十年公开 API 承诺**。imencode 的 int 键值对参数三级容错:本编码器认识生效/别家认识警告忽略/没人认识忽略——`std::vector<int>` 是 ABI 稳定的可扩展协议。

## 4.2 videoio:后端工厂与 FFmpeg 宏解耦

后端 ID 是稳定历史数值(CAP_FFMPEG=1900 等);优先级由数组下标派生,两个环境变量可覆盖(OPENCV_VIDEOIO_PRIORITY_<NAME> 调单个/设 0 禁用,PRIORITY_LIST 重排全部);文件/相机/Writer 是三张不同的投影表。**cap_ffmpeg_impl.hpp(3600 行)是与 FFmpeg API 断层的全部减震器**:标尺 CALC_FFMPEG_VERSION 对每处断点给出带上游 APIchanges 链接的宏(codec 字段→codecpar、PTS 改名、send_frame 新 API、FFmpeg 8.0 旋转元数据第三次搬家);对外收敛成 C ABI 使 FFmpeg 后端可编译成独立插件——这也是 Windows 预编译二进制规避 LGPL 的包装方式。帧序=dts 到帧号的换算(fps×sec+0.5);无 MCAP 组件(grep 证实)。

## 4.3 T-API 交集(如实)

imgcodecs 完全无 UMat 路径——静态图解码本质是第三方库的 CPU 指针 API,单帧小,GPU 往返通常亏;videoio 唯一例外是 FFmpeg 硬解:retrieveFrame 检测到 UMat 时尝试零拷贝(帧已在显存的窄门)。

## 4.4 设计动机

1. **读靠内容写靠声明**:读端可能来自网络/改名;写端格式是用户意图,扩展名最自然;
2. **后端枚举显式**:用户可钉死后端屏蔽静默回退;运维可用环境变量重排;日志逐后端归因;
3. **FFmpeg 宏兼容层**:同一份源码覆盖十余年 API 跨度(0.7.x 到 FFmpeg 8.0),断点收进约 20 个版本宏;
4. **imgcodecs 不走 UMat**:单帧小、GPU 往返亏;只有"帧天然在 GPU"的硬解才值得开窄门;
5. **内嵌第三方**:Windows 无包管理器,内嵌保证开箱即用;FFmpeg 许可证不能内嵌就退化为预编译二进制+C ABI 插件;
6. **int 键值参数**:ABI 稳定的可扩展协议,新参数不破坏二进制,未知键只警告不失败。

## 4.5 FAQ

**Q1:imread 怎么认格式?**
文件头前缀 memcmp 比对解码器签名表,完全不看扩展名。

**Q2:imwrite 为什么看扩展名?**
写格式必须由用户显式选择;findEncoder 匹配编码器声明的扩展名串。

**Q3:PNG 解码器有两个?**
libpng 与 libspng 双实现互斥注册,SPNG 优先(轻量安全替代)。

**Q4:VideoCapture 能钉死后端吗?**
能:构造传 CAP_FFMPEG 等 ID;或环境变量重排优先级。

**Q5:FFmpeg 版本差异怎么处理?**
CALC_FFMPEG_VERSION 宏对每处 API 断点条件编译,每条锚定上游 APIchanges。

**Q6:解压炸弹有防护吗?**
OPENCV_IO_MAX_IMAGE_WIDTH/HEIGHT/PIXELS 默认限 2^20 边长 2^30 像素。

**Q7:多页 TIFF 怎么读?**
imreadmulti:nextPage 快进后循环 readData;imcount 惰性数页。

**Q8:视频帧时间戳哪来?**
FFmpeg 后端 dts/pts 换算 fps×sec+0.5 为帧号;首帧偏移记入 dts_delay。

**Q9:硬件解码输出能进 UMat 吗?**
能:FFmpeg 硬解的 UMat 零拷贝窄门(cap_ffmpeg.cpp:109-114)。

**Q10:JPEG 质量 95 怎么传?**
imencode params 键值对:IMWRITE_JPEG_QUALITY=95;未知键警告忽略不失败。
